# Presentation craft

目标是让听众看清研究问题、方法与证据，并能参与讨论。默认重点照顾**论文组会**和**自己的实验进展**：由数据制作的图表、原始证据和结果是视觉中心，解释靠近证据，结论保留条件。学术风格不等于白底列表，也不等于商务路演中的大数字、口号和装饰卡片。

使用宿主已有的 AI 和免费的本地制作、渲染工具；不依赖额外付费 API、素材库或云平台额度。软件免费不表示宿主 AI 额度免费，也不表示每个开源模型都同样可靠。

## 接收任务

读取材料与明确要求，确认听众、用途、时长、播放软件、输出格式、语言、必须呈现的证据和参考风格。只有缺失信息会实质改变内容或交付时才询问；其余采用可逆默认并说明。未指定时用中文、16:9、完整可编辑 PPTX 和可重建源文件。论文阅读默认从“清晰学术”或原图较多时的“黑白论文”开始；实验进展默认从“实验手记”开始。学校模板与用户指定风格优先，不要求每次先选样式。

现场汇报只在需要分步解释的方法、推导或对照页加入基本的按点击出现，其他页保持静态；用户要求静态时遵从。根据材料和时长决定页数，不机械固定模板或页数，也不按“一分钟一页”硬套。

用户只要提纲、设计或局部修改时遵守该范围。改已有文件先保留副本，只改指定内容及必要的关联页，不重新提取所有原材料。

## 根据成品选择工具

实际制作或修改成品文件时，先读 [工具与运行](references/toolchains.md)，探测当前可用依赖；仅需提纲、选型或设计建议时不启动工具链：

```text
python scripts/doctor.py
```

- 默认选择 PptxGenJS 直接创建 PPTX，适合原生文本、表格、数据图与后续编辑。
- 基本的逐条出现、图片依次显示和流程分步优先使用原生 PPTX 动画；读 [基本动画](references/basic-motion.md)，生成后按明确的内容步骤添加出现或淡入。不能因需要基本动画就改交付为网页、PDF 或多张静态副本。
- 公式、代码、交互或网页视觉更重要时，可选择 Slidev；交付实际 PPTX/PDF，或用户接受的离线网页。
- 用户给模板时优先保留模板的母版、字体与内容结构，避免转换造成无谓损失。
- 不为了流程完整同时运行多个生成引擎。图片式 PPTX 适合固定展示；如果用户要求可编辑，不能将整页图片冒充可编辑成品。说明复杂图形和公式的实际编辑边界。

依赖尽量复用宿主运行时，代码、素材和 QA 放在任务目录，不放在技能目录。缺工具时安装最小的免费依赖到任务或专用环境；遵守宿主权限，不能改全局配置来绕开限制。无需新增 plugin、永久 MCP 服务、浏览器账户或云订阅。

## 从材料到设计

1. **建立论证。** 读 [内容与证据](references/story-and-evidence.md)，区分作者主张、报告者解读与自己的实验结果。给每页写清作用、一句主旨、支撑证据、必要条件和讲述过渡；丰富的解释放入备注或附录。用户有详细要求时保留覆盖表，避免为了好看漏掉必需内容。
2. **选择样式。** 读 [视觉设计](references/design.md)；从 [12 种学术样式](references/styles.md) 选择匹配内容的方向。可查看 [实际 PPTX 样张](assets/style-gallery.pptx) 和 [样式总览](assets/style-overview.png)，并从 [主题参数](assets/themes.json) 读取配色、字号和构图约定。用户要选项时，用同一内容展示 2–3 个匹配候选；不把 12 种风格混进一套正式汇报。样张包含明确标记的演示数据，不能迁入用户的研究结果。
3. **选择页型。** 科研图、方法、公式和结果表等页面读 [学术版式](references/academic-layouts.md)，按证据形状选择大图、总览与局部、方法流程、结果对照、消融、失败分析或决策页。不要逐页照搬样张，更不要把所有内容装进相同三卡片。
4. **选择图表。** 有数据需要新制图或表时，读 [数据图表与表格](references/charts-and-tables.md)。按要比较的大小、趋势、分布、关系、组成、矩阵或三维结构选择图形；需要精确查值时选表。决定主图、直接标签、重点注释和对照尺度，让图表承担论证；不能只贴默认图，也不为丰富种类硬塞饼图或三维图。这里指导选型与展示，不要求重学数据处理或绘图库。
5. **试做再扩展。** 新稿先做一页核心方法、一页最密集的证据，并带入真实长中文标题和中英文混排；渲染检查后扩展全稿。数据图的试做要包含实际轴、图例、单位和注释，不能只检查外层标题。已有明确方向时直接制作。参考须实际查看，标明内容参考还是视觉参考；没有外部标杆就据实说明是本次设计判断。
6. **制作成品。** 保持全稿字体、间距、图表语义和引用位置一致，按页面职责变化构图。图表用真实数据或原图；原始科研图不能被生成式绘图重画而改变数值。保留图注、单位、误差和必要限定。公式、表格和原图的字太小时，优先删去非必要信息、拆分或放大，不先缩小全页字号。

样张是可编辑的构图起点，不是现成的完整论文汇报。需要重建或只比较部分样式时：

```text
python scripts/build_style_gallery.py --output task/style-options.pptx --theme seminar-blue --theme lab-teal
```

样张使用本机可用的 `python-pptx`；普通新稿仍优先原生 PPTX 路线。源稿中的主题参数应随任务保留，不引入机器专属路径。

需要数据图表的视觉参考时，可查看 [图表与表格样张](assets/chart-gallery.pptx) 或 [图表总览](assets/chart-overview.png)。这些示例从演示数据生成，覆盖部分常见图型，不是给正式稿套数据的通用脚本；重建入口为 `scripts/build_chart_gallery.py --help`。

## 审查实际输出

用 [质量检查](references/quality.md) 对内容、画面与导出分别检查。动画在最终文件上添加，再做审查。下列脚本只是确定性的辅助，不判断学术真实性或审美，也不替代看图和放映。

```text
python scripts/audit_pptx.py task/deck.pptx --report task/qa/audit.json
python scripts/render_pptx.py task/deck.pptx --out-dir task/qa/render-01
```

查看每页实际渲染图；同时在缩略图总览检查节奏、风格和重复布局。清楚区分：阻断阅读的缺陷、主要视觉落差和个人偏好。先修缺字、截断、重叠、数据/引用错误，再修构图、层级、图片质量和视觉一致性。无溢出只是底线，不代表美观。

修订后重新生成、审查受影响页面；最终审查必须对应最终交付文件。记录 `qa/review.json`，格式见质量参考。需要交付 PPTX 时，可核对证据是否对应当前文件：

```text
python scripts/finalize.py task/deck.pptx --audit task/qa/audit.json --render task/qa/render-01/manifest.json --review task/qa/review.json --report task/qa/final.json
```

不能伪造看图记录或修改检查结果来绕过已知缺陷。工具不足时换可行的免费路线；仍不能渲染实际成品时，说明未完成视觉验证，不把仅浏览器预览或 XML 检查写成导出验证通过。已明确接受草稿的用户可以收到带准确限制说明的草稿，不冒称完成。

含动画的成品需要检查实际放映中的初始显示、每次点击、返回和重播；静态 PDF/PNG、XML 节点或演示软件导入成功不能替代放映检查。记录实际检查范围，播放环境不可用时明确说明未验证的部分。

## 交付

交付请求的最终格式及足够重建/继续修改的源稿和本地素材。通常 PPTX 加源文件即可；PDF、预览总览、附录按用户要求或实际需要提供。QA 与试验文件保留在任务目录，不把它们全部塞给用户。

简要说明内容与设计选择、实际可编辑程度、做过的检查及剩余限制。仅有生成成功不能保证“各方面都好”；根据真实成品报告结果，不给没有依据的综合分数或保证。
