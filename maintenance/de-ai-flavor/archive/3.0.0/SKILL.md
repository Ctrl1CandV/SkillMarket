# 去 AI 味：剥掉机器习气，写自然的现代汉语

把绕口、僵硬、套路化的机器腔洗干净，换成动词清楚、语序顺畅、呼吸自然的中文。

**事实底线**：保留原文的事实、数字、专名、否定、条件与概率限定（如“初测”“仅在”）、引用归属及固定界面文案。只用已有材料展开；缺失关键信息时直接询问或标出待补，绝不为显得生动而编造个人经历、数据或产品承诺。

## 一、有样稿时：先抓声线再动笔

若提供了作者原稿或样稿，动笔前先从样稿提取四项可观察特征，按这套声线写或改：

1. **句长与停顿**：看单句通常包含几个分句，长句与短句如何交替。
2. **衔接方式**：看句间是靠语序和主语省略直接推进，还是习惯使用特定的过渡词。
3. **人称与口语颗粒度**：看样稿是用“咱们、你”像老同事当面点拨，还是用平实书面语；样稿若带鲜活的口语词和吐槽劲道（如“别一上来就……”“多半是……”），新稿直接沿用同档颗粒度的口语词，绝不把作者原有的鲜活腔调洗成温吞的标准书面语。
4. **进场与收束劲道**：看开头是直接拿反面教训当头点醒还是先摆现象，结尾是留一句接地气的忠告还是讲完即止，照着同样的劲道起落。

没有样稿时，按目标读者与文体场景直接采用下方的现代汉语习惯。

## 二、六类高频 AI 习气与直接改法

当前模型的“AI 味”主要集中在句法包裹、形合过度与结构强迫症。定位具体句段的问题后，按右列动作直接动刀：

| 高频 AI 习气 | 典型病灶 | 直接改法 |
| --- | --- | --- |
| **1. 虚词外壳与名词化** | 用“进行……的处理”“作出……的调整”“在……层面呈现出”“实现对……的覆盖”把普通动作包成抽象名词 | 剥掉虚词外壳，让具体动词直接做谓语，写清谁做什么 |
| **2. 欧化长定语与生硬被动** | 一个名词前连套两三个“的”字长定语；生硬套用“被……所……”“由……来进行” | 拆成汉语流水短句，把前置长定语改写为后置分句或谓语 |
| **3. 连接词拐杖（形合过度）** | 句句离不开“因此、然而、此外、与此同时、值得注意的是、换言之、从某种意义上说” | 顺承与明显因果靠事理先后和主语承前省略直接咬合；仅在真实转折或易混条件处保留连接词 |
| **4. 总分总套路与段尾回音壁** | 每段先戴概括帽、中间凑三点，段尾必加“可见……”“总而言之……”“这不仅……更……” | 按读者关心的问题排顺序；事实或道理讲完立刻停笔，删去段尾同义复述与价值升华 |
| **5. 四字格堆砌与工整对仗** | 连续排布“深入浅出、循序渐进”“精准发力、全面赋能”；生造“不是 A，而是 B”的假对立；句句等长 | 换回具体动作、现象或数据；有几条写几条，用长短句交错打破节拍器式的均分节奏 |
| **6. 半空说教、客服腔与制作痕迹** | 用“需要指出的是、本质上”端架子；报错提示写成公关软文；正文残留“本模块为新增、以下是优化版” | 平视读者，直说状态与下一步动作；直接删去混在正文里的布局与版本制作话语 |

## 三、三组核心改法对照

### 1. 剥掉虚词外壳 + 砍掉连接词拐杖与段尾回音

AI 习气稿：

```text
在日常数据同步层面，系统会针对近期产生的查询结果进行本地缓存处理。因此，当相同的请求再次到来时，系统就能够实现对已有结果的直接复用，从而有效降低重复计算的开销。此外，值得注意的是，缓存中的数据在时效性方面存在过期的风险。总而言之，合理利用缓存机制是平衡响应速度与数据新鲜度的关键一环。
```

自然好稿：

```text
系统会把近期的查询结果缓存在本地。同一请求再次到来时，直接复用旧结果，省去重复计算。不过缓存里的数据会过期，对实时性要求高的接口要单独设有效期。
```

### 2. 拆开欧化长定语 + 打破假对立与空泛四字词

AI 习气稿：

```text
这不仅是一套由多部门联合整理并经过三轮现场核对的设备维修台账，更是一场跨越时间的工程对话。它通过全面覆盖、精准追溯的管理闭环，为后续排查工作的高效开展奠定了坚实基础。
```

自然好稿：

```text
这本维修台账由三个部门一起整理，现场核对过三轮，按月份记清了每次故障的原因和换件记录。后续设备再出同类毛病，翻一下就能对上历史处理办法。
```

### 3. 去掉客服煽情与制作话语

AI 习气稿：

```text
【新增上传模块】很遗憾，您的文件探索之旅遭遇了小小挑战！由于当前文件体积突破了 20 MB 的边界，让我们共同将它压缩后再重新开启上传吧。
```

自然好稿：

```text
文件超过 20 MB，请压缩后重新上传。
```

## 四、执行路径

### 从零撰写

1. **定读者与用途**：确认给谁看、用来做什么。通知先写事项与行动，技术说明按操作依赖排步骤，评论与文章直奔核心问题，跳过“背景—意义—三点—展望”模板。
2. **先立具体内容，再顺呼吸**：材料有多少就写多实在；需要展开篇幅时，靠推导过程、因果条件和具体例子推进，省去同义复述。
3. **朗读去刺**：默读一遍，拆开一口气读不完的长定语，删去顺承句首多余的“因此、此外”和段尾的总结帽。

### 修改已有文本

1. **先抓结构与复述，再改词句**：合并翻来覆去说同一件事的句段，把真正有信息量的句子留下来；随后剥掉“进行、实现、在……层面”等虚词外壳。
2. **保护有效内容**：专业术语（如“闭环控制”“宿主环境”）、真实纠错（如“这不是备份，而是同步，删掉本地文件也会同步删掉云端”）、必要推导步骤和限定词原样保留。
3. **适可而止**：已经自然清楚的句子直接留用，维持原文合理的长短句变化与个人印记。

## 五、交付自检

1. 动词是否直接出现，长定语是否已经拆顺？
2. 删掉句首的“因此、此外、同时”和段尾的总结句后，上下文是否依然紧扣？
3. 数字、专名、否定、范围限定与证据强弱是否与材料完全一致？
4. 语气与格式是否契合当前载体（按钮用短词，正文与讲稿用完整句子）？

默认只输出可直接使用的成品正文，省去前导寒暄、分隔线与修改备注；仅在用户明确要求审校或解释改动时，才列出具体病灶与修改理由。
