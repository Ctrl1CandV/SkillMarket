# write-with-judgment 1.0.0 重构与 pi 对照实测报告

日期：2026-11-21
模型：`deepseek/deepseek-flash`（`pi 1.6.0`，`--mode json --tools read`，自然触发，不加 `/skill:` 强制前缀）

## 一、重构要点（0.2.1 → 1.0.0）

1. **静态指标（否定与对冲词密度）**：
   - `0.2.1`（4 个文件）：非代码正文 7,117 字，否定与对冲词 **75 处**，平均 **94.9 字/处**（导致严重的“审稿人瘫痪”与对冲腔）。
   - `1.0.0`（`SKILL.md` + `references/exemplars.md` + `references/revision-and-diagnosis.md`）：非代码正文 5,828 字，否定与对冲词仅 **3 处**，平均 **1,942.7 字/处**，主文件 2,610 字（≤ 3,000 字）。
2. **核心内容改动**：
   - 彻底摒弃 `0.2.1` 的二阶抽象评论腔（“使内容在阅读中成立”“承担相称的分量”）和研究认识论免责条款（“删除后效果仍在不证明原表达无作用”），改用短促、笃定、动作导向的现代汉语重写。
   - 建立 **4 个正向写作生成动作**：
     1. **切口**：第一段直接踩在支点上（反直觉区分 / 具体卡点 / 在场细节 / 核心决定），砍掉万能助跑开场；
     2. **写厚**：当材料只有干瘪结论时，靠“算清具体反差、往前推一步因果、标明适用处境与边界、摊开真实取舍”从已有材料内部长出内容；
     3. **走势**：按“问题推进”安排详略与操作时机（边看边做的前提必须写在动作前面；叙事悬念允许先抛现象后解释）；
     4. **声音与留白**：平视读者，守护个人经历与情感中的“未知边界”（原作者说不清原因时不替其编造心理分析与童年往事），在最有分量的地方停笔。
   - 新增 `references/exemplars.md`（覆盖说理分析、教学操作、叙事随笔、工作汇报四类文体的 7 组完整“平庸稿 → 有判断力的好稿”对照与动刀拆解）与 `references/revision-and-diagnosis.md`（实质改稿病灶表与 4 步极简审校诊断框架）。

## 二、pi 实测设计（4 题 × 3 组）

所有评测输入均独立于技能内范例：
- `01-data-reasoning`：客服组 5 笔退款响应耗时（`10、12、15、13、200` 分钟，最后 1 笔因跨行清算接口夜间维护卡 3 小时），把组长一句干瘪的“平均 50 分钟、中位数 13 分钟，建议改看中位数”改写为既有内部数据推导、又划清管理边界的周会汇报。
- `02-narrative-emotion`：收拾爷爷旧工具箱看到缠黑胶布的羊角锤，保留“记不清小时候看他钉过什么、说不清为什么偏偏那天下午难受”的真实未知状态，测试是否会越界编造往事或强行升华。
- `03-timing-and-comm`：整合两段零散材料（顺序写反的订单库分片迁移步骤 + 原因尚在联合风控组排查的积分兑换模块延期上线），测试操作前提重排与未知原因的事实分寸。
- `04-diagnosis-only`：对一篇“头尾全是云原生套话、中间有一句‘半夜三点的误报把值班员训练成了对真正故障麻木的人’极佳、第三段措施同义反复且归因自相矛盾”的技术短文做只作诊断/审校。

组别：
- **A 组**：无技能基线
- **B 组**：挂载旧版 `write-with-judgment 0.2.1`（自然触发）
- **C 组**：挂载新版 `write-with-judgment 1.0.0`（自然触发）

## 四、关键质量差异与中途调优

1. **01 数据说理：从“公文小标题+列表”变为连贯有劲道的推演段落**：
   - A 组（无技能，1206 字）列了 3 个大标题 + 4 个列表项，像规章制度汇编；B 组（旧版）末尾还带了一句防御性的括号免责声明“（文中 12.5 分钟……均由这 5 笔工单算出，未引入外部数据）”。
   - C 组（新版，891 字，0 标题、0 列表、0 显性连接词）一气呵成：直接算清“第五笔 200 分钟一笔就顶另外四笔加起来（50 分钟）的四倍……50 分钟这个数里有八成来自一次夜间接口维护”，接着自然推进到“中位数回答的是另一个问题”，再交代“那 200 分钟不能从报表里消失，有三类问题只有它能回答”，最后点明“上周只有 5 笔，样本太小，等工单量上来建议加看 P90，先别把 13 分钟当成固定标准写进制度”。
2. **02 情感随笔：守住事实与留白，告别虚构物理细节与长篇解释**：
   - A 组（无技能）和 B 组（旧版）都忍不住替作者编造了原文没有的感官细节（A 编了“铁皮响了一声、铁锈混着机油的味道”；B 编了“常年握着的那一段磨得发亮、锤头一侧有锈、挪出来的东西摊了一地没接着收拾”），且都在正文后附了大段“改动说明”。
   - C 组（新版，239 字，0 额外说明）只把动作推进理顺（“上面的东西得一样一样挪开，才够得到箱底……我伸手去拿，握住的瞬间才发现，锤头比看着要沉。就是这一下，眼睛忽然热了”），严格停在“到现在我也没想明白”，干净克制。
3. **03 操作时机与通知：中途补强 `description` 与“篇幅相称”提示**：
   - 首轮运行中，`03-timing-and-comm-C` 把两句话的延期通知扩写得偏长（3,539 字节），并在正文里写出了“目前能确认的和还不能确认的，需要分开来说”的分析台词。
   - **修正**：在 `SKILL.md` 第二节补入“**篇幅与文体相称**：日常工作通知、变更邮件与操作清单以清爽够用为准……绝不把两句话的延期通知扩写成冗长规章，也不在正文里写‘以下区分已知与未知’之类的分析台词”，并在 `description` 中显式纳入“操作说明、工作汇报、通知邮件”，在第五节末尾补入“**交付约定**：新写与改稿默认只输出可直接使用的成品正文”。
   - **复测结果**：`03-timing-and-comm-C` 自然触发（`tools=1`），篇幅回到紧凑的 552 字（1,954 字节），既将“1. 先切只读 → 2. 再查未决事务 → 3. 执行迁移 → 4. 观察新分片写入 QPS”按防踩坑顺序排好、点明“带着未决事务执行迁移时，切换后这些事务会落到新分片上，与旧分片已有主键发生冲突”，又清爽交代了延期影响与下午三点的排查安排。
4. **04 只作诊断：一针见血的审校与改写样板**：
   - C 组主动读取了 `SKILL.md` 和 `references/revision-and-diagnosis.md`（`tools=2`），第一句整体印象直指要害：“三段像是三个人写的。第二段是现场，头尾是会议纪要。读到第三段开始发闷，原因是刚被第二段立起来的问题，第三段又原样说了一遍，一个字没往前推，还顺手把归因掉了个头。”
   - 在第四部分给出的改写样板中，C 组主动用 `〔待确认：目标量〕`、`〔待确认：误报率上限〕` 标出原稿缺失的验收数字，示范质量明显优于 A 组和 B 组。
