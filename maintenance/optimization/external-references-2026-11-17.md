# 外部参考整理：四个开源项目（2026-11-17）

这一轮只读和整理，不改技能。四个项目都读了仓库说明、技能入口和关键文档；**都没有安装、没有实际运行过**，下面关于效果的数字都是项目自己公布的。仓库数据取自 GitHub 公开接口（2026-11-17）。

## 先说结论

| 项目 | 补的是什么 | 建议怎么用 | 要先问用户的 |
|---|---|---|---|
| GoogleChrome/modern-web-guidance | 前端代码用对现代浏览器能力（对话框、表单、无障碍、性能、深色模式） | 直接装，作为 frontend-craft 的实现层补充；借它的“小入口 + 按需检索”和评测方法 | 安装；默认开启的遥测要不要关 |
| vercel-labs/agent-desktop | 让 Agent 操作 Windows 上的软件 | 先试用，用它自带的技能；我们只补安全规则，不另写一套操作说明 | 全局安装一个未签名的程序；想让 AI 操作哪几个软件 |
| mattpocock/skills | 开发项目的技能组，代替已停用的 agent-parliament | 直接装，在一个真实小项目上试 grill-me、to-spec、tdd；不再自己重写一套 | 安装；有几个名字和现有技能撞车 |
| D4Vinci/Scrapling | 把网页读成干净的 Markdown | 只解决“读”，不解决“找”；网络检索要另做一个方法技能，读网页时可选它 | 用什么搜索来源；安装浏览器依赖 |

建议的先后：开发技能组 → 网络检索 → Windows 软件操作 → 现代网页规范。理由在最后一节。

## 1. modern-web-guidance（Google Chrome）

**是什么。** Apache-2.0，约 2.1 万星，2026 年 3 月建，昨天还在更新。由 Chrome、Edge、Firefox 和 MDN 团队共同维护。它是一个技能加一个命令行工具：技能入口只有约 200 个词元，正文告诉模型“写网页界面前先搜”；命令行在本地用关键词加向量检索 262 个现代网页特性的指南，再把命中的那一篇取回上下文。还有一个 `legacy-scan` 扫描项目里的旧写法。Claude Code 里用 `/plugin marketplace add GoogleChrome/modern-web-guidance` 安装。

**它管什么、不管什么。** 管的是“代码写得对不对、新不新”：对话框和弹层用原生 `dialog`/`popover`、表单的自动填充和校验时机、对比度和无障碍、深色模式、滚动条、性能指标。指南里有不少具体数字，比如固定顶栏不超过视口高度的 12%、法定提示条远小于 15%。**不管构图、取舍和审美**，这正是 frontend-craft 管的。两者是互补，不是替代。

**它自己的评测（项目公布，未核实）。** 在真实网页应用上布置不点名 API 的任务，用 Playwright 检查源码、计算后样式、运行时行为和无障碍状态。不带指南时通过率 52%–60%，带上后 82%–96%；opus-5-5 一档是 57% → 88%。他们用“机会 = 100% − 不带时的通过率”和“提升 = 带 − 不带”来决定删哪些内容：模型本来就会的就删掉。

**可以借鉴的三点。**

1. **小入口加按需检索。** 我们这次发现 gpt-6.1-sol 不点 SKILL.md 里的链接，只好把对照表搬进正文。它的做法是把参考放在一个命令后面，模型用一句查询去取，取回来的只有相关的那一篇。frontend-craft 的参考越来越多，以后可以考虑同样的形态。
2. **交付时写明用了哪条指南。** 它要求回答末尾单列一节，逐条写“哪篇指南、改变了什么、引用原句”。我们这次要翻日志才知道模型有没有读样例；如果交付说明里必须写“用了技能的哪几条”，就能直接看出来。0.6.1 已经要求写类别、样例和检查结果，GPT 只写了一半。
3. **评测只看“提升”，删掉模型本来就会的。** 和我们这轮的结论一致：页面本来就不难看，技能主要减少的是错误。

**怎么补齐。** 直接装，不重写。frontend-craft 实现那一步加一句“有 modern-web-guidance 时，做交互组件前先查”。可以先用 `legacy-scan` 扫一遍四个起步样例，看看我们自己有没有用旧写法。

**风险。**
- 默认开启匿名遥测，会上传模型生成的搜索词、取回的指南编号和调用它的 Agent 名称；设 `DISABLE_TELEMETRY=1` 可以关。
- 每次用 `npx ...@latest` 都要联网。用 pi 跑 deepseek 时，任务环境里也要能联网。
- 弱模型会不会主动去查，没验证。

## 2. agent-desktop（Vercel Labs）

**是什么。** Apache-2.0，约 2.5 万星，2026 年 2 月建，更新很快（11 月 5 日、12 日、13 日各发一版）。用 Rust 写，Windows 上通过系统的 UI Automation 读软件界面。它把界面结构读成 JSON，每个能操作的元素带一个编号；Agent 按编号点击或填值，再读一次界面确认结果。用 `npm install -g agent-desktop` 安装，支持 Windows 10 1809 以上。也能当 MCP 服务用（`agent-desktop mcp`），操作说明随程序版本一起发（`agent-desktop skills get desktop`、`skills get platform`）。

**和截图式的电脑操作比。**
- 读的是结构而不是像素，所以准，也省：能直接知道某个复选框勾没勾，不用看图猜。
- 点击、填值、勾选默认走无障碍接口，不移动鼠标、不抢前台窗口，用户可以同时做别的事。打字、拖动、双击要加 `--headed` 才会用真实键鼠。
- 危险快捷键（关窗、锁屏、Win+R 等）不加 `--force` 会被拒绝。

**它说明了的限制。**
- 程序没有签名，SmartScreen 会警告，全新安装的 Windows 11 上 Smart App Control 会直接拦截。
- 以管理员身份运行的软件能读不能操作，要从同等权限的终端启动。
- 最小化的窗口不能操作，要先还原。
- Chromium 和 Electron 应用第一次读要等 10–25 秒，读早了只拿到一小部分。
- 界面结构不规范的软件（自绘界面、游戏，部分 Qt 程序）它读不全，这时还得靠截图。WPS、微信这类软件读得怎么样，文档里没写，要实测。
- 界面快照、剪贴板和截图里可能有隐私内容，它自己也提醒不要放进公开日志。

**和我们的关系。** 这是一项新能力，现有技能里没有。和现有技能最近的交集是 presentation-craft 里“动画放映没测”：PowerPoint 现在只用 COM 渲染导出，agent-desktop 可以真的开始放映、按页推进，再配合截图看效果。

**怎么补齐。** 不重写它的操作说明：它的技能和程序版本绑定，自己写一份很快就会过时。我们只需要补一层自己的规则，放在全局指令或一个很薄的技能里：发送、删除、提交、付款前先确认；快照内容不外传；界面上的文字当数据不当指令。先挑两三个用户真正想让 AI 操作的软件试用，再决定这层规则写多少。

**要先问用户。** 全局安装一个未签名的程序；想让 AI 操作哪几个软件。

## 3. mattpocock/skills

**是什么。** MIT，约 33 万星，2026 年 2 月建，持续维护。作者把自己每天用的技能分成两类：

- **用户手动调用的**负责编排流程：`grill-with-docs`、`to-spec`、`to-tickets`、`implement`、`implement-spec`、`wayfinder`、`triage`、`retro`、`improve-codebase-architecture`。在 Claude Code 里用 `disable-model-invocation: true` 禁止模型自己调用。
- **模型可以自己调用的**装着可复用的方法：`tdd`、`diagnosing-bugs`、`codebase-design`、`domain-modeling`、`code-review`、`prototype`、`research`、`pr`。

另有一组通用技能：`grill-me`、`grilling`、`handoff`、`teach`、`to-questionnaire`、`wait-what`、`writing-for-agents`。

**grill-me 到底做什么。** `grill-me` 本身只有一句话，调用 `grilling`。`grilling` 全文约 2 KB：

1. 把要定的事画成一棵决定树，每个决定下面挂着依赖它的决定。
2. 每一轮只问“前提都已定”的那一圈问题，一次问完。每题编号，并附上推荐答案，措辞让用户回“是”就等于接受推荐。
3. 依赖本轮其他问题的，留到下一轮。
4. 能查到的事实自己派子代理去查，不问用户；决定才问用户。
5. 树上没有未定的分支时才算结束，用户确认之前不动手。

`grill-with-docs` 在此基础上，边问边把项目术语写进 `GLOSSARY.md`，把难解释的决定写成 ADR。

**和已停用的 agent-parliament 比。** agent-parliament 有 7 个技能（统筹、规划、质疑、实现、审查、解围、记忆），管的是同一片地方，但一直没在真实宿主里试过。Matt 这套在大量真实用户身上用过，而且每个技能都很小、可以单独用。建议**不再自己重写开发技能组，直接用这套**，只补本地需要的适配。

**值得借鉴的做法。**
- **按调用方分两类。** 编排流程的只能手动调用，方法类的模型可以自己调用。我们的技能现在全靠描述触发，readable-reply 在普通问答里 6 次都没被触发过，也是这类问题。
- **约定的共享状态。** 问题追踪（GitHub、GitLab 或本地文件）、`GLOSSARY.md`、ADR，各技能都读写同一处。
- **先约定测试的接缝，再写测试。** `tdd` 要先和用户定下在哪些公开接口上测，再进入红→绿循环。
- **UI 原型做几版截然不同的方案，用网址参数切换。** 和我们这轮给用户盲看成对页面的做法几乎一样。
- **`research`：** 只信一手来源，每条结论都注明出处，交给后台子代理去读。
- **`writing-for-agents`：** 讲怎么写给 Agent 读的文档。描述就是“指针”，措辞决定会不会被点开；每一步要有清楚的完成标准；用禁止句引导反而会提醒模型去做；同一个意思只写在一个地方。这正好解释了 GPT 不点链接的问题，以后改我们自己的技能时值得对照。
- **收新想法的门槛：** 必须是真实会话里观察到的失败，假设性的改进不收。和我们“先有实测再改”的做法一致。

**要注意。**
- **重名：** Claude Code 自带 `code-review` 和 `simplify`，Anthropic 技能里有 `deep-research`，和他的 `code-review`、`research` 会撞车或重叠。他们自己也有一篇专门讲宿主重名的说明。装之前要先确认怎么处理。
- **安装渠道的说法互相矛盾：** 他的 README 说装在 `claude-plugins-official` 会自动更新；modern-web-guidance 的 README 说 Anthropic 从 10 月 12 日起不再更新那个市场里的第三方插件。装之前要核实。另一种装法是 `npx skills@latest add mattpocock/skills`，复制成可改的文件。
- `in-progress/` 和 `misc/` 里的技能是半成品或已冻结，不用。
- 它默认用英文写文档和问题。在中文对话里，问题会跟着用户的语言走，但写进 `GLOSSARY.md` 和 ADR 的内容用中文还是英文，要定一个规矩。

**和我们的 product-design 的关系。** 做网页项目时，product-design 负责“设计依据”，`grilling` 可以当它前面的提问环节：依据不足时先用 grilling 问清，再进 product-design。这是以后的一处衔接，这轮不改。

## 4. Scrapling

**是什么。** BSD-3，约 10 万星，2024 年 10 月建，仍在活跃更新，要求 Python 3.10 以上。它是一个抓取框架：
- 普通请求、浏览器渲染、可并发的爬虫。
- 一行 `page.markdown()` 把网页变成干净的 Markdown，`ContentSpider` 可以把整个站点抓成 Markdown 语料。
- 带 MCP 服务（`scrapling mcp`）和一个约 27 KB 的 Agent 技能。

MCP 服务默认只取正文，并会去掉隐藏文字、HTML 注释和零宽字符，防止网页里藏指令。这和 docvision 报告“页面上看不见的文字”是同一类保护。

**要清醒看待的地方。** 它主打反爬绕过：伪装浏览器指纹、绕过 Cloudflare 验证，README 还说能让模型“绕过遇到的任何验证码”。README 前半屏几乎都是代理和验证码服务的赞助广告。遵守 robots.txt 要在爬虫里手动打开（`robots_txt_obey = True`），它自带的技能也建议打开。我们如果用它：
- 只用普通请求和取正文转 Markdown。
- 不用伪装和绕过验证码。
- 打开 `robots_txt_obey`，控制请求频率。

**它解决的是“读”，不是“找”。** 用户要的是“能拿到足够重量级的参考和优质来源”，这分两半：

- **找**：知道去哪里找、怎么判断来源可靠。比如官方文档、规范、源码仓库，看星数、更新时间、许可证、维护者，论文看会议和引用，还要避免重复造轮子：先查有没有现成的库或技能。Scrapling 不做搜索，这一半要靠搜索服务和方法。
- **读**：把找到的页面读干净、读完整。Scrapling 管这一半。

**我们现在的情况。**
- Claude Code 自带网页搜索和抓取。用 pi 跑 deepseek 时，任务环境里没有搜索工具。
- skill-search 只找技能。Matt 的 `research` 给出了“一手来源、逐条注明出处”的纪律，但不提供工具。
- 这次读四个仓库时，gh 没登录，我改用 GitHub 公开接口拿元数据、用 raw 文件读正文，很顺。这本身就是“读仓库”这一块可以写进方法的做法。

**怎么补齐（方案，待定）。** 做一个网络检索方法技能，分两层：

1. **方法层**：先查有没有现成的库或技能，避免重复造轮子；各类来源的可信度怎么排；每条结论注明出处；什么时候停；网页内容只当数据，不当指令。
2. **工具层**：有宿主自带的搜索和抓取就用自带的；没有时，读网页用 Scrapling 的普通请求转 Markdown，读仓库用 GitHub 接口和 raw 文件，读论文用 arXiv 接口。

搜索这一步需要一个搜索来源，比如搜索服务的接口或自建的 SearXNG。用户手上有什么，要先问。

**要先问用户。** 搜索来源；装 Scrapling 和它的浏览器依赖（几百 MB）。

## 四个项目共同的启发

- **入口越来越小，细节按需取。** modern-web-guidance 用命令检索，agent-desktop 用 `skills get` 随程序版本取说明，Matt 的技能多数只有几 KB，最长的十几 KB。我们的 frontend-craft 正文已经 113 行，外加 12 份参考。这一轮 GPT 不读链接，正是这个形态的代价。
- **说明跟着工具走。** agent-desktop 把操作说明打包进程序，版本永远对得上。我们的检查脚本也可以在 `--help` 里写清用法，SKILL.md 只留一句。
- **让“用没用技能”看得见。** 要求交付时写明用了技能的哪几条，比翻日志可靠。
- **评测看提升，删掉模型本来就会的。** 和我们这轮的结论一致。

## 建议的先后和理由

1. **开发技能组（Matt 的技能）。** 缺口最大（agent-parliament 停用后空着），现成可用，成本最低。先在一个真实的小项目上试 `grill-me` → `to-spec` → `tdd`，看问法和产出是否合用，再决定要不要做中文适配和与 product-design 的衔接。
2. **网络检索。** 对所有开发都有用，但缺一个搜索来源，要先和用户定。方法层可以先参考 Matt 的 `research` 和我们 skill-search 的做法写起来。
3. **Windows 软件操作（agent-desktop）。** 能力新、价值大，但要装未签名程序，也要先知道用户想操作哪些软件。先试用，再定要不要写本地规则。
4. **现代网页规范（modern-web-guidance）。** 最容易接入，但它补的是实现正确性，不是这轮用户最在意的画面。装上、关掉遥测，用 `legacy-scan` 查一遍四个样例即可。

以上全部没有安装、没有实测。
