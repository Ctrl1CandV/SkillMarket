# 用 pi + DeepSeek Flash 制作《time machine》完整 MV

这次考核把整套技能交给 pi。委托只指定歌曲、完整原声、可播放的成片与可继续编辑的工程。构思、画面、分镜、时间线、试渲染和完整导出均由 DeepSeek 负责。考核目录另存到交付区，商业原曲和独立 MV 不随可分发的技能包发布。

## 音源和委托

用户指定 mj apanay feat. aren park 的录音，并给出开头供核对。从标注这两位艺人的公开下载页取得双声道 44.1 kHz AAC，原样重封装为 225.071 秒的 M4A，SHA-256 为 `725ea8a2ddae919bd44e8974aeeb9e6f9e2a01758a981a0a0c8e0576b95f8612`。无歌词提示识别到了用户给的开头。另取 Apple 官方约 30 秒试听里相隔的三个 3 秒片段，在本地与完整音源滑动比对，相关系数约为 0.9986、0.9987、0.9985；三个窗口的对齐位置均相隔同一固定时差。该比对检验了录音版本，完整片音轨另与用户实际使用的输入文件核验。[艺人发布页](https://audiomack.com/mjapanay/song/time-machine) · [Apple Music 曲目](https://music.apple.com/us/song/1733110516)

## 复验

运行环境为 Windows、pi 1.4.0、provider `deepseek`、model `deepseek-flash`，设备上有 Node、Python、Chromium、Playwright 和 FFmpeg。需要能调用此模型的 pi 配置。以下命令中的媒体路径和新工作目录由复验者提供。

```text
python run_exam.py original.m4a "mj apanay feat. aren park" new-run
python check_recording.py original.m4a new-run/task/output/final.mp4 new-run/log/audio-check.json
```

[运行器](run_exam.py)把歌曲与题目放在独立工作目录，记录技能快照中各文件的散列、启动参数、模型、事件和退出状态。[音轨核验](check_recording.py)会比较压缩音频包，估计解码后音轨的起点偏移，并每三秒比较一段双声道波形。整首 MV 的构图、镜头发展与声画关系仍需从最终画面和声音分别判断。

## 从原声到第一版成片

DeepSeek 在本地分析了整首录音的能量变化、节拍和重复段落，再独立编写时间线与 Canvas 场景。它选了卷盘录音机作为故事中的“时间机器”。房间墙上的合影引出两个人曾经同在的海岸。暖色回忆达到高潮后，海岸上只剩一个人，录音机停转，天色逐渐亮起。片中没有提供预制人物、海景或分镜。

试渲染里海岸镜头一度全黑，房间暗处的人物也难以辨认。DeepSeek 从联系表定位问题，修正画面，重画轮廓后重新取帧。连续查看数十张图片后，pi 会话在正式编码前连续出现连接错误。保留现场后使用 pi 自带的历史压缩，原会话、模型和工程继续工作，成功导出 5,402 帧。这个问题也写回了[长片审片方法](../../../../video-craft/references/review.md)，附按音乐段落生成小联系表和按时间码复查局部的命令。

## 最终交付与观看记录

首轮启动后，《纸鸟》的五项参考素材又修了一遍首句。两条导出工具随后修复了 Windows 临时目录权限的继承，审片说明也补入了长片的做法。保存首版影片及会话备份后，把最终 120 个技能文件另存为快照，在**同一 pi 会话、同一模型**中复查整片。DeepSeek 从编码成片取帧，检查片尾文字、切点和音轨，用最终版工具重新合入原声。首轮与最终 MP4 的 SHA-256 均为 `d61e9bcac19a0d81b5d79d91ffc08bbbedaacb3a5a216aa57760eca3e16d13a9`。重新导出的文件可以由桌面用户及默认检查账号读取。[原会话恢复](resume_exam.py) · [最终版复查](final_review.py)

独立看片时，01:30 左右两人还隔着一段海岸，02:02 的远景和 02:06 的近景已能辨认两人同时抬手，03:00 同一片海岸只剩一人。00:50 和 01:50 的走廊在小画面上仍很暗，主要能看到中央的光和站姿。人物拉近后，关节和动作的重复也较明显。这是本次成片在表演上的局限。开头、段落间以及片尾的黑场均与时间线对应。
