# 2026-11-11 评测：有技能 vs 无技能（pi + openai-codex）

## 设置

- 题目：科普短片「GPS 是怎么知道你在哪的」。横屏 1920×1080、30 fps、50–60 秒，中文，无配音，音乐和音效用代码生成，交付 `output/final.mp4`（H.264 + AAC）。原文见 `2026-11-11-gps-BRIEF.md`，机器环境说明见 `2026-11-11-ENV.md`。
  - 选这个题目，是因为它同时考三样：
    - 设计：地球、轨道、太空、地图蓝点；
    - 技术：球面相交的三维几何、镜头、声画同步；
    - 讲解：第四颗卫星和相对论修正都不容易讲清。
  - 它和三个示例都不重合，也和 11-09 的两题不重合。
- 运行：pi 1.5.0，`pi -p -a --no-context-files --offline --no-extensions --no-prompt-templates --no-mcp --no-skills`。有技能的一组另加 `--skill <video-craft 快照>`。
  - 两组的提示都是“请阅读当前目录下的 BRIEF.md 和 ENV.md，按要求完成任务。”
  - 每组一次，两组并发，上限 2.5 小时。
- 技能版本：dev 上 0.2.0 的工作区快照，含当时未提交的 MP4 faststart 修复。
- 工作区：`~/.local/share/vc-eval/ab-1111/`（不入库）。
  - `run.sh`：启动一组运行；
  - `tools/metrics.py`：统计用时、工具调用、看图次数和花费；
  - `tools/sheet.sh`：生成每秒一帧的联系表；
  - `tools/review.py`：生成本地盲看页面，A/B 随机分配，我的审查藏在“揭晓”按钮后面。

## 经过

1. **DeepSeek 失败（11-10）**：4 路 pi + deepseek-flash 都没交付。单次回复要 5–15 分钟，之后 `api.deepseek.com` 握手就被断开。环境问题记在 useProblem 的 ISS-002。11-11 复测仍连不上，改用 openai-codex。
2. **gpt-6-luna**：两组都在 3 分钟内结束，都没看过自己渲染的画面，两条都不能发布。
   - 有技能的一组读完了 SKILL.md 和六份参考，但没用工具包，也没照流程做：约 25 行的画布场景，568 字节的渲染脚本，声音是一段单调的低音。
   - 用户看后判断这个模型不适合这类任务，删掉了这一轮，换模型重跑。
3. **gpt-6.1-sol**：下面的结果都来自这一轮。

## 结果（gpt-6.1-sol）

| | 无技能（A） | 有技能（B） |
|---|---|---|
| 用时 | 10 分钟 | 16 分钟 |
| 工具调用 | 32 | 52 |
| 看图 | 8 张 | 11 张 |
| 花费（pi 统计） | $0.35 | $0.56 |
| 成片 | 59 秒，6.5 MB | 58 秒，27.5 MB |
| 响度 | −18.2 LUFS，峰值 −5.6 dB | −16.2 LUFS，峰值 −1.7 dB |
| 做法 | 自写 Playwright 渲染、Node 合成音轨，7 章 | 复制 starter 示例和工具包，事件表驱动配乐、换场时压低音乐，16 个小节 |

**用户（盲看）**：“58 秒这个视频比 59 秒那个好很多，59 秒那个更像一个 PPT，并且内容想展示的太多显得杂乱无章。”58 秒那条是有技能的。

**我的审查**：看了联系表、每条 6 张原尺寸关键帧、换场前后的帧条、响度和频谱。两条都到了“小改后能发布”的水平，我最初写的是 B 略好。讨论后，我同意用户的判断：讲解视频清楚比精致重要，差距比我写的大。

- **A**：
  - 单帧很精致，是一套深色信息图，大数字和相对论条形图都清楚。
  - 但它是幻灯片：每章先暗成一帧空画面，再重新搭下一章；章内画面常停 6–10 秒。
  - 每帧有五六层字。三颗卫星那段太乱。
  - 声音：120 Hz 以下的能量比上面所有频段加起来还大，持续的正弦低音按固定的 5.2 秒循环断开，和画面无关。
- **B**：
  - 有故事线：从地图出发，进太空讲原理，回到地图，四颗卫星的连线汇到蓝点上。
  - “每天偏 10 公里”画成地图上漂开的一个点。
  - 球面一步步收窄到一个点，讲清楚了。
  - 声音跟着信号、交点和定位锁定。
  - 毛病是整个画面交叉淡化，两镜的图和标签叠成重影：27 秒、36 秒两处字压着字；左侧文字比右侧图早约 0.4 秒换掉。它自称检查过转场，还是漏了。

## 据此做的修改（发布前）

技能的审查清单只写了“两句字幕不要叠”，没覆盖“两镜的图和标签在淡化时叠在一起”。发布前补了两处文档，没有改工具包和示例：

- `references/review.md`：
  - 切点帧条要找半透明重影，并看文字和图是否同一刻换；
  - 常见问题表加了两行：换场重影、文字和图各自计时。
- `references/motion.md`：普通换场默认“先退后进”，只有不带字的背景层可以交叉淡化；同一镜的文字和图从 `T` 里取同一个换场时刻。
- `SKILL.md` 的交付前核对：加一条“换场没有重影”。

## 局限

- 只有一个题目，每组只跑一次。
- 结果受模型影响很大：gpt-6-luna 下两组都没投入，技能起不了作用。
- 我看过运行过程，我的审查不是盲审。用户的判断是在不知道 A/B 对应关系时做的；不过我在进度消息里提过两条的时长，理论上能对出来。
