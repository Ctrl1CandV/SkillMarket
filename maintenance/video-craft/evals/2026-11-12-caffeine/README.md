# 2026-11-12 实测：竖屏数据短片「下午三点那杯咖啡，晚上还剩多少」

目的：补上 0.2.0 评测没覆盖的竖屏和数据故事，并在 Windows 本机（显卡 WebGL、系统 Chrome、ffmpeg 8.1）上走一遍完整流程。任务单见 [BRIEF.md](BRIEF.md)，环境说明见 [ENV.md](ENV.md)，运行脚本 [run_pi.sh](run_pi.sh)。成片和完整日志在仓库外，没有入库。

## 条件

- pi 1.4.0 + `openai/gpt-6.1-sol`（用户指定），工具 read/bash/edit/write，技能按描述自然触发；技能用开跑时复制的快照，避免运行中途被改。
- 提示只有一句：“请阅读当前目录下的 BRIEF.md 和 ENV.md，按要求完成任务。”
- 每个版本只跑 1 次。

## 第 1 次（技能 0.2.0）

| 项目 | 结果 |
|---|---|
| 用时 / 工具调用 / pi 记账费用 | 12.5 分钟 / 59 次 / 0.40 |
| 成片 | 1080×1920，30 fps，32.0 s，H.264 + AAC，3.2 MB |
| 响度（我复测） | −16.6 LUFS，峰值 −1.8 dB |
| 数字 | 150 / 75 / 49 / 38 / 75 mg，全部按公式算出并四舍五入，与任务单一致 |

做对的：按流程跑了 doctor、读了全部参考、从 starter 复制起步；做了样帧、每秒联系表、mixcheck、textcheck、切点帧条、编码后抽帧和响度检查。核心画面是“杯中液面 + 15:00 到次日 01:00 的时间轴”，一眼能懂；入夜换成深色背景；最后两杯并排对比 5 小时和 8 小时半衰期。交付说明如实写了“未做人工听音试听”。

看到的问题：

1. **画面经常冻住。** 每段动画做完就停住几秒：开头 0–3 s、9–11 s、14–16 s、22–26 s、29–31 s，合计约 13 秒没有任何变化，像翻幻灯片。模型看过自己的联系表（连续几格一模一样），没有处理。技能里只在结尾卡写了“2–3 秒，加缓慢推近”（它的结尾停了约 5 秒），中间段没有标准。它照着改的 starter 示例自己开头就静止 4 秒。
2. **结尾一句话被拆开。**“睡不好的话 / 试试把最后一杯”在顶部，“往前挪。”落在时间轴下方，读起来断了。
3. **标题先于画面。** 数字还在往下数（如 22:33 时 53 mg），标题已经写着“大约还剩三分之一”。
4. **工具包在 Windows 上的问题。** `audiocheck.mjs` 用 `/` 截路径找 score.html，Windows 上报 `ERR_FILE_NOT_FOUND at file://score.html/`（我用原版复现过）。模型在自己的副本里修好后才用上。

任务目录之外：用户级 site-packages、字体、全局 npm、conda 环境与运行前一致；`~/.pi/agent/auth.json` 有改动，是 pi 刷新登录凭据，不是模型所为。

## 修改（0.3.0）

- `render.mjs sheet`：把和上一格几乎没有变化的格子标成“= same”（96 px 灰度，变化像素少于 0.2%），连续静止 2 秒以上时在输出里列出时段和合计，并提示“要么有理由，要么加缓慢运动或缩短”。校准：本片报出 5 段、约 13 秒，与目测一致；sky、promo 两个示例一段都不报；每秒 0.3% 的缓慢推近就不再算静止，不会逼模型加大动作。
- starter 示例加了整片的缓慢推近（每秒 0.4%），读字时画面不再冻住；改后联系表无静止段，textcheck 通过。
- `review.md` 看联系表一节写明静止段怎么处理，问题表加一行“每段动画做完就停住几秒”；SKILL.md 交付核对加一条；`kit.md` 补 `--still`。
- `audiocheck.mjs` 用 `dirname` 拼 score.html 的路径，Windows 上恢复可用；`montage.mjs` 的图注用 `basename`。
