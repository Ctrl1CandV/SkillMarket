# 实验记录

工作区 `~/.local/share/vc-lab/`：`kit/` 是这次写的通用工具，`queue/` 是实验 1 的工程。

## 工具（kit/）

| 文件 | 作用 |
|---|---|
| `kit.js` | 缓动（cubic-bezier 求解）、弹簧解析解、种子随机数、颜色混合、字体预载、`register({seek})` |
| `render.mjs` | 驱动可定位页面：`stills` 原尺寸静帧、`sheet` 联系表、`strip` 切点帧条、`video` 逐帧截图 → VP9 WebM，`--audio` 时用 ffmpeg 流复制合入音轨 |
| `sound.js` | WebAudio 离线合成：拨弦、贝斯、铺底、点击、弹出、钟声、低音撞击、嗖声、倒带声、滑音；BS.1770 积分响度；前瞻限幅；WebCodecs Opus 编码 + 手写 EBML 写出 WebM；分轨测响度 |
| `audio.mjs` | 从场景页读事件表，在乐谱页合成，输出 WebM（可选 WAV）并报告响度 |
| `audiocheck.mjs` | 把音频解码回来，画包络和频谱，叠上场景事件竖线，用眼睛核对声画同步和混音 |
| `montage.mjs` / `vstack.mjs` | 把几张原尺寸帧横排或竖排缩成一张图，省看图成本 |
| `n` | 设置 Chromium 库路径和字体后运行 node |

本机限制下的音视频链路：页面截图（JPEG）→ ffmpeg-1013 编 VP9；声音在浏览器里合成并编 Opus，自写 WebM 容器；ffmpeg `-c copy` 合并。不需要完整 ffmpeg。

## 实验 1：排队悖论（竖屏科普，2026-11-10）

### 先找核心画面

题目要讲清两件事：选中最快队的概率只有 1/3；被超过记得更深。0.1.x 的 DeepSeek 版本都是给结论贴标签。这次先问“什么画面能让观众自己看出 1/3”，得到的是：

1. 真的模拟三条队（每位顾客的服务时间随机），看一次谁先到；
2. 镜头拉远，这一次变成 30 次实验里的一格，其余 29 格同时跑；
3. 30 个结果按谁先到分成三堆（9/10/11），观众看到三条队机会差不多；
4. 左右两堆并到一起，20 对 10，即 2/3；
5. 记忆偏差：你站在画面下方，统计图变成你头顶的想法泡泡，橙色（你最快）的几次褪掉，蓝色（被超过）的每次闪一下、你抖一下，最后泡泡里只剩蓝色。

这一步决定了视频的大部分质量，后面的风格和动效都是在它上面加分。

### 做法

- 同一个排队模型画两种细节：近景是收银台和人，远景是格子里的点。拉远镜头就是在两种细节之间按缩放比例淡入淡出，所以“商店 → 30 格”是一个连续镜头，不需要转场规则。
- 竖屏分区：上方 176–400 px 放叙述字幕（无声视频里字幕就是旁白），中间放画面，计数和标签放在画面内部，下方 450 px 只放装饰（结尾的“你”的身体）。
- 第一帧就有内容：开场标题和正在排队的人同时出现，三秒内左右两队都动了、你这队卡住；然后“倒回开头”，冻结在起点标出前面各 4 人，再正常播放。

### 每轮看到的问题和改法

| 轮次 | 看到的问题 | 改法 | 结果 |
|---|---|---|---|
| v1 联系表 | 开场标题压到收银台；结尾大字换成三行并盖住画面；拉远时有一段只有一个小卡片 | 画面整体下移、标题缩小；结尾改成独立的大数字卡；其余格子在拉远过程中提前出现 | 已解决 |
| v1 原尺寸 | 俯视的人（深色头 + 浅色肩）像眼球，看不出是人 | 改成略高的背后视角：圆头、耳朵、圆肩上衣，衣服颜色有变化；收银台后加收银员 | 一眼能看出是排队 |
| v2 | “你”的标签压到前一个人；收银员的头碰到字幕 | “你”直接印在橙色上衣上；用 TOP 常量整体下移 | 已解决 |
| v3 联系表 | 换字幕时新旧两句叠在一起；格子结果的颜色太淡；字幕说“次次都排错”时画面还写着 2/3；开场看不出“你”在着急 | 下一句等上一句退出后再进；结果格改成实色；记忆段把 2/3 换成“你记住的”；开场给“你”加逐渐变强的晃动 | 已解决 |
| v3 转场序列 | 卡片一边飞一边变形，中间是一团乱 | 拆成两步：先原地缩成色块（像点阵），再自下而上飞进三堆，三根柱子同时长高 | 明显更清楚 |
| v4 联系表 | 21–34 秒十三秒都是柱状图，记忆偏差只是标签 | 加入“你”和想法泡泡，统计图成了你的记忆 | 这一段有了人物和情绪 |
| 音频 v1 | 包络图显示每小节一个低音尖峰，中间几乎无声；分轨测得音效峰值比音乐低 5 dB | 低音改成长音并降低，加铺底和弦；音效提高 3.5 dB | 包络连续，事件清楚可见 |

### 学到的、可以带进技能的东西

1. **先找能让观众自己得出结论的画面**，再谈风格。用代码的优势：能真的模拟、能跑 30 次、数字由画面产生而不是贴上去。
2. **一个模型、两种细节、一台摄像机**。连贯来自同一个模型在不同尺度下的画法，比事后加转场可靠。
3. **认得出比好看重要**：用缩略图检查观众能不能一眼认出画的是什么（眼球 vs 人）。
4. **统计段落要有人**：把图表放进人物的想法泡泡里，抽象的偏差就成了故事。
5. **变形与移动分两步**：先原地变形，再移动；同时进行会糊成一团。
6. **字幕不交叉淡化**：上一句完全退出再进下一句；字幕区和画面区分开，不互相压。
7. **听不到也能混音**：分轨测响度、画包络 + 频谱 + 事件线；第一次混音的问题（尖峰、空洞、音效被盖住）都是从图上看出来的。
8. **看图顺序**：每秒一帧的联系表 → 三张关键帧原尺寸并排缩小看 → 转场按 0.2–0.3 秒取帧 → 字幕交接处按 0.1 秒取帧。每一轮都发现了读代码看不出的问题。

### 成本

- 包括写工具在内约两小时。42 秒视频渲染约 90 秒，音频约 6 秒。
- 场景代码约 560 行，乐谱约 90 行。

### 还拿不准的地方

- 音乐是合成的，我听不到，只能从图上判断，需要用户听。
- 30 格阶段格子里的点仍偏密。
- 时长 42 秒，比题目的“约 40 秒”略长。

## 实验 2：天空为什么是蓝的（横屏科普，2026-11-10）

工程 `~/.local/share/vc-lab/sky/`：`brief.md`（任务、事实核对、核心画面、美术方向、分镜表）、`atmo.js`（大气散射着色器）、`land.js`（远山、人、树）、`micro.js`（光波、分子、散射波纹）、`space.js`（地球剖面示意）、`scene.js`（时间线、相机、字幕、颗粒和暗角）。

### 这次刻意改变的地方

- 换题、换横屏，不参考任何旧版本。
- 把画面质感当作第一目标：天空由物理着色器实时计算（瑞利 + 米氏单次散射，加臭氧吸收），远山按空气透视着色，太阳有光晕，分子有高光和景深，光是叠加混合的发光线，全片加颗粒和暗角。
- 一条连续的相机路线贯穿全片：山谷上摇到太阳 → 沿光线推进到空气内部 → 拉回天空 → 延时到日落 → 升入太空看地球 → 俯冲回日落的山谷。场景之间都是镜头运动，没有翻页。
- 代码的强项用在内容上：白光拆成六条波时，六条波叠在一起本来就是白的（叠加混合），分开后才显出颜色；天空颜色不是画的，是同一个散射公式在不同太阳高度下算出来的。

### 每轮看到的问题和改法

| 轮次 | 问题 | 改法 |
|---|---|---|
| 着色器 v1 | 正午天空灰、发白；日落上方发灰绿 | 提高曝光、去掉额外伽马；加臭氧吸收（黄昏天顶变成蓝紫，是标准做法） |
| 全片 v1 联系表 | 第 9 秒两句叙述叠在一起；第 39 秒太阳正好穿过问题文字；汇聚到人眼的光线在亮天空上显成白色；从真实地平线切到示意地球时形状对不上，出现一个怪圆 | 叙述严格先退后进；问题文字改到右上；光线改成饱和蓝加浅色芯、正常混合；示意图以“从地平线拉远”的方式进场（选好缩放中心，让地球顶部的弧线从真实地平线的位置开始） |
| 关键帧原尺寸 | 太阳高时光晕把一大片画面烧白 | 光晕半径和强度随太阳高度变化，低太阳才大而暖 |
| 编码后解码检查 | 标题和结尾文字周围有一个浅色方框 | 原因是逐行遮罩（overflow:hidden）把文字的柔和阴影切出硬边；给遮罩留出足够的内边距并用负外边距抵消 |
| 同上 | 正午远山灰黄发土；日落时远山被照成亮黄色 | 取色点改到地平线以上 3°、远离太阳一侧；太阳低时远山按逆光加深 |

### 学到的、可以带进技能的东西

1. **质感来自“光”**：渐变天空、光晕、叠加混合的发光线、颗粒、暗角、景深，这些全局手段对观感的提升远大于把图标画得更细。
2. **能算就别画**：天空、光的颜色这类有物理规律的东西，用公式算出来比手调颜色更真实，也会自动保持前后一致。
3. **一条相机路线串起全片**：用跨尺度的推拉（宏观 → 微观 → 太空）代替换页，转场就是剧情。
4. **示意图进场要接住上一镜的形状**：选缩放中心，让新画面里的关键轮廓从上一镜同一位置出现。
5. **文字遮罩要给阴影留边**，否则编码后能看到方框；这种问题只在解码后的帧上才明显。
6. **远景颜色从天空里取**，而不是写死，日落时再按逆光加深。

### 成本

约 3 小时（含着色器调试）。59 秒、1770 帧渲染约 4.7 分钟（天空在 640×360 上算，再放大）。成片约 22 MB（颗粒让码率升高）。

## 实验 2 补声音（2026-11-10）

工程同上：`sky/score.js`，场景页导出事件表（`meta.events`），成片 `sky/out/sky-v3-av.webm`。

- 声音跟着画面里的规律走：每种颜色一个音高（红低紫高）；白光是六个音同时响，拆开时依次弹出；日落光束丢掉蓝光时高音逐个消失、只剩红色的低音；散射段蓝光每弹开一圈响一声，红光音量是蓝光的 1/5.9。声音本身也在讲同一件事。
- 铺底用暖垫音 + 柔和钢琴旋律（开头的问句动机 A–D–E–F# 在结尾补完）；山谷段有风声，空气内部换成低沉的室内底噪，太空几乎只有一个空五度。
- 混音：解释性音效处让音乐自动退 4 dB（ducking），而不是一味加大音效；用新工具 `kit/mixcheck.mjs` 画音乐、音效、总混音三条瞬时响度曲线叠事件线，确认每个关键音效在事件处比音乐高 5–9 dB。

问题和改法：

| 问题 | 原因 / 改法 |
|---|---|
| 第一版音效整体比音乐低 6–10 dB，“光线汇入眼睛”完全被盖住 | 对照曲线逐段加大，并在这些段落压低音乐 |
| 分轨测量时音效轨里混进了音乐 | 分轨静音用的是总线增益，被配乐里的总线自动化覆盖；改为每条总线后加独立的静音节点 |
| 低频一直很满 | 持续低音降 3 dB |
| 包络里 `exponentialRamp` 目标为 0 时报错 | 包络峰值加下限 |

## 实验 3：「两清」App 宣传片（横屏，带音乐，2026-11-10）

工程 `~/.local/share/vc-lab/promo/`：`brief.md`（模拟的用户需求、数据、核心画面、分镜、节拍）、`index.html` + `scene.js`（DOM 实现，手机和界面都是 HTML/CSS）、`score.js`（120 BPM 配乐和音效）。成片 `promo/out/promo-v3-av.webm`，28 秒。

### 做法

- 产品是虚构的（旅行 AA 记账），不出现任何真实品牌。片中所有数字由一张支出表算出：五人共 3500、每人 700；各转各的 5×4=20 笔，最少 4 笔（安安→小林 490、阿杰→小林 70、阿杰→老周 150、美美→老周 50）。
- 核心画面：暗场里群聊消息越堆越乱 → 画面变亮，消息先原地变成票据、再飞进手机变成账单 → 推进屏幕，五人之间 20 根箭头织成乱网，收网后只剩 4 根粗箭头 → 拉回手机，4 笔转账逐拍打勾、余额归零 → 红色“两清”印章盖下（取自旧账单上的“两讫”章），印章变成 Logo。
- 节拍网格：所有出现和切点落在拍或半拍上；音乐结构跟叙事走：闷住的鼓 + 越来越密的消息提示音 → 画面变亮时鼓组全开 → 收网那一小节鼓停 → 粗箭头每拍一个音、音高上行 → 印章落在第 11 小节重拍。
- 穿过屏幕的镜头：推进时让屏幕底色先填满画面再换成关系图（两者底色相同）；拉出时关系图跟着屏幕一起缩小并淡出。

### 每轮看到的问题和改法

| 轮次 | 问题 | 改法 |
|---|---|---|
| v1 联系表 | 消息按聊天记录往上滚，要飞进手机的账单消息早已滚出画面顶端，“原地变形”看不到 | 消息改成散落在右侧的一堆，全程留在画面内；第一帧就有标题和三条消息 |
| v1 | 推进屏幕前界面先淡出，画面里只剩一个空手机 | 界面保留到推进后段 |
| v2 半秒联系表 | 8–9 秒只有手机没有字，结尾卡静止 5 秒太长 | 补“谁该转谁？”；结尾缩到 3 秒，全片 28 秒 = 14 小节 |
| v2 关键帧 | 印章是平的红方块 | 加噪点遮罩做出油墨斑驳和毛边 |
| 解码帧 | 推进时屏幕还没盖满画面，关系图就开始出现，能看到手机边框 | 推进在 0.85 秒内完成后才出关系图 |
| 切点帧条 | 拉出时手机边框隔着淡出中的关系图透出来 | 关系图随屏幕同比例缩小 |
| 混音 v1 | 音乐比界面音效响 15–27 dB | 音乐降 5 dB、音效总线 +7 dB，并逐类调整 |
| 混音 v2 | 峰值因数 21 dB，限幅器压 7 dB | 降低两次冲击音；贝斯根音提高一个八度（笔记本扬声器放不出 50 Hz 以下） |

### 学到的、可以带进技能的东西

1. 产品片也要先找“能让观众自己看懂卖点”的画面：20→4 根箭头比任何“智能算账”字样都有说服力，而且数字是算出来的。
2. 题材自带的道具最出彩：旧账单的“两讫”章 → 「两清」印章 → Logo。
3. 问题段暗、产品段亮，亮暗切换本身就是转折。
4. 动画不要从画面外开始：要变形的元素必须先在画面里被看见。
5. 镜头穿过屏幕时，底色一致才能无缝；推进必须在新画面出现前完成，拉出时新旧画面要一起缩放。
6. 节拍网格让画面和音乐自然对上：先定 BPM，再把所有时间写成拍的倍数，重要冲击放在小节重拍。
7. 混音看曲线：界面音效在事件处至少与音乐持平，关键冲击高出 5 dB 左右；同时盯峰值因数，冲击音太大会让限幅器把整段压扁。
8. 结尾卡 2–3 秒足够。

### 成本

约 1.5 小时（含配乐）。DOM 方案渲染很快：840 帧 83 秒；音频合成 6 秒。场景约 330 行，配乐约 110 行。成片 4.8 MB。
