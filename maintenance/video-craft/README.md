## 0.7.0 · 回到看得见的质量标准，补上画、歌、声三块

用户看过 0.6.0 的审片包后不满意：《time machine》整首 MV 不好看，旁白仍不自然。这一轮先审了 GPT 在 0.4–0.6 的思路，再动手做了一段 MV 和三种旁白的对照，按做出来的东西改技能。

### 练习：《time machine》副歌（手做）

`practice/time-machine-chorus/`，歌曲 1:52.2–2:26.6，34.4 秒，纯代码。他只有睡着才能见到她：熄灯，镜头穿过窗进入星空；她被一笔一笔画成星座，每个八分音符点亮一根骨骼；唱到 “time machine”，镜头转向北天，星轨倒转，流星向上飞；他的星座出现，两只手在一个小节线上碰到一起；唱到 “will end” 天亮，连线断成星尘。`shotlist.py` 量得 8 个镜头，长度 1–6 秒不等，7 个切点里 6 个落在拍点 1.5 帧内，没有标记。与 DeepSeek 同段的左右对照在 `out/compare.mp4`。歌曲和由它生成的 `song.js` 不入库。

做这段时学到、已写进技能的：近景要按新尺度重画并给出新细节（星尘沿连线流动），不能放大位图；节奏型动作用拍点数组算；推镜穿窗要对准窗格中心，否则切点前会露出窗棂；镜头里动作做完以后，相机和光还要继续动。

用户看后的意见：效果不错，但和这首歌本身的意思差一些。回头读歌词，这是一首关于失去和后悔的歌：只有在梦里才见得到，求别让自己醒，最后还是要放手。我把高潮画成两只手碰到一起，等于把遗憾拍成了团圆。技能里的概念步骤原来只问“歌在讲什么情境”，没有问“唱的人怎么看这件事”。已在 MV 参考的第 2 步加上这一问（态度、矛盾或转折，高潮和结尾必须落在这个态度上），写段落表后要把这句话和高潮、结尾两格对照读一遍；交付清单和 drawing.md 里的同一个例子也改成了“差一点碰到，天亮散开”。

### 旁白对照

`practice/voice-ab/`。同三段文字（教学、广告、叙事），A 为 Edge 整段生成，B 为 VoxCPM1.5（约 2 GB），C 为 VoxCPM2（约 5 GB），B、C 克隆同一张由 VoxCPM2 声音设计做出的卡。三者转写都没有读错字（残余差异是“称/撑”“倒场/导场”这类同音）。速度：1.5 约 1.7 倍实时，2 约 1.2 倍实时，显存约 2 GB 与 5 GB。声音设计不总听话：“年轻男性”三次里两次生成了女声（音高 235、276 Hz），所以卡要多试几次并量音高。盲听页 `index.html` 已交给用户。

用户盲听结论：1.5 和 2 几乎没有区别，只在句子衔接处有很细微的差别，2 GB 的 1.5 就够了，声音效果“已经非常好了”。所以默认用 VoxCPM1.5 克隆声音卡；VoxCPM2 只在需要按文字描述做新声音卡时使用。九枚硬币（70.3 秒）和倒场广告已用 1.5 重配并重渲预览。

独立审查后改了 `narrate.py` 的静音裁剪（改为相对峰值 −40 dB）和挑选规则。用改后的工具在临时目录重跑九枚硬币的全部旁白（14 句，每句 3 遍），选中的遍次基本相同，各句起止最多差 0.13 秒，所以随附的旁白和预览没有再换。整轮在 RTX 4070 Ti SUPER 上 391 秒，含加载模型和转写核对；单遍约 4.5 秒生成 6 秒语音。

### 独立审查与修正

另起一个没参与制作的子代理审查了 0.7 的工具和文档，找到的问题和处理：

| 发现 | 处理 |
|---|---|
| `songAt` 的 `kick` 用全部低频重击，几乎每拍都跳，会把画面做廉价 | `songmap.py` 新增 `accents`：每拍最多一个，取 8 小节邻域里最强的 15%，约每小节一个；`kick`/`snap` 默认用它。《time machine》上从每小节 6.6 次降到约 1 次 |
| `songmap.md` 的段落没有小节序号，页面里要自己数，容易差一 | 段落带 `bar`（`downbeats` 下标），表里加 `first bar` 列，`same as #n` 取代 A/B 标签 |
| 截取一段歌做 MV 时，`shotlist.py` 按成片秒数对歌曲拍点 | 加 `--offset T0`；练习片用它量得 7 个切点中 6 个在拍上，中位偏差 15 ms |
| 歌曲文件尾部的静音把最后一段的响度拉低，被标成 quiet | 每小节只平均到声音结束为止，静音按 −60 dB 封底 |
| `narrate.py` 绝对阈值裁剪会切掉轻声句首；只有两遍时按长度挑会误选 | 改为相对峰值裁剪；三遍以上才用长度项 |
| 英文台词的数字被改成汉字，转写误差按字算 | 按台词猜语言（`--language` 可指定），数字只在中文时转换；voice.md 加英文旁白一节 |
| `ridge()` 不给 `base` 时静默产生 NaN | 直接报错并说明参数 |
| 示例 `build_voice.py` 的 `--takes` 和 `narrate.py --takes` 意思不同 | 改名 `--recordings`（第二次审查后去掉了旧名别名） |
| pictures.md 允许黑场开头、“干脆切黑”结尾，和 MV 参考冲突 | 第一帧要有画面；黑场只做有意的一拍 |
| 交付清单要求整首原声也归一到 −16 LUFS | 原声合片保留母带原样 |

另外新增 `kit/shader.js`（片元着色器层，供星云、极光、银河），drawing.md 加“着色器层”一节；`doctor.mjs` 检查 Python 环境并编译检查所有 kit 脚本。

### 示例：《最后一盏灯》

`examples/last-light/`。0.6 的 MV 失败在“没有跟歌”，而已有的两个 MV 示例（纸鸟、回潮）都是自己写的曲子、时间自己知道，没有一个示范“手里只有录音”。这个示例先用 `sound.js` 合成一首 54.7 秒、96 BPM、带两拍弱起的器乐当作录音，页面只读 `songmap.py` 的结果：镜头切在 `downbeats` 上，对岸的窗随 `accents` 亮、随桥段钢琴音（`hits.mid`）熄，熄灯在第 14 小节第一拍。概念按新的第 2 问定：`songmap` 显示桥段鼓停（`quiet, drops`），回来的副歌不比第一次更响，尾声没有重音、慢慢散掉，是放下而不是等到，所以船不回来，他自己熄灯，银河升起。和弦来自我们自己写的乐谱，brief 里只作旁证并说明来源。

做的过程本身也在检验技能：`songmap.py` 把前奏并进了主歌、把尾声并进了最后的副歌（示例里按 `first bar` 自己拆开，写进了 brief）；文件尾的 3 秒静音把最后一段标成 quiet，由此修了响度计算。第一版画面的问题靠全尺寸看帧找出：对岸的房子排成一堵等高的墙，码头像一条平面色带，窗灯倒影被行位移切成斜的平行四边形，银河像一抹烟。改成成簇的前后两排房子加树和雾，码头加暗的底面、侧板、木纹和近边高光，倒影逐行独立位移再轻微模糊，银河里加按同一条带分布的密集星尘。`shotlist.py` 最后：14 段（其中一处是镜头内熄灯被当成切点），13 个切点全在拍上、中位 25 ms，镜头 1.2–8.7 秒；桥段长镜头和最后副歌全景原被标成静止，加大运镜、湖面流雾和重音上的流星后，剩下的两处约 2 秒停留和结尾停留在 brief 里写了理由。渲染 1640 帧约 80 秒。

### 第二次独立审查

做完《最后一盏灯》后，另起一个没参与制作的子代理审查这个示例和这一轮新改的文档、工具，找到 14 处，都已改：

- 示例换成别人的歌会出 NaN：歌少于 20 小节时直接报错并说明要改 `SHOTS`；某段没有重音时退回小节线；余音很长时结尾淡出仍保底 1.5 秒。
- 示例的第 2 问用的是乐谱里的和弦，却声称页面只读录音：brief 改为从 `songmap` 读出的证据，和弦只作旁证；music-video.md 写明器乐的态度从标题和曲子的形状里找，拿不准就问用户。
- MV 参考的 `bar()` 只能取小节线：改成 `bar(n, beat)`，镜头可以切在第 3 拍；没法试听时的规则同步改成“小节线或第 3 拍”。
- `songmap.py`：段落响度把开头的静音也平均进去；转写判断 CUDA 改问 CTranslate2，不再在同一进程里 import torch。
- `shader.js`：`uniforms` 与 `draw` 的键重复时重复声明；没传的键沿用上一帧的值，帧不再是纯函数；每换一组键就重编译且不释放。改为按签名缓存程序、缺席的键为 0、用 `t`/`res`/`o` 作键时报错；注释和 drawing.md 示例里未定义的 `m` 改掉，kit.md 写全签名。
- `shotlist.py` 在 `VC_FFMPEG` 指向 `ffmpeg.exe` 时找不到 ffprobe；加 `VC_FFPROBE`，否则按同目录同扩展名找。
- 交付清单写 −1.5 dBTP，`audio.mjs` 实际限的是采样峰值：改成“采样峰值不高于 −1.5 dBFS”，与 sound.md 一致。
- voice.md：做声音卡时每个 seed 输出到自己的目录，免得互相覆盖；Edge 读英文默认改用英文声音（`narrate.py` 按台词语言选）；用户录音入口点名 `worked-lesson/build_voice.py`。
- pictures.md：从声音开始时从一点微光淡入，不从纯黑淡入。
- `song/score.js` 里重建录音的相对路径写错；brief 的 13 个切点说明为 12 个设计的切点加 1 处镜头内熄灯。

### 本机小模型改编

在本机通过 Ollama 调用 `qwen3.5:2b-q4_K_M`。原型试验时，先给模型完整输入或秒数，然后尝试精简改编字段，把可验算的部分交给工程。模型读给定字段或片段说明，脚本负责执行它返回的数据。结果只对应本次任务与提示。没有把这些尝试当作不同模型或通用视频审美的对照测试。

## 0.4.0 · 2026-11-18

目标是让 AI 自己决定拍什么，技能只在创作者已经有意图以后帮助设计、制作、剪辑和复核。旧入口以讲明白一个结论为中心，统一要求第一帧出现标题、按拍排满和留结尾卡。这轮把具体数值和做法还给各自的场景。新版从最难成立的一镜或一段乐句开始，在完整制作之前先用可播放的动态分镜调整顺序和停留时间。

前三个自包含工程加入 `video-craft/examples/`，连同原有 starter、sky 和 promo 共六个。复用真实软件的试用未打包进技能，它依赖另一个目录的产品。新增 `cut.mjs` 将静帧、存在入点的录屏和独立渲染镜头编成 MP4，可带歌曲母带或按镜头保留同期声；`captions.mjs` 将已有 SRT 折算到选段时间。原有画面渲染入口可等待异步绘制，试剪局部时音轨入点跟随画面，成片声音检查可将事件移到片段时间。

开发机上的复查命令（网页渲染沿用下文 Windows 的 `VC_CHROME`、`VC_NODE_MODULES` 配置）：

```text
node maintenance/video-craft/evals/check-cut.mjs
node maintenance/video-craft/evals/check-captions.mjs
node maintenance/video-craft/evals/check-seek.mjs
```

剪辑回归包含真实解码的颜色、声音入点和尾部、同期声起步偏移、单帧插镜、失败后保留上一版输出。字幕回归包含双语、重叠、截断、重新计时和无效输入。逆序取帧比较合成后的网页像素（含 DOM，边缘舍入容差 1/255）。另用带中文、空格或井号的路径、异步场景和外部 WAV 从第 1 秒试剪，验证片段开头的实测音量，并在 1 秒输出中对齐位于原片 1.5 秒的事件。

本轮没有新旧技能的同题盲评。MV 样片使用原创器乐，真实演唱和口型同步仍待试用。响度、频谱与解码验证不能代替听感判断。实拍人物、多分钟叙事及 HDR 交付还需要对应的素材和任务。

## 定位与取舍（2026-11-09，0.1.0 开发中）

- **做成技能，不做插件。** 本仓库的技能约定不依赖具体宿主；插件的命令和钩子只在 Claude Code 中生效，换到 GPT、DeepSeek 等宿主就失效。用户的出发点正是“GPT 和 DeepSeek 做的视频效果不好”，所以方法写成通用文字，确定性的部分写成只依赖 Python 标准库与 ffmpeg 的脚本。
- **不重复引擎技能。** Remotion 官方有 `remotion-dev/skills`（约 12 个子技能，管 API 正确性）；HeyGen 的 HyperFrames 自带约 20 个技能（含 `motion-doctrine`、`cut-the-curve` 等运动规范）。它们都不管或很少管：一句话要点与结构、口播写法、分镜作为时间来源、样帧、配音驱动时间线、字幕规范、响度、看成片。video-craft 补这些，并在 engines.md 指向官方技能。
- **抓最大的杠杆。** AI 写视频代码的常见问题（据调研与常识）：幻灯片式镜头、居中堆字、线性/统一淡入、镜头之间无关联、转场杂乱、时长手写导致音画错位、中文豆腐块、从不看成片。对应做法：分镜里强制写作用/主体/构图/衔接；样帧先行；timeline.json 作为唯一时间来源；联系表 + 切点帧条 + 自动检测。
- **正面示范优先。** 遵守仓库的技能写法：每节先写“好的样子”，用具体数值和示例（content.md 的 HTTPS 两种写法、motion.md 的 8 秒镜头编排、assets 里的完整分镜与令牌），少用禁止清单。
