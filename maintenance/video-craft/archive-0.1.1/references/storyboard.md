# 分镜与构图

好分镜的样子：每个镜头有一个明确作用和一个视觉主体；景别和构图随内容变化，不是一串相同的居中版式；每个切点都有东西从上一镜延续到下一镜；节奏有松有紧，关键结果前有短暂停顿，结尾有停留。

分镜写成 `storyboard.json`，它是时长、旁白和画面的唯一来源。代码从它生成的 `timeline.json` 读取时间，不在组件里另写秒数。

## 1. 文件格式

完整示例见 [示例分镜](../assets/storyboard.example.json)。顶层字段：

| 字段 | 含义 |
|---|---|
| `title`、`takeaway` | 片名与一句话要点 |
| `format` | `width`、`height`、`fps`，可选 `platform`（如 `douyin`、`bilibili`、`youtube`） |
| `language` | `zh` 或 `en`，决定语速和字幕规则 |
| `target_duration` | 目标总时长（秒） |
| `transitions` | 全片允许的转场词汇，2–3 种 |
| `shots` | 镜头数组，按播放顺序 |

每个镜头：

| 字段 | 必填 | 写什么 |
|---|---|---|
| `id` | 是 | 英文短名，如 `s03-exchange`，用于文件名和配音分段 |
| `purpose` | 是 | 这一镜让观众得到什么，一句话 |
| `duration` | 有配音时可省 | 计划秒数；有配音时以实测配音为下限 |
| `hero` | 是 | 视觉主体：观众第一眼该看的东西 |
| `layout` | 是 | 构图名，见第 3 节，用来检查版式是否单调 |
| `shot_size` | 建议 | `wide`、`medium`、`close`、`detail` |
| `role` | 建议 | `hook`、`setup`、`step`、`compare`、`reveal`、`payoff`、`outro`、`beat` |
| `vo` | 有配音时 | 这一镜的旁白原文 |
| `onscreen` | 可选 | 屏幕文字数组（不含字幕），每项是关键词、数字或短语 |
| `camera` | 可选 | 镜头运动，如 `slow push 1.00→1.06` |
| `motion` | 建议 | 镜头内发生什么，按先后写 |
| `carry_out` | 建议 | 什么东西跨过切点进入下一镜，以及运动方向 |
| `transition` | 可选 | 进入下一镜的转场，须在顶层 `transitions` 中 |
| `beats` | 长镜头建议 | 镜头内的节拍：`{"at": 秒, "event": "…"}` |
| `sfx` | 可选 | 音效：`{"at": 秒, "name": "whoosh", "gain": -14}` |
| `vo_file` | 可选 | 配音文件路径，默认找 `--audio-dir/<id>.*` |

## 2. 镜头的作用

先决定这一镜在讲述里做什么，再决定画面：

| 作用 | 典型画面 | 典型运动 |
|---|---|---|
| 建立 | 全景，交代所有参与者和它们的关系 | 慢推或静止，元素按层级依次入场 |
| 聚焦 | 特写一个部件、一行代码、一个数字 | 推近，非焦点压暗或虚化 |
| 比较 | 左右或上下并列，同一尺度 | 两侧同步变化，差异处高亮 |
| 过程 | 沿一条路径推进的步骤 | 载体沿路径移动，镜头跟随 |
| 揭示 | 遮住的部分打开，或拉远看到全局 | 遮罩擦除、拉远 |
| 转折 | 预期被打破的瞬间 | 0.3–0.75 秒静止后突变 |
| 收束 | 回到开头的画面，带上新的理解 | 拉远或回到建立镜头的构图，停留 |

## 3. 构图

**一个焦点。** 每一刻画面上只有一个最亮、最大或正在动的东西。其他元素降低对比度、缩小或静止。

**用网格放置，不用随手坐标。** 先定画面网格，再把元素放到锚点上。横屏 1920×1080 可用 12 列、左右边距 120 px；三分线在 x=640/1280、y=360/720。竖屏 1080×1920 用 6 列、左右边距 72 px，主体放在上中部（y 约 500–1200），避开平台界面遮挡区（见 [画面与风格](visual.md#5-安全区)）。Manim 用 `next_to`、`arrange`、`to_edge` 相对定位，HTML 用 grid/flex，避免绝对坐标堆叠导致重叠。

**常用构图名**（写进 `layout`）：

| 名称 | 画面 |
|---|---|
| `center-hero` | 主体居中占画面高度 40–70%，四周留白 |
| `thirds-left` / `thirds-right` | 主体在一侧三分线，另一侧放标签或说明 |
| `split` | 左右或上下对比，两边同一尺度 |
| `stack` | 竖向排列的步骤或列表，当前项高亮 |
| `full-bleed` | 图片、界面或图表铺满画面，文字压在留出的平静区域 |
| `diagram` | 节点与连线，按阅读方向从左到右或从上到下 |
| `chart` | 数据图占画面主体，标签和结论贴在数据旁 |
| `code` | 代码面板占 60–75%，当前行高亮，结果在旁边或下方 |
| `type` | 纯文字排版，大字号，网格对齐 |

连续三个镜头用同一种构图会显得像翻页；`storyboard.py check` 会提示。

**三层景深。** 背景（低对比的色块、纹理、渐变）、中景（主体）、前景（标签、光标、高亮框、粒子）。镜头运动时三层以不同速度移动（背景最慢），就有了空间感。

**视线和运动方向指向下一处。** 箭头、人物视线、元素运动方向都指向观众接下来该看的位置，切点前的运动方向就是下一镜的入场方向。

## 4. 景别与镜头运动

动态图形里的“镜头”就是整个舞台的缩放和平移。把所有元素放进一个舞台容器，对容器做变换：

| 电影语言 | 动态图形中的做法 | 用来表达 |
|---|---|---|
| 全景 → 特写 | 舞台从 1.0 推到 1.6–2.5 倍，对准部件 | 从整体进入细节 |
| 慢推 | 整个镜头内 1.00 → 1.04–1.08 | 强调、让静态画面保持生命 |
| 拉远 | 从特写退回全景 | 揭示上下文、收束 |
| 横移 / 跟随 | 舞台沿 x 或 y 平移，跟着载体 | 时间线、流程、序列 |
| 焦点转移 | 非焦点模糊 4–8 px 或压暗到 30–50% 不透明度 | 同一画面里换讲述对象 |
| 匹配剪辑 | 下一镜中同形状、同位置的元素接上 | 跨场景延续同一概念 |

一个镜头只用一种主镜头运动。景别要变化：全景交代关系，中景展示过程，特写给出细节和数字。

## 5. 镜头之间的衔接

切点是“像幻灯片”还是“像一支片子”的分界。

- **载体。** 让一个具体元素跨过切点：数字飞进下一镜的图表变成一个柱子，卡片放大成为下一镜的背景容器，光标点击后下一镜从点击处展开，同一条消息贯穿全片。没有天然载体时，用主体本身带着运动方向出镜和入镜。
- **方向一致。** 全片选一个主方向（通常是内容从右侧进入、向左离开，与阅读方向的“往前走”一致），普通切点都沿它走；向上表示升华或结论，推进（放大穿越）表示深入同一个概念，拉远表示揭示更大的图景。方向改变要有原因：一次点击、一次碰撞或章节变化。
- **在运动中切。** 出镜元素在切点时仍在加速离开，入镜元素已在途中减速到位，两边的速度相近。先停稳再切，或切完从静止开始，都会留下一个“死拍”。
- **转场词汇少而固定。** 全片 2–3 种转场反复使用，写进顶层 `transitions`。交叉淡化只用于时间流逝或情绪段落。

每个非结尾镜头都写 `carry_out`。写不出来，说明两个镜头的关系还没想清楚：要么合并，要么在中间补一个过渡动作。

## 6. 节奏

- 镜头时长随信息量变化：钩子和节拍镜头 1–3 秒，步骤镜头 4–8 秒，复杂图示可以 10 秒以上，但每 2–4 秒要有一个新的可见变化（新元素、高亮移动、镜头运动的变化）；长镜头用 `beats` 写清内部节拍。
- 竖屏短视频节奏更紧：每 2–3 秒一个变化，单镜很少超过 6 秒。
- 关键结果出现前留 0.3–0.75 秒静止，结果出现后停留到观众读完。
- 结尾画面至少停留 1.5–2 秒，标志和链接停留 2 秒以上。
- 整体是“紧—松—紧”：开头快，讲解段按信息密度呼吸，结尾收束时放慢。

## 7. 检查分镜

```text
python <skill>/scripts/storyboard.py check video/storyboard.json
python <skill>/scripts/storyboard.py check video/storyboard.json --json   # 机器可读
```

脚本会核算总时长、每镜旁白是否放得下（按语速估算）、屏幕文字是否读得完、连续重复的构图、转场种类、没写衔接的切点和结尾停留。它只检查可计算的部分；镜头是否好看、衔接是否自然，要在样帧和草稿上看。
