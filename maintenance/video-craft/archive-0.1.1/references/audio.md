# 声音与字幕

好声音的样子：人声清楚、音量稳定，画面变化落在说到的词上；音乐在说话时自动让开，停顿时回来；音效稀少而准确；字幕一行读得完，断在意思完整的地方；整片响度符合平台习惯。

## 1. 声音是时钟

有配音的视频，先有配音，再定画面时间：

1. 口播稿按镜头切分，每个镜头一段，文件名用镜头 `id`（`video/audio/vo/s03-exchange.wav`）。
2. 生成或录制每一段，检查读音。
3. `storyboard.py timeline` 量出每段的真实时长，生成 `timeline.json`：镜头时长取“计划时长”和“前导 + 配音 + 尾部留白”中较大的一个。
4. 代码只从 `timeline.json` 读取镜头起止、配音起点和节拍时间。改了配音就重新生成时间线，重新渲染、重新审查受影响的镜头。

默认前导 0.2 s（画面先于声音一点点）、尾部留白 0.35 s、最后一镜至少停 1.5 s；章节之间可以在分镜里把 `duration` 写长，留出 0.6–1 s 只有画面和音乐的呼吸。

只需要镜头内更细的对齐（某个词出现时高亮）时，用带词级时间戳的 TTS 或语音识别对齐（如 Whisper 一类的工具）得到词时间，写进对应镜头的 `beats`。

## 2. 配音来源

按用户已有的条件选择，并在交付说明里写清用的是什么：

- 用户已有的 TTS 服务（各大云厂商、ElevenLabs、OpenAI 等），按其条款使用；
- 本机开源 TTS（如 CosyVoice、IndexTTS、F5-TTS 等，需要合适的显卡）；
- 非官方接口（如 edge-tts）只适合草稿，正式发布前确认服务条款；
- 用户自己录音：给出分段稿和每段的目标时长。

同一支片子用同一个声音、同一语速。不模仿真实人物的声音；克隆声音须有本人授权。

检查读音：多音字、数字、英文缩写、专有名词最容易错。宿主能听音频就逐段听；不能听时，用语音识别把配音转回文字和原稿比对，差异处改写原稿（例如把“行”换成不会读错的词）再生成。两者都做不到时，在交付中说明读音未经核对。

## 3. 字幕

中文字幕的常用规范（参考 Netflix 简体中文字幕规范）：

- 每行不超过 16 字（必要时 18 字），通常一行；竖屏按字号和安全宽度可能只放得下 14 字。
- 阅读速度不超过每秒 9 字（成人内容）。
- 每条显示 0.83–7 秒。
- 断在意思完整处：不拆开词语，不把“的、了、和”放在行首。
- 行末不加逗号和句号，句中逗号用空格代替；问号、感叹号、书名号、引号保留。
- 字幕与语音同步出现和消失，误差不超过 2–3 帧。

`storyboard.py srt` 按标点切分、在配音时长内按字数分配时间，生成 SRT 和同名 JSON（供代码烧录字幕时读取），并报告超长、过快、过短的条目。按比例分配是近似值；需要精确时用语音识别得到的词级时间替换。

交付时同时提供烧录字幕的成片（竖屏平台通常需要）和独立的 SRT（便于平台识别和修改）。烧录字幕的样式见 [画面与风格](visual.md#4-中文字号与排版)。

## 4. 音乐

- 选曲看情绪和速度：讲解类选旋律简单、中低音域的器乐，人声频段（约 1–4 kHz）不要太满；宣传类可以更有推进感。
- 剪辑点可以对齐节拍：一拍 = 60 ÷ BPM 秒（120 BPM 时 0.5 s）。强转场放在小节开头，比放在任意位置更有力。
- 说话时音乐比人声低约 15–20 dB，停顿时回升到比人声低约 8–12 dB；`mix_audio.py` 用侧链压缩自动完成这种“让位”。
- 开头 0.5–1.5 s 淡入，结尾在乐句结束处淡出，不在半句突然截断。
- 只用许可清楚的音乐：用户提供的、明确允许该用途的免版税曲库、按要求署名的 CC 曲目。曲名、来源、许可写进 `audio/SOURCES.md`。

## 5. 音效

- 少而准：主要转场一个“嗖”声，光标点击一个“咔”声，关键数字出现一个轻提示音。大约每 2–3 秒最多一个，不给每个元素都配音效。
- 音效对齐画面事件发生的那一帧；比人声低 12–18 dB。
- 同一类事件用同一个音效。

分镜里写 `"sfx": [{"at": 0.4, "name": "whoosh", "gain": -14}]`，把音效文件放在 `video/audio/sfx/whoosh.wav`，`mix_audio.py --sfx-dir` 会按时间线放置。

## 6. 响度与混音

- 网络平台常用目标：积分响度约 −14 LUFS，真峰值不超过 −1 dBTP（第三方汇总的数值，平台不一定公开说明）；广播用 EBU R128 的 −23 LUFS。
- 先混音（人声、音乐、音效的相对关系），最后整体做一次两遍法响度标准化。
- 不同来源的配音段落音量要一致；`mix_audio.py` 会先测各段响度并统一。

```text
python <skill>/scripts/mix_audio.py --video video/renders/draft.mp4 \
  --timeline video/timeline.json --music video/audio/music.mp3 --sfx-dir video/audio/sfx \
  --out video/renders/final.mp4
```

完成后用 `video_qa.py probe` 和 `detect` 核对响度、真峰值和静音段。
