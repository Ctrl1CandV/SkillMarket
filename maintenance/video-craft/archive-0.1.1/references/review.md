# 审查

代码写完、渲染成功，只说明有了一个文件。成片好不好要看画面、看切点、听声音（或核对声音的测量值）。审查分三个时机：样帧、草稿、成片。

## 1. 生成审查材料

```text
python <skill>/scripts/video_qa.py all <视频> --timeline video/timeline.json --out video/qa/draft-01
```

会生成：

| 文件 | 内容 | 看什么 |
|---|---|---|
| `sheet-*.jpg` | 联系表：每个镜头的中段帧和末帧，标有镜头 id 和时间 | 构图、主次、风格一致性、版式是否单调 |
| `cuts/cut-*.jpg` | 每个切点前后 7 帧（−0.4 s 到 +0.4 s） | 切点在运动中、方向一致、没有空帧和白闪 |
| `entries/entry-*.jpg` | 每个镜头开头 1.2 秒内的 7 帧 | 入场顺序、错峰、缓动是否利落 |
| `report.json`、`report.md` | 编码参数、黑帧、白闪、长静止、静音、响度、切点偏差 | 自动检测结果 |

还没编码成视频、或机器上暂时没有 ffmpeg 时，按同样的时间点直接看引擎输出的静帧或帧序列（各镜头中段与末帧、每个切点前后 ±1、±4、±10 帧、每个镜头开头 1.2 秒内的几帧），把它们排成一张图来看。

没有时间线时用 `--every 2` 每 2 秒取一帧。竖屏平台视频加 `--guides vertical`，在帧上画出界面遮挡区；横屏加 `--guides title-safe`。

单独使用：

```text
video_qa.py probe  <视频>                                编码与时长
video_qa.py detect <视频> --timeline <时间线>            黑帧、白闪、静止、静音、响度、切点
video_qa.py sheet  <视频> --every 2 --out <目录>         联系表
video_qa.py strips <视频> --timeline <时间线> --out <目录>  切点与入场帧条
video_qa.py frames <视频> --times 3.2,7.5 --out <目录>    原尺寸单帧
```

## 2. 怎么看

每张图都要实际打开看。先看联系表把握全片，再看帧条检查运动，最后只对有疑问的地方裁出局部原尺寸看细节。联系表和帧条已经把几十帧缩在几张图里，比逐张读原尺寸帧看得全，占用的上下文也少得多。

**联系表（每一格）**

- 第一眼看到的是不是这一镜的主体；缩小看（眯眼看）时主次是否仍然清楚。
- 文字不小于最小字号，对比足够，不压进安全区边缘和平台遮挡区。
- 元素对齐网格，没有重叠、被裁切、溢出画面。
- 上一镜的元素已经离场，没有残留在后面的镜头里（隐藏写错时，代码看起来没问题，画面上却叠着旧内容）。
- 颜色、字体、线宽与 `style.json` 一致；全片看起来是同一个风格。
- 中文没有豆腐块，标点不在行首，没有被两端对齐拉开的字距。
- 相邻几格的构图和景别有变化，不是一串相同的居中版式。
- 数字、标签和材料一致。

**切点帧条**

- 切点左侧仍在运动，右侧已经在途中；没有先停稳再切的死拍。
- 两侧运动方向一致，速度相近；推进穿越两边都在放大。
- 没有全黑、全白、半透明叠加露底的帧。
- 有载体的切点，载体位置和大小在两侧连得上。

**入场帧条**

- 主体先到，次要元素跟随，顺序与层级一致。
- 缓出明显：前两三帧位移大，后面逐渐变小。帧间位移均匀说明用了线性曲线。
- 同类元素的入场方式和时长一致。
- 整片第一帧已经有主体（平台封面和自动播放的第一眼就是它），镜头开头没有半秒以上近乎空白的画面。

**整体与声音**

- 节奏有变化：开头紧凑，关键结果前有停顿，结尾停留足够。
- 字幕与语音同步，每条读得完；屏幕文字没有和字幕重复整句。
- 响度接近目标（网络平台约 −14 LUFS），真峰值不超过 −1 dBTP；没有意外的长静音。
- 宿主能听音频时，从头到尾听一遍；不能听时说明这一点，用语音识别核对读音。

## 3. 问题分级

| 级别 | 例子 | 处理 |
|---|---|---|
| 阻断 | 豆腐块、文字越界被裁、元素重叠、白闪、意外黑帧、音画不同步、数字或引用错误、编码不兼容 | 交付前必须修 |
| 主要 | 焦点不明、字太小、节奏拖沓或过快、运动没有原因或方向打架、风格不统一、转场种类过多、切点停顿 | 修完再交付；时间不够时如实列出 |
| 偏好 | 换一个强调色、某个镜头多停半秒 | 记录，按用户意见处理 |

自动检测只覆盖能计算的部分。检测通过不等于好看；检测报出的“长静止”也可能是有意的停留，要对照分镜判断。

## 4. 修订循环

1. 第一版完整草稿渲染出来后，先把它放到约定的交付位置，再开始修改；之后每次得到更好的版本就替换它。这样时间或额度用完时，用户手里始终有一个可用的成片。
2. 把这一轮发现的问题一次写全到 `video/qa/review.md`：时间点、镜头、看到了什么、级别、怎么改。
3. 能改在令牌或通用组件上的，改在令牌和组件上，不逐镜头打补丁。
4. 一次改完这一轮的问题，再重新渲染受影响的镜头（Remotion `--frames=<起>-<止>`、Manim 按 section）检查，最后渲染整片。
5. 草稿通常改一到两轮；第二轮之后只处理阻断问题和主要问题，偏好留给用户决定。
6. 对最终文件重新运行 `video_qa.py all`，审查记录对应最终文件。

不修改检测结果来掩盖已知问题，也不把只看了代码写成看过画面。

## 5. 交付说明要写的

- 成片路径、时长、分辨率、帧率、响度。
- 实际看过的材料（联系表、哪些切点帧条、是否听过声音）。
- 已修的问题和剩余问题，各自的级别。
- 没验证的部分：读音、平台实际显示效果、在真实手机上的观看。
- 素材、音乐、字体的来源与许可。
