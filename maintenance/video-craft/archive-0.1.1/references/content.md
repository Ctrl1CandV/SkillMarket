# 内容与脚本

好内容的样子：一支视频只交付一个核心要点；每个镜头只做一件事；观众在开头几秒就知道为什么要看下去；画面承担解释，旁白承担连接，屏幕文字只放关键词、数字和术语。

## 1. 先写一句话要点

动笔前写下三行：

```text
观众：谁，已经知道什么
要点：看完能说出的一句话（不超过 30 字）
行动：看完会做什么（记住、试用、点开链接、理解下一节课）
```

写不出这句话，说明素材还没取舍完。材料多时按“这个镜头删掉，观众还能得到要点吗”逐项删减，删下来的放进简介、评论区或下一支视频。

## 2. 按类型选结构

时长占比是起点，按材料调整。

| 类型 | 结构 | 常见时长 |
|---|---|---|
| 解说 / 科普 | 钩子（反常识现象、具体问题、先给结果）→ 一个具体例子建立直觉 → 机制分 2–4 步，每步一组镜头 → 回到开头的问题收束 → 一句话总结 | 60–180 秒 |
| 产品演示 / 宣传 | 用户处境里的痛点 → 产品出现（标志停留不超过 1.5 秒）→ 2–3 个能力，每个用真实界面动作展示 → 结果或数字 → 名称与入口停留 2 秒以上 | 15–60 秒 |
| 数据故事 | 结论写成标题 → 主图逐步建立（先坐标与基线，再数据，最后高亮）→ 一个关键对比或转折 → 原因 → 含义 | 30–90 秒 |
| 教程 / 代码讲解 | 先看 2–3 秒最终效果 → 每步：一句意图 + 局部代码高亮 + 运行结果 → 回顾 | 1–6 分钟 |
| 竖屏短视频 | 前 1–2 秒同时给视觉钩子和文字钩子 → 每 2–4 秒一个可见变化 → 结尾回扣开头或留一个问题 | 15–60 秒 |
| 片头 / 动态标题 / 标志演绎 | 一个动作：聚合、揭示或变形 → 停住 | 3–10 秒 |

教学类视频的参与度在 6 分钟后明显下降（Guo、Kim 与 Rubin 对 edX 视频的研究，2014），内容多时拆成几段，每段一个要点。

## 3. 开头

开头要在画面上给出理由，不靠“今天我们来聊聊”。可用的形式：

- **先给结果**：成品、最终图表、反差数字直接出现，再倒回去讲怎么来的。
- **具体问题加可见悬念**：“为什么这条曲线在第 3 年突然拐弯？”同时画面停在拐点上。
- **反常识陈述**：一句话加一个能证明它的画面，下一镜立刻开始给证据。
- **熟悉情境**：观众每天遇到的一个瞬间（加载转圈、排队、账单），再引出原理。

第一帧就要有主体：很多平台把第一帧当封面，自动播放时观众最先看到的也是它，不要从全黑或全空的画面淡入。标题卡、品牌标志和目录放到开头之后，或者省掉。

## 4. 口播稿

口播是写给耳朵听的：

- 一句一个意思，长句拆短；书面连接词（“此外”“综上所述”“值得注意的是”）换成口语（“还有”“所以”“注意看”）。
- 每句能对应一个画面动作，写稿时在句后标注 `[画面：……]`，后面写分镜直接用。
- 数字写成读出来的样子：“1.5x”写“一点五倍”，“2026/3/5”写“三月五号”；英文缩写注明读法；多音字和专有名词先试听或转写核对。
- 少用括号、引号和“如下所示”，听众看不到标点。
- 结尾一句回到要点，不追加新信息。

语速决定字数。常见的中文专题和解说配音约每分钟 200–240 字（约 3.5–4 字/秒），节奏快的短视频可到 260–280 字，新闻播音约 250–300 字；英文解说约每分钟 140–160 词。写稿时按目标时长倒推字数：60 秒解说约 220 字，再留出 10–15% 给停顿和只有画面的镜头。`storyboard.py check` 会按镜头核算。

## 5. 画面、旁白、屏幕文字的分工

以下几条来自多媒体学习研究，Mayer 的综述里效应量多为中到大；独立的元分析得到的效应偏小，有的在部分条件下不显著。把它们当作默认做法，不当作铁律。

| 原则 | 做法 |
|---|---|
| 时间邻近 | 说到什么，画面就在同一刻出现或高亮什么。画面先于语音 0.1–0.3 秒出现最自然，晚于语音会显得慢半拍。 |
| 信号提示 | 用高亮、放大、箭头、压暗其他部分，把注意力引到正在讲的对象上。 |
| 空间邻近 | 标签贴着对象，不放在远处的图例里；数值写在柱子或曲线末端。 |
| 去冗余 | 屏幕上不同时堆放旁白全文。字幕可以有（很多人静音观看），但字幕之外的屏幕文字只放关键词、数字和术语，每组不超过 12 个汉字。 |
| 连贯 | 删掉不服务要点的装饰、背景音效和无关图片。 |
| 分段 | 复杂过程拆成小步，每步结束留 0.5–1 秒让观众消化，再进下一步。 |

屏幕文字和旁白讲的是同一件事，但不是同一串字：旁白说“这一步把时间从三秒压到了零点四秒”，屏幕上写“3 s → 0.4 s”。

## 6. 准确性

数字、引用、代码、产品界面都来自用户材料或可核对的来源。示意性的图形和演示数据要看得出是示意，不冒充真实统计或真实截图。代码讲解中的代码先实际运行过。

## 7. 示例：同一个主题的两种写法

主题：“HTTPS 为什么能防窃听”，45 秒，竖屏。

**幻灯片式写法**（AI 常见输出）：

```text
镜头1 标题“HTTPS 原理”
镜头2 三条要点逐条淡入：加密传输 / 证书验证 / 密钥交换
镜头3 一张流程图整体淡入，旁白逐步讲解
镜头4 “总结”页，重复三条要点
```

观众要自己读字，流程图一次全部出现，看不出讲到了哪一步；四个镜头同样居中，没有一处在“演示”。

**有分镜的写法**：

```text
s01 钩子 2.5s：咖啡店 Wi-Fi 图标，一条消息“密码 123456”从手机飞向服务器，
    中途被一只放大镜截住，字面清晰可见。旁白：“在公共 Wi-Fi 上，你发的东西别人看得见吗？”
s02 1.5s：同一条消息再发一次，飞行途中字面变成乱码，放大镜里只剩乱码。屏幕字：“HTTPS”
s03 6s：镜头推近乱码，揭开第一步：浏览器和服务器各拿出一把“锁”（公钥），
    旁白讲到“交换钥匙”时两把锁交换位置。
s04 8s：……（每一步沿着同一条从左到右的路径推进，消息始终是那条消息）
s07 收束 4s：拉远回到咖啡店，消息安全抵达，屏幕字“看得见流量，看不懂内容”，停 2 秒。
```

同一条消息贯穿全片，是跨镜头的视觉载体；每一步只讲一件事，讲到哪里画面就演到哪里；屏幕文字只在开头和结尾各出现一次。
