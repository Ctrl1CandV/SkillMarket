# 画面质感

先选画面该让人注意的东西，再找能把它托出来的材质、色彩、字号和构图。用目标画幅试一张最能代表方向的样帧，再试一张文字最密或主体最小的反例。以下参数来自或适配于 1920×1080 的示例，可按题材与实际输出修正。

| 画面任务 | 可以先尝试 |
|---|---|
| 识别界面、代码或统计差异 | 稳定的水平线与背景、清楚的局部裁切。让界面和图表的底色保真，标注避开坐标和值。 |
| 看出尺度或空间变化 | 保持轮廓、消失点或地平线的连续，改变镜头距离；由前景遮挡、明暗与对焦点说明深浅。 |
| 形成情绪或音乐中的视觉主题 | 选一个能反复变奏的元素，如单侧硬光下的剪影、丝网印刷的双色套版或连接不同画面的同一轮廓。把材质效果集中到需要触感或情绪变化的镜头。 |
| 明确对应某个品牌或物件 | 选代表性的品牌颜色、形状或用法，在真实素材上看它和画面关系如何。用少量稳定的镜头条件保住物件的可辨识度。 |

## 光

- **需要柔和的空间光时**，试径向渐变，亮心放在主体后方，例如 `radial-gradient(1200px 800px at 66% 52%, #1B2230, #10141B 60%, #0B0E13)`。浅色环境可以从 `#F8F9F5 → #EEF0EB → #E3E6E0` 试起。平涂、剪纸、图表和正视的界面也可以用纯色底保住轮廓与对比。
- **发光的线**可用 3–4 遍叠加描边。示例取宽 30/14/6/2.4 px、透明度 0.07/0.18/0.45/1，混合模式 `lighter`。画光波时让光芯保持可辨，核对几条彩线叠在一起时想要的混色。
- [sky](../examples/sky/brief.md) 的太阳位置与曝光一起变化。可先试在太阳高时画小而白的光晕，低时画大而暖的光晕，再避免它淹没地平线的层次。
- **在亮背景上**，加法混合几乎看不见。改用饱和色加浅色芯，例如深蓝 `rgba(40,105,255,.85)` 外层配浅蓝芯，混合模式用 `source-over`。

## 空气与景深

- **远景从天空取色**：远山每一层按距离往地平线颜色混。地平线颜色在画面里采样，取点在地平线上方约 3°、远离太阳的一侧，不要写死。逆光时远景整体压暗。
- **景深**：把小球之类的元素预先做成 4 档模糊的精灵图（0/2.5/5/9 px），按深度选用。离焦点越远越模糊，越靠后越暗。
- **散景**：几十个很淡的大圆（透明度 0.03–0.1），用加法混合慢慢漂。

## 颗粒与暗角

- **颗粒**可用 256 px 的噪声图平铺，`overlay` 混合，起始透明度 6–7%，每帧按帧号和种子算平移。轻微噪声有时能减轻渐变色带，也可能增加码率或让界面、细线微微闪动。比较编码后的同一帧再定。
- **暗角**可以用径向渐变收拢视线，例如从画面中心 45% 处开始，到边缘 0.16–0.42 的黑。用它之前先看四角是否有需要保留的细节。
- **字幕有背景干扰时**，试在叙述区下方加一条渐变。深色示例采用约 380 px 高、0.38 → 0 的透明度变化。直接字幕底条或移动字幕也可以，效果以同一镜头明暗变化中都读得清为准。

## 颜色

- 能计算的颜色就算出来：天空、光的颜色、按物理规律变化的东西。公式算出的颜色更真实，前后也会自动一致。
- 从题材需要持续辨认的对象和状态选色，写成常量或 CSS 变量。比如 [promo](../examples/promo/brief.md) 使用以下颜色：
  - 「两清」的印章红 `#D9382E`、结清绿 `#179F6A`、欠款珊瑚 `#EE6A4C`、墨色 `#151A22`、纸面 `#EEF0EB`；
  - 五个人的头像色全片一致。
- 稳定颜色的含义，例如绿代表结清，珊瑚色代表欠款。重要区分同时可用符号、轮廓或标签识别。
- 亮暗变化可承接叙事。两清示例先用暗底聚集欠款关系，再展开浅色背景。维持同一光线也可以让一个小的状态改变更显眼。

## 字

- 1080p 横屏可从中文标题 92–128 px、叙述约 54 px、行高 1.3–1.42 试起。画面高的 1/30 是工具包字幕检查的默认参考。界面、终端和图表里的关键小字，可用裁切放大；标题、字幕和说明在实际播放尺寸下看得清才算完成。
- 数字做主体时可试 200 px 左右，旁边的单位仍要读得全。对照数据中的数字可以用等宽数字减少跳位。
- 成段叙述可以左对齐，横屏的 [starter](../examples/starter/index.html) 是一个参考；文字本身为主体的片头或 MV 可以选择居中或随画面构图变化。
- 字体文件要预先加载（`loadFonts`），CSS 里写上系统字体作后备（`FONT_STACK`）。

## 构图

- 横屏常用左文右图：文字占左侧 140–760 px，主体放在右侧三分线附近。
- 用明暗、面积与运动让视线有明确的先后。需要观众同时比较两个画面时，留够两边的阅读空间，给同类对象相同的视觉权重。
- 1080p 可从四周 80–140 px 的安全边距试起。竖屏按实际发布界面的操作区和文案覆层试裁，尤其看底部及右侧。
- 远小近大，前景有遮挡（山坡、人物剪影），画面才有纵深。

## 设备与界面

- 设备是主体时，可参考 [promo](../examples/promo/brief.md) 的镜头做出实体感：
  - 边框用深色渐变，侧面有按键；
  - 投影两层：`0 70px 120px` 和 `0 24px 40px`，透明度 0.18–0.28；
  - 轻微三维倾斜：`rotateY(-16deg) rotateX(5deg)`，再加 ±4° 的缓慢摆动。
- 演示操作或功能结果时，把界面转正，裁到关键信息足够大；保留真实控件与状态。使用经核对的示例数据，画面里的结果和输入相符。
- 做无缝穿屏效果时，让屏幕底色接上下一个镜头，预留一帧专看边框是否被完全盖住。

## 样帧

动画之前，按最终分辨率试最关键的静帧。把它们缩小拼成一张看整体（`montage.mjs`），再看原尺寸的对齐、细线、文字和边缘。靠运动、停顿或节拍成立的画面再做一个短样段，避免仅凭静帧决定整片的速度和情绪。
