# frontend-craft 0.4：规则重审与参考取舍

2026-10-25。当前 `frontend-craft/` 是 0.4.0 候选；本次规则调整已按项目约定同步至 main/dev，尚未单独打包安装。修改基于成熟项目的方法与源码审查，未声称已证明审美提升。0.3.3 [完整基线](../archive/v0.3.3-2026-10-24/)保留。此文合并了原 0.4 修订说明与后续诊断，避免并存多份过时结论。

## 这次收敛的重点

用户的主要目标是美观、中文可读、适合日常开发的界面，同时减少 AI 常驻的功能解释和无用分区。上一轮把大量时间用于 demo、截图与评测设施，偏离了修改 Skill 的主任务；按用户要求停止扩展这些工作，回到规则本身。后续用真实任务发现的问题确认方向，验证不再成为独立工程。

主要问题是指导力度不均：内容删减、对齐和技术检查写得具体，构图、尺度与题材表达写得抽象。模型容易先把模块排正确，再装饰表面。这个判断来自规则之间的关系，不是从某张 demo 反推唯一原因。

## 已落实到 Skill 的修改

| 决策问题 | 本次处理 |
| --- | --- |
| 内容正确后才考虑构图 | 删除“页面上限在内容”的单向断言；主流程提前确定视觉主角、阅读路径、图文尺度与疏密，样式支持构图 |
| 整齐被当作普遍美感 | 改为共同阅读、比较的元素保持对齐；有意错位与叙事变化可保留。单调先检查主次、尺度和节奏，不默认铺底色 |
| 抽象允许多样，完整示例却引向同一色板 | 删除固定 OKLCH 配色代码，保留颜色角色、取色依据和实际对比度；工具仍可柔和，展示由素材和品牌决定 |
| 展示页面被工具页逻辑压平 | 补作品观看顺序、比例、裁切与节奏；不要求所有事实挤入主视觉，也不把大量留白当通用答案 |
| 方向比较演变成多份 demo | 仅在整页方向开放或被否定时轻量比较实际构图；选定后实现，局部精修继承已成立关系 |
| 参考与检查越读越多 | 改为按当前决策加载；review 先看整体，诊断表按问题查，修改后只复看相关区域，无新问题就交付 |

继续保留上一轮有价值的修正：需求里的产品行为不直接变成页面承诺；即时状态贴近对应控件；低频帮助按需出现；删文字同时撤掉无用容器；必要输入条件、权限、费用和数据去向在决策前可见；保存和刷新按真实实现。聊天可以留白，不能用欢迎语和能力介绍填满。

中文排版仍保留真实字体与字重、混排、窄屏断行等指导。0.4 的兼容性修正保留：`text-autospace` 显式启用并作为渐进增强；`text-wrap` 不保证消除孤字；`text-spacing-trim` 按目标浏览器核对。相关 MDN / W3C 来源在运行参考中。

## 为什么原来的 demo 没证明升级更好

用户认为原展览更好，并在框架×素材交叉检查中选择 C，即旧框架＋旧素材。[交叉页面](../evals/diagnostic-2026-10-25/crossed-exhibition/index.html)与[选择记录](../evals/diagnostic-2026-10-25/user-preference.json)保留。整体选择不能推断字体、色块或标题各自获得了认可，更不能泛化成所有页面都用同一种风格。

原 baseline 作者确实接触了另一代理的研究摘要，见[原始 notes](../evals/v0.4/runs/baseline/notes.md)，严格隔离失效；影响方向和大小未知。共同 brief 又指定了较强的展览美术方向，新旧素材、文案和版式一起变化，且每个作者连续做三页、没有作者看图修订。因此不能用原结果量化某条规则的收益，也不能把旧版表现全归于污染。

0.3.3 本来已有内容精简与分组方法；无 Skill 的模型也保留训练中的设计能力。旧规则中的强制顶边对齐、单调就加底色、固定色板在两版都存在，是值得修正的机制风险，却不能单独解释版本差异。当前合理结论仍是：原 0.4 没有证明稳定的综合提升。

## 直接对照后的校准：面向谁，比删多少更重要

用户随后要求三组直接对照，并反馈：阅读页新版更清爽，旧版知页标识与配色更好；文献和展览页的新内容收益有限，旧版更自然。进一步以 PaperDesk 澄清，问题是阅读者通常不需要知道文献抓取通道、压缩策略、普通连接测试的机制清单或模型范围的自明解释。目标不包含删除必要内容、品牌和视觉细节。

检查发现，旧规则残留的“每条内容必须帮助操作”“装饰需要增加信息”“底色仅用于分组”和固定首屏问题清单，会把不同用途的内容压进同一精简标准；费用与数据后果的笼统要求又可能反过来催生逐按钮免责声明。这些是需要修正的机制风险，不是页面差异的唯一因果证明。

已将主要使用者与当前任务放到起点，分开主体内容、操作帮助与实现要求。正文、导语、作品叙述和常用判断依据保留恰当表达；开发沿革、实现策略和正常行为承诺不进入普通使用者页面，也不统统塞进帮助。文献出处与原文入口仍可供引用和判断；若处理造成实际缺失，说明缺失本身。新收费方式、新接收方、权限或不可逆后果在有关决定前告知，已知常规行为不逐按钮重复。

视觉方面明确保留认可的标识、配色与关系，允许图形、材质、色块和控件细节建立品牌与氛围，不再以文字、区域或样式数量作为质量目标。三页沿用已有素材定向精修，细节与检查见[直接对照记录](../evals/direct-comparison-2026-10-25/README.md)。独立只读审查收敛了首屏模板与底色用途的残留矛盾，没有新增实验矩阵。

## 清理与后续

保留 0.3.3 基线、冻结输入、原始 HTML/notes、有效截图与用户偏好证据；删除 298 个重复工作包、无效截图、重复交叉 HTML 和未完成评审设施文件，共 6,671,582 字节，另合并删除一份重复报告。初稿与修订页面 HTML 均保持原样；notes 和清单中的本机路径已替换为占位符，并重算受影响文件的 SHA-256。停止临时预览服务。维护目录只在 dev 管理，运行技能没有新依赖。

下一步以用户真实页面为准：遇到具体的构图、可读性或提示冗余问题，先判断当前规则如何导致该选择，再作小范围修正。只有需要区分明确竞争解释时，才安排最小对照；不默认重启完整评测矩阵。
