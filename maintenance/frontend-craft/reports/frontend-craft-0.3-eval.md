# frontend-craft 0.3 评测报告

日期：2026-10-14 至 2026-10-16。范围：评测用的输入、各组生成的页面、盲评映射与统计都在 `evals/v0.3/`；v0.2.0 的完整副本在 `archive/v0.2.0-2026-10-03/`。技能本身的运行文件在 main 分支的 `frontend-craft/`。

## 要回答的问题

1. 加载 frontend-craft 后，生成的页面比不加载时更好吗？
2. 增益在不同模型上是否相同？（Opus 5.5 与 Haiku 5.5）
3. 开销（token、耗时）是否可接受？

## 方法

- **案例**：1 论文筛选工具页；2 中文导读阅读页；3 杂乱招新材料整理页；4 局部精修（修一个有遮挡的电台页）；5 订单管理后台（留出案例，写技能时没有出现过它的材料）。
- **条件**：无技能（none）、v0.2.0、v0.3（及 0.3.1 至 0.3.3 的后续修订）。每组由独立子代理生成，输入和 brief 完全相同。
- **早期 Opus 带提示**：第一轮基线的 brief 带有“可以截图、可以修订一轮”的提示；后期改为不带提示。Haiku 的组一直不带提示。
- **盲评**：页面随机打乱为 A/B/C，对应关系存在 `gallery/blind*-key.json`。选择由作者本人完成，没有其他评审者。
- **案例 4 不是盲测**：v0.3 的看图清单是依据该案例的问题归纳的。
- **渲染环境**：无头 Chromium，中文字体只有思源宋体和思源黑体，楷体由宋体替代。字体观感与 Windows 不同。

| 案例 1 Haiku | v0.3 | 选择因为多了右侧的选中论文信息栏；去掉这个栏后作者认为 v0.2 更好 |
| 案例 2 Opus | 差不多 | |
| 案例 2 Haiku | 差不多 | v0.2 略好 |
| 案例 3 Opus | v0.2 | 有醒目的标题区和分区 |
| 案例 3 Haiku | 差不多 | v0.3 略好 |
| 案例 4 Opus | v0.3 | 非盲测 |

| 案例 5 Opus | v0.3 | 留出案例 |

合计：v0.3 明显胜出 5 组，无技能明显胜出 1 组，v0.2 明显胜出 1 组，3 组差不多。

第二轮（Opus，v0.3.1 复测，3 组）：案例 1 未选（作者认为颜色上 v0.3.1 最好，但版式上有空白）；案例 3 选 v0.3.1；案例 5 选 v0.3（暖色版）。

第三轮（案例 5，v0.3.2 配色修正）：作者认为 v0.3.2 的冷色蓝加红色状态色色差太大，暖色统一的 v0.3 更好。随后做了一版只改颜色的页面，作者认为柔和一些，但仍不如暖色版。该页面是我手动调整 CSS 颜色变量得到的，不是技能生成的产物，归档在 `evals/v0.3/runs/case5-final/` 中仅供参考。

## 开销

token（子代理报告的总量）/ 耗时（秒），数据见 `evals/v0.3/stats.md`：

- **Haiku**：v0.3 相比无技能约 +3%，v0.2 约 +29%。
- **Opus（第一轮，案例 1–4 合计）**：v0.2 约 +45%，v0.3 约 +50%。
- **Opus 案例 5（留出）**：v0.3 约 +32%。
- v0.3.1 之后的开销没有可靠比较：案例 1、5 中途因额度中断后续跑，数字偏高；唯一完整跑完的案例 3 为 98.5k，高于 v0.3 的 70.5k。

**结论**：Opus 上的开销没有达到目标（+20% 以内），本次未解决。

## 修订的脉络

- **0.2.0 → 0.3.0**：SKILL.md 从约 3.5k 字符压到约 1.3k；新增内容编排、中文排版、看图清单、范例；删去六个参考文件。否定词密度由每 52 字符一个降到每 243 字符一个。
- **0.3.1**：依据第一轮盲评，发现 v0.3 过密、层级平。加入“分区”和按页面类型定密度，压缩规则只限工具页；修正宋体粗体的歧义。
- **0.3.2**：加入大众偏好的研究依据（Palmer & Schloss 2010 的颜色偏好理论）。但订单后台的配色修正方向有误：主色选了饱和的蓝，配红色状态，色差突兀。
- **0.3.3**：依据作者的反馈，改成“先统一，再谈色相”，明确低饱和、冷暖按场景选。SKILL.md 开头补充审美立场：以多数人的感受为准，不以个别偏好为准。

## 局限

1. 盲评只有一位评审，而且是作者本人，结论不能视为大众的判断。
2. 案例 4 不是盲测。
3. 每组只生成一次，没有重复采样，单次结果的方差未知。
4. Opus 的开销没有降下来。
5. 没有在真机、Windows 系统字体、深色模式、键盘操作下检查过生成的页面。
6. `text-autospace` 在 Chrome 上的支持现状，查到的资料有冲突，技能中已标注“需核实”。
