# 页间：本地资料阅读与证据核对

## 启动

无需依赖安装或构建。应用文件为 `index.html`、`styles.css`、`app.js`、`data.js`；保持它们在同一目录。

本次环境由协调者提供仓库根目录 HTTP 服务（端口 **8766**）：

<http://localhost:8766/maintenance/frontend-craft/upgrades/2026-10-26/evidence/runs/reading-evidence/A/index.html>

另一个本地启动方式：在仓库根目录执行 `python -m http.server 8766 --bind 127.0.0.1`，然后访问上述地址（已有服务时不重复启动）。页面不请求互联网，可在断网状态下通过本机 HTTP 服务使用。

也为直接打开 `index.html` 做了准备：数据以普通本地脚本载入，不使用 fetch、模块导入、外部字体或 CDN。**本轮未完成 file:// 浏览器实测**：工具明确拒绝该协议，未绕过限制；已验证的启动方式是本机 HTTP。直接文件模式中的本地存储行为取决于浏览器，建议使用已验证的 HTTP 方式。HTTP、file://、不同端口或不同浏览器的存储互不共享。

## 范围与内容

- 全部 6 篇资料、18 个章节、36 个原文段落、5 张表格、6 个预置问题及全部回答与引用。题名、作者、原文、表注、回答和局限均来自提供的数据，没有新增研究事实。
- 题名、摘要、标签的即时搜索；无结果提示及清空搜索返回全部资料。
- 目录跳转、阅读进度；引用定位并高亮具体段落。桌面同时显示原文和回答，手机通过工作区导航与“返回回答”往返。关联笔记也可回到原文，并返回笔记。
- 属于当前资料的多条笔记；可从原文段落新建，或独立新建；关联可选、可移除；支持修改，空内容校验，最长 2000 字。
- 切换资料、改编辑另一条笔记或取消编辑时，未保存更改提供继续编辑、放弃更改、保存并继续。离开页面有 beforeunload 提示；尚未保存的草稿不作为已保存笔记恢复。
- localStorage 保存当前资料、问题、各篇阅读位置与已保存笔记。位置记录含段落锚点、偏移量与滚动值。失败时明确反馈并保留编辑文字，保存成功后才更新笔记列表。
- 恢复演示数据须确认，会恢复初始资料、初始两条笔记并清除本页面状态。只操作本应用存储键 `yejian-reading-evidence-A-v1`。
- 常驻简短演示提示；原文、预置回答、个人笔记明确分区。未实现账号、上传、联网检索、实时生成或云同步。

`data.js` 是同目录 `data.json` 的完整 JavaScript 包装副本，供离线载入。修改源数据后需重新生成包装副本。原始 `data.json` 未改动。

## 设计依据

已读取指定 baseline 中的 product-design、frontend-craft，以及 frontend-craft 的视觉样式、中文排版、看图清单参考。

| 任务依据 | 设计决定 | 验证方式 |
| --- | --- | --- |
| 先理解文章问题，再核对回答 | 原文占据中心和最大宽度，完整摘要置于章节之前；预置问答独立侧栏 | 桌面首屏、完整原文与表格实看 |
| 判断依赖范围与局限 | 原文和回答完整保留，引用带章段编号；琥珀色只标识正在核对的段落 | 逐篇核对引用目标；查看高亮与后续局限段 |
| 原文、回答与个人判断不能混同 | 不同区域分别标明“文章原文”“预先编写的演示回答”“我的笔记” | 问答、笔记和编辑状态实测 |
| 阅读需要连续，手机空间有限 | 桌面三栏独立滚动；手机资料、原文、问答与笔记切换，保留段落位置 | 390×844 的首屏、文章底部与引用往返 |
| 视觉应承托中文长文 | 暖白正文、浅绿色工作区、深绿标题与主操作；原文采用系统宋体常规字重，界面使用系统黑体 | 两种尺寸实看中文、中英混排、断行与密度 |

## 实际检查记录（2026-10-26）

使用 Windows 环境中的 Codex / ChatGPT in-app browser（IAB），通过 cua_repl 进行真实页面操作、只读 DOM 检查和截图，未以静态检查替代视觉验证。浏览器版本未另行查询。读取的技能参考为上述指定 baseline 文件，未访问其他运行目录或其他实现，也未查询外部设计参考。

1. **1440×1000**：查看初始文章、完整摘要、章节、引用高亮、表格和下半部局限；六篇资料逐一打开。DOM 检查每篇 3 章、6 段、2 个回答分段，表格数依次为 1/1/1/0/1/1，所有引用都指向存在的原文段落。
2. **搜索**：输入不存在的词得到空态；清空回到 6 篇；“双语术语”标签匹配第五篇。
3. **笔记闭环**：从第一篇 2.2 段新建关联笔记；填写后切第二篇触发保护弹窗；选择继续编辑保留文字；再次切换选择保存并继续；回第一篇找到新笔记；编辑内容并移除关联；刷新后新文字与未关联状态保留。
4. **390×844**：查看第六篇首屏、原文底部、问答和引用高亮；点击引用打开 2.1 段，再返回回答。通过目录跳到第三章，隐藏阅读区后刷新，当前资料保持第六篇，滚动位置前后均为 1784.8px（当时尺寸与内容下）。最终检查页面宽度 390px、文档宽度 390px，无全页横向溢出。
5. **存储故障**：使用临时 sandbox iframe（仅 allow-scripts，拒绝 localStorage）实际触发读取与写入失败。点击保存后出现清楚的失败原因与重试建议，原有 20 字草稿仍保留，未加入保存列表。临时校验页面已移除，截图保留。
6. **恢复演示数据**：实际确认恢复并刷新，回到第一篇、初始笔记数量 1（另 1 条仍属于第五篇）、阅读滚动位置 0；自检新建的笔记已清除。
7. **语法与内容**：`node --check app.js`、`node --check data.js` 通过；正常应用页面无捕获到的 error/warn 日志。数据包装副本与 JSON 作完整对象一致性检查。
8. **对比与修正**：测得原次要文字组合低于 4.5:1，调整为 `#64705b`，在侧栏 `#f7f8f2` 上约 4.90:1，在正文 `#fffefa` 上约 5.19:1；引用文字与底色约 5.36:1。此为关键配对抽查，不声称完整 WCAG 审计。

实际修复：手机提示条换行造成的外层额外滚动；隐藏阅读区时错误记录段落位置；本地存储读取失败仍显示“保存在本机”的状态；若干次要文字对比。工具标签补充左右方向键、Home、End 切换。

未验证：真实手机软键盘/安全区、其他浏览器与系统字体、长时间多标签并发编辑、操作系统清理存储、file:// 入口。没有进行用户研究或声称用户验证通过。未模拟容量用尽，但真实存储拒绝走过同一异常处理路径。
