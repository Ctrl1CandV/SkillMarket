# 共同构建条件与隔离说明

所有构建者由 `collaboration.spawn_agent` 创建，`fork_turns="none"`，不设置模型或推理覆盖，继承同一宿主父模型。宿主没有暴露不可变模型构建编号，本轮不能补填一个猜测版本。

每次只提供其自己的 brief.md、data.json、指定技能目录、唯一输出目录，以及相同工程条件：原生 HTML/CSS/JS、空工程、无需安装依赖、可使用宿主相同工具、约 1440/390 宽、最多 25 分钟一次实现机会、允许正常自查和修复、输出 index.html 和 BUILD.md。构建者可按技能自行查看公开参考。没有传入 PLAN、REQUIREMENTS、ACCEPTANCE、对方产物、升级聊天或预定视觉答案。

最初两次启动指明本地 HTTP 端口 8765；该沙箱进程不能响应请求，随后向两位构建者发送同样环境更正：8766 已实际运行，服务根目录是仓库，不必自己启动服务。后续启动直接采用 8766。这是共同环境修正，不是设计指导。

每组使用相同字节的 brief/data，哈希在 run-manifest.json。全部尝试留存，最多一次初始构建/版本/场景。运行预算是发给执行者的相同墙钟上限，并非宿主硬性 token 限额；没有逐 token 计费或隐藏模型路由记录，不能声称精确算力控制。

隔离为新的无历史上下文和明确文件访问范围。宿主仍提供共同安全及权限指令，文件系统本身没有建立互不可见的容器；不声称物理沙箱或双盲。根代理协调启动和保存映射，构建者当然知道自己读取的技能文本。独立评审只收到中性 A/B 运行目录、原始任务和证据，先写观察再查看映射。

候选资源冻结后复制到 `candidate-snapshot/`；旧版固定在 `baseline/`。`version-map.json` 属于揭盲资料，盲评前不向评审者提供。协调者不会在盲评之前给构建者来自另一实现的缺陷或美学建议。

该有限配对只能支持当前模型、环境和三个原始任务的工程判断，不是统计显著性实验、用户调研或跨模型质量保证。
