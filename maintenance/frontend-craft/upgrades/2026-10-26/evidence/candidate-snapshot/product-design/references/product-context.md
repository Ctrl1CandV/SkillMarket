# 项目上下文与接续

## 围绕当前决定获取材料

产品说明和用户原话提供目标；对象、路由、组件与运行流程说明能力；真实内容与素材说明画面将承受什么。先定位相关材料，再追踪会改变当前设计的缺口，不以遍历仓库为目标。

| 类型 | 记录与用途 |
| --- | --- |
| 已确认的要求 | 指向用户要求或项目约定；作为当前约束。用户认可整体，不自动确认每一种旧颜色和布局 |
| 实际事实 | 指向文档、代码、画面或操作结果；区分已实现、受限和缺失，计划不充当运行能力 |
| 假设与提议 | 简述依据、影响和待核对处；不写成访谈、使用数据或已确认结论 |

接口名、字段和既有菜单帮助理解实现，用户认识的对象及其关系帮助决定产品结构。能力存在、入口可达、当前突出分别判断。材料中反复出现的要求是理解线索，其强调次数不直接决定视觉权重。

## 只澄清会改变重要决定的未知

若不同答案会改变核心对象、流程、角色权限或已有承诺，且现有材料无法判断，集中询问该分歧，继续不依赖答案的工作。先核对来源、适用范围和有效时间；不要把可解决的材料冲突原样留到交付时。

可逆的排布、字形和组件处理自行选择合理起点。无额外审美偏好时，依据相近任务的成熟参考与已有品牌推进，不默认发一套访谈问卷或反复让用户选颜色。

对缺失数据和素材标明临时假设，例如“这些样本检验长商品名，库存能力尚未接入”。未知值不填成 0，示例不充当业务证据。优先覆盖会改变布局和操作的内容差异、关键状态与失败恢复，不穷举无关矩阵。

## 留下能被画面兑现的决定

沿用项目现有材料及其分工，避免第二份权威 PRD。持续工作缺少合适位置时，一份短 Markdown 通常足够。下面是可选框架，不要求固定格式、空章节或新交接包。

| 内容 | 保存会影响后续工作的部分 |
| --- | --- |
| 范围与任务 | 当前工作对象、主要情境、本次完成标准和交付范围 |
| 关系与状态 | 对象如何关联，哪些需共同查看或持续使用，跨页选择和位置如何延续 |
| 内容与素材 | 真实材料位置、样本用途、关键长度和差异、素材缺口 |
| 保留与变化 | 用户认可的身份与能力、明确锁定的内容，以及可重审的默认实现 |
| 关键取舍 | 依据、竞争目标、选定方向、预期可见变化与检查方式 |

一个决定可以很短：

> 核对结果需要看到依据，长文又需要持续阅读。保持结果、引用标记和原文定位的联系；页面设计依据实际宽度安排共视或切换。用一条长结果和多处依据往返，检查位置、选择和阅读是否延续。

实现中把这条决定与具体区域、入口和操作对应起来。若只改了说明文字，而需要改善的共同可见、连续阅读或操作关系仍未成立，继续完成设计；不要用更长的解释替代可见结果。已满足需要的关系可以保留，无需为每个像素记录理由。

## 两种能力的职责

product-design 确定任务与完成标准、对象与页面关系、关键内容和状态、保留范围，以及影响表现的取舍。frontend-craft 选取具体视觉依据，完成页面级内容编排、空间分配、文字、色面、素材和控件的整体解法。

产品方向约束应实现的关系，不固定每个栏宽和字体；前端的实际结果又可以检验产品判断。上下文足够即可接续，配套能力按宿主机制发现，不要求固定文件路径、两个 Agent 或额外确认轮次。

## 何时重开判断

新事实或实际画面、操作结果造成实质影响时，只修正对应决定。例如：

- 必须比较的内容被分到互斥页面，反复切换仍无法完成判断：重新安排相关页面或共视关系。
- 真实内容使原先的并置假设无法提供足够阅读空间：先检查可调整的空间；仍不成立时重审该工作模式。
- 实际素材无法支撑选定主视觉：更新素材假设与表达方向，不能用占位图宣布完成。
- 字形偏轻、按钮沉重或局部间距失衡：留在页面层解决，通常不需要重做产品分析。

维护当前有效结论，简述被替换决定的原因。继续建设时只更新本次变化，普通修订不扩张为全平台调研。仅要求讨论或评审时，在答复中说明即可。
