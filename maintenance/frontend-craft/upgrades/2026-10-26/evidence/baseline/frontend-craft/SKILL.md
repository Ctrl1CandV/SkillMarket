# Frontend craft

好页面让内容、构图和操作共同成立：内容充分，阅读顺畅，视觉有自己的气质。清晰可以来自准确的层次、比例、配色与编排；简约、丰富、安静或鲜明都可能合适，不把文字少、区域少、样式少当作质量目标。

先明确谁在用、要完成什么，再判断美感：主次分明，比例与间距协调，字体易读，颜色与素材符合题材。熟悉的操作保持熟悉；阅读页让正文连贯，展示页让作品与主题有表现力。一般设计研究作为参照，用项目约束和真实反馈校准；项目或用户有明确偏好时，按他们的来。

## 开始前

读用户给的内容、现有页面和项目约定，明确页面主要服务谁、此刻在做什么。面向读者、编辑者和维护者的页面需要不同的信息；开发需求里重要的实现细节，不天然是使用者需要阅读的内容。先读当前任务相关的产品与设计依据，包括核心任务、页面关系、展示重点，以及认可的页面及原因、否定过的方向和品牌规范。项目已确认的决定优先于本技能的默认取向；用户在对话里的要求又优先于它。

新建整个平台、跨页面重设计或核心流程调整，依据不足时先使用可用的 product-design 补足任务、对象关系与变化范围；已有依据足够就直接推进。按实际变化判断，一页也可能重构流程，多页也可能只改样式。配套技能按宿主机制读取；不可用时利用现有材料补足必要判断，不依赖固定路径或重复交接。页面级内容与构图仍由本技能决定，仅评审或方案任务按相应范围交付。

先判断范围。改版先识别值得保留的标识、配色、内容语气与视觉关系，局部精修只改目标区域和受它影响的地方。用户喜欢清爽的结构，不代表要替换原有品牌或削弱样式。新建或整体重做先定构图，再实现；项目已有的组件、素材和页面也是设计依据，不因缺少设计文档就重新发明风格。

内容和布局已确定、只做样式精修时，直接从样式与复看入手，保留内容、分区、主要间距和操作语义；调整配色、字形、表面、边缘与光影的关系。更换字体后复查断行与体量，必要适配单独说明，不以精修为由重排整页。

## 流程

1. **编内容。** 按主要使用者的阅读与操作目的排先后，保留正文、导语、作品说明等内容的完整表达，区分它们与操作辅助说明、实现要求。尽早使用真实或脱敏内容；缺少数据时用符合实际长度、数量和状态的样本并标明，不为整齐删必要字段或缩短所有标题。用户指定展示的内容、关键事实与输入条件保持准确、可访问；辅助信息按用途安排，常用的判断依据直接可见。
2. **定构图。** 先决定第一眼看什么、随后怎样读或操作，再分配主次尺度、图文比例和留白。工具页围绕当前对象与动作，阅读页围绕连续正文，展示页围绕作品和主题。有实际方向分歧影响选择时，用相同内容做最小必要的构图比较；文字或小草图即可，不固定候选数量。方向明确时直接深化，不默认制作多套页面。
3. **落实样式与响应式。** 用字体、颜色、图形、材质与交互细节完成选定构图，控件保持熟悉。新建或结构确需调整时，先给正文、表格和图足够空间，再安排导航和辅助区，窄屏按任务重排。设计细节可以建立识别与氛围，不必每一笔都承载新的业务信息。
4. **看图修订。** 用代表性内容判断整体主次、阅读节奏与当前任务是否相称，再查断行、对比、遮挡和操作。新页面看桌面与窄屏、页面下半部及相关关键状态；涉及跨页流程时检查对象、选择和上下文是否连续。局部修改只看改动及相邻区域。新事实与主要任务、页面关系或已确认约束冲突时更新对应依据；普通样式问题在页面内解决。集中修复主要问题，再复看受影响处；没有新问题就交付，不默认追加 demo、完整测试矩阵或多轮评分。
5. **交付。** 说明改了什么、为什么这样改、看过哪些画面、还有什么没验证。

## 辅助说明按需出现

面向使用者写界面，避免把实现机制、开发沿革和“系统会怎样保证正确”的自我解释变成常驻文案。正文、导语、品牌表达、作品叙述和常用备注按各自用途编排。标签、选中值和操作已表达清楚的信息不再复述；说明确实影响当前选择、输入或恢复时，才贴近相关控件出现。

新增收费方式、向新的接收方发送内容、扩大权限或不可逆操作等实质后果，应在相关决定前清楚告知。已知的常规行为不在每个按钮旁重复声明；低频帮助只收纳确有查阅价值的内容，不把删下来的实现说明统统塞进折叠区。

说明删改后检查容器是否仍有分组或视觉作用，再决定去留。聊天区可以留白，合适的起始入口也可保留。必要标签、可访问名称和状态反馈保持清楚，保存、刷新与连接行为以实际实现为准。具体取舍见[内容编排](references/content.md)。

制作过程、开发版本号和检查记录放在开发文档或交付说明里。访客确实可能被误导的地方（比如数据是示例）留一处简短说明；使用者需要的引用来源、文档版本与修订记录正常保留。

## 边界

技术栈、依赖、发布和提交按项目现状和用户授权处理。外部图片、字体和代码按许可使用，不用真实品牌制造背书。PDF、DOCX 和原生 App 交给相应的技能：这里的设计判断可以带过去，验收按那个媒介重新做。

方法上参考了 oil-ui、Impeccable、Anthropic frontend-design 与 Vercel Web Interface Guidelines 的公开做法；按本技能的中文内容和日常工具场景取舍。
