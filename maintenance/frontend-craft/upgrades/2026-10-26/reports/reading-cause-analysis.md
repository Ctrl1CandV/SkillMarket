# 阅读结果相当的原因诊断

2026-10-26，按用户新的判断口径进行：不要求所有场景显著提升，允许局部未达预期，邀请用户直接比较并评价。此报告诊断现有产物与指引的关系，不替用户预先认可，也不把原终审按旧门槛作出的结论改写成已通过。

**当前最有证据支持的解释是：两版共享的有效指引与任务约束已经能导向相近的阅读结构；新版这次实际借鉴的参考又主要加强同一关系，因此变化集中在文字、入口和局部表面。尚未发现必须修改技能正文的确定规则缺陷。** 单组产物不能分离模型常见选择、实现者取舍与某一条技能变化的因果贡献。

## 已得到支持的判断

### 1. 旧版已经具备这份任务所需的主要方法

旧 frontend 主技能的开头及“流程”已明确连续正文、主次尺度、先给正文/表格足够空间、真实内容、窄屏重排和实际看图；旧 product 的“把依据转成可执行的表现方向”已有依据→决定→界面影响→检查方式。旧版并非只会删文案或堆卡片。

brief 又明确提供了六篇完整材料、预置回答、具体引用、自己的笔记、保存恢复和 1440/390px 条件。两边都需要组织资料集合、原文和回答/笔记；BUILD 中两边都将正文宽度、资料支持区、回答并置与手机切换写成依据充分的决定。它们有不同入口和样式，但核心分工已经能够由共同任务及旧规则推出。

这能解释为何新版没有显著增加新的核心关系，不能说明此任务只能做成三栏。brief 最后明确把视觉和页面组织留给执行者，未指定栏数或色板；新版保留成熟结构本身也不构成失败。

### 2. 实际空间和正文尺度的变化很小

两份 [A styles.css](../evidence/runs/reading-evidence/A/styles.css) / [B styles.css](../evidence/runs/reading-evidence/B/styles.css) 的 1440px 默认 `.workspace` 均为三栏：左侧 254px，中间自适应，右侧分别 342px / 346px；文章两边内距均为 48px，桌面 `.passage p` 都为 17px、1.95 行高。截图也显示正文左右边界和支持区面积基本相同。

因此用户看到相似的主体比例有直接实现依据。新版去掉部分 Q/A、工作台装饰，回答字号增大，摘要从有底色容器改成细左线，手机笔记独立成为入口；旧版的正文衬线、琥珀引用强调和持续目录另有价值。它们主要是同一结构里的取舍，尚未自然形成“整体更好”的单向结果。

相同数值不能证明抄袭、提示泄露或某条规则强制了布局。现有记录没有显示跨版本读取；本报告不从样式相近倒推未经证实的来源。

### 3. Tufte 被实际使用，但这次提取的关系与旧版能力重叠

新 B 的 BUILD“实际读取与查看的参考”明确只看过 [冻结快照中的 Tufte 图](../evidence/candidate-snapshot/frontend-craft/assets/references/tufte-css/desktop.jpg)，并记录借鉴“正文连续、较窄旁注在侧、可关联”的关系。这张图确实提供了连续正文、邻近小旁注及文字尺度的整体依据；没有展示长回答、多来源核验、可编辑笔记和来回定位的工作过程。

新页面兑现了连续正文与旁侧支持，但旧 A 在没有该图的情况下也兑现了这一点。现有材料支持“此次参考的可见增量较窄”，不支持“参考无用”或“执行者没看图”。新版没有采用 Tufte 的英文衬线和完整尺寸也符合迁移规则，不能要求视觉复制才算使用成功。

终审后来补入的 Wikipedia 图不在这次构建快照里，不能被用于解释 B 为什么变好或没变好。当前参考覆盖已经补齐；是否需要增加更贴近完整核对流程的案例，应由真实的使用缺口触发，不作为本轮默认扩图任务。

### 4. 高亮、字族和目录的得失，主要能定位到这次实现选择

| 观察 | 可核对的位置 | 现有规则能否支持更好的处理 |
| --- | --- | --- |
| 新版浅绿色定位面与其他绿色表面接近；旧版琥珀色更易从整页区分 | A `.passage.highlight` 为 `#fbefcf`，B `.passage.selected` 为 `#f0f3e7`；B 另用深绿 `.citation.active` 补偿当前引用状态 | [visual-style](../../../../../frontend-craft/references/visual-style.md) 的“角色配对”和“变化中的界面”已要求状态/选择/焦点可辨，未要求统一用绿；适合在具体页面里调节，而非新增“引用必须黄色”规则 |
| 新版统一无衬线，旧版正文使用衬线；两者桌面正文名义字号和行高相同 | 两份 CSS 的字体栈与 `.passage p`；各自 BUILD 的视觉说明 | [cjk-typography](../../../../../frontend-craft/references/cjk-typography.md) 明确宋体可以用于阅读、效果取决于实际条件，且提供阅读字族栈；没有强制换成无衬线，字族差异须交实际阅读感受判断 |
| 旧版目录在阅读工具条持续可见，新版目录在文章开头，滚动后不常驻 | 两版首屏/引用图，新版 `.contents` 位于文章内容流；旧版引用图仍有章节选择 | [scenarios](../../../../../frontend-craft/references/scenarios.md)“连续阅读、查阅与批注”允许多种目录形式，并要求收起后仍可找到位置和入口；未要求删除持续目录。新版目前仍能回到文章目录，是否构成值得修复的负担取决于实际跳章频率和用户评价 |

这些都有明确的局部调整空间，但尚未证明技能缺少相应原则。为每个单次选择再补一条强制规定，容易重新造成此次升级要修正的固定答案问题。

### 5. 记录对功能修复很具体，对整体视觉增益的说明较少

两份 BUILD 都记录了真实画面查看。新 B 的“已执行检查及修复”尤其详细列出了滚动位置、笔记、存储失败、当前资料身份和返回标签等修复；没有同样具体地记载一次针对主体比例、文字系统或整体明暗的修订前后收益。可确认的是这些功能问题被发现并解决，以及视觉结果被看过；不能据此断言执行者从未考虑整体设计。

因此，“功能检查已经完成”解释不了“整体设计为何更好”。这与之前终审没有把功能可用直接折算成审美胜出是一致的。是否存在有限时间内偏重工程闭环的注意力分配，只是合理假设；共同预算没有逐步时间账本，无法将其写成已证实原因。

## 尚不能确认的解释

| 假设 | 目前证据边界 | 什么信息能有针对性地区分 |
| --- | --- | --- |
| 同一模型的惯常解法使两版趋同 | 相近空间、颜色与文字数值存在，但没有针对变量的隔离比较；也可能是任务关系和已有技能共同作用 | 只有用户认为这种趋同本身妨碍目标，或必须识别因果贡献时，再安排预先约定范围的一组比较 |
| 新版对“整体参考”的要求还不够可执行 | 它已经要求说明继承关系、会改变的决定和实际复看；本次记录只表现出有限增量 | 先看用户指出的整体不足是否已经落在现有规则内，以及执行记录能否显示该关系被处理 |
| 功能要求挤压了视觉深化时间 | 修复记录偏功能，但缺少精确阶段用时，且两版都有实际看图 | 不能靠增加一条“必须多花时间设计”规则自证；必要时未来运行记录关键设计决定和最大视觉修订即可 |
| 新版实质没有价值 | 只有一组阅读产物，且手机入口、回答可读性等有局部收益；跨场景另有局部得失 | 用户对实际结果的整体判断与可接受取舍，是当前更直接的新增证据；不能由单场景相当推翻整轮资源和规则价值 |

## 本次处理建议

**现阶段不建议修改运行技能正文，也不将新增配对设为默认前置条件。** 先让用户查看原始成对页面，明确哪些差异对他的日用目标有价值、哪些可以接受、哪些是不愿接受的退步。用户的评价可以作为本轮质量判断的直接依据，同时保留其范围是这批产物及个人使用目标，不外推为所有调用都会更好。

用户若认可新版总体方向且接受阅读场景相当，可在新验收口径下结束本轮，保留“各场景并非都显著提升”的记录。用户若指出具体不可接受的关系，再定位处理层级：页面选择问题按现有规则定向修正；明确的技能冲突、缺项或反复无法落实的要求才修订对应段落。对仅修改示例页面的情况，要把页面改进与技能生成能力的证据分开。

当前最值得交给用户直接判断的是：新版回答和手机笔记入口的便利是否抵得上旧版持续目录和高亮辨识的优势；中文长文更喜欢哪套文字节奏；整页是否已经达到其日用质量。这里不预设他必须选新版，也不要求他证明每个场景都显著提升。最终结束结论由协调者按用户本次明确的新标准和实际反馈形成。
