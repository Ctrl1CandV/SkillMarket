# 用户参与后的验收依据重审

2026-10-26。本文按用户最新说明重审结束条件，不改动原 ACCEPTANCE、原始盲评、既有终审或运行产物。审查者已知此前结论和版本映射，因此这是对验收依据与证据边界的复核，不是新增盲评；本次没有运行浏览器或修改技能。

**当前判断：主要阅读“整体相当”不再自动阻止本轮结束。** 用户已明确允许部分场景提升有限，并要求参与实际比较；接下来需要取得其对具体成品的评价，再结合可靠性核查判断是否存在足够的整体收益和可接受的取舍。目前尚未收到这份具体评价，不能预先标为用户通过。

## 用户新要求及其影响

用户本次明确提出：“我们并不追求所有的场景都能显著提升”，“如果只是局部场景效果不达预期，是可以接受的”；对于“可解释且足以影响任务体验的改善”，希望亲自参与对比和评价；并授权先分析没有改善的原因，再决定是否修正。

原 [R33](../REQUIREMENTS.md) 是一项跨场景的效果与退化要求，并不是一个名为 R33 的场景。它原本要求主要阅读有可定位的改善，工具与展示无明显规则诱发退化；原 [ACCEPTANCE](../ACCEPTANCE.md) 第 5 节据此把阅读差异不清判为缺证。原 [终审](final-review.md) 在这些条件下给出的 INSUFFICIENT_EVIDENCE 有依据，应作为历史结论保留。用户现在明确调整了这项条件，新的结束判断应采用新的用户意图；这不属于执行者为得到 PASS 擅自降低原标准。

| 原判断中需要调整的部分 | 当前应采用的处理 |
| --- | --- |
| 主要阅读必须有意义地胜过旧版，否则本轮不能结束 | 阅读可保持相当，甚至存在用户能够接受的局部取舍；判断整轮收益是否值得采用，不把单场景胜出作为硬前提 |
| 由 agent 对“有意义”的解释独自决定效果 | 用户对整体构图、文字、气质、完成度和使用意愿的实际评价可作为直接证据；不强制把这些价值换成任务耗时或点击数 |
| 缺证后默认再生成一组阅读对照 | 先诊断并让用户看现有产物；只有具体疑问需要新生成才能分清时才追加 |
| 所有已测场景/每个维度都不应下降 | 保留必要能力与事实可靠性；同时允许经用户了解、认可的非关键视觉和入口取舍，不以细小局部差异无限延长任务 |

用户表达了愿意参与及可接受取舍的原则，尚未评价现有六个实现，也未表示认可新版某一风格。这两件事不能合并成“用户已经验收”。已交叉核对协调者新增的 [用户验收追加说明](../ACCEPTANCE-ADDENDUM-2026-10-26.md)，其优先级、历史保留、场景收益边界和等待实际评价的表述与上述用户意图一致；未发现需要修改的冲突。

## 现有结果能支持什么

核对了 ACCEPTANCE、R33/R34/R36、冻结盲评、揭盲比较和终审，并亲自以原尺寸打开六张关键截图：阅读 A/B 的 `desktop-citation-s2-p2.jpg`、密集操作 A/B 的 `desktop-initial.jpg`、公共展览 A/B 的 `desktop-initial.jpg`。这些图的具体关系与报告一致。本次没有把既有操作记录说成本人重新执行，也没有用六张桌面图替代窄屏与全部状态证据。

| 场景 | 新版已经可见的局部优势 | 同时存在的得失 | 当前可作出的结论 |
| --- | --- | --- | --- |
| 阅读与证据核对（A旧/B新） | 回答视觉字号较大，顶部和问答装饰较少，手机笔记入口较直接 | 旧版黄底引用更易从绿色表面中辨认；持久目录对跳章有利。两版核心并置关系和已核查往返大体相当 | 目前不能说新版显著改善，也不能说它没有价值；用户可判断文字与整体气质的收益是否足以接受这些取舍 |

因此，用户问题里“其他场景能感觉到明显变好”目前需要校正为“其他场景有可见的局部改善，也有取舍，尚未获评整体明显变好”。用户可能在实际查看后给出更鲜明的偏好，这将是新增的个人评价证据；不能倒写进先前 agent 的盲评。

## 用户评价怎样进入验收

优先让用户看到已有同内容、同视口和同状态的三组产物，以及可操作的原页面。展示时不要先用“这边更成熟/这边已修复”等文字引导赢家；可暂用中性标记。用户已在聊天中见过新版阅读图和分析，因而不应声称此轮用户评价严格盲化。实际对照的价值不因此消失。

用户不需要填写逐项打分表，简短描述就可以形成判断依据：整体更愿意使用或展示哪一边、具体喜欢什么；哪些局部代价不能接受；若阅读只是相当，结合其他场景和技能资源是否足以接受本轮。只谈观感也有意义，必要时再通过实际操作核对其背后的可用性影响。不能要求用户把“更好看、更有完整感、愿意继续阅读”证明成效率数据。

收到反馈后，将用户原意、所看页面与状态、总体选择及不可接受点单独记录。用户的偏好结论和 agent 发现的事实各保留出处；若用户的具体判断与之前 agent 评价不同，说明分歧在什么价值权重上，不用多数投票覆盖用户的实际需要。

用户可以接受“整体值得采用、部分场景相当”的候选。如果用户认为尚无明显视觉提升，但明确愿意将本轮按规则与资源完善收尾，也可以记录这一收尾范围；届时仍需写明页面效果提升未被验证。当前仅有原则性说明，不足以代替这两种具体接受意见中的任何一种。

## 仍需保留的核查底线

现有文件、来源、样张与关键行为核查不因验收意图变化而失效。应继续确保：内容和来源不被伪造，必要字段与能力没有被删去，已声称的保存/返回/校验真实可用，主要任务不存在阻断或明显数据错误，宽窄屏仍可完成约定流程。不能用“更喜欢外观”掩盖已确认的关键故障。

用户允许局部效果不达预期，并不要求每一个字重、留白、色调或入口位置都优于旧版。已经记录的阅读高亮色、章节导航、队列编号/时间及展览首屏比例，应按具体任务影响和用户反馈区分为必要修复、可接受取舍或后续建议，不自动全部升为阻塞项。

证据范围继续限于当前样本和环境；一次用户偏好可以支持个人采用决定，不能证明每次调用都更好或将来普遍稳定提升。后补 Wikipedia 资源没有参与此前生成，不能将已有页面的收益归因于它。发布、安装和移除 RC 仍应按实际后续任务处理，结束评估不自动包含这些动作。

## 何时修订或追加构建

1. **没有可复用的规则缺陷，用户认可整体结果与取舍：** 可以依新的验收依据收尾。记录读取到的现有证据、用户具体评价及接受边界，无需为让阅读胜出而重跑。
2. **用户指出具体不满意，且诊断能关联到指引含糊、冲突或参考转化不足：** 修订相应最小范围，复核受影响的内容与行为。若要声称修改改善了技能生成能力，再用新的隔离构建检验受影响场景；只手工改一个演示不能承担这种因果结论。
3. **局部问题只来自一次实现选择，当前技能已有合理规则：** 不据此给技能植入特定颜色、栏数或这份数据的答案。根据用户是否将它视为重要代价，保留为页面层问题或作最小核查。
4. **用户仍难以判断，或怀疑结果主要由一次生成偶然性造成：** 仅追加能回答该疑问的一组对照；预先记录比较问题和停止条件，保留所有结果。不要重复抽样直到出现偏好的赢家。

新的结束判断可据此表述：既有实现与资源已完成必要核查；用户基于实际三组产物确认整体采用价值或明确接受本轮限定收益；未解决问题均属已知、可接受的非关键取舍；若进行了实质修订，受影响范围已复核。独立审查者据此确认事实与结论一致，即可结束当前约定范围，主要阅读相当本身不再是否决理由。

在用户实际评价到来前，本报告仅确认上述适用标准和处理分支，不预先给出新版获胜、用户认可或新的 PASS。
