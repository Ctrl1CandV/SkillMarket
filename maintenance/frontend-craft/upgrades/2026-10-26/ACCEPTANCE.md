# 验收与结束条件

本文件评审这轮升级，不作为两个 skill 每次使用时的强制手续。审查结论依赖实际证据，不能用机械分数或文件数量代替。

## 1. 证据按能力分开

| 要判断的事 | 需要的证据 | 不能拿来代替的材料 |
| --- | --- | --- |
| 文件与引用完整 | 最终目录、差异、静态检查报告、版本与 manifest | 截图漂亮、口头说明 |
| 参考已被查看且可转用 | 原始来源、实际画面、视口/状态、查看记录、迁移关系和使用依据 | 单个 URL、图片路径、文章摘要、网站知名度 |
| 样张可用 | 真实浏览器截图、关键交互与键盘检查、窄屏观察、相关对比检查 | 只有 HTML/CSS、语法通过、脚本模拟点击日志 |
| 技能能改善真实输出 | 同条件独立生成的新旧产物、相同状态截图、关键任务操作记录、盲化比较 | 原则更完整、作者打分、某一张精选图 |
| 这一轮可以结束 | 以上证据及独立终审报告 | 执行者写“已完成”、仅脚本 --release 返回 0 |

截图可以在项目环境生成；工具不可用时可用其他实际浏览器和人工检查。不能伪造捕获、用生成图冒充页面、或把未执行检查写成已通过。对未验证的地方，报告局限比编造结论更有用。

## 2. 资源完整性

两个技能和相对路径完整、版本一致，没有相互矛盾的规则或隐藏的固定依赖。runtime 不包含维护报告与对比数据；实际仓库的用户改动得到保留。公开参考的状态与证据一致，所有已登记截图能打开。

外部可复用画面至少覆盖：

- 连续阅读与证据核对；
- 密集工具操作；
- 内容或作品展示。

这是任务覆盖，不要求每项各做一套独立图库。允许同一案例覆盖确有证据支持的多项。至少来自两个实际独立的发布主体；方法文档中的局部插图可以补充，但不能凭一张营销页产品小图覆盖完整工具关系。每个计入覆盖的案例须有有用的完整工作视口，相关细节或状态按需补充。

保留来源及使用条件。无法确认可再分发条件时可只留链接作为 candidate/documented，不把该条计算为完整的本地可复用画面资源。优先改选来源与条件明确、任务关系同样适用的开源案例。条件不足就如实记录，不自动向登录墙、付费墙或其他访问限制索取例外。

## 3. 样式样张

三主题都需实际打开宽屏视图，不能只测试默认主题。使用 1440 × 1000 CSS px 作为共同比较起点；对 390 × 844 CSS px 至少检查每主题的主要阅读/操作关系，并对布局或颜色差异相关的状态补查。只在具体风险需要时追加设备，不做无意义的全组合矩阵。

检查可见主体、真实长标题、中文混排、正文舒适度、表面/文字/边界关系、主要操作与次要信息的分量。验证主题切换、视图切换、搜索筛选、引用往返及样张声明支持的行为。窄屏没有非预期页面横向溢出；宽表等有意滚动区域有明确边界。键盘焦点可见、不被固定元素遮挡，状态有颜色之外的表达。按实际计算或工具检查所用文字及关键控件的对比；不能把对比合规当成好看。

记录浏览器版本、实际字体与回退、视口、主题和状态；在常规显示比例查看，不能只看缩小后的全页缩略图。源码检查和色值计算只能作为辅助证据。

## 4. 新旧版本公平比较

在相同模型与版本、工具权限、依赖、运行预算、原始用户任务、数据和视口条件下，分别使用基线与候选的两个技能。一个版本的产物、诊断、检查表和评审结论不进入另一个版本的构建上下文。

先确定相同运行预算；两边都允许按各自 skill 自查修订，但次数与资源机会对等。若旧版资源缺失或工具不可用，先处理共同环境或标为不可比较，不悄悄削弱旧版。不从多次结果只挑出最好的一张。记录所有尝试；因明确失败重跑时，对另一版本作对称处理或说明为什么仍可比较。

构建者只看到原始 brief、数据、选定版本两技能和共同工程条件。不要把 PLAN、REQUIREMENTS、验收答案或本轮“应减少卡片/应使用某色”的诊断注入构建。评审者另行拿到完整任务与证据。可将配对产物随机标为 A/B，映射由协调者保管；先独立观察，再揭示版本。

三组任务各完成一组配对实现，主要阅读任务作为效果判断的重点。这是有限样本的工程验收，不是统计证明；报告须说明无法据此承诺每次输出都更好。若资源只能支持更少运行，可交付已有结果，但终审不得把相应场景证据标为充分。只有初始结果存在具体不确定性，例如主要差异可能由内容缺失或偶然布局造成，才追加针对该问题的配对，不机械重复也不无上限重试。

## 5. 怎样判断视觉与使用结果

先进行任务与事实核对，再看完整画面、实际尺寸和操作过程。比较时回答：

| 观察维度 | 可核对的问题 |
| --- | --- |
| 产品到界面的兑现 | 主要对象、判断依据、操作与结果的关系是否真正成立？有哪些具体区域或行为体现？ |
| 整体构图 | 第一眼能否辨认主体？主从比例、连续面、并置关系和疏密节奏是否合理？ |
| 文字与阅读 | 中文、英文、数字、标题、正文和注释是否各有角色？长内容是否仍可读？ |
| 配色与表面 | 大面积底色、前景、边界、强调和状态是否协同？改善是否超出了换按钮色？ |
| 内容与操作完整性 | 是否保留必要依据、字段和能力？减少内容有没有损害核验和发现？ |
| 变化过程 | 窄屏、选择、定位、加载、错误、刷新时，位置、焦点与上下文是否稳定？ |
| 场景迁移 | 密集操作和展示是否仍成立？有没有所有任务被套成论文工作台或同一种卡片页面？ |

每项可记录 `better / comparable / worse / unclear`，附具体截图位置、操作步骤或内容例子。不计算一个总平均分掩盖关键缺陷，不设没有依据的“提升 30%”。细小像素差异不单独决定结果。

主要阅读任务的配对结果应支持有意义且可描述的改善，且没有功能、事实、可访问性或上下文连续性退化；密集操作和展示不应出现本轮规则引起的明显退化。若旧版已较好而差异不清，结论是证据不足，不能为了宣称升级成功强行判胜。可根据具体失败修订后，在同样条件下重测受影响任务并保留原结果。

## 6. 终审结论

- **PASS**：逐项要求已落实；资源、样张与实际使用证据充分且相互一致；主要效果目标成立；没有未解决的阻塞或重要退化。本轮可以结束，结论限于已测试任务与环境。
- **NEED_FIX**：证据足以确认具体失败、矛盾、错误声明或重要退化。列出严重性、定位、影响和最小修复，修后只复测受影响部分与必要回归。
- **INSUFFICIENT_EVIDENCE**：无法判断核心结论，例如缺真实画面、关键行为未运行、比较不公平、主要结果不稳定或必需环境不可用。列出最小补证步骤。即使没有发现 bug，也不能 PASS。

若同时有已确认问题和缺证，主结论用 NEED_FIX，并单列缺证项；不能因缺证掩盖已知问题。细微且不影响目标的建议可保留在非阻塞改进中，不据此无限延长本轮。

终审只评审本轮约定。不得为了结束降低门槛、悄悄改写任务、宣称用户已认可风格，或自动把 RC 改为稳定版并发布。
