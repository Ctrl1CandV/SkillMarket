# 统一浏览器验收记录

日期：2026-10-29。A/B 映射见协议；本记录由知道版本映射的根任务填写，独立视觉评审另见 `blind-review.md`。未修改六个首轮原型，也未据这些题目反向修改候选技能。

## 条件与证据

- Codex 内置浏览器，先在 960×720 检查初始画面及主要路径，再在 400×820 检查相关恢复、参数修改和操作可达性。每题每组一次生成，无浏览器自修订轮。
- 主体采用页面自然滚动；实测窄屏六个原型 `scrollWidth = clientWidth = 385`（400 CSS px 视口内含 15 px 滚动条）。桌面参考的文档宽度为 945。没有发现横向溢出。
- 原型在 `preview/evaluation/a/`、`b/`；视口、全页及状态截图在 `preview/evaluation/captures/`。初始截图使用一致业务初态。状态截图不一定代表相同操作时刻，不能拿一方未展示某状态推断其缺失。
- 工具返回的 JPEG 有时按比例缩为 945×709 或 385×789；这些是图像像素，不是实际 CSS 视口。A3 窄屏截图使用备用浏览器截图入口，得到 400×820。查看器按同一比例展示，未用图片编辑补造界面。
- 初次 A1 采集因新标签页没有继承窗口宽度而不合条件，已重新设定并替换初始截图；其后均在新标签页导航后设定视口。截图工具偶发旧帧/失败，核对实际像素后保存，未计为产品缺陷。
- 数量输入最初用 `fill` 后 Tab 未触发页面的 change；改用真实逐键输入（Ctrl+A、输入数字、Tab）后 A/B 均正确校验。此工具行为不计入原型缺陷。A3 Enter 提交路径也通过。

A 的 HTML 第 31–32 行把 `城市` 和 `东店` 写成了选项外的裸文本，缺少 `<option>` 开标签。浏览器 DOM 实际只有全部主题/自然/手作，以及全部取书点/西店；这不是定位器未找到的推测。功能硬门槛因此不通过。这个首轮代码错误不能直接证明旧设计规则存在因果缺陷，也不作为新版审美优势的依据。

两者都把筛选目录与完整携带清单分工，支持窄屏工作区切换、对象备注与暂缓恢复。B 底部持续提供完整清单入口，数量错误同时留在受影响对象附近；A 目录中可直接修改数量，B 的数量编辑集中在清单或单书详情。两种组织均有使用条件，未规定某一种是唯一正确答案。

## 结论边界

B 三题的五条关键路径均完成；A 前两题完成，第三题因筛选缺项未达功能门槛。视觉与结构上可观察到不同的合理取舍，不能只用通过数或截图变短宣布全面提升。没有真人计时、用户满意度、跨模型重复采样、完整辅助技术或跨浏览器验证。本轮是小样本定向检查，原型也不是生产应用。
