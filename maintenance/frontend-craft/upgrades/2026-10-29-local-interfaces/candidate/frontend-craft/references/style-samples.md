# 候选样式样张

用实际界面观察文字、颜色、表面与状态怎样配合，再决定是否适合当前页面。这组样张是本轮编写的原创候选起点，不是外部成熟产品的截图，不代表已获得用户认可，也不证明 skill 已提高视觉质量。

## 文件与用途

| 文件 | 用途 |
| --- | --- |
| [打开样张](../assets/style-lab/index.html) | 在同一组代表性中文内容上观察整体风格、正文、列表与控件 |
| [样式实现](../assets/style-lab/styles.css) | 查看角色配色、文字、表面与控件的实际配合 |
| [演示行为](../assets/style-lab/lab.js) | 支持样张切换及已有交互示例；不代表目标产品的业务能力 |
| [藏品借展安排](../assets/style-lab/local-interface.html) | 原创复杂局部样张：完整解释、对象身份、关联字段、条件显隐、状态、保存与恢复；沿用三个主题 |

样本内容用于检验接近真实使用的长度、混排与层级，业务事实以样张的标注为准。不要把演示中的论文、数字或状态当成真实业务证据。项目实现时替换成真实或脱敏内容。

藏品样张使用虚构机构、教学复制件与借展约定，不提供实际文物运输规范。它示范在同一连续界面中分配解释、安排、保护条件和操作的地位，不要求其他业务照搬双栏。可切换运输方式、修改日期与场馆确认状态、保存、恢复未保存修改、撤销最近保存和查看记录；效果仅在当前页面存在，刷新后重置。代码见 [局部样式](../assets/style-lab/local-interface.css)与[局部行为](../assets/style-lab/local-interface.js)。这是指导样例，不兼作未知任务的效果验收；实际看图与操作范围按本次验证记录说明。

## 三个候选方向

| 主题 ID | 主要探索的关系 | 使用时要看什么 |
| --- | --- | --- |
| neutral-cobalt | 中性亮底承托内容，深色文字建立清楚层级，钴蓝用于交互强调 | 白色内容面是否有足够层次，正文与辅助文字是否清楚，选中与主操作是否分工 |
| ink-cyan | 深墨底与稍亮表面分层，冰青用于局部交互 | 大面积明暗、长文可读性、焦点与状态是否过亮，深色图像和边界是否可辨 |
| paper-berry | 近白纸面与深色文字形成阅读感，深莓色建立强调关系 | 字形与阅读面是否协调，纸面底调是否干净，正文、引用与操作是否相互承托 |

这些名称用于定位资源，不是“学术、后台、创意”等行业标签。paper-berry 不意味着所有阅读产品都要纸张隐喻；深色也不自动更适合技术产品。保留用户已有品牌时，可以只借鉴某种文字、表面或状态关系。

## 怎样使用

1. 先按当前任务、内容形态、使用环境与已有身份判断是否需要样式起点。方向已成立的局部修复可以直接沿用项目。
2. 打开实际样张，查看与本次相关的内容和状态。文件存在、源代码可读或截图已生成，都不等于已经观察了画面。
3. 选定有依据的关系：例如正文与工具文字的尺度差、内容面与外框的明暗、选中标记与主按钮的分量。只有实质分歧影响选择时才比较其他候选，不要求每次查看全部主题或让用户选三套。
4. 将关系映射到项目现有组件和语义变量，保留有效实现。不要为了使用样张更换技术栈、覆盖整套设计系统，或按样张的数据数量缩减真实内容。
5. 用真实中文、英文、数字、长标题和实际状态查看目标页面。根据内容调整字形、行高、间距、表面和颜色面积，再按[看图与修订](review.md)检查。

样张适合提供样式关系的起点；整体信息结构由当前任务决定。一个样张中的列表、阅读面和控件不要求在每个目标页面同时出现。外部整体参考的选用见[参考选用](reference-selection.md)，两类材料的来源与验证状态分别保留。

## 复用哪些内容

- 复用角色之间的配合：页面底与内容面，正文与辅助文字，主操作与前景，选中与标记，焦点与相邻背景。
- 同时观察文字、边界、图标及控件尺寸，避免只拿走一组色值后保留不匹配的旧样式。
- 按本次真实需要处理相关状态。选中、焦点和处理中可能共同出现，单独状态好看不保证组合仍清楚。
- 将图片、图表和长内容放回目标页面检查；样张不能代替复杂数据、流式输出或移动输入的项目验证。
- 项目已有变量名称与组件职责明确时，在原系统中适配，不额外维护一套名称不同、含义重复的 token。

具体数值都是起点，不是跨字体、设备和内容的质量承诺。改变前景、背景或透明度以后重新检查对比；不能继承样张在另一种组合中的结果。

## 验证状态如何表述

只记录实际发生的验证：查看了哪个主题、什么视口或状态，是否检查了字体与相关对比，仍有哪些限制。没有操作过的演示不写成“交互已验证”；未在真实产品使用的方案不写成“适合该产品”。

本组样张与外部参考库分开管理。样张即使通过本地渲染检查，仍是原创候选；外部案例有文档依据但尚未查看画面时，也不能代替实际截图证据。是否适合作为后续项目的稳定起点，根据成品与任务结果逐步确认。

## 后续扩展

只有现有方向确实无法覆盖某种任务、内容或视觉关系时，再增加样张。优先补有意义的差异，例如新的文字角色配合、明暗结构或素材承载方式；仅更换强调色不足以说明新增方向的价值。

维护每个样张的真实来源、用途与验证记录。候选质量不足时修订或撤出推荐，不以图库数量作为完成标准。
