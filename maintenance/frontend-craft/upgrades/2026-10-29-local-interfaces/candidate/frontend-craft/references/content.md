# 内容编排

让内容形成可以理解、比较和继续使用的关系。保留正文、作品表达和必要依据的完整性；用编辑和呈现时机处理重复，不把字数少、区域少当作完成标准。

## 先建立理解与判断路径

从当前使用者和任务出发，找出主要对象，以及用户在行动前需要知道什么。区分主体内容、判断依据、操作辅助说明和实现要求；接口字段和开发说明不是页面内容清单。已有产品依据直接使用，只补本次会改变画面的判断。

先确定以下关系，再选择段落、列表、表格或其他形式：

| 内容关系 | 设计需要解决什么 |
| --- | --- |
| 语境与主体 | 用户需要先理解什么，才能读懂正文、对象或结果；导语可提供背景、论点或语气 |
| 对象与判断依据 | 哪些属性帮助识别，哪些差异决定选择；必要依据能否共同看到 |
| 结论与证据 | 出处、原文或计算依据怎样与结论保持关联，核查后能否继续原任务 |
| 连续论述 | 哪些内容需要连着读，标题、图表、引文怎样帮助理解而不切碎论述 |
| 动作与状态 | 操作针对谁，当前处于什么状态，结果或下一步在哪里出现 |

**分配地位，不把优先级直接变成置顶顺序。** 当前任务、判断条件和使用时机决定信息的地位。面积、对比、稳定位置、持续可见和相关状态中的突出，都能表达优先级。使用频率有证据时可作为依据；材料重复强调的次数只作线索，不据此把信息全部堆到首屏。

记录会改变界面的少量决定即可，例如“比较时同时显示日期与费用；长说明进入详情”。不另造一份完整内容清单或交接包。

一个卡片、面板或窗口内需要同时组织多种信息和功能时，见[局部界面组织](local-interfaces.md)，把这些关系落实为分组、顺序、控件与动作区域。

## 对象、属性与操作

识别“认出对象”“判断对象”“深入查阅”三种用途，但不为它们设置永久视觉等级。对象身份保持稳定可识别；名称、状态、价格或关键差异谁更醒目，由当前判断任务决定。简短备注或摘要可以是直接判断依据，不默认折叠。

**按查找方式处理标签和值。** 比较结果时可突出数值；用户按参数名称查找时，标签可能更需要突出。单位、范围和语境保持清楚。格式与上下文足以消除歧义时可合并标签和值；表单仍保留可访问标签，placeholder 不替代标签。

**让操作与对象保持明确关联。** 高频且容易理解的操作可直接出现；复杂操作可进入选中后的工作区、详情或菜单；多对象处理可使用与选择状态相连的批量入口。根据实际频率、操作成本和误操作后果选择，不要求每行重复全部按钮。悬停入口同时提供键盘与触屏路径。

**按判断方式选择分组、排序和筛选。** 分组支持逐类处理或理解阶段；排序形成跨对象的连续次序；筛选聚焦子集。它们可以配合，但不因字段存在就全部添加。分组如果打断了用户需要的全局比较，应改用更合适的顺序或呈现。

## 选择内容形式

- 稳定维度的横纵比较可用表格；不同长度的解释、图像比例或窄屏条件可能需要其他组织。保留比较所需的共同依据。
- 真实先后顺序可用编号步骤；并列核对可用列表；持续论述保持段落与章节。容器表达内容关系，不按需求条目逐项生成卡片。
- 文章、品牌与作品标题可以保留意象、语气和节奏；信息查找型标题优先提供明确定位。需要时用邻近内容补足语境，而非把所有标题改成卖点。
- 真实素材会改变表达形式。图、正文、引用和说明一起安排，不先用等长占位内容确定版式，再迫使真实内容迁就它。

## 编辑与呈现时机

**保留事实和表达。** 用户要求保留的内容、关键数值、来源与限制准确可得。来源保真不等于把所有背景材料渲染到页面；编辑表达不等于改写原始记录。宣传主张需要相应依据，品牌叙述和创作表达不必每句都带来操作收益。

**合并没有独立价值的重复。** 判断每处出现是否帮助理解、识别或确认，不只统计次数。长页、流程切换或关键决定中，重复当前对象、选择或必要条件可以减少回看；相邻区域反复介绍同一功能通常可以合并。

**按需展开，但保护当前判断。** 经常用于当前选择的依据直接可见；低频长详情可进入明确入口，例如“全部作者”。低频不等于不重要，与当前决定相关的条件不应被藏到操作之后。说明应帮助用户作决定，不能靠小字号让它在形式上存在。

**让首屏成为当前任务的入口。** 有内容的工具显示可工作的对象与判断材料；无内容时提供真实的开始入口。阅读页可以通过标题与导语进入主题，展示页可以由作品和有表现力的文字建立观看入口。首屏不必总结全部能力，也不要求所有事实都挤进主视觉。

## 辅助说明与真实状态

先判断说明服务什么用途，再选择位置和时机：

| 用途 | 处理 |
| --- | --- |
| 输入、选择或恢复所需信息 | 贴近相应决定和控件；内容准确，入口与实际能力一致 |
| 加载、保存、连接等即时状态 | 随真实状态更新；相关但不同的状态分别表达，操作后用户能辨认结果 |
| 新的费用、接收方、权限或不可逆后果 | 在相关决定前清楚可得；已知的常规行为不逐按钮重复声明 |
| 低频且有查阅价值的帮助 | 使用说明明确的按需入口，支持键盘和触屏 |
| 标签、当前值或动作已经表达的信息 | 合并重复说明，保留必要标签与可访问名称 |
| 开发机制、历史或自证说明 | 留在开发记录、日志或面向维护者的页面；不把移出的内容全部塞进帮助区 |

例如，阅读问答需要表达当前材料范围与引用来源；内部抓取链路或压缩算法通常不属于阅读内容。若处理导致内容缺失，说明会影响理解的具体缺失。模型选择、连接测试和保存状态按实际能力呈现，不用常驻说明代替清楚的控件和真实结果。

删改说明后，重新看相邻分组、标题和容器是否仍有作用，并调整整体比例。内容减少不自动要求撤掉全部表面，也不应用欢迎语或统计卡填满合理的等待空间。

## 处理未知与矛盾

核对来源、有效时间和项目已确认要求。未知不填成 0，样本明确用途，不编造用户研究、能力或业务事实。材料矛盾仍无法解决时，判断它是否阻塞当前核心决定：阻塞的及时澄清；不受影响的部分继续，缺口明确记录。不要默默删除关键条件，直到交付时才提出影响页面成立的问题。

## 两个应用推演

以下是方法示例，不是已验证的页面成果。

**连续阅读并核查依据。** 假设用户要理解一段论述，并随时检查引用。标题、必要导语、连续正文与图表形成阅读路径，引用标记通向可定位的依据。短注可以随文呈现，长证据可展开；检查依据后仍能回到原位置。取舍是同时可查与正文连续，不能为“全部可见”把论述拆成许多小卡，也不能为干净把出处全部隐藏。

**比较可选时间段。** 假设用户已经知道候选对象，需要按时间、费用和可用条件选择。对象名称保持可识别，当前决定性差异获得较高分量；字段相近时使用稳定对齐。复杂说明进入详情，已选条件在确认时再次出现。取舍是快速比较与充分理解，不能固定让名称压过所有判断属性，也不能为了去重取消确认所需的信息。

## 完成后核对

- 用户能否建立语境、找到当前对象，并读到必要的判断依据？重要内容是否获得了相应地位，而不是都被放到顶部？
- 正文、证据、作品表达是否完整？真实长度和差异是否改变了呈现，而不是被删到整齐？
- 操作、说明和状态是否在需要时出现？必要重复是否帮助继续任务，无用重复是否仍抢占画面？
- 内容变化后，原有比例、分组和阅读路径是否仍然成立？与[构图](layout.md)一起判断，必要时参考[完整范例](exemplars.md)。

## 方法来源

- Heleen van Nues、Lennart Overkamp：[Priority Guides](https://alistapart.com/article/priority-guides-a-content-first-alternative-to-wireframes/)，借鉴内容优先级与最终布局分开的方法。
- Sophia V. Prater：[Object-Oriented UX](https://alistapart.com/article/object-oriented-ux/)，借鉴对象、关系、动作与属性的判断。
- Adam Wathan、Steve Schoger：[Labels are a last resort](https://refactoringui.com/previews/labels-are-a-last-resort)，同时保留突出数值与突出标签的适用条件。
- Nielsen Norman Group：[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)、[Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)，借鉴渐进呈现与减少记忆负担；不把它们转成统一折叠或数量规则。
