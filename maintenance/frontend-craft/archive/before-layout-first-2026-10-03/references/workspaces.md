# 内容操作型界面

目标是让人高效找到对象、比较信息、完成操作，同时获得有视觉完成度的工具体验。不是营销展示，但也不能把能用当成好看。

- 从正面视觉标杆提炼布局比例、字体层级、色彩面积与细节精度，再适配当前信息密度；业务参考和旧后台不自动决定外观。不要默认侧栏、统计卡和等权网格的组合。
- 克制靠准确的比例、对齐、留白节奏与细节形成品质，不靠全页同字号、灰框或低对比。先做代表页并与标杆同屏审视，保留熟悉交互而非机械沿用旧皮肤。
- 先列实体及关系：订单、客户、库存、任务、文档等按实际业务区分层级。把系统建议与用户状态分开；未知不画成 0%，未保存不画成成功。
- 高频对象用稳定行列和一致位置；相同属性才纵向比较。列表、表格、树各有用处，不因“反卡片”或“反模板”禁用它们。
- 首页显示一个可信起点和可检索的对象；分组帮助选择，不重复整个侧栏。回访与首次使用如需不同内容，依据真实状态，而不是猜测。
- 工具栏靠近作用对象；说明筛选范围、当前数量、清空方式。没有筛选结果与没有数据是不同空态。更新失败不能变成空结果。
- 对桌面密集表格，窄屏保留题名、状态、主动作，次要属性展开；确实要跨列比较时允许局部横向滚动，给可发现的提示。别用隐藏列偷偷删信息。
- 文字不可读时先改列宽、层级和内容分组，再考虑字号。12px 元数据不应用于承担结论的长段落。常规交互目标优先 44px，WCAG 2.2 AA 的 24px 最小目标还涉及例外与间距，不能混为同一标准。
- 稠密不等于拥挤：减重复容器、统一行距，保留组间距；避免通过缩小字、降低对比、禁换行制造“装得下”。
- 图形表达关系时同时提供文字入口和关系含义。来源关系与编辑建议读序要区分。图无法看清时不靠无限缩放解决所有问题。

## 代表链路

搜索对象 → 看到匹配数 → 打开详情/依据 → 返回原筛选位置；检查长名称与中英混排、无结果、清空、加载失败重试。具有保存功能时增加保存→重读→失败保留内容。

可参考 shadcn data-table 的按需组合与 Radix 的焦点契约，但先查项目已用的组件。原生 input、button、details 足够时不用为小样安装 React/Tailwind。
