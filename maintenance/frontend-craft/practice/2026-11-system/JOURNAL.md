# 小系统练习手记：学生公寓报修处理台（2026-11-18）

11 月手做的九类页面都是单页。用户说做系统时前端效果很重要，而“系统”我没练过：几个页面要像一家，列表、详情、表单、统计各有各的事。这次手做一套，同时用同一道题跑模型作对照（见[对照报告](../../evals/2026-11-18-repair/REPORT.md)）。目的和上次一样：攒我自己的判断，页面本身不是目的。

- 方向 B（只做了主屏）：[三栏调度台](b/index.html)

## 先看了什么

- **GitHub Issues 列表**（实测，1440 宽）：每行两层，标题 16 px 中等粗细，下面一行小字；行高约 65 px。颜色只出现在状态图标和标签上，界面本身是白底细线。筛选不是单独一块，就放在列表的表头里。左边的导航是一列安静的文字。
- Ant Design Pro 的在线演示要登录，没有看。Linear 没有实测，只凭印象，不能算数。

从 GitHub 学到的一条：工作列表的一行可以是“一句话加一行小字”，不一定是七八列的表格。

## 写代码前定的三件事

1. **这是哪一类东西。** 值班员一个人坐班，整天开着它，电话一响就要用。它是工作队列，不是“管理后台”。所以不要侧栏、不要指标卡、不要欢迎语，打开就是待办。
2. **谁带颜色。** 只有时间压力：紧急单的倒计时、超时。状态、类别、师傅都是黑字。全站一种红。
3. **内容是什么形状。** 先看数据再画框：
   - 七种状态，对值班员只是三种处境：轮到我（待派单）、在师傅手里（已派单、处理中）、等学生（待确认）。所以列表分三组，不做七个标签页。
   - 派单时要知道的只有一件事：谁手上活少。所以把在手单数直接写在派单按钮上，点名字就派出去，可以撤销。
   - 催单是按师傅催的，一通电话问完他手上所有的单。所以右栏按师傅分。
   - 电话里大家说“竹园 2 栋 512”，没人报工单号。所以房间号是每行最大的字，工单号只在详情的角落里。
   - 网络问题唯一的动作是转交，所以那一行的按钮直接是“转交信息中心”。
   - 数据里有因为“重复报修”被取消的单。所以新建时，右边会提示这间宿舍还有没完成的报修。

这三件事定下来以后，版式基本就出来了。**这次最大的体会：和模型成品的差别几乎全部来自这一步，不是来自后面的样式。**

## 方向 A 和方向 B

- **A 派工单**：白底黑字细线，粗黑线分组，房间号用 Bahnschrift 大号数字，只有时间压力是红的。列表就是派工板，派单在列表里一下完成。
- **B 三栏调度台**：左边分类，中间列表，右边直接看单并处理，不换页。蓝绿主色，状态用彩色圆点区分，圆角大一些，更像常见的软件。

我自己选 A：值班员最常做的事（派单）点一下就完，画面也更有自己的样子。B 的好处是查一张单不用换页，学生来电话催的时候快。这是要请用户选的。

## 看图改掉的

第一轮（列表页）：

- 右栏每张单的“急”和左栏一样是红底，一屏里红色出现八处，“红色等于现在要动手”就不成立了。右栏改成描边。
- 派单按钮上的数字只写了“1”，看不懂。改成“1 张”。
- 手机上时间栏把内容挤成三行。把时间挪到房间号下面，内容回到两行。

第二轮（另外三页）：

- 表单里“哪栋楼”“哪一类问题”两个题目变小变灰了。原因是统计页图例也叫 `.legend`，类名撞了。看图才发现，检查脚本量不出来。
- 紧急勾选框里的说明文字整段是粗体。
- 详情页头部和“下一步”面板各写了一遍红色的超时，只留头部那一处。
- 热力表各列宽度不一样，改成等宽。

检查脚本之后：

- 手机上按钮和切换开关只有 36 px 高，改到 44 px。
- 热力表中间深浅的格子上，黑字白字的对比度都不够。改成三档深浅，每一档都配得上字色。

## 检查脚本这次的表现

- 抓到的：手机点击区域太小。
- 报错了但报得不对：热力表的底色是 `color-mix()` 算出来的，脚本读不懂，报成对比度 1:1。顺着去查，才发现中间那一档确实不够。
- 误报：折叠起来的“改派给别人”里的文字，被算成“文字压文字”。
- 漏掉的：类名冲突让标签变样、红色用得太多。这两个都是看图发现的。

## 和模型成品摆在一起

带技能和不带技能的两份（gpt-6.1-sol，各一次）几乎是同一个页面：侧栏、英文小标题、口号、四张指标卡、警示横幅、标签页，第一张工单排在第 600 多像素，第一屏只看得到两三张单。暖米色加墨绿，不带技能也是这一套。数字见[对照报告](../../evals/2026-11-18-repair/REPORT.md)。

我的判断（用户还没看过，先记下）：

- 模型的成品不难看，整齐、统一，单看任何一个局部都挑不出大毛病。问题是它是“管理后台”这个模板，不是为这位值班员做的。
- 技能现在管的是模板里面的细节（字号、对比度、表单写法），没有管“要不要用这个模板”。

## 想放进技能的（还没放，等用户看过再定）

1. 写代码前先写下三件事：这是哪一类、谁带颜色、内容的形状怎么决定版式。写不出来就先别动手。
2. 工作类页面的几条明确的“不要”：不要口号，不要装饰用的英文小标题，待办页不要先放一排指标卡，第一屏要能看到要处理的东西。这些可以量：第一条待办出现在第几像素、第一屏有几条。
3. 一套系统页的起步样例，结构和配色分开。
4. 检查脚本：读懂 `color-mix()`；折叠的内容不算重叠；加一项“第一屏里彩色有几种”。
