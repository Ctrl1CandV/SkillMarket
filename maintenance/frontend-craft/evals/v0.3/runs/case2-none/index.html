问题 → 方法 → 实验 → 局限

在 ReAct 之前，大语言模型的两种能力基本是分开研究的：一边是推理，比如 Chain-of-Thought（CoT）让模型先写出中间步骤再给答案；另一边是行动，比如让模型生成动作计划、在环境里一步步操作。

ReAct 的想法很直接：让模型交替写“想法”和“动作”，想法帮助它制定、跟踪和修改计划，动作让它从外部取得新信息。这篇导读按“问题—方法—实验—局限”的顺序梳理全文，重点放在方法和实验设计上。

一这篇论文想解决什么

只做推理的模型有一个老问题：它所有的判断都来自自己的参数，遇到需要事实的问题时，推理链看起来通顺，却可能建立在一个记错的事实上，而且错误会沿着链条一路传下去。论文把这类问题称为幻觉（hallucination）和错误传播（error propagation）。

只做行动的模型则相反。它能调用搜索、能在环境里操作，但没有显式的推理过程，很难把大目标拆成小目标，也很难在某一步失败后意识到需要换一种做法。

作者的判断是：人在完成任务时本来就是边想边做的，想的内容决定下一步做什么，做的结果又反过来修正想法。如果让模型也按这种方式工作，两种能力应该可以互相补足。

二ReAct 怎么做

ReAct 不训练新模型，核心是一种提示方式。提示里放一两个人工写好的解题轨迹，模型照着格式往下生成。每条轨迹由三种内容交替组成：

  • Thought想法模型生成

    用自然语言写下当前的判断，比如“我需要先查出这个人出生在哪一年”。想法不改变外部环境。

  • Action动作模型生成

    调用一个外部接口。在问答任务里，作者只给了三个动作：

    • search[实体] 搜索维基百科页面
    • lookup[字符串] 在当前页面里找关键词
    • finish[答案] 给出最终答案
  • Observation观察环境填入

    外部接口返回的结果，由环境填入，不由模型生成。

这样，模型每一步都能看到真实返回的信息，再决定下一步。对知识类任务，想法和动作通常一一交替；对需要很多步操作的决策类任务，想法只在需要的时候出现，比如拆分目标或者发现计划走不通的时候。

三实验看什么

论文在两类任务上测试 ReAct。

知识密集型推理

HotpotQA 多跳问答、FEVER 事实核查。模型只能通过上面三个动作访问维基百科。

交互式决策

ALFWorld 是文字版的家务环境，WebShop 是模拟的网上购物。

读实验部分时，建议关注三个结果。

  1. HotpotQA 与 FEVER：查资料减少幻觉，但要和 CoT 结合

    ReAct 通过查维基百科，明显减少了 CoT 中常见的幻觉和错误传播，生成的轨迹也更容易被人读懂和检查。但只用 ReAct 并不总是最好的，论文把 ReAct 和 CoT 结合起来，按条件在两者之间切换，效果更好。这说明内部知识和外部检索各有长处。

  2. ALFWorld 与 WebShop：一两个示例胜过训练方法

    ReAct 只用一到两个示例，成功率就比模仿学习和强化学习方法分别高出：

    +34个百分点ALFWorld
    +10个百分点WebShop

    这是论文里最醒目的数字（绝对值）。注意它比较的是提示方法和需要大量训练数据的方法。

  3. 错误分析：搜不到和原地打转

    ReAct 的失败有不少来自搜索没有返回有用信息，以及模型反复生成相同的想法和动作、陷入循环。读这部分可以帮助理解后来的工作为什么要加入反思或记忆。

四局限与延伸阅读

ReAct 依赖人工写的示例，示例的质量和风格会影响结果；轨迹较长，复杂任务容易超出上下文长度；动作空间也是人为设计的，换一个任务就要重新定义。作者还尝试用 ReAct 轨迹微调较小的模型，这部分可以作为选读。

读完 ReAct，可以接着读两篇工作：

Reflexion

让模型在失败后写下反思、存进记忆再重试，直接回应了上面提到的“原地打转”问题。

 Toolformer

让模型自己学会在什么时候调用什么工具，而不是靠提示示例。
