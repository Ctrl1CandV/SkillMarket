# 开源文档翻译协作

一个开源前端框架的 v4 英文文档要译成中文，二十多位志愿者在业余时间参与。现在靠一个 issue 认领章节，谁在译什么、译到哪、哪章等着审校都要翻长长的评论；术语各译各的，同一个词在不同章节里有三种译法。

请做一个文档翻译协作的网站，真的会用，要好用，也要好看。它有几个页面，要像同一个网站。

## 页面

1. **章节总览**：所有人看整本文档的进度：每个部分有哪些章节、哪些没人认领、哪些在译、哪些等审校、哪些已完成；英文原文更新后过时的译文也要看得出来。
2. **章节详情**：一章的字数、译者、审校者、认领时间和截止日、审校意见。在这里认领、提交审校、处理审校意见；要能对照看几段英文原文和中文译文。
3. **我的任务**：当前志愿者看自己认领的章节、到期时间、待处理的审校意见。
4. **术语表**：大家查某个英文术语该怎么译、哪些不译；可以提议新术语、给别人的提议投票。

## 已知情况

- 志愿者多在晚上和周末用电脑参与，也有人在通勤时用手机看进度、回意见。
- 章节标题、术语、代码保持英文原样，界面是中文。
- 认领后 21 天内要提交，过期没动静会被释放给别人。
- “现在”是 2026-11-19（周四）21:00。当前志愿者是贾浩宇。

## 数据

- `data/translate.json`：9 个部分 54 章（字数、状态、译者、审校者、审校意见、原文更新日期）、26 位志愿者、6 段示例原文、50 条术语和 3 条术语提议。`data/translate.js` 内容相同，写成 `window.TRANSLATE_DATA = {...}`，可以用 `<script>` 引入（双击打开的页面读不了 json 文件）。
- 只给了几段示例原文，没有完整章节内容。人名都是示例。

## 要求

- 用 HTML、CSS、JavaScript 写，双击文件就能在浏览器里打开，不联网也能用。可以分成多个文件。
- 认领、提交、处理意见、提议和投票之后，刷新页面还在。浏览器本地存储就够，不需要服务器。
- 成品放在当前目录，交付时告诉我怎么打开、做了什么取舍、哪些没做。
