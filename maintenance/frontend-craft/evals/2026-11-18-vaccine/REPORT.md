# 对照结果：frontend-craft 0.7.0，加不加 modern-web-guidance（2026-11-18，各跑一次）

依据开跑前写定的 [PLAN](PLAN.md)。两组都用 pi + deepseek-flash，技能快照为仓库提交 `7d1617f`。成品留在本地临时目录，没有入库；对照截图见 [shots/compare.jpg](shots/compare.jpg)。

> 同日补跑了 0.6.2 基线（C）和修订后的 0.7.0（A2），结论有更新，见文末“补充”。

## 一句话结论

**两组的差别比预想的小。** 只带 frontend-craft 0.7.0 的 A 组，也用了原生对话框、rem 字号、包含深色的 `color-scheme`、`aria-invalid` 和强制颜色轮廓，这些正是 0.7.0 正文里“没有该技能时至少做到”的几条。B 组多出来的是：
- 格式说明放在输入框上方；
- 家长姓名开了自动填充；
- 取消对话框的默认焦点用 `autofocus` 明确指定；
- 交付时写明用了哪几篇指南。

代价是费用多了 62%。每组只跑了一次，而且没有跑 0.6.2 当基线，所以分不清 A 组的这些写法，是 0.7.0 正文带来的，还是模型本来就会。

## 由此得到的待办

- **Playwright 临时目录残留**：frontend-craft 的 `env.mjs` 和 pagecheck 每次运行都可能在 Windows 的临时目录留下一个 Playwright 浏览器目录，越积越多。可以考虑在启动时指定一个固定的临时位置，结束后自己清掉。
- **要不要跑 0.6.2 基线**：如果想知道 0.7.0 正文本身起了多大作用，可以用同一题目再跑一次 0.6.2 当基线。这次没跑。
- **画面**：两组方向不同。A 是分步骤加整张日期×时段表；B 是一页分三块，桌面版有一张固定在右侧的核对卡。没有请用户盲看。

### 分析

1. **0.6.2 已经会用原生对话框**，默认焦点和 Esc 也都对。0.7.0 正文真正带来的变化是：
   - rem 字号；
   - 写错离开就报错；
   - 写了强制颜色规则。

   A 组在思考里明确写着“没有 modern-web-guidance，按正文那几条做：`<dialog>`、rem、最小高度、color-scheme”。
2. **指南的增量是三处细节**：说明放上方、家长姓名自动填充、安全按钮上的 `autofocus`。B 组比 A 组多花了 0.207，其中：
   - 输出和思考多了约 9 万 token，约占一半；
   - 读进来的指南约 20 万字符，之后的每次调用都带着，加上截图更大，约占四成。

   B 还多做了一个确认框，所以多花的钱不能全算在指南头上。
3. **这三处细节，A 组的 review.md 里其实写了一部分**（说明放上方、离开才报错），但 review.md 是做完才读，没起作用。正文第 5 步那几条是动手前读的，模型照做了。所以修订时把清单放进第 5 步。
4. **修订后的 A2 拿到了 B 组的三处细节**，费用 0.362，比 A 多 8%。每组只跑了一次，这 8% 在单次波动范围内，不能当成清单本身的成本。
5. **补跑时发现 pagecheck 的漏洞**：
   - 页面以本地文件打开时，Chrome 把外部样式表当成别的来源，读不到里面的规则，px 字号检查就悄悄跳过了。C 组的 HTML 和 CSS 分成了两个文件，68 条 px 字号一条也没报出来。A 和 B 都是单文件，所以前面没发现。
   - 已修：启动浏览器时允许读本地文件，并加了回归用例。只在 `<meta>` 里声明深色、靠脚本切换主题的页面，现在也会另存深色截图。

### 决定

- **modern-web-guidance 不发布**，技能文件移到 `maintenance/modern-web-guidance/skill/`，已从 Claude Code 和 Codex 的技能目录删除。理由：
  - 增量能用几行清单拿到；
  - 它的描述要求所有 HTML/CSS 任务都先执行，装上以后，视频、幻灯片之类的 HTML 任务也会去查。
- **frontend-craft 0.7.0 按修订版发布**。它不增加每次任务的成本，换来 rem 字号、离开即报错、强制颜色、说明放上方、自动填充这些可测的改进，以及 pagecheck 的三处修正：color-mix 颜色、320 宽度、外部样式表。
- 这次没有改变画面和版式，0.7.0 本来也不针对这些。前端“好不好看”仍要另想办法。
