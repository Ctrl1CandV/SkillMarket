# 拾声档案工作台：0.4.2 修订样例

2026-10-25。使用工作区 `frontend-craft` 0.4.2 与 `product-design` 0.1.0；版本哈希见同目录 `analysis.md`。本轮未修改运行技能。HTML 由主执行者在已有对话及用户反馈下重新实现，不是独立、受控的新旧技能实验。

## 内容与任务

虚构档案编辑林嘉宁，处理澄湾口述计划的六份录音记录。任务是辨认与选择档案、阅读和修正逐字稿、处理待确认内容、保存草稿、把本机状态转为待复核。六份内容包含长短不同的标题与文本、不同校对状态，以及无法从现有笔记确认的信息。

这些都是示例设定，不是访谈研究或真实用户数据。未提供录音，因此不能真实核对音频；页面保留这一限制，不提供假的播放按钮。

## 视觉决定

| 依据 | 页面决定 | 要检查的结果 |
| --- | --- | --- |
| 编辑者要反复在档案之间切换 | 左侧完整档案队列，选中档案与逐字稿共同可见 | 标题、人物、地点、状态可直接用于选择 |
| 当前对象应先进入视线 | 默认打开第一份档案，去掉统计卡和欢迎介绍屏 | 第一屏直接呈现录音身份、正文与确认项 |
| 逐字稿需要持续阅读与改字 | 正文 16px、行高 1.85，标题 22–24px；辅助文字至少 12px | 不通过缩小正文容纳旁栏 |
| 旧稿背景和表面过于相近 | 深梅外框、暖灰档案队列、近白纸色正文形成区域分工 | 导航退居外框，当前记录与正文得到明确承托 |
| 颜色需要分清动作与状态 | 梅色主操作，琥珀待确认，蓝灰待复核，中性灰归档 | 状态有文字，不只靠色相判断 |
| 窄屏仍需连贯处理同一档案 | 700px 以下列表与详情分两步，提供返回入口 | 不把三栏压成很细的三列 |

构图取舍：如果沿用概览首页，进入校对还需一次切换，内容重点分散；直接列表加编辑区更符合这份样例的主要任务。颜色方向没有从“管理后台”机械推出蓝色，也没有把绿色列为禁用色；本次选择来自对旧稿区域分工、对比和阅读尺度的具体修订。

## 实现范围

- 标题、人物、地点、编号及标签搜索；状态筛选；待处理、全部档案、待复核范围切换。
- 记录选择、三段逐字稿编辑、待确认片段勾选、档案信息查看。
- 保存草稿、提交复核、退回校对；已归档只读。待确认项未完成时不能提交复核。
- 切换记录时，未保存的内容仍保留在当前页面内；关闭页面前有未保存提示。
- 保存到当前浏览器的 localStorage，重新打开可读取。保存失败时提示错误，不把未保存内容报成成功；空逐字稿不能保存。
- 无搜索结果时显示恢复入口；移动端返回列表及键盘页签操作。

不连接真实服务、不向其他用户提交、不执行真实归档发布。双击 `management.html` 可打开；没有外部字体、图片、脚本或构建依赖。

## 已验证与未验证

已做 JavaScript 语法、静态 ID/引用、外部资源检查。通过 Node VM 和轻量 DOM 桩检查了六条记录、搜索、无结果及恢复、切换保留编辑、保存持久化、确认后转待复核、复核范围、退回校对、空文阻止及存储失败保留修改。它们是状态逻辑检查，不是浏览器点击测试。

静态配色计算：正文/纸面 15.15:1，次级字/纸面 5.77:1，次级字/队列 4.69:1，侧栏次级字/深底 8.96:1，按钮白字/梅色 8.36:1；已查的三种状态标签约 5.19–5.91:1。不能据此声称画面已经好看。

代码审查发现并修正了两处移动端问题：无结果时退出详情模式、恢复空状态入口；选择档案时先显示详情，再计算逐字稿高度，避免在隐藏元素上得到零高度。

未进行浏览器实际画面、窄屏截图和真实键盘/触屏验收。此前本地 file URL 浏览器访问受工具策略限制，本轮没有绕过。仍需用户在实际浏览器查看字号、断行、区域比例和整体观感。
