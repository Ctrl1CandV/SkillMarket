# 页面生成请求

使用调用者指定的 frontend-craft 技能，完成以下三个独立页面。目标是做出美观、中文可读、能实际操作的页面。每个页面交付独立 HTML，CSS 和 JavaScript 内联，不用构建、网络字体、远程图片或外部服务。可以自行绘制 SVG。使用 Windows 可用的系统字体，支持桌面和手机。

这些是本地交互原型：请求、导入、保存用浏览器内状态模拟，不访问真实服务。交付说明写明模拟范围。由统一验收者渲染和检查，因此本次生成者只做实现和代码自检，不启动浏览器、不看其他生成结果，不加载另外的设计技能。不要修改指定输出目录之外的文件。所有必要功能必须保留；页面的组织与视觉设计由你决定。

## reader.html：研究阅读与问答

为个人科研阅读工具“知页”做一篇中文导读页，桌面能边读边问，手机也能完成阅读和提问。文章题目为《检索增强系统：为什么多取几篇不总是更好》，阅读范围有“整篇文章”和“当前章节”。文章至少包含下面三节正文，可做必要编辑，但不添加实验数值或作者结论。

1. 检索与证据：检索器找回的文本只是候选证据。相似度回答的是表达是否接近，不能单独证明段落能够支持问题中的结论。阅读时先确认问题所需的证据类型，再检查候选段落的对象、时间和条件。把相关性和支持关系分开，才能识别看起来切题但不能回答问题的材料。
2. 上下文预算：增大 top-k 会增加可见材料，也可能引入重复信息和冲突。生成模型需要在有限的上下文中定位依据；当新增段落没有带来新的证据时，更长的输入未必改善回答。这里讨论的是需要验证的机制，不能直接推出所有任务都应减少 top-k。
3. 怎样检验：先固定生成模型、问题集和检索索引，再改变候选数量。分别观察答案质量、依据是否支持结论，以及延迟与成本。对于改善或退化的样本，回查新增段落究竟补齐了证据，还是挤占了有效上下文。结果应区分任务切片，避免用总体均值掩盖差异。

问答面板支持范围选择、输入问题、发送、显示带所选范围的回答、开启新对话。提供两个可点击的起始问题：“相关性和支持关系有什么区别？”、“怎样设置公平的对照？”。发出问题后保留历史；本地返回一段与对应章节一致的简短回答。

AI 设置从问答面板可打开：连接方式有“订阅账号”和“API”，初始订阅已连接，模型有“均衡”“深入”，改变模型后需要显式保存。授权正常情况下自动续期。刷新状态会重新读取模型；实现加载和读取失败的状态，失败可重试。可以断开连接，不自动切换到 API；用户主动选择 API 时说明按调用量计费，配置一个测试用地址后才允许切换。提供低调的原型故障复现入口使验收者能触发一次模型读取失败。

## import.html：实验数据导入

为“试验簿”做 CSV 导入界面。当前项目“检索对照”，已有 24 条记录。接受 UTF-8 CSV，最大 5 MB，必需列为 run_id、method、score；score 必须是 0 到 1 的数值。用户可选择本地文件、查看预览、调整导入方式并执行导入。提供可用的内置样例和一个格式错误样例入口，便于不上传文件也能体验；错误样例为一条 score=1.4 的记录。

内置有效样例：r025, dense, 0.72；r026, hybrid, 0.79；r027, rerank, 0.81。

导入方式为“追加”和“替换全部”。追加是默认项；替换会不可恢复地清除现有 24 条记录，应在执行前获得明确确认。预览阶段不会改数据。导入失败时保留用户的文件和选项，并能重试。实现成功、校验错误和一次模拟导入失败，可用低调的原型入口触发失败。

可选云同步初始关闭，启用后会将实验记录及文件名上传到第三方“CloudBox”，不上传原始 CSV 文件；关闭后停止后续同步，不自动删除已经上传的记录。启用前让用户能了解并选择是否同意。云同步选项与导入都需要可以用键盘操作。
