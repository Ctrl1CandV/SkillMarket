# 视觉样式

## 判断起点

第一眼的偏好研究可以帮助检查复杂度和熟悉感，不能直接推导出所有界面的色度、色相或留白配方。先按目标用户、任务和素材判断，再用实际画面与反馈校准。

- **层次来自关系。** 对齐、比例、组间距、字体角色共同区分主要内容和辅助信息；减少重复后仍要有视觉主角，不能只剩一屏相同的灰字。
- **熟悉感服务操作。** 工具的控件与导航遵循惯例，阅读页保护正文，作品展示让作品当主角。个性可以来自排版、色彩、图形和素材，不必重造操作方式。
- **复杂度要有用途。** 删除无关内容与装饰，保留任务需要的复杂度。聊天的等待空间、文章的段落节奏和展示页的留白都可以成立。

## 方向：在惯例的骨架上找主题特色

- **先看成功标准**：工具让用户完成操作，阅读页帮助理解，落地页支持选择，作品页呈现作品的气质。密度跟随内容量与使用频率，个人工具不必像企业后台一样紧凑。
- **从主题找特色。** 如样本库的孔板定位图、任务状态轨迹、纪要里指向原话的编号。它应帮助识别或理解；没有合适元素时，用字体、比例与配色完成设计，不必硬加一个装饰组件。
- **有设计参考说明就按它定方向。** 没有的话，先写一句方向描述（比如“像实验室台账一样，密而有序”），后面每个样式决定都拿它来检查。
- **方向不明确时才比较。** 展示页整体改版或用户反复否定视觉方向时，可用相同内容比较两种不同构图；普通局部修复直接继承现有设计。长期项目复用已认可的设计约定，有必要时简短记录新增决定。

## 字体

- **角色**：标题、正文、界面文字、数字与编号，各定一种处理方式。一款黑体配几个字重往往就够了；宋体等衬线体适合正文阅读和需要书卷气的标题；等宽字体适合编号、时间码和代码。
- **尺度随页面类型变化**：
  - 数据密集的管理页：界面文字 13–14px，表格行高 36–44px。
  - 十几到几十条的个人列表：条目标题 15–17px。
  - 阅读页：正文 16–18px。
  - 展示页：标题可以很大。
- **至少一级标题要拉开差距**，让层级一眼可见。
- 上述字号是起点；手机、长中文和实际字体要重新看，不能为塞进屏幕持续缩字。
- 中文字体的细节见[中文排版](cjk-typography.md)。

## 颜色

**统一颜色的角色与面积。** 先分清背景、正文、主要操作、选中、语义状态和数据系列，再决定色相。减少相互争夺注意力的色块，保留必要区分；不要求所有颜色向主色靠拢。

- **日常工具的起点**：柔和背景、明确正文、克制的强调色，冷暖均可。继承项目已认可的颜色，避免同一屏多个高饱和大色块竞争。
- **展示与品牌**：由作品、照片和品牌决定颜色及面积。朱红、深棕、墨黑或鲜亮色都可能合适；明度、比例和可读性比色相名称更能指导修改。
- **状态与图表**：状态优先可辨识，数据系列优先能区分，不能为统一低色度把警告或相邻数据混在一起。文字、形状或纹理提供额外区分。

**生成阶梯**：可用 OKLCH 管理颜色档位。下面只是浅色工具页的柔和起点，不是色度上限；换底色、字号或颜色后仍需检查实际对比度：

```css
:root {
  --h: 250;                                   /* 主色相 */
  --bg:      oklch(98% 0.008 var(--h));       /* 页面底，带一点主色倾向 */
  --surface: oklch(95% 0.015 var(--h));       /* 分区底色、浅色色带 */
  --line:    oklch(88% 0.02  var(--h));
  --muted:   oklch(52% 0.03  var(--h));       /* 次要文字 */
  --ink:     oklch(25% 0.03  var(--h));       /* 正文 */
  --brand:   oklch(45% 0.08  var(--h));       /* 主色：标题强调、选中项、主要按钮 */
  --accent:  oklch(62% 0.09  calc(var(--h) + 40));  /* 强调色：相邻色相，小面积 */
  --danger:  oklch(50% 0.09  22);             /* 语义色单独定义 */
  --warn:    oklch(52% 0.07  70);
}
```

- **面积分配**：
  - 工具页的大面积背景通常较安静，让正文、当前选择与主要动作更明显。
  - 分区先靠对齐和间距；底色帮助分组时再用，不必每组都铺色带。
  - 展示页可用大面积品牌色或深色承托作品，按实际画面判断比例，不设全页深色块数量上限。
- **语义色**：成功、警告、错误单独定，不和主色、强调色混用。
- **状态表达**：用颜色加形状或文字一起表达，比如实心、半实心、空心，图标，文字标签。
- **对比度**：在实际底色上计算。普通文字至少 4.5:1，大字至少 3:1；识别控件和状态必需的边界或图形至少 3:1。次要文字也要可读。
- **深色主题**：单独调整。大面积降低亮度，强调色适当提亮，状态色重新核对。

## 素材与图形

- **先想清楚它承担什么信息**：说明流程、展示真实对象，还是营造氛围。能由数据本身画成的图形，比如进度点、分布条、孔板、时间轴，优先于装饰插画。
- **没有获得授权的素材时**，用排版、色块和由数据生成的图形完成画面。

## 细节

- **圆角、边框、阴影**：各定 2–3 档，全页统一。
- **阴影**：只给浮在页面上的东西，比如弹层、下拉菜单、拖动中的卡片。
- **图标**：用同一套、同样的线宽，和文字基线对齐。
- **编号、日期、ID**：用等宽字体或 `tabular-nums`，对齐成列。
