# 看图清单

页面好不好，看渲染出来的画面才知道。代码里看着合理的布局，渲染后常常出现遮挡、断行和首屏落空，这些只有看图才发现得了。

## 怎么看

- **渲染方式**：用当前环境能用的任何方式，比如浏览器、无头浏览器或截图工具。看的是实际像素。
- **至少看这些画面**：
  - 桌面宽度（约 1280px）和手机宽度（约 390px）各看首屏和整页，包括页面下半部。
  - 至少一个非默认状态：空结果、出错、选中、展开或最长的内容。
- **先确认字体**：无头环境缺中文字体时，中文会显示成方块或别的字体，要先解决再评审。渲染引擎报告的实际字体，比 CSS 里声明的字体可靠。
- **看到够用就停**：一般看两轮，第一版一轮，修订后一轮。额外的宽度和状态，只看和这次任务直接相关的一两个；交互只验证主要流程。没有新问题就停止检查，交付。
- **静态检查只是补充**：构建、链接检查、对比度计算可以补充，但关于画面的结论要来自看过的图。
- **按任务验收**：工具页看能否直接操作，阅读页看正文是否连贯，展示页看主题和素材是否有表现力。分别判断内容、功能与视觉，不把多做一个功能直接算成审美进步。

## 逐项检查

| 问题 | 怎么看出来 | 常见修法 |
| --- | --- | --- |
| 遮挡与重叠 | 文字被图形、浮层或固定栏压住 | 把绝对定位的元素放回文档流；给固定栏留出等高的空间 |
| 首屏落空 | 页头和说明挤走结果、正文开头或主要操作 | 合并重复介绍，让主内容进入首屏；聊天空白和展示页主视觉按用途判断 |
| 重复控件抢眼 | 每一行都有一个相同的按钮，比内容还显眼 | 降低次要操作的视觉权重；若按悬停显示，保留键盘和触屏入口，整行可点也要有语义明确的链接或按钮 |
| 制作话语 | 制作过程、开发版本号和检查记录抢占页面 | 移到交付说明；必要的示例数据提示留一处，产品本身的版本、来源与修订信息保留 |
| 解释过量 | 标题、导语、placeholder、帮助重复用途；正常行为承诺常驻 | 控件已表达的删掉，必要条件保留；临时状态回到对应控件，低频帮助按需出现 |
| 区域过碎 | 同一对象的状态、选择、动作各占一张卡；删完文字还留空壳 | 合并相关区域，撤掉失去用途的标题、卡片和分隔，不靠缩小字或全部折叠解决 |
| 中文断行 | 标题末行只剩一两个字；日期、数字或固定短语被拆开；标点落到行首 | 标题用 `text-wrap: balance`；不该拆的短语加 `white-space: nowrap`；断行规则用 `line-break: strict` |
| 字距被拉开 | 两端对齐的段落夹着长英文词，手机上某一行的字距明显变大 | 窄栏改左对齐，或允许长词断开 |
| 对齐线错位 | 相邻区块的左边缘或顶边不在一条线上，比如侧栏顶部和主栏标题错开 | 统一容器内边距，让相邻区块共用起点 |
| 分区不清 | 不能辨认主内容与辅助区；同层级用了相互竞争的划分方式 | 先合并没有独立用途的区块，再用对齐、组间距和确有作用的标题建立层级 |
| 过于复杂 | 颜色、字号、边框、标签的种类太多，处处都想强调 | 合并样式档位，把强调留给一两处；层级靠字号和明暗拉开 |
| 色差突兀 | 多块饱和颜色争夺主次，状态比内容更抢眼 | 先调面积、明度与强调角色，再按需要降色度；保留品牌含义与状态辨识 |
| 颜色沉闷 | 主体与背景明度过近，大片暗色压住内容或不符合题材 | 检查真实底色上的对比，调整明度、面积或素材；不按色相名称直接换成蓝绿 |
| 空着的栏 | 一个独立栏没有持续用途，却压缩了主内容 | 取消或并入主区；需要选择才能查看时给入口，默认预览仅在无业务副作用且符合任务时使用；聊天留白正常 |
| 过于单调 | 整页只有灰色和一个点缀色，所有文字一样大，区块之间没有明暗变化 | 用主色系的明暗做分区底色，拉开标题层级 |
| 空洞与拥挤 | 无用途的容器占位，或元素挤在一起看不出分组 | 去掉无用途的容器，按组内与组间关系调间距；保留阅读节奏和未来内容所需空间 |
| 窄屏拆散 | 相关信息被拆开，操作离对象太远，固定条盖住内容，页面横向滚动 | 按任务重排，不要等比缩小；横向滚动只留在表格或代码自己的容器里 |
| 字体回退 | 实际字体与设计不同；粗体是合成的（宋体常没有真粗体） | 换成有对应字重的字体，或换一种强调方式 |

## 操作检查

精简后走一遍主要流程：键盘能找到并操作控件，焦点可见且不被固定栏盖住；表单仍有标签，错误关联到字段；保存前后与失败重试的状态明确，异步结果可被辅助技术感知。悬停才出现的操作在触屏上也可找到。检查原生下拉框展开后的文字与底色，不只检查关闭时的外观。

费用、数据上传、权限和不可逆后果在有关操作前可见；短文案没有改变实际保存、刷新、选择或连接语义。用相关状态验证这些条件，不另造一套常驻“使用说明”。

## 修订顺序

每轮挑影响最大的三处，先判断它属于哪一层：

- **结构问题**：主次颠倒、分组误导、首屏落空、窄屏拆散。回到内容和结构重新排，靠调颜色或加阴影解决不了。
- **样式问题**：字体角色、颜色面积、素材质量不对。换一个选择。
- **细节问题**：局部修即可。

修完后，在相同的宽度和状态下重新看改动处和它相邻的区域。

## 交付说明里写什么

写清楚看过哪些宽度和状态、改了哪几处、还有什么没看（比如真机、深色模式、键盘操作）。没看到渲染画面就直接说明。自己看图得出的结论称为“自检”，不等于用户验收。
