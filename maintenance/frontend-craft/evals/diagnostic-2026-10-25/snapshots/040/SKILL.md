# Frontend craft

好页面首先是内容编得好：访客要的东西在前面，相关的信息放在一起，每个元素都说明一件真实的事。结构和样式把这种编排变成看得见的层次，两者同样重要。最后用实际渲染的画面检验，不凭代码推断效果。

先明确谁在用、要完成什么，再判断美感：主次分明，比例与间距协调，字体易读，颜色与素材符合题材。熟悉的操作保持熟悉；阅读页让正文连贯，展示页让作品与主题有表现力。一般设计研究作为参照，用项目约束和真实反馈校准；项目或用户有明确偏好时，按他们的来。

## 开始前

读用户给的内容、现有页面和项目约定。项目里有设计参考说明（认可的页面及原因、否定过的方向、品牌规范）时先读它，它优先于本技能的默认取向；用户在对话里的要求又优先于它。

先判断工作量。局部精修只动目标区域和受它影响的地方，直接从第 4 步开始；新建或整体重做走完整流程。

## 流程

1. **编内容。** 按访客的任务排先后，区分要展示的内容、要实现的行为和背景材料。用户指定保留的内容、关键业务事实与输入条件保持准确、可访问；重复解释合并，无关背景可以不进入界面。决定哪些内容直接可见、哪些按状态或需要出现。
2. **定结构。** 按内容之间的关系选排法：连续阅读、列表加详情、比较表、主栏加侧栏等。先给正文、表格和图留够空间，再分配导航和辅助区，并想好窄屏时谁让位。
3. **定方向和样式。** 由任务、内容量与素材决定密度和视觉主角：高频数据操作可以紧凑，个人工具要有呼吸空间，长文保持阅读节奏，展示页围绕作品组织构图。从主题自己的材料、器物和用语里找特色，不必另造装饰区。字体、颜色、间距、圆角设统一角色；柔和配色可作工具页起点，品牌和素材决定其他场景的表达，状态仍需清楚可辨。
4. **看图修订。** 用当前环境能用的方式渲染页面，看桌面和手机宽度下的首屏和整页，以及空结果、出错、长内容等关键状态。按看图清单逐项检查，每轮先修影响最大的三处，再看一遍改过的地方。一般两轮就够了。
5. **交付。** 说明改了什么、为什么这样改、看过哪些画面、还有什么没验证。

## 页面上只写访客需要的内容

让内容、控件和当前状态承担说明。标签、选中值和操作已经表达清楚的信息，不另加功能介绍或正常行为的承诺。辅助说明在影响当前选择、避免真实错误或帮助恢复时出现，贴近相关控件；低频帮助提供明确入口。费用、权限、数据去向和不可逆后果在决策前可见，不能仅藏在 tooltip 中。

减少文字时，也撤掉失去用途的标题、卡片和分隔。聊天区可以留白；不要为填满页面制造内容。保留必要标签、可访问名称和状态反馈，保存、刷新与连接行为以实际实现为准。具体取舍见[内容编排](references/content.md)。

制作过程、开发版本号和检查记录放在交付说明里。访客确实可能被误导的地方（比如数据是示例）留一处简短说明；产品本身需要的版本、来源或修订信息正常保留。

## 按需阅读

新建或整体改版，先读内容编排、排布手法和视觉样式；实现后用看图清单验收。局部修改只读对应参考和相关检查项。中文页面读中文排版，同一任务已读过的不重复加载；场景与范例用于尚未解决的设计问题。

## 边界

技术栈、依赖、发布和提交按项目现状和用户授权处理。外部图片、字体和代码按许可使用，不用真实品牌制造背书。PDF、DOCX 和原生 App 交给相应的技能：这里的设计判断可以带过去，验收按那个媒介重新做。

方法上参考了 oil-ui、Impeccable、Anthropic frontend-design 与 Vercel Web Interface Guidelines 的公开做法；按本技能的中文内容和日常工具场景取舍。
