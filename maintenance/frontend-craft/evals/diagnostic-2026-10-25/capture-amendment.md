# 截图方式执行偏差与比较边界

日期：2026-10-25。性质：在原协议生成、首稿冻结及两份作者修订之后登记的执行补充，不是生成前预注册，也不替换或追改 [protocol.md](protocol.md)。本复核只阅读执行记录、检查清单、首稿/修订文件清单与组织者本轮说明；没有启动浏览器或查看各页审美。

## 原约定、故障与替代方式

原协议约定同一浏览器、字体与缩放环境，桌面 1280×800、手机 390×844，提供默认首屏、整页与一个预定关键状态，再由原作者作一次修订。该补充登记时 p152、p447 已收到旧截图包并完成一次修订；随后其余十位也各完成一次修订。最终截止状态为 12 份首稿检查完成、12 份修订产物完成，但仅 p152 完成修订浏览器复验，p447 只打开未验；用户要求收敛后停止剩余检查，详见 [execution.md](execution.md)。

组织者本轮直接报告：用户切回会话后，普通 `tab.screenshot` 的 viewport 一度成功，fullPage 随后仍持续失败；原生 `tab.getScreenshot` 在 Control+Home/End 后已能随 DOM scrollY 显示相应内容，保持固定视口。此前发生过原生截图滞留，因此这次可刷新是恢复证据，不能仅凭一次 Home/End 校验保证往后每张捕获都新鲜。本文件不独立认证该工具已全面恢复。

实际采用固定视口、重叠滚动的原生截图序列覆盖首稿页面：不拼接、不拉高视口，不修改 HTML/CSS 以适配截图，每段记录 scrollY、文档高度、视口及文件名，并给尚未修订的作者其本人的完整序列与预定关键状态。此法保留真实响应式宽度和逐屏阅读，适合继续检查；它改变了整页呈现方式，**不能称原协议已完全执行，也不能把分段序列称为原 fullPage 截图的等价替身。**

## 首稿与修订机会分开解释

| 判断对象 | 可保留的可比性 | 必须保留的限制 |
| --- | --- | --- |
| 12 份首稿的生成 | 首稿早已冻结，截图方式变更不改变其任务、Skill、作者隔离或原始代码 | 它只解决观察方式，不能追认浏览器、视觉或功能已通过 |
| 首稿的统一视觉评审 | 可对全部 12 份冻结首稿按同样分段方式、视口、状态重新取证，再做同任务同阶段比较 | 应包括 p152、p447；若仍有人只看 fullPage、有人只看分段图，就不能声称呈现条件一致。整页节奏的整体把握与一张长图不同，结论限于分段观察或明确记录的原页浏览 |
| 每个作者的修订机会 | 每人仍只修订一次；不向 p152、p447 再反馈补拍图或允许第二次修订，可以避免增加轮次数 | 同样一次不等于相同视觉输入。两个旧包与十个分段包在画面数量、整体概览、滚动上下文与阅读负担上不同 |
| 修订成品的统一复查 | 所有修订完成后，可再用同一分段方式、视口、状态检查全部成品；同一运行前后也可用统一观察材料并列 | 统一结果展示不能消除作者修订时已经受到的不同截图输入。可描述哪些成品更受偏好、哪个运行发生何种变化，不能将组间变化完全归因于 Skill 或“统一截图后修订”的净效果 |

另一个实际差异是 p551 作者所见手机内容宽度为 390 px，其余原生分段通常为 375 px；两者 CSS 视口均为 390 px，滚动条占用不同。后补 p551 的 375 px 图只供观察，没有送回作者。p551 的关键状态图使用早期 PNG，默认序列为 JPEG。

这里有具体的不均衡：p152 属于 0.4/research，p447 属于无 Skill/collection；旧截图包并未均匀分布于三个条件。p447 的旧手机 viewport 还保留了非零滚动位置，未显示页眉；完整手机图包含页眉。该偏差已记在 [execution.md](execution.md) 与 [browser-checks.json](browser-checks.json)，作者也已识别。补拍可纠正评审者看到的默认首屏，不能倒改作者已经收到的输入。

因此不需要仅为截图方式改变而废弃、重生成首稿；也不能把这次修改说成彻底恢复原设计。修订阶段应列明每次实际获得的截图形式和例外，保留全部运行。不能为了得到“干净结果”静默删掉 p152/p447：删掉会改变原来每格两次的矩阵，且其偏差并非作者生成污染。若另看剩余十次，只能标作不平衡子集的探索性观察。

## 固定分段取证的最低一致性

以下保留本次恢复后的操作约定并注明实际偏差；不以文件数量代替完成状态。无效图已清理，有效原始图与排除记录仍保留。

1. **冻结与状态。** 先核对目标 HTML 哈希和阶段，保持原文件；默认状态重新加载或明确复位为任务约定状态，再确认顶部实际 `scrollY=0`。关键状态仍按原协议动作形成，不因某页看起来如何而挑另一状态。有效旧截图和原作者收图记录保留，补拍另命名；已确认无效捕获在收尾清理中删除，排除原因留在执行记录。
2. **视口与环境。** 桌面固定 1280×800，手机固定 390×844，保持浏览器缩放与字体环境。记录实际 CSS 视口、图像像素尺寸，必要时记录 DPR；两者不能混为一谈。若捕获含浏览器界面或实际尺寸不一致，标记，不将其自动混入页面截图组。
3. **从顶到底完整覆盖。** 原补充建议约 25% 重叠，实际手机 PageDown 步长约 738.4 px；在 844 px 视口中重叠约 105.6 px（12.5%），并非落实了 25%。已保存默认序列按实际纵向区间检查无缺口，末段到达底部；不倒改原协议或把建议写成已执行事实。使用实际 scrollY，不以按键次数估算。按内容长度自然产生的张数差异可以保留，不强制每页截同样张数，也不按内容好坏截取有利区域。文档高度或布局若在过程中改变，注明并重新取得稳定的序列。
4. **逐段确认新鲜度。** 保存每张时记录 run、stage、viewport、state、segment 序号、scrollY、document height、文件名与捕获方法；核对画面中的可辨内容与当前 DOM 位置，并检查相邻重叠是否连续。已有重复图像时结合实际位置判断：相同顶部/底部本可重复，明显相同内容却对应不相容的 scrollY 要标无效重拍。Home/End 成功一次不免除逐段核对。
5. **区分滚动容器。** 文档区间覆盖只证明根页面滚动范围被采样；固定栏、sticky 元素、弹窗或内层滚动容器可能遮挡内容。仍按实际画面确认内容可达。若关键状态的内容需在弹窗内滚动，则记录该容器的位置与必要分段，不能用根页面 scrollY 宣称它已完整覆盖。不为取得无遮挡图隐藏固定元素或修改布局。
6. **固定交付方式。** 对尚未修订的作者，只提供该运行、按桌面/手机及滚动顺序排列的有效完整段图和预定关键状态，加客观状态与视口说明；不加审美评语或他组材料。把这批分段图作为统一的实际反馈包，避免因为某运行历史上碰巧成功捕获 fullPage 就额外附送它；若确实附送，逐项记录为额外输入。作者仍仅修订一次。

上述新鲜度核查是判断捕获是否有效的技术步骤，不是额外的作者审美反馈。补录 p152/p447 的首稿及全部修订成品只供组织者和最终评审查看，不送回作者继续修改。其余作者也不获得额外的浏览器循环。

## 最终可作与不可作的声明

截至收尾，可说“12 份冻结首稿已完成所列检查”“每个作者都只有一次修订”。不能说“全部修订成品已按相同方式复查”：仅 p152 完成，p447 只打开未验，其余未验；也不能把作者收到的 PNG/JPEG 与内容宽度差异消除为完全统一的输入。分段画面、功能操作证据、作者自检和用户偏好仍分别记录。

不能说“严格按原协议完成统一首屏与 fullPage 输入”“所有作者收到等价截图”“0.4 的修订增益已被公平识别”，也不能把滚动范围被覆盖当成已获得用户视觉验收。原先两次重复的样本量限制、组织者已经知道版本与用户旧偏好的限制仍然存在。

本轮最可靠的比较仍是经统一重新取证的首稿。同一作者前后变化和修订成品之间的偏好可作为附带截图输入差异说明的探索性结果。若未来必须独立判断不同 Skill 的看图修订收益，应另行预先固定截图形式与反馈包，运行新的平衡批次；本次不通过追加第二轮或事后挑样本来伪造这种一致性。
