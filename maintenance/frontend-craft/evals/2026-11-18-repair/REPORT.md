# 画面质量基线：报修处理台（2026-11-18）

想回答的问题：frontend-craft 现在对强模型做“系统”时的画面，到底有没有帮助。

任务见 [BRIEF](BRIEF.md)：一套给值班员用的学生公寓报修处理台，四个页面（工单列表、工单详情、新建报修、近两周情况）。数据是 [data/](data/) 里的 60 张工单，由 [make_data.py](make_data.py) 生成。三份成品用同一份说明、同一份数据：

- **S**：pi + gpt-6.1-sol，带 frontend-craft 0.7.0 和 product-design 0.3.0，提示词不点技能名。
- **N**：pi + gpt-6.1-sol，不带任何技能。
- **手做**：优化者自己做的方向 A，见[练习手记](../../practice/2026-11-system/JOURNAL.md)。

S 和 N **各只跑了一次**，下面的差别不能排除单次运行的偶然。运行脚本是 [run_pi.sh](run_pi.sh)。三份成品和截图在 [review/](review/index.html)，匿名成甲、乙、丙，对应关系在 review/KEY.md。

前四行数字是优化者用脚本在三份成品的列表页上量的，脚本是临时写的，没有收进仓库。“派单点几下”：两份模型成品各点了第一步并截图，后面几步是照着截图数的，没有真的派出去；手做的那份实际派过。

**S 和 N 几乎是同一个页面。** 两份都是：左侧栏、面包屑顶栏、英文小标题（REPAIR WORKSPACE）、一句口号、四张带图标的指标卡、一条警示横幅、标签页、筛选行，然后才是表格。配色都是暖米色底加墨绿，连起的名字都像（“寓安”“寓修”）。带技能的那份字大一些，这是检查脚本的作用。

**所以这次的结论是：对 gpt-6.1-sol 做系统，技能没有改变画面的样子，多花了约六成费用和一倍时间。** 暖米色加墨绿也不是技能样例带出来的，不带技能时模型自己就用这一套。

## S 用技能做了什么

日志里能看到的：

- 读了两个技能的 SKILL.md，读了三个起步样例（工作台、看板、设置）并复制作起点，读了局部界面组织和中文排版两份参考。
- 检查脚本跑了 6 次，看了 20 多张截图。
- **没有打开**构图与布局、视觉样式、配色方向、类别场景、看图与修订这几份参考。和画面最相关的几份都没读。
- 复制来的样例最后被整页重写成了侧栏加卡片的结构。
- 它在说明里写“不做与当班任务无关的大总览”“强调色克制”，画面上却是四张指标卡加横幅、九种彩色。自己说遵守了，画面并没有。

## 手做的那份差在哪几个决定

手做的版本和两份模型成品的差别，来自写代码之前定的三件事，不是来自样式细节：

1. **这是值班员整天开着的工作队列，不是“管理后台”。** 所以没有侧栏、指标卡和横幅，第一屏就是待办。
2. **全站只有一种东西带颜色：时间压力（紧急、超时）。** 状态、类别都用黑字。
3. **版式跟着内容的形状走。** 七种状态对值班员只是三种处境（轮到我、在师傅手里、等学生），所以分三组；派单要看谁手上活少，所以把在手单数写在派单按钮上、右栏按师傅列；大家用“哪栋哪间”称呼一张单，所以房间号是每行最大的字。

技能里现在没有哪一步要求模型在写代码前定下这三件事，也没有系统页的样例。这是下一步修改的方向，但还没有验证：要等用户看过三份成品，确认手做的方向确实更好，再把它写进技能、回到这道题上复测。

## 任务目录之外

- 字体、全局 npm 包、Python 包、全局技能目录、用户主目录：运行前后一致。
- 系统临时目录多了 3 个 `playwright_chromiumdev_profile-*` 文件夹和几个 `.tmp*` 文件。Playwright 的文件夹可能来自这两次运行，也可能来自优化者自己截图；`.tmp*` 来源不明（同一时间另有会话在工作）。都没有删除。
- 两次运行都没有安装任何东西，没有联网下载。

## 没做的、没验证的

- 每组只有一次运行；只有一个模型。Claude Code、Codex 里没有试。
- 只有一道题。换一类系统（比如偏内容的、偏数据的）结论可能不同。
- 用户还没有看过三份成品，“手做的更好”目前只是优化者自己的判断加上面几项量得出的差别。
- 没有比较三份成品的无障碍细节和操作的正确性；手做的那份走过 32 项操作检查，另外两份只是打开截了图。
