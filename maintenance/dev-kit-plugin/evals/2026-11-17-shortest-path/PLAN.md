# 试用计划：图论课程设计

用户的真实课程设计，用来试开工和收尾两个技能。课题的细节（用什么语言、怎么可视化、交什么材料）事先都不问，全部留给 dev-kickoff 去问，这样才算真实测试。

## 任务书（用户提供，原文）

> 最短路径问题在城市交通规划中的应用
> 任务描述：使用图论中的最短路径算法（如 Dijkstra 算法或 Floyd-Warshall 算法）来设计一个城市的最优交通路线图。考虑不同的路线权重，如距离、交通拥堵或道路质量。
> 编程要求：可以使用 Python、Java 或任何合适的编程语言，结合图论算法库进行路径规划和数据可视化。

（用户原文写的是“Djkstra”。）

## 第一遍：用户在 Codex 里跑

- 项目文件夹：`D:\Program Project\ShortestPathTraffic`，是一个新的 git 仓库，里面只有 `任务书.md`。
- 技能：原计划临时放在项目内的 `.agents/skills/`；后来用户要求直接装进 Codex，改为装在 `~/.codex/skills`，项目内那份已删除。
- 模型：gpt-6.1-sol。
- 开场只说一句：“用 dev-kickoff 开工：做这门课程设计，任务书在 任务书.md。”开工的问题由用户本人回答。
- 做完以后先不提醒，看它会不会自己进入 dev-acceptance；不会的话，再说“收尾”。

试完要看的：

| 看什么 | 怎么看 |
|---|---|
| 有没有先读任务书，再问问题 | Codex 会话记录（`~/.codex/sessions`） |
| 有没有用 request_user_input 提问，问了几轮 | 会话记录 |
| 六个方面是否都问到，问题好不好答，有没有多余的 | 用户的感受 |
| 确认单写得是否完整、验收条目能不能判断过没过 | `docs/briefs/` |
| 收尾有没有开子代理审查，审查者只拿到了哪些东西 | 会话记录 |
| 验收结果里写的，是否和实际情况相符 | 自己重跑一遍核对 |
| 提交是否按完整单元，有没有自己推送 | `git log` |
| 有没有改动任务目录之外的东西 | 运行前后的环境快照 |

## 第二遍：pi + deepseek-flash（由优化者跑）

- 从第一遍用户确认过的确认单出发，放到另一个空文件夹里，跑实现和收尾。
- 用 `--skill` 加载技能快照，不安装。
- 开工的提问由优化者按第一遍的真实答案代答，报告里注明是代答。
- 重点看两件事：弱模型能不能照着确认单做完并逐条自测；pi 子代理审查能不能发现问题。
