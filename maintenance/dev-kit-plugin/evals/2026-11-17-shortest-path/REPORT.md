# 试用记录：图论课程设计

## 第一次：pi + deepseek-flash（2026-11-17，只跑了一次）

用户要求先用 pi 跑一遍，再在 Codex 里正式开发，所以顺序和 [PLAN](PLAN.md) 相反：pi 这一遍从开工开始跑。

### 运行条件

- 技能快照：仓库提交 `067f0ec`，即 dev-kit 0.1.0，另加 frontend-craft 0.6.2、product-design 0.3.1、git-governance。
- 运行方式：用 `--skill` 加载技能，关闭了技能自动发现和其他扩展，只加载 pi-subagents。脚本见 [pi-deepseek-1/run_dk_pi.sh](pi-deepseek-1/run_dk_pi.sh)。
- 工作目录：系统临时目录下的一个新 git 仓库，里面只有任务书。
- Python：用 conda 环境 skillmarket，其中有 networkx 和 numpy，没有 matplotlib。
- 模型：主会话和 3 个审查子代理都是 `deepseek/deepseek-flash`，子代理继承主会话的模型。

**开工时的问题全部由优化者代答，不是用户本人的回答。** 代答原文：

- 第一轮：程序加 Markdown 报告；Python 加浏览器页面，后端用标准库 http.server，不装新包；纠正它说的“没装 networkx”；自制示例路网；做 Dijkstra 和 Floyd-Warshall，不做 A*；同意验证档位。
- 第二轮：基本按推荐，另有两处改动：备选路线只要前 2 条；审美参考高德地图网页版的浅色样式，主路径用蓝色。
- 第三轮：确认开工，备选按“最优加 1 条备选”理解。

### 过程

| 轮 | 用时 | 工具调用 | 费用 | 做了什么 |
|---|---|---|---|---|
| 1 | 13 秒 | 4 | 0.005 | 读任务书和 dev-kickoff，定档位为“交给别人评分”，问第一轮 5 题，每题附推荐答案（[原文](pi-deepseek-1/turn1-reply.md)） |
| 2 | 15 秒 | 2 | 0.003 | 查了环境，问第二轮 7 题，覆盖路网、权重、功能、布局、审美、报告和运行方式（[原文](pi-deepseek-1/turn2-reply.md)） |
| 3 | 20 秒 | 2 | 0.005 | 写出确认单，含 12 条验收条目；对“前 2 条”的两种理解单独请用户确认（[原文](pi-deepseek-1/turn3-reply.md)） |
| 4 | 20.5 分钟 | 115 | 0.272 | 实现、自测、3 轮子代理审查、修复、提交一次 |

3 个审查子代理另外花了 0.047、0.069、0.018，用时 2.2、2.9、0.7 分钟。

### 结果

- **开工**：六个方面都问到了。问题分轮问，依赖前一轮答案的问题放到了下一轮。代答里不在选项中的内容（备选 2 条、参考高德）都写进了确认单。确认单格式完整，12 条验收条目都能判断过没过（[确认单与验收结果](pi-deepseek-1/brief-with-results.md)）。
- **实现**：自己实现了 Dijkstra（二叉堆）、Floyd-Warshall 和 Yen 备选路线，后端只用标准库，前端用原生 SVG。50 项测试由优化者重跑，全部通过。页面见 [截图](pi-deepseek-1/01-overview.png)：整洁，可以演示。可见的小问题是分段明细里同一条路连续列了 6 行“北环路”，没有合并。
- **收尾**：
  - 交给审查者的说明完全照 reviewer.md 的模板填写，自测结果标明“仅作为待核对的说法”。
  - 子代理审查了 3 轮：第 1 轮提出 5 条问题，第 2 轮复核时又提 5 条，第 3 轮确认没有阻塞项。全部修完后才提交。
  - 所有改动一次提交，没有推送。
  - 验收结果填回了确认单，写明了审查方式和限制。
- **测试顺序**：先写代码后写测试，没有走 tdd 的红绿循环。确认单定的档位只要求“核心算法有测试”，这不算违规。

### 看到的问题（已在 0.1.1 修改）

1. **没查环境就下结论。** 第一轮说“没装 networkx”，实际上它没跑过任何检查命令。被纠正后，第二轮才去查。→ dev-kickoff 第 1 步加了一句：环境情况先用命令查过，再写进事实。
2. **确认单写了“交给 frontend-craft、product-design”，实现时一次都没读这两个技能。** 页面效果还可以，但这条衔接等于没起作用。→ dev-kickoff 第 4 步之后加了一句：用户确认后，先读确认单里写明要交给的技能，再动手。
3. **审查者不能运行命令。** pi 内置的 reviewer 只能读文件，用户的 pi 配置里给它的工具也只有读取类。第 1 轮它把需要运行的条目如实标成了“没验证”，运行类的证据最后由开发者提供。→ dev-acceptance 第 3 步加了一句：选能运行命令的代理，比如 pi 的 delegate；只能只读审查时，在验收结果里写明。
4. **收尾没清理现场。**
   - 最后一个服务留在 8000 端口没关，优化者事后按进程号把它关了。
   - 开发过程中它按端口号强制结束过 3 个进程。核对后确认都是它自己先启动的服务，但这种做法有误杀别的程序的风险。
   - 系统临时目录里留下了 12 个无头浏览器临时目录、7 个日志文件和一个截图文件夹，已删除。另有一个 Chrome 下载临时目录和一个 scoped_dir 时间也对得上，但无法确定是不是它建的，没有动。
   → dev-acceptance 第 5 步加了一句：按进程号只关自己启动的进程，并删掉放在项目外的临时文件。

### 任务目录之外

- 运行前后做了快照对比：用户 site-packages、字体、conda 和 PATH 上 Python 的包、全局 npm、全局技能目录、Codex 配置都没有变化。
- 临时目录里还出现了 `briefbias-reproduce-*`，属于用户另一个项目，与这次无关，没有动。

### 没验证的

- 只跑了一次。开工的回答是代答，用户本人回答时问题是否好答，还要看 Codex 那一遍。
- 0.1.1 补的四句话没有在 pi 上重跑；在 Codex 上的表现见下一节。

## 第二次：Codex + gpt-6.1-sol，用户本人开发（2026-11-17，只跑了一次）

### 运行条件

- 技能：dev-kit 0.1.1 等，装在 `~/.codex/skills`，由 VS Code 里的 Codex 加载。用户的 Codex 还装着 superpowers 等第三方插件，模型同时也读了其中的 brainstorming、test-driven-development、verification-before-completion。
- 开场提示词由优化者提供，只点名 dev-kickoff 和 dev-acceptance，写了几条约定，没有写技能内部的步骤。
- 项目在 `D:\Program Project\ShortestPathTraffic`，22:16 到 23:02，约 46 分钟。其中用户审阅确认单用了约 14 分钟。

### 过程

- **开工**：
  - 先读任务书，查了 Python、NetworkX、pytest、Tk 和浏览器，又上网核实了 OpenStreetMap 能导出哪些字段，然后才提问。
  - 用 Codex 的提问工具（request_user_input_async）问了三轮共 10 题，每题第一个选项是推荐答案，同时也把问题列在对话里。
  - 用户有两题没选选项，自己写了答案：
    - 论文和 PPT 由用户自己负责；
    - 不要重庆，那里的道路是立体的，要选北方城市的平面城区。

    Codex 据此把城市改成天津五大道—小白楼，并核实了那里的数据。见 [提问与回答](codex-gpt-1/question-rounds.md)。
  - 写出确认单后，Codex 自己开了一个子代理复核确认单。用户回“确认开工”之前，它没有写功能代码。
- **实现**：
  - 主会话先写路径算法的测试，再写算法；路网数据和页面分别交给两个子代理并行做。
  - 页面子代理读了 frontend-craft 的正文、review.md 和 pagecheck.mjs，但没有运行 pagecheck，而是自己写了一个浏览器检查脚本，按 1280×720 和 1920×1080 两档截图核对。
  - 自测时修正了一处问题：地图标签遮住了高亮路线。
- **收尾**：
  - 开了一个全新的子代理当审查者，不继承开发过程的对话。
  - 审查者读了 reviewer.md 和 code-reviewer，自己写了一个浏览器检查脚本，在限制外网的 Chrome 里实跑，跑了 pytest，还从原始数据另建 NetworkX 图，复算了 8 个地标的 192 个起终点与策略组合，全部一致。
  - 没有发现需要返工的问题。验收结果逐条填回确认单（[确认单与验收结果](codex-gpt-1/brief-with-results.md)）。
  - 只提交了一次，提交前申请了提权，没有推送。
  - 自己删掉了浏览器临时目录。截图和服务日志留在项目里已被忽略的 `.qa/` 下，服务没有留着不关。

### 结果

- 交付：真实的天津城区有向路网（498 条道路、2,273 个节点、3,212 条有向边）、手写 Dijkstra、三种权重策略、可离线运行的本地网页、README 和 16 项测试。
- 测试：16 项由优化者重跑，全部通过。
- 页面：见 [截图](codex-gpt-1/review-1920x1080.png)。以地图为主，配色克制，信息清楚，用户看过后认为效果可以。

### 任务目录之外

- `~/.codex/config.toml` 新增了这个项目的受信任登记。这是 Codex 在会话开始时自己写的，属于正常行为。
- 用户的 Python（`%APPDATA%\Python\Python312\site-packages`）在 22:38 新装了 edge-tts 和它的依赖（aiohttp 等）。这个时间在会话期间，但 Codex 主会话和 5 个子代理的记录里都没有安装命令，也没有出现 edge-tts，不像是这次开发装的，需要用户确认来源。
- 临时目录里新出现的几张 `ScreenShot_*.png`，在会话开始前就已经有同类文件，不是这次开发产生的。

## 两次对照与验收结论

| 检查点 | pi + deepseek-flash（0.1.0，代答） | Codex + gpt-6.1-sol（0.1.1，用户本人） |
|---|---|---|
| 先查事实再提问 | 第一轮没查环境就下结论 | 查了环境，还上网核实了数据来源 |
| 提问方式 | 在对话里列出，两轮 12 题 | 用提问工具，三轮 10 题 |
| 用户自己写的回答 | 写进了确认单 | 两处都改变了方案 |
| 六个方面都问到 | 是 | 是 |
| 确认前不写功能代码 | 是 | 是 |
| 交给展示技能 | 没读 frontend-craft | 读了，但没跑 pagecheck，换成了自己写的检查 |
| 独立审查 | 子代理 3 轮，只能读文件，不能运行 | 1 个全新子代理，亲自运行并独立复算 |
| 一次提交、不推送 | 是 | 是 |
| 清理现场 | 留下服务和临时文件 | 已清理 |

**结论：dev-kickoff 和 dev-acceptance 通过这一轮验收。** 依据是两个宿主、两个模型各跑一次，其中 Codex 那次由用户本人回答。用户的评价是效果可以。两个技能实际做到了以下几点：
- 把“开头问清、结尾对照”这条主线走通了；
- 用户自己写的回答能改变方案；
- 审查确实由没参与开发的一方来做。

**还没验证的：**
- tdd、codebase-design、diagnose 这次没有真正用上：Codex 读过 tdd，但实现时主要按 superpowers 的同类技能来做；也没有遇到需要排错的 bug。
- code-reviewer 被审查者读过，三个打分脚本一次都没运行。
- 每种配置只跑了一次。pi 那次的开工是代答；0.1.1 在 pi 上没有重跑。
- 在 Codex 里，superpowers 插件和 dev-kit 有重叠（测试先行、完成前核验、规划），这次没有看到冲突，但模型会两边都读。
