# Docvision 0.4.0：个人论文阅读优化

日期：2026-10-29（Asia/Shanghai）。在 `0bf5ad5` 基线之上修改当前工作树；未提交或发布。目标是个人大批量论文初读，以及关键公式、表格、图表和架构图的可核对精读。

## 结果与范围

MinerU 是当前 **docvision** 使用的本地引擎之一；此次修改的是 docvision 技能、CLI、引擎适配与验证资料。保留原有 MinerU/Paddle OCR 路线，新增 core 的文字层初读，以减少数字论文筛读时不必要的模型启动和推理。

必要的通用能力继续修复：首次使用能走通，配置按说明生效，缓存不串版本，源图与识别结果能相互追溯，凭据更新不残留旧别名。本轮没有扩展多租户、多平台安装矩阵或常驻模型服务；这些功能对单人工作流的近期收益不足，而且引入额外维护成本。这是范围筛选，不是认定通用质量已经完成。

## 已落地的改动

| 范围 | 改动 | 对阅读的影响 |
|---|---|---|
| 批量初读 | `auto + --tier fast` 的本地 PDF 使用 `text-local`，只依赖 core；跳过为决定 OCR 而重复抽取全文 | 数字论文先读摘要/正文，再为选定页付出 OCR 和精读成本 |
| 结果边界 | 保留物理页号；文字层不伪造 bbox、不声称公式/表格已准确识别；空文字层给出 OCR/页面图下一步 | 筛读与精读依据更清楚，扫描件不会被假装完成 |
| 本地精读 | 对已知兼容 PaddleOCR 3.7.x，公式/表格裁图关闭重复版面分类并指定专业任务；整页仍做版面分析 | 避免区域再次被误分为普通文本；实际精度收益仍需同图测量 |
| 批量复用 | 每批建立一次元数据索引，复用前重新检查候选与 QA；force 覆盖 resume | 减少大量输出目录中的重复扫描，并避免强制重跑被缓存吞掉 |
| 缓存身份 | 按当前 provider 的有效配置生成签名；无关配置和上传同意不使本地结果失效 | 少做无意义重识别；模型、路径、档位、页范围等真正变化仍重新处理 |
| 耗时可见 | 整批时间、实际处理页数及检查/路由/缓存/provider/写入校验阶段 | 可以区分启动、查找和识别耗时，避免把缓存速度当模型速度 |
| 环境与文档 | core-only doctor 正确报告文字层可用；MinerU 安装范围收窄到 4.0.x；说明约束文件的实际用途 | 首用路径和安装承诺与实现一致 |

本地区域参数依据 PaddleOCR 官方 [v3.7.0 CLI 实现](https://github.com/PaddlePaddle/PaddleOCR/blob/v3.7.0/paddleocr/_pipelines/paddleocr_vl.py)；未知/旧版本不会盲传参数。版本契约测试不能替代模型实测。

## 原审查问题的关闭情况

| 原审查 | 修复及验证 |
|---|---|
| P1 本地 VLM 经外部代理 | 专用 HTTP opener 禁用代理、禁止重定向，并验证 loopback HTTP(S) URL；有代理环境下的实际 urllib 路由回归 |
| P2 core-only 推荐流程无法使用 | 新增 text-local；真实论文完成 fast → packet → 实际看图。无文字层扫描件明确走 pages 看图或 OCR |
| P2 旧坐标裁剪新源文件 | render/crop 核验当前源 SHA256，变化后要求重新转换 |
| P2 新文档关联旧精读 | 按来源、上下文和块位置过滤关联记录；历史保留在磁盘 |
| P2 dry-run 修改同意 | 预演不写 consent；以配置文件字节不变验证 |
| P2 强制重试后仍命中旧结果 | 同请求按数值顺序取最新 attempt；最新失败/未完成不退回旧成功；旧历史保留 |
| P2 VLM 环境变量不生效 | 执行、发现和缓存使用同一有效配置解析；显式参数、DOCVISION、OPENAI、配置文件按优先级覆盖 |
| P2 token 别名轮换仍使用旧值 | 保存同组凭据时清除旧别名，其他凭据组保留；不输出值 |

新增测试同时覆盖来源路径相同内容的复制、手动 bbox 变化、写入锁、缺失产物、并行/中断尝试、空文字层和选页。旧测试中一处清空所有环境变量会破坏 Windows SSL，已改为仅隔离测试相关的 token 别名；未关闭 TLS 校验。

## 验证结果

自动化验证使用隔离配置、假凭据和临时输出；网络审计仅允许本机回环。207 项 unittest 中 **206 通过、1 项跳过**，跳过原因为 Windows 符号链接权限；另 **5 项契约检查通过**，技能元数据验证通过。`git diff --check` 通过。此结论只覆盖已执行的检查。

真实阅读样本为公开论文 Attention（15 页）、ResNet（12 页）、VAE（14 页），共 **41 页**。使用 Python 3.12.14、pypdf 6.10.0、pypdfium2 5.14.0、Pillow 12.3.0；输入来源、SHA256、每轮与每文件耗时保存在 [数据记录](../evals/personal-workflow-0.4.0-2026-10-29.json)。命令为：

```text
python docvision/scripts/docvision.py convert <三篇论文目录> --tier fast --workers 1 --resume --output <独立输出目录> --json
```

三轮分别使用新输出目录和独立 CLI 进程，然后重复相同命令。首读总耗时为 1.7069、1.6826、1.6930 秒，中位数 **1.693 秒**；复用总耗时中位数 **0.4566 秒**，每轮全部 3 份跳过、重新处理 0 页。时间包含解释器启动，但不包含模型初始化，因为该路线不调用 OCR 模型。操作系统文件缓存未清空，不把这些数据叫作冷磁盘性能。

另用 300 份合成元数据、30 次查询测量缓存查找：逐次遍历读取 4,380 次，约 1.4665 秒；一次建索引再查找读取 330 次，约 0.1959 秒。该测试只反映索引开销，不代表整篇 OCR 的加速倍数。

独立审阅者从技能说明执行前向任务：批读三篇、阅读摘要、选 Attention 第 3 物理页制作 300 DPI 架构图精读包，实际打开图片和上下文，再复用初读并检查三份输出。流程无阻断错误，结构检查均通过。看图确认了编码器输出到解码器中间注意力层的连接、残差旁路和 Linear → Softmax 输出顺序，并区分图内 N× 与同页正文的 N=6。程序记录仍为 `review_required / accuracy_verified=false`，没有把包生成成功自动算作准确率验证。

## 效果判断与尚需优化的部分

**已经证实的是数字论文初读和复用流程可用且开销低，以及原有可靠性缺陷修复；尚未证实新的 OCR 精度提升或本地/云端速度排名。** 当前硬件是 RTX 4060 Laptop 8 GB，现有环境为旧 MinerU 3.4/Paddle 2.9.1，未运行所需 MinerU 4/PaddleOCR 3.7 模型。本轮没有改动这些已有环境、下载模型或调用真实云端 API。早期 4070 Ti SUPER 16 GB 的成绩不能套用到当前机器。

实际分工先采用“文字层快速筛读 → 按问题选页/选区 → OCR 或实际看图复核”，不预先指定云端一定更准。历史公开小样本中，本地/云端 Paddle 公式和表格结果一致，不能据此认定云端更准，也不能把同源模型当两份独立证明。下一项有价值的性能工作是用同一组人工校正的难页，在当前设备与真实 API 上分别测冷启动、连续处理、区域识别、公式关键符号、表格合并关系和错误页，再决定更准确的一条负责精读、实测更快的一条负责批量。

还需保留的验收项是：8 GB 下长文档显存与稳定性、20–30 页代表性 OCR 难页对照、全新设备安装，以及真实云端额度耗尽行为。这些已在 [TODO](../TODO.md) 中保留，未用文字层速度或 mock 测试替代。常驻推理只在计时证明模型启动占主要成本且使用频率足够时再考虑。

0.4.0 缓存签名有变化，旧结果可能需要一次重建；原始输出和精读历史不因此自动删除。此次修改未触及其他技能的已有未跟踪文件。
