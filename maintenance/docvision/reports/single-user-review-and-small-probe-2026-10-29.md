# 单人通用性与小规模 OCR 对照

日期：2026-10-29（Asia/Shanghai）。范围是单人跨项目长期阅读论文；本次重点为必要改进筛选与少量真实识别对照，测试发现的导出修复进入 0.4.1。

## 必要改进的取舍

已有的固定环境/模型目录、凭据隔离、缓存与源版本核验、显式上传授权、原图和精读历史保留，应继续维护。固定一个个人 `--output` 目录即可跨项目复用现有文献，无需新建数据库、Web 服务或多租户平台。

| 优先顺序 | 必要性及当前缺口 | 最小实现边界 |
|---|---|---|
| 1. 留住校正结果 | `refine.py` 保留原结果，但 `accuracy_verified` 始终 false，缺少保存人工/宿主校正的入口。实际看图结论只能另存报告，下一次读取未必知道已经改过什么 | 独立 correction 记录绑定源 SHA、原页/选区和原识别结果；保存修订、复核者类型、时间和未确定项。`read` 展示有效修订；不覆盖原 OCR，不把局部复核当全文准确 |
| 2. 恢复云端任务 | `paddle_cloud.py` 得到 jobId 后只在内存轮询，成功返回前没有持久化任务身份；中断/下载失败后无法可靠按现有任务继续获取 | 提交成功立即写脱敏任务日志；恢复仅 GET/下载，不重新 POST。提交回应丢失时仍标记未知，避免重复消耗额度 |
| 3. 搬动文献仍可读 | `read.py` 只认 meta 中的原绝对源路径；精读图片/上下文/结果也记录绝对路径，移动目录会破坏访问和复用 | 内部文件相对引用；增加显式源文件重绑且 SHA 必须一致。不自动扫描整台机器，不绕过版本检查 |
| 4. 环境升级可回退 | `setup_cmd.py` 可复用显式配置的现有环境，安装发生在验证之前；失败时原配置未更新并不意味着环境未改变 | 安装前保存配置和版本快照；新环境单页验收后再切换。只完善实际使用设备的路径和恢复，不建设跨平台发行矩阵 |

前三项直接保护读过、改过和已提交的工作，第四项随安装维护落实。本轮对现有旧环境采用独立新建方式；上表功能为明确的后续实现范围，未宣称已经加入 CLI。待办见 [TODO](../TODO.md)。

## 测试设计与判断方式

输入是公开论文的 3 个物理页：Attention 第 4 页（公式）、第 8 页（合并/稀疏表格），VAE 第 4 页（复杂公式）。将其合并为 3 页 PDF，再准备 VAE 公式 (7) 和 Attention Table 2 的 300 DPI 裁图。已经实际打开三页图及两张裁图，预先写下 20 项核对点。

每条路线固定 4 个独立 CLI 进程：3 页整页 OCR、公式裁图、表格裁图、公式裁图再识别一次；最多处理 6 个页输入。单并发，无 docvision resume 缓存，不自动重试；发生失败即停止。本地整页采用 standard，裁图采用 quality/advanced，与现有 `refine` 的默认档位一致；云端选区使用专业 formula/table 任务。首次安装/模型下载不计入识别耗时；模型初始化、上传/排队、下载和输出保存计入对应端到端耗时。操作系统、模型运行库和服务端缓存不受本脚本控制。

检查点覆盖 2 项流程/来源要求、9 项公式要求、9 项表格要求，分别报告具体漏项、错符号、错列与不确定项，不将其换算成通用“准确率”。数学等价的 LaTeX 排版允许不同；表格的空白、合并单元格和科学计数指数须正确。架构图的语义关系继续由宿主实际看图验证，不用 OCR 转写成绩替代。

如果关键内容同样正确，优先更快的路线；整页与局部速度不同则按任务大小分工。若出现关键错误，就比较该类区域的可靠性。两次时间接近或波动较大时不强行排名，只有结果不足以决定分工才补一个相关样本。

样本、输入 SHA、原页/bbox、核对点、准备脚本、测试脚本与原始输出放在忽略目录 `_docvision/small-probe-2026-10-29/`。`run_probe.py` 默认只预演，显式 `--run` 才执行；真实云调用另需 `--allow-remote`。只上传上述公开材料。

## 当前设备与准备

当前为 Windows 11、RTX 4060 Laptop 8188 MiB。旧 MinerU 3.4.0 的 PyTorch CUDA 可用，但缺少当前适配器需要的 mineru-kit，配置的模型目录不存在；旧 PaddleOCR 2.9.1 缺 PaddleX，旧缓存不适用于 VL-1.6。历史 16 GB 机器的识别时间不能直接作为本机结论。

用户已授权搭建本地环境，并通过 credentials 命令安全录入 Paddle token；凭据文件受 Git 忽略，不进入报告。独立 MinerU 4.0.12 环境及标准模型已安装，模型 verify、doctor、单页 OCR 均通过；保留现有旧环境。Windows 打包应用将用户 AppData 路径解析到稳定的 Codex LocalCache，正式配置使用已验证的规范路径，避免随机 sandbox 目录。已备份并合并正式用户配置，仅更新 core、MinerU 和模型目录；API 设置原样保留。core 也复用新环境，自带 pypdf/pypdfium2/Pillow，后续使用不依赖 Codex 的 bundled Python。

安装收尾的日志包装器曾遇到 GBK 编码错误；之后独立验证已确认安装成功，没有因此重复安装。单页首次验收约 31.828 秒，不与后续 3 页测速混作同一个样本。日志确认后端为 llama-cpp；GPU 采样不足以归因具体进程，所以不宣称已验证 GPU 加速占比或 CPU-only。

## 结果

| 相同输入 | 本地 MinerU 4.0.12 | Paddle API VL-1.6 | 本次判断 |
|---|---:|---:|---|
| 3 页整页 | 30.906 秒 | 126.053 秒 | 本地更快 |
| 复杂公式裁图首次 | 22.010 秒 | 10.300 秒 | API 更快，但缺公式编号 |
| 合并表格裁图 | 19.577 秒 | 46.526 秒 | 本地更快，抽查表格数据均正确 |
| 相同公式再次处理 | 18.698 秒 | 1.048 秒 | API 疑似服务端复用，不当成正常重新推理速度 |

两端共 8 个对照调用、12 个逻辑页输入；另外本地有 1 页安装验收。逻辑输入数不等于账单页数或模型实际重新推理页数。云端公式两次 jobId 不同、均未命中 docvision 缓存，但原始 JSONL 连同 logId 和资源地址完全相同，支持服务端复用的推测；响应无缓存命中/计费标记，不能断言具体机制。时间包含所有 CLI 开销；本地模型此前已经通过单页验收，不能将 3 页结果称为全冷启动测试。

**精度方面，本地在这组关键内容上更完整，云端没有表现出精度优势。** 两端都保留了 VAE 公式里的 KL 负号、求和边界、条件分布和两种 epsilon 上标差异；本地还保留编号 (7)，API 两次公式裁图均丢编号。两端表格的 9 个预设检查点均通过，包括合并表头、真正空值、科学计数指数与跨列成本。云端正文另外将缩放因子 `d_k` 识别成 `d_x`，本地此处正确。

本地也有不足：表题的 `newstest2014` 误成 `newestest2014`，并重复输出部分脚注公式。检查点通过不代表整篇无错，也不是通用准确率。人工校对未独立计时。

测试暴露的云端脚注问题已经修复：原始结果识别了 3 条脚注，主 Markdown 却遗漏；现已将缺失的已识别脚注/图表文本补回并去重。离线重解析原 JSONL 后三页脚注都恢复，结构检查通过、所有块原文保持不变；新增 API 请求为 0。`d_x` 和缺公式编号属于服务识别问题，未被程序猜测改写。

本地也修复了两类导出缺陷：嵌套的算法/图注内容被转成 Python list/dict 字面量，以及表格题注在按页/按块输出中遗漏。现在按原序展开已有文字和数学 span，保留 caption 与原始 HTML；离线重新解析后算法文本与上游可读结构逐字相同，表格 HTML 和模型原拼写不变，主 Markdown 字节不变，QA pass。原 ZIP 已随 staging 清理，因此重解析明确使用保存的 raw 成员与图片重建归档，未声称拥有原 ZIP，也没有新增推理。

最终回归为 **210 项中 209 通过、1 项 Windows 符号链接权限跳过**，另 **5 项契约检查通过**；技能元数据与 diff 空白检查通过。正式默认配置经 doctor 确认为本地引擎/模型可用，系统 Python 入口可自动使用新 core 环境完成 fast 转换。

可提交的脱敏数据与预设检查点见 [small-probe-2026-10-29.json](../evals/small-probe-2026-10-29.json)。原始识别与修复后重解析分别保留，不用修复后的导出来伪装原始模型成绩。

## 初始分工

当前设备优先采用：数字论文文字层筛读 → 本地 standard 整页 OCR → 关键区域本地 quality 或实际看图。Paddle API 保留给本地存疑或希望较快取得公式第二份识别的区域；其输出仍须核对编号、下标与原图。表格无需因有 token 就默认再上传，整篇也不应默认双跑。

这组小样本已足以支持上述初始分工；没有必要为了作决定继续扩大实验。后续只把真实阅读中遇到的新错误页加入回归，或在引擎/设备更新后复测现有小样本。
