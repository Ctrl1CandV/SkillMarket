## 结论与使用范围

0.2.0形成可用的本地批量→按页/块定位→专业区域精读→原图核对流程。以MinerU承担本地初稿，Paddle官方API复核关键公式/表格；架构图由当前宿主实际看图，Gemini是可选路线。

“正式版”指本轮承诺的运行链路、原文定位、缓存与输出归属、凭据加载和安装交付已经核验。它不等于任何论文免复核，也不把少量样本当成全市场准确率或8GB硬件保证。

## 最终审查与修复

独立审查者final_code_review未参与本轮实现，使用实际代码、临时反例与本地HTTP/索引桩审查。初审发现并最终复核关闭：

| 问题 | 实际反例 | 修复 |
|---|---|---|
| 强制重转仍使用旧页面图 | 红图转蓝后meta更新，精读仍返回红图 | 页面缓存包含实际源文件完整SHA、物理页、DPI；旧缓存不复用 |
| 并发同名输入输出相互覆盖 | 不同目录same.png同时选中同一个输出目录 | 原子预留每级目录；force只复用同源路径，源/目录独占锁保护写入 |
| 更换Mistral/GLM端点仍命中旧精读 | 改remote端点而请求ID不变 | 所有remote provider的实际配置进入哈希签名 |
| uv遗漏额外索引、默认策略遮蔽官方版本 | 生成命令丢PyPI；补回后first-index又只查fallback旧包 | 传递extra_args；uv多索引且无用户指定策略时采用pip兼容的候选选择，单索引/conda/显式策略不变 |
| 凭据使用文档与CLI脱节 | 已支持.env但SKILL未说明全局参数位置 | 写明--env-file在子命令前、选择顺序、环境优先、PADDLEAPIKEY别名 |

uv解析差异由两个127.0.0.1索引与内存假wheel的dry-run复现：默认策略拒绝vendor指定版本，显式策略后选中指定版本；没有为此重装GPU环境。

另由真实难例发现：公式裁图仍被自动分类成普通文本。现对已定位formula/table区域使用官方promptLabel并关闭重复布局分类；整页保留布局分析，输出格式和公式编号显式开启。提示词版本升至2，旧精读缓存不直接复用。

## 新增真实实验

来源为公开[Attention Is All You Need v7](https://arxiv.org/abs/1706.03762)，原15页PDF SHA256：`bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697`。本轮新增物理页5和9，分别覆盖双行多头注意力、带编号FFN公式、稀疏合并表格；原图用图像工具实际查看。

机器：Windows10、RTX4070 Ti SUPER 16GB、约32GB RAM。模型已缓存，时间均为单次端到端观察，不作统计排名。

| 操作 | 耗时 | 看图核对结论 |
|---|---:|---|
| MinerU standard+ocr，物理页5、9 | 16.39秒 | 页码[5,9]、图/表结构落盘，QA pass；双行公式原初稿有多余排版符号 |
| 云端双行公式，旧自动分类路线 | 50.75秒 | 普通文本输出，where head_i被读成head1，不采用为最终公式 |
| 云端双行公式，专业formula路线 | 64.25秒 | aligned LaTeX；head_i与Q/K/V投影上下标恢复，与原图一致 |
| 云端复杂表格，旧自动路线 | 59.33秒 | 可读HTML和合并结构 |
| 云端同表，专业table路线 | 6.78秒 | 21行、13列表头；纵向合并4/2/7/4行、横向8列；抽核base/big数值与空值正确 |
| 云端FFN公式，专业formula路线 | 4.02秒 | max表达式、W/b下标与右侧tag{2}均保留 |
| 上述公式/表格重复请求 | 命中缓存 | cached=true，没有再次提交；自动路线正确选中已配置Paddle |
| 架构图任务，只有Paddle凭据 | 精读包约0.25秒 | auto生成packet，未把OCR冒充语义理解；原页3、bbox与图注/邻块齐全 |

本轮新增5次云端提交；其后重复请求均复用缓存。来源只限公开论文图块，没有上传用户的私人文档。公式/表格原始输出保存在本机临时目录，仓库仅存[脱敏实验摘要](../evals/release-0.2.0-evidence.json)。前轮真实云端/本地同图对照见[原验证报告](paddle-cloud-verification-2026-10-28.md)。

本例说明区域任务传参会实质影响公式质量。服务排队使请求耗时波动明显，精读只选关键区域；没有证据承诺云端总比本地快或准。结构pass与服务成功不是准确率分数。
