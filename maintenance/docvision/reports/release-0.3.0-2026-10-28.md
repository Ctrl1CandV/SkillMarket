# Docvision 0.3.0 通用使用发布核验

## 结论与范围

上一轮 bfa0a09 未完全满足通用使用要求。本轮修复后按每系统用户独立配置、固定运行环境/模型、项目内结果与临时文件、可选 Paddle API 的方式交付。保留既有本地批量 OCR 与区域精读功能；没有重新测量模型识别成绩，也没有消耗真实 API 额度。

## 验收与修复

| 用户要求 | 当前行为与证据 |
|---|---|
| 适用人群与首次指引 | SKILL 说明 Python、硬件、安装、无 API/无 GPU 路线；先 doctor 再选安装计划 |
| 设备是否适合本地 | doctor 报告 OS/架构、RAM、GPU/显存、环境及模型两处可用磁盘；低于规划门槛建议 core/economy、单页单并发，未知平台不承诺可用 |
| 长期环境 | 新 conda/uv 环境在当前用户应用数据目录 envs；conda 使用显式 -p，不复用未知同名环境；已有配置可显式复用 |
| 稳定模型根 | setup 保存绝对路径，旧相对配置锚定配置文件目录；全局模型根优先，provider/doctor 使用相同解析；dry-run 不写配置 |
| 安装不能假成功 | MinerU 下载后 verify，失败退出非零；Paddle 依赖检查失败不保存新配置；未进行真实推理时明确未验证 |
| 首次 API 选择 | unset/拒绝均不能上传；remote 同意加每次 allow-remote 才上传，CLI、自动选择、精读及统一 dispatcher 一致 |
| 密钥与多人使用 | 终端 --prompt 隐藏输入或 --stdin；本机/系统用户绑定，自动发现不安全文件警告跳过，不继续换文件；显式开发 env 保持支持 |
| 凭据权限 | POSIX 私有文件分支；Windows 创建时私有 DACL、验证所有者/规则；拒绝符号链接及父级重解析点，随机私有临时文件、原子替换 |
| 项目内过程文件 | convert 的 staging 在输出 .staging，refine 工作目录在记录 work；成功/失败/中断执行 finally 清理，KEEP_TEMP 可保留，兄弟任务互不误删 |
| 发布安全 | main 仅运行资源；dev 留维护测试/报告；真实 .env、凭据、模型、文档输出不提交到任何分支 |

另恢复本地 VLM 正向协议/落盘测试，先复现成功响应 NameError，再修复未定义的 local 变量。运行时版本与 SKILL metadata 已统一为 0.3.0 并添加一致性回归。

## 验证

- 隔离配置、用户目录、凭据、模型根与临时项目；全部凭据为 fake，socket 审计阻断外网。
- unittest discover：161 项，160 通过、1 跳过、0 失败/错误（10.587 秒）。跳过项为当前 Windows 无创建符号链接权限；真实父 junction 拒绝、共享目录私有 DACL、并发保存测试通过。
- check.py：5 项全通过（1.036 秒），含 loopback 本地 VLM 正常请求/落盘/验证。
- 外网连接尝试：0。既有模型质量/API 证据仍引用历史报告，不能将 mock 与权限检查写成新的识别实测。
- skill-creator quick_validate：通过（临时 uv PyYAML 环境，Python UTF-8）；git diff --check 通过。
- 独立 staging 审计：11 项离线判别通过，覆盖成功、异常、中断、保留、并发与调用位置。

独立用户流程验证通过：两个临时项目复用同一模型根，实际 adapter（mock 进程结果）与实际 packet 裁图均正常；拒绝远程跨项目保持，删除项目输出不动模型/环境。其发现的无 GPU 首次路线建议、uv 显式环境复用已补回归并独立复测。

独立代码终审发现凭据 override 提前 resolve 绕过 junction 检查、进程 VLM key 阻止文件 Paddle token 加载两点，均先复现后修复，并由原审查者独立复核通过。保留原始凭据路径直至检查、按凭据组保留进程环境优先级。当前无未关闭的重要发现。

两分支发布仅同步 docvision 运行资源及 README 对应条目，维护侧仅进入 dev；实际提交及推送结果以 Git 记录为准。

## 实证限制

未执行全新机器从零下载/安装，未在 8 GB 显存、Linux/macOS 真机重新推理；POSIX 权限分支本轮未实机运行。硬件建议是规划门槛，模型能否稳定处理用户材料必须单页验收。多人隔离以独立系统账号为边界，共用同一系统账号无法隔离不同自然人；身份绑定也不能代替文件权限和分发时排除密钥。
