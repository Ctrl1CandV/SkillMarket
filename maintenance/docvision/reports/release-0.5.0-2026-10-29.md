# Docvision 0.5.0 收口与发布范围

日期：2026-10-29（Asia/Shanghai）。用户接受 OCR 中不可避免的误识和疑难内容，授权在两个目标达到当前验收范围后提交、推送。按仓库已有约定，目标分支为 dev 和 main。

两项目标均可收口：

| 目标 | 已完成的结果 | 验收边界 |
|---|---|---|
| 单人使用为主的通用性修复 | 初次使用、凭据/配置、缓存与来源一致性；校正持久化、云任务恢复、文献搬家、环境验收和回退 | 当前 Windows 设备及隔离回归已验收；不以多用户平台、全操作系统矩阵作为本轮门槛 |
| 阅读速度与识别效果优化 | 数字 PDF 轻量筛读和批量缓存提速；修复脚注、算法/图注、表题导出损失；真实小样本确定本地主识别、API 疑难区域辅助纠错 | 不宣称模型零误识或本地在所有文献上优于 API；公式/表格关键内容继续看原图，按真实失败页再迭代 |

依据：0.4.0 的 41 页文字层计时、0.4.1 的本地/API 同样本 OCR 对照，以及 0.5.0 的完整隔离回归（265 项中 264 通过、1 项权限跳过，另 5 项契约检查通过）和真实输出副本的校正/搬家验收。详见 [0.4.0](personal-reading-upgrade-0.4.0-2026-10-29.md)、[小样本对照](single-user-review-and-small-probe-2026-10-29.md)、[0.5.0 维护实现](personal-maintenance-0.5.0-2026-10-29.md)。发布前另对暂存快照导出验证，记录保存在本地发布工作目录。

分支范围：dev 提交 docvision 运行资源、README 的 docvision 条目，以及 maintenance/docvision 的测试、脱敏结果和报告；main 仅接收同版 docvision 运行资源及 README 对应条目。真实凭据、配置、模型、原始 OCR 结果和一次性实验文件保持本地，其他 skill 的工作区修改不进入这两次提交。版本与提交身份以各分支 Git 记录为准，不创建额外功能分支，不整条合并 dev 到 main。
