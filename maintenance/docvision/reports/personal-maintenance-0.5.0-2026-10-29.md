# Docvision 0.5.0：API 定位与单人长期阅读维护

本轮完成用户指定的四项改进，并把 API 调整为“疑难区域的辅助纠错来源”。理由来自上一轮同图小样本：本地整页/表格更快，API 首次公式裁图更快，但没有表现出精度优势，且会漏公式编号、误识行内符号。API 可以提供不同模型的第二份转写，最终采纳仍以原图为依据；识别成功或两份 OCR 一致都不能自动等同于校正正确。

默认流程现在为：数字 PDF 文字层筛读 → 本地 OCR 建立需要的版面与内容 → 实际看图核对关键区域 → 有具体遗漏、歧义或错误时按需调用 API → 记录已采纳的校正与未确定项。本地暂不可用、需要一份独立转写等情况仍可显式选择 API。小样本支持这个使用策略，不能推导出所有文献上本地都更准。

## 已实施的四项能力

| 改进 | 现在的行为 | 关键边界 |
|---|---|---|
| 校正长期保存 | `correct add/list/revoke`；记录源 SHA、页/块/bbox、原文与指纹、修订、复核者、证据、未确定项与时间；read 默认展示当前 accepted 校正，`--original` 查原稿 | API 候选不自动采纳；源或原结果改变后旧校正不套用；bbox 只作范围附注；原 OCR 不改写，局部校正不扩大为整篇正确 |
| 云任务恢复 | POST 前保存未知提交意图，jobId 返回立即落盘；`jobs resume` 只继续 GET、下载与解析，恢复完整输出并回写精读状态 | 没有 jobId 时保留未知；未完成任务阻止重复 POST；端点、授权和源 SHA 不符时停止；回执不保存密钥或签名链接 |
| 文献搬家 | 新精读内部路径相对文档目录；`relink --source` 核验 SHA 后更新源，兼容旧绝对引用；完整文档改名后保留可用读取与裁图 | 不扫描磁盘、不凭相似文件重绑；跨 Windows 卷保留绝对源路径；原文件内容改变须重新转换 |
| 环境可回退 | 安装前记录配置和包版本，始终建立新环境及模型目录；单页验收通过后原子切换；`setup --history/--rollback` 查看与恢复 | 失败保留旧默认；OCR 验收显式走 OCR；回退不删除环境/模型，不覆盖当前远程同意；旧运行文件或显式模型目录缺失则拒绝恢复 |

两个直接可见的行为变化：`refine --provider auto` 对公式/表格/转写始终生成 packet，即使已有 token 和上传许可；需要 API 时显式选择 provider。实际 OCR 安装必须给 `setup --sample`，可用 `--sample-page` 只验收 PDF 的一页；`--no-models` 只跳过预下载，上游可能在验收时下载模型。

独立审查补充了安装失败/回退写盘、未更新引擎模型路径、临时环境变量不能持久化、并行云任务编号归属、已搬家任务后续恢复等边界。设计仍采用本地文件和短时锁，没有新增服务、数据库或多用户平台。

## 验证与证据

- 最终完整隔离回归：265 项 unittest，264 通过、1 项 Windows 符号链接权限跳过；5 项契约检查通过。新增校正、恢复、搬家、安装事务与并行任务归属测试；外网由测试审计钩子禁止。
- CLI 保存/读取/原稿/撤销/区域附注/重绑闭环通过。真实 core 验收完成 PDF 生成、文字提取和页面渲染；没有重新安装或下载模型，安装切换及回退通过隔离 mock 验证。
- 真实样本副本：查看先前 Attention 第 8 物理页表 2 的裁图，确认题注应为 `newstest2014`，对 MinerU 的 `newestest2014` 只保存题注范围的宿主校正。原 `content.json`/主 Markdown 哈希不变，移动原文与输出后校正有效、记录字节不变、页面仍能渲染。副本在 `_docvision/maintenance-0.5.0/moved-library/reading`，原始实验结果未修改。
- 运行时 doctor 仍能发现现有 MinerU 4.0.12、标准模型与 core；本轮未切换用户现有配置。skill 元数据验证、`git diff --check` 通过。

本轮没有新增真实 OCR 或 API 请求，所以不新增速度/识别精度排名。云恢复由 mock/localhost 服务覆盖；实际服务未来仍可能使旧结果链接过期。URL 来源只记摘要，无法验证已提交字节，因此不支持可靠恢复；需要恢复能力的输入先下载为本地文件。自动单页 QA 只验结构，模型升级后仍需人工/宿主查看关键内容。
