# Imagecraft 开发与验收

本目录仅保留在 `dev`。向 `main` 整合时，只选择 `imagecraft/` 运行资源及根 README 的索引改动，不整体合并本目录。

## 当前定位（0.2.1 第二轮）

本技能是**辅助型技能**，不是生图产品：交付标准是“任务能不能往前走”，而不是成图能多惊艳。典型用途是文章配图、页面方案比较、需要一张图才能继续的讨论；另一种情况是宿主本身没有生图能力，由本技能补上出图、取回、校验与记录的链路。

先看内容是否必须精确、以后是否要改：是则选 HTML/SVG/TikZ/PPT 原生绘制；可接受栅格成果时再选通道。本机保持 FLUX 默认作极速素材/编辑，Z 显式用于低密度文字；16GB＋32GB 是唯一完整实机配置，reserve 6.5/10.5 仅有卸载模拟证据，不称真 12GB/8GB 验证。订阅脚本已分别授权完成正式无字素材和中文界面两例，generate 到原生 PNG、status/resume 同任务复查均通过。中文界面指定内容 130/130 可见匹配，但有额外刻度及尺寸偏离；验收已完成，不称完整契约全对，详见下方任务 3。当前选路以 [三层分工](../../imagecraft/references/routing.md) 为准。

产物与中间文件统一放用户项目的 `.imagecraft/`（briefs、jobs、scratch、evidence），可整目录删除，不散落到家目录。

## 本次范围

用户已批准开发与测试：给不同 Agent 提供按需使用的通用生图工作流，重点照顾人像、动漫、网页视觉参考和架构图相关任务，但其他方向不为了效果预装专用模型。先测试 FLUX.2 klein 4B，再由用户判断是否增配或更换。

保持以下约束：优先复用现有 ComfyUI 与权重，不升级原 H3 核心/Python/PyTorch/节点，不覆盖其启动器或全局默认工作区；代码、环境、权重、状态和产物分离，下载固定版本并校验，禁止静默云上传/付费服务/管理员安装。实际机器路径、真实配置、日志、模型和一次性探针不入库。

运行实现位于 `imagecraft/`，初版是一项独立 skill 加 Python CLI，直接使用本地 HTTP API，不强制新增 MCP 服务或 Pi 专有扩展。网页图片不冒充可交互软件。架构先有内容清单，可以采用经核对的生成图、少量局部修补或可编辑结构，不强制以代码框图替换丰富视觉；生图的文字和拓扑不能免验收。

## 本地测试

使用已有 Pillow、numpy、OpenCV 的 Python（完整测试中的局部擦除用例需要 OpenCV；纯叠加工具不要求它），不自动安装：

```text
<python> -B -m unittest discover -s maintenance/imagecraft/tests -v
```

测试用临时小文件和回环假服务器，不下载模型、不使用 GPU、不改真实 ComfyUI。第二轮全套 88 项；标准库订阅回归也只运行假 CLI / stdio JSON-RPC，不消耗订阅。静态复核在与源码逐文件哈希一致的冻结副本中配置现有 Python/Pillow 和脚本搜索路径，23 个 Python 文件零诊断；私有解释器路径不入库。覆盖下载完整性/续传/分段组装、不覆盖文件、回环与重定向限制、绕过推理代理、原生节点/参数检查、参考图处理、任务幂等、提交结果不明、忙队列、输出校验及损坏检测。另有局部修补的源哈希/尺寸、无覆盖、像素范围、文本框、路径、可选依赖和不支持输入检查。

真实推理是另一个独立验收阶段，不能用单元测试替代：

```text
<python> maintenance/imagecraft/benchmark.py --python <selected-python> --config <private-config.json> --output <new-external-evidence-directory>
```

先确认显存和现有队列空闲，在用户授权后启动所选现有服务。该脚本默认生成六张基础图和一张单参考编辑图：通用冷/热启动、人像、动漫、网页方向稿、绘画式架构示意。提交后用 `--wait 0` 返回，再续接同一个任务；重复一次已完成请求核对幂等。提示词完全合成，不使用私人素材。`--only <case>` 可做单项诊断，不覆盖已有证据目录。

资源记录为约一秒采样的**整卡显存与全系统 RAM**，不是 PyTorch/进程精确峰值，也不能归因于单个模型。服务执行秒数来自 ComfyUI history；命令墙钟时间还含预检、权重哈希、上传/取回等成本。冷启动须来自新启动、尚未加载该模型的服务；不同 seed 的第二张图不能误算成完整缓存命中。

完成后实际打开每张输出，再写脱敏验收记录。记录观察到的优点与缺陷、通过/不通过项、未测范围、原环境包版本及关键文件哈希是否不变；原始日志和图片保留在工作区外。单个 seed 的视觉结果只是首轮样本，不是模型排名或质量保证。

## 扩展样例

`suites/expanded-v1.json` 是公开合成夹具，不含用户真实提示词或参考素材。预先列出 24 项：20 次文生图和四次参考编辑，覆盖人物/插画、产品/场景、网页资产/文字边界、计数/低尺寸与编辑。不会为失败样例自动重抽，也不筛掉失败图。真实用户素材仍须放工作区外，不追加进该夹具。

先只读查看任务预算；此命令不创建输出、不调用服务、不占 GPU：

```text
<python> maintenance/imagecraft/run_suite.py --suite maintenance/imagecraft/suites/expanded-v1.json --dry-run
```

获得生成授权、启动并核验本地服务后，显式执行：

```text
<python> maintenance/imagecraft/run_suite.py --suite maintenance/imagecraft/suites/expanded-v1.json --python <selected-python> --config <private-config.json> --output <new-absolute-external-directory>
```

脚本最多接受 32 项显式任务，参考图只能来自同一组之前已完成的任务；输出目录必须全新且在仓库外。技术错误、等待未完成或回执不明时停止整组，不自动重交，也不自动停止仍可能在运行的服务。先检查现有任务，再决定续接。外层墙钟含采样线程收尾，不是纯服务端推理秒数；`--dry-run` 及夹具边界另有无 GPU 单元测试。

`suites/focused-v1.json` 是后续的 20 项聚焦夹具：复杂架构六项、页面六项、人物细节八项，全部文生图、1536 长边、无参考素材。使用同一执行器，替换 `--suite` 路径即可；仍须先 dry-run，真实执行另有 GPU 成本，不因夹具存在而自动运行。

## 当前限制

- FLUX 与显式 Z 两种本地模型（Z 另有文本精度配置），不做自动路由、微调、LoRA、精确蒙版扩散编辑、放大、视频或自动换模型。独立 CPU 工具的矩形擦除/排字不是神经语义局部重绘，也不自动判断拓扑。
- 仅回环 HTTP，不实现远程账号认证、公网服务或云托管。
- 续接依赖服务保留的队列/历史；服务清空历史后不保证找回未下载输出，更不会自动重交。
- 复用服务时，客户端哈希验证不等于证明远端进程在重名模型路径下加载了同一文件；须核对其外部模型映射。
- 下载网络与现有代理可能是瓶颈；并发分段和已有 HF/Xet 客户端是可选路线，不以第三方镜像或关闭证书校验掩盖连接问题。

尚未完成的真实测试只能标“未验证”，不能在发布说明里写成已通过。
