# 丰富生图视觉、准确文字与局部修补对照

核验日期：2026-11-01。本轮回应用户明确的取舍：网页和架构仍希望保留生图的丰富视觉，不全部改为 HTML/CSS/SVG；网页允许少量不显眼瑕疵，正式架构的文字、节点和边必须正确。此前的结构化重建仍是选项，不再作为所有场景的默认替代。

## 预算与实际执行

预先限定本地最多五次、Plus 最多两张，不自动重抽、不装新模型或依赖。检测到活跃游戏进程及约 4GB 整卡占用后，没有启动本轮 ComfyUI，也没有关闭用户程序；新增本地生成实际 **0 次**。本地对照改用前轮保存的原图，CPU 修补/排字不调用生图模型。

Plus 实际两次客户端提交，各收到一个 completed 的原生 imageGeneration 项，两张均解码并查看。复用官方 Codex 管理的 Plus 登录，没有重新登录、读取凭据、使用 API key、购买 credits 或重提任务。控制模型为 gpt-6-astra、low；图像模型 ID 未提供，不把控制模型当成图像后端。

未执行的本地计划包括：本轮新提示词的准确文字/拓扑生成、六个无字组件素材、少字网页、参考图改字，以及正确参考图保字保线润色。它们不能记为成功，也未因排期而自动延期运行。前轮已有相关失败样例不能代替这些具体新测试。

| Plus 架构局部修正版 | 只擦除错线并补任务队列→执行器，全部六节点/七边复核正确，原有文字和立体插画未重绘 | 本次明确内容清单验收通过；约 0.749% RGB 像素变化，不能外推任意复杂拓扑 |

网页的 18 个不同指定字符串对应画面 20 处文字实例（Done 出现三次）。实际核对的指标为 Accuracy 92.4%、Loss 0.267、Latency 18ms；这些是合成演示值。曲线是视觉示意，没有宣称对应真实测量序列。

本次架构内容清单独立于旧六边或十二节点 RAG 样例：用户端→接入网关、接入网关→任务队列、任务队列→执行器、执行器→推理模型、推理模型→执行器、执行器→对象存储、对象存储→用户端。图标内部的装饰符号不当作组件之间的额外连线。语义验收来自实际看图与清单对照，不是修补工具自动判定。

第一版补线的箭头尖部有杆线延伸，修正了绘制方式并另存最终版；没有重生成或覆盖原图。修补例选择的是少量文字/孤立错线，不能推广为复杂纹理、大面积遮挡或缺失结构的无损修复。Hero 的无字留白要求来自前轮提示词，本轮才写具体中文文案，不声称当时已锁定所有文字。

## 成本与用量

- 两张 Plus 的回合墙钟分别为 **79.864 秒**（架构）、**58.871 秒**（网页），合计 **138.735 秒**。包括原生控制回合，不是已单独测出的图像服务器推理时间，也不包括本轮研究、工具开发和全部审图。
- 同一路默认 Plus 登录、同 Codex 池、相同窗口及重置时间，五小时读数 **2% → 4% → 6%**；期间观测约 +4 个百分点，周读数维持 25%。整数取整、调度及未独立排除的同账户并发仍影响归因，不能给每张固定 2% 或可生成张数的保证。
- 第二张首次后置额度查询成功得到 6%，后续查询网络失败，未完成三次稳定回读。原生回合和图片项均 completed、图片已解码，外部探针总状态却因后置异常写成 `inspect_existing_thread_do_not_resubmit`。原报告保留，另作产物/视觉判定，没有重交请求。正式适配器需要拆分生成状态与用量观察状态。
- 两个旧图修字进程各约 **0.41 秒**；最终补线函数约 **0.40 秒**；无字 Hero 合成函数约 **0.31 秒**。这些是坐标和文案已给定后的程序时间，范围不同，不能直接当总工时排名；不包含找错、定文案、定位、宿主推理和审图，本轮未单独计量这些阶段。
- 新增权重、软件包、字体安装均为 **0**。擦除复用已有 OpenCV/Pillow/numpy；纯叠加无需 OpenCV。字体来自本机，未分发。原图哈希、叠加层、擦除蒙版及改变像素范围分别核对。

不同本地旧图与 Plus 样例的提示词、密度和内容不同，因此不是同条件模型排名，也不能据两个 Plus 样例估计普遍错误率。实际支持的结论是：当前任务可保留丰富生成视觉，主要内容准确时直接交图，少量明确问题再修；不必默认全图代码重建。

## 方法与许可核验

- OpenAI 官方图像文档仍提醒文字清晰度/位置和结构化构图存在限制；实际架构错边也说明原生云端不是免验收通道。
- AnyText2 官方仓库提供代码和 checkpoint 路径，用字形/位置/字体/颜色控制，不只是更强提示词；需另建环境、下载权重，官方建议至少 8GB 显存。论文准确率不是 100%。本轮仅核验资料，没有安装、测试其 Windows/FLUX 兼容性，也没有因此增加模型。
- IOPaint/LaMa、AutoFigure-Edit 的复杂修复/重建链作为备选，未安装或执行，不拿其宣传图当本机证据。
- Microsoft Fluent Emoji 的 MIT 许可允许按条款复用，须保留版权与许可声明，并逐件核对素材/用途；本轮没有下载或合成外部素材。unDraw 的许可另有 AI/ML 训练、验证/测试和自动集成限制，不作为默认抓取库。网络存在图片不等于整张图适合当前结构或可以直接拿来用。

## 工程落地与边界

新增独立 `imagecraft/scripts/repair_image.py` 及 [用法](../../imagecraft/references/raster-repair.md)：绑定源哈希/尺寸，矩形擦除不超过全图 10%，检查文本框、路径/箭头、变化范围，拒绝覆盖与不支持的图像格式/色彩管理输入；只写技术完成状态，仍要求视觉和语义验收。采用惰性导入明确可选依赖，没有自动装包；真实环境执行验证补充了 LSP 不能静态推断第三方导入的局限。

新增 11 项 CPU 单元测试，与旧 41 项合计 52 项，覆盖原图保留、区域外像素不变、哈希/尺寸、覆盖防护、非法区域与大面积擦除、错误规格、无 OpenCV 的纯叠加、缺可选依赖、非法箭头、文字溢出、透明/色彩管理输入。真实样例另外进行原图哈希和补丁范围核对；单元测试不替代语义审图。

技能文档改为整图生成、无字素材合成、少量修补、结构化重建按用途选择，不再强制全部 HTML/SVG。Python 生成 CLI 仍仅有 ComfyUI 后端；Plus 使用外部限定探针，正式云端适配、稳定恢复和硬预算尚未实现。全部原图、派生图、原生回执、私有规格、源快照和一次性脚本留仓库外；未提交、发布或同步宿主。
