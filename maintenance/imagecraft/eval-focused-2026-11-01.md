# Imagecraft 聚焦样例：复杂结构、页面与人物细节

日期：2026-11-01。用户认可前组的动漫环境与山水样例后，要求增加复杂架构图、较复杂页面、精细面部与人体样例。本轮仍使用同一套 FLUX.2 klein 4B distilled FP8，没有增加模型、节点、依赖、LoRA 或云端生成；运行环境仍为 ComfyUI 0.31.0 / Python 3.11 / PyTorch 2.8.0+cu128，显卡为 16GB RTX 4070 Ti SUPER。

## 预先固定的范围

公开合成夹具为 `suites/focused-v1.json`：20 次文生图，架构六张、页面六张、人物八张；每项只生成一次，无参考素材、重抽或筛图。人物均为原创合成成年人。所有图片为 1536×1024 或 1024×1536，seed 2101–2120；仍用 4 steps、CFG 1、Euler、batch 1，不做超分或后期锐化。当前 CLI 像素上限不变。

先完成 dry-run 和预算测试，再运行整组。20 个最终 PNG 均下载成功；随后逐张打开原图，写入用途相关的人工观察并离线校验。总览与分组图保留全部样例，另提供原尺寸的面部/手部裁切；缩略图不用于证明正文或手指正确。视觉 verdict 不是用户批准，也不是模型的一般成功率。

## 实际观察

| 项目 | 可借鉴的部分 | 未满足或仍有限制的部分 |
|---|---|---|
| 01 RAG 架构 | 简单分区与配色 | 标签错字、重复和缺项，未满足显式 12 节点、16 有向边 |
| 02 多 Agent 编排 | 分支/并行的基本视觉形态 | Planner/Coder 等重复，审批与结果关系错误 |
| 03 微服务 | 服务与数据库的分层 | 标签错误，事件总线与通知消费者关系偏离要求 |
| 04 训练与推理 | 流程式排布 | 训练链合并缺项、Model 重复，部署反馈不准确 |
| 05 双分支方法 | 两路输入与中间融合的形态 | 三层编码器、注意力/融合与输出头的文字和边不准确 |
| 06 深色系统图 | 深色分层与图标风格 | OCR/Parse 被合并，组件数量与连线不全 |
| 07 RAG 工作台 | 三栏、证据块、暖白底调 | 正文乱码，输入框变成按钮，额外浏览器式边框 |
| 08 可观测性 | 暗色折线、日志、瀑布图组合 | 四指标变三块，轴标签/数值/日志文字不可用 |
| 09 项目看板 | 卡片与右侧详情 | 三列变两列，Done 被挪作按钮，正文乱码 |
| 10 电商详情 | 商品大图与购买区的对照 | 缩略图数量/一致性、规格与相关商品不完整 |
| 11 移动财务 | 金额、折线与交易列表层级 | 日期金额错误，三分类和四底栏未满足 |
| 12 中文科研平台 | 表格与右侧实验详情布局 | 中文标题导航不准确，行列/数据不符 |
| 13 写实近脸 | 皮肤纹理、细发、眼睑、嘴部与反光 | 部分纹理偏锐，不等于真实摄影 |
| 14 男性侧转脸 | 胡须、耳部、眼睛与三分之四视角 | 只是单张合成人物，不证明身份一致性 |
| 15 严格侧脸 | 鼻唇下颌、皮肤与头发材质 | 仍露出远侧眼/睫毛，不是要求的严格 90 度 |
| 16 女性全身 | 完整头脚、肩胯膝踝和衣料 | 手指弯曲/遮挡，不能证明五指全部独立可见 |
| 17 男性弓步 | 全身姿态和肌肤/衣物细节 | 短裤额外白色标志违反要求；未验证运动教学正确性 |
| 18 面部与托杯双手 | 人脸、双手、杯子关系及材质 | 部分手指被杯子遮挡，年龄观感偏成熟 |
| 19 动漫近脸 | 眼睛、发丝、鼻唇与耳部线条 | 仅验证此次构图与风格，不推广成稳定角色一致性 |
| 20 动漫全身 | 服装与配件的基本绘制 | 出现多余手臂/手，不能交付为合格人体结构 |

本轮最适合继续用同一模型的是近脸摄影式素材、动漫头像及经过逐张检查的全身图。复杂页面可以供讨论布局与色调，但完整文字、数据、列数和控件语义没有跟随到位；不能冒充前端实现。复杂架构不应依赖扩散模型直接绘制准确节点、边与标签。全身图中面部占据的像素远少于近脸特写，不能要求两者呈现同等细节，也不能把本轮不同提示词的结果当作分辨率的受控对照实验。

## 结构化对照，不冒充模型能力

另按 01 的显式节点/边需求，用代码生成独立 SVG，并通过浏览器查看 1536×1024 渲染。XML 核对了全部 12 个节点与 16 条有向边的身份集合，实际看图检查方向、标签与布局；Storage 位于检索区下方，Cache 位于请求链上方。与原扩散图的对照保留在外部证据目录，原图没有被覆盖。

这是人工确定图结构后的代码绘图，不是 FLUX 输出、OCR 自动修图、图像到矢量转换或 imagecraft 已实现的自动功能。它核对的是这份测试图定义，不证明其为所有生产 RAG 系统的正确架构。

## 订阅额度与持久登录：研究结论，不是接入验收

用户同时持有 Plus 与高用量 Pro，询问 Plus 五小时窗口内单张稍复杂图的占比。本轮只查官方文档与本机 CLI 0.154.0 导出的协议，没有发起 OpenAI 生图、登录或模型回合，没有实测任何账户的额度变化。

官方说明生图回合平均约以相似普通回合的 3–5 倍速度消耗包含额度；它不是每张图占 3–5%。普通回合占比为 `p%` 时，`3p%–5p%` 仅可作为规划示例。核对当日页面对不同模型给出了差异很大的 Plus 消息估计，并写明 Pro 当前没有五小时限制；须读取实际账户的池、窗口与重置时间，不能简单按“20×”换算。

官方认证支持缓存与使用期间的令牌自动刷新，通常可首次浏览器登录后复用。现有协议包含能力检查、账户额度读取和图片完成事件的可选落盘路径；这些字段不证明实际工具已暴露或可以交付文件。建议先经授权做一张 Plus 样例的同窗口前后差值，再决定是否值得实现官方 app-server 适配；既不使用私人认证接口，也不将订阅变成 API key。详情与来源见 [云端备选](../../imagecraft/references/cloud-fallback.md)。

## 验证与证据边界

新增聚焦夹具预算测试后共 41 项单元测试通过。原始 PNG、回执、采样、逐图观察、总览、裁切、SVG 与浏览器渲染留在仓库外；公开目录仅存合成夹具、执行器、测试和脱敏记录。源码快照标记为未提交工作树，文档更新发生在生成之后。

这批样例没有验证其他 GPU/低配设备、长期压力、多人物复杂遮挡、真实身份/产品保真或云端端到端链路。没有安装其他模型、同步宿主技能、提交、推送或发布。
