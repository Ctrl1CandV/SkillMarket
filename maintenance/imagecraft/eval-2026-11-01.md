# Imagecraft 0.1.0 首轮验收 · 2026-11-01

## 结论与范围

**本地执行链路通过首轮验收，但不同用途的视觉结果并非全部通过。** 同一套 FLUX.2 klein 4B 完成九次真实生成/编辑；物体、人像、动漫与简单改色可作为当前样本的可用起点。网页图可参考构图，文字明显不可靠；扩散生成的架构图违反节点和连线要求，不能交付为准确架构图。另用显式节点/边构造了 SVG，并在真实浏览器渲染、看图和逐边核对，验证结构化替代路线；这张 SVG 不是模型输出，也不是 CLI 自动转换结果。

本次没有下载第二套模型，没有安装 ComfyUI、Python 环境、自定义节点或新依赖。只复用已有环境，新增固定版本的三个权重文件和独立本地状态/产物目录。尚未合入 `main`、提交、推送或同步到宿主的技能安装目录。

机器与环境（脱敏）：Windows 10，RTX 4070 Ti SUPER 16GB，约 32GB RAM；ComfyUI 0.31.0、Python 3.11.15、PyTorch 2.8.0+cu128，驱动 610.88。启动方式为独立目录、回环端口、禁用自定义/云 API 节点、low-VRAM、2.5 GiB 预留、禁用 pinned memory/async offload。没有比较其他启动策略，不能据此宣布本机最优配置。

## 耗时与资源

模型组件是 manifest 中的 FP8 diffusion、BF16 Qwen3 4B 编码器和 Klein 包的 BF16 VAE，精确合计 12,451,817,860 字节（十进制约 12.45GB）。全部经过完整 SHA-256 校验。

均为 batch=1、4 steps、CFG=1、Euler。首例与重启例是**新服务进程的模型冷启动**，没有清空操作系统文件缓存。墙钟时间含客户端启动、完整权重哈希预检、轮询/续接与 PNG 取回；两阶段任务取提交和续接两次命令的时间之和，不含服务启动本身。

约一秒采样的**整卡显存最高 15,728 MiB（约 15.36 GiB）**，全系统 RAM 最高 11,434 MiB（约 11.17 GiB）。这包含桌面和其他进程，不是模型独占占用或 PyTorch 精确峰值；采样也可能漏掉短暂更高值。2.5 GiB 预留启动参数不是硬显存上限。这台 16GB 卡已接近满载，不应同时运行 H3、GPU OCR 或其他重任务。

上述每项只有一次主要样本，未给出均值、标准差或画质排名。不能把服务端约 2–3 秒说成用户端总耗时，也不能把单例输出当成所有提示词都能稳定复现的保证。

## 下载与部署观察

普通 HTTP 单连接在现有网络下只有约数百 KB/s；短探针对比表明回环代理可访问官方 CDN，而直连超时。已安装的 HF/Xet 客户端在本次尝试中没有形成有效成品，停止后未更改其依赖。最终采用 16 条有上限的 HTTP 范围请求，精确检查范围/长度、组装并核验整文件 SHA-256；没有使用第三方镜像或禁用证书校验。

分段下载缓存与标准库单连接/HF 暂存不是同一套续传格式，不能笼统声称彼此无缝切换。下载期间最多需要多一个组件大小的组装空间。官方权重固定到不可变 revision，运行时只读取本地文件；三个精确哈希见运行目录中的模型清单。
