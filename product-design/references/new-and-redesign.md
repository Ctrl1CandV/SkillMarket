# 新建、重设计与继续建设

## 从零建设

先组织第一条能体现核心价值的完整任务：用户从哪里进入、围绕什么对象作出判断或行动、得到什么结果、如何继续使用。页面与导航从这个过程生长出来，功能清单用于核对遗漏，不直接成为菜单。

同时查看实际内容、品牌与素材。欣赏、期待和信任可能是产品价值的一部分，应影响第一版的视觉方向；不能把它们推迟到功能框架完成后才补一层装饰。

明确必需能力与未来设想，按用户要求落实本次范围。第一条流程应能暴露主要关系和约束，不固定为首页；需要的空态、进行中和失败恢复一并考虑，但不制造无关状态。成功后继续完成约定的其余部分，而非把流程样例当作整个平台。

缺少素材或服务时，区分当前能实现的交互与尚未成立的能力，保留真实输入条件；不要用等长卡片或欢迎语掩盖对象和流程尚未确定的问题。只有用户要求或待验证问题需要时才制作独立原型。

## 已有平台重设计

先记录当前流程、具体不满和目标变化，用已有反馈、画面、操作或代码定位问题。没有研究数据时，把观察与推断明确分开。局部问题先在局部解决；范围由问题所在层面决定。

把保留与可变内容拆开判断：用户认可的标识、品牌关系与习惯需要尊重；核心任务、数据含义与工程限制要理解；偶然形成的容器、菜单或 CSS 默认值可以在本次授权范围内重审。保留品牌不等于冻结所有旧样式，重设计也不等于更换品牌或技术栈。

| 观察到的问题 | 优先核对 | 可能改变的决定 |
| --- | --- | --- |
| 核心任务被次要功能遮住 | 任务优先级、展示时机 | 入口、页面职责与内容顺序 |
| 跨页重复录入或丢失选择 | 对象关联、共享状态与返回路径 | 流程连续性和上下文保留 |
| 内容结构合理但画面平庸 | 真实素材、视觉方向和元素关系 | 交由 frontend-craft 深化构图、色彩、字体与细节 |
| 同类控件表现不一 | 共同组件与规则的实际来源 | 修正共享实现，检查受影响的相邻页面 |
| 截图整齐，换成真实内容就拥挤 | 长度、数量、字段与响应式假设 | 比较方式、空间分配、状态及窄屏安排 |

这张表用于定位，不预先宣判原因。选择最能暴露问题的核心流程先修改，查看相关状态和共用组件影响，再完成本次其余范围。已有布局与内容明确、只要求视觉精修时，直接进入 frontend-craft，不能借表中检查扩展成导航重构。

## 已有方向的继续建设

读取已确认的产品依据、设计系统和相关页面，复用有效决定。新页面不自动需要新的风格；相同对象、状态和控件延续共同语义，不同任务可以有自己的尺度、密度和节奏。

只在目标、内容、素材、流程或约束发生实质变化时重审相关决定，并更新原因。几十页的统一样式调整不要求重新做平台调研；单页改变核心交易流程则需要追踪它对相邻页面的影响。

## 检查与收敛

分别检查任务是否完成、跨页关系是否连续、真实内容下画面是否优秀、实现是否有效。修正应指向证据暴露的层面；分析更加完整却未影响界面时，补足具体设计决定；画面仍普通时，继续深化视觉与素材，不重复同一套产品分析。

重设计比较可以改变结构，但说明实际改变了什么，保留可比较的主要任务与真实内容。不把一次同时改变多项因素的结果说成某条规则的因果证明。只能进行文本推演或静态检查时，明确其局限，真实体验与视觉效果留待实际查看和操作验证。
