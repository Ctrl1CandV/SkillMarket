# 项目上下文与交接

## 从材料得到什么

阅读围绕当前决定展开，不以遍历仓库为目标。产品说明和用户原话提供目标；路由、数据模型、组件与运行流程说明现有能力；内容和素材说明画面将承受什么。先定位相关部分，再追踪会改变设计的缺口。

三类信息分别记录：

| 类型 | 记录方式与用途 |
| --- | --- |
| 已确认的要求 | 标明用户要求或项目约定；作为当前设计约束。用户认可整体，不等于认可每种旧颜色和布局 |
| 实际事实 | 指向相关文档、代码、画面或操作结果；说明已实现、受限或缺失，避免把计划当能力 |
| 假设与提议 | 写明依据、影响及待核对处；不能改写为调研结论，未经确认的提议不标为已确认 |

代码有某项能力，不代表使用者需要持续看见它；接口名、数据库字段与现有菜单可以帮助理解，但不能代替任务模型。建设者希望“高级”，仍需结合对象、素材和使用节奏解释其画面含义。

## 补充询问的尺度

先判断缺失信息会改变什么。如果两个答案会导致不同的核心对象、流程、角色权限或已有承诺，且现有材料无法确定，就集中询问这项分歧，并继续不依赖答案的工作。不要默认发出一套产品访谈问卷，也不要把常规设计决定都交回用户。

可逆的排布、字形或组件细节可先作有依据的选择。对缺失数据和素材写清临时假设，例如“样本用于检验长商品名，库存与配送能力尚未接入”；未知值不填成 0，样本不充当真实业务证据。用代表性内容覆盖明显的长度、数量、差异与相关失败状态，无需穷举测试矩阵。

出现冲突时，核对当前用户要求和可定位的事实，保留仍有效的决定。无法解决且影响核心流程的冲突才请求澄清；更新受影响处与简短原因，不把整个项目重新分析一遍。

## 保存到哪里、保存多少

通用方法保留在技能里，具体产品事实与选择放在目标项目中。沿用已有文档及职责，避免创建第二份权威 PRD；必要时用短索引指向产品、设计系统和当前任务说明。缺少合适位置且需要持续建设时，一份短 Markdown 通常足够。

以下是可选内容框架，不要求空章节或固定格式；已知内容可以直接引用：

| 内容 | 留下能改变后续工作的部分 |
| --- | --- |
| 当前范围与目标 | 产品价值、本次交付、主要使用情境与完成标准 |
| 对象与流程 | 主要对象及关系、进入到取得结果的路径、跨页共享状态 |
| 页面职责 | 用户在该处看、判断和操作什么；与相邻页面如何衔接 |
| 保留和可变范围 | 已认可的品牌与能力、允许重审的结构和样式默认值 |
| 内容和素材 | 真实输入、样本用途、重要素材缺口及来源位置 |
| 设计决定 | 依据、展示重点、页面或区域的表现方向，以及将如何检验 |
| 实现与未知 | 关键状态、设备与工程约束、待确认事项及其影响 |

重要决定可以写成一行：`需要同时核对原文与引用（任务说明）→ 同一工作上下文可互相定位 → 宽屏并置、窄屏切换时保留位置 → 用长文和多条引用实际往返检查`。这是表达粒度示例，不是固定布局建议。

维护当前有效结论，不为每个像素或一次试色写记录。方向被否定或新内容推翻假设时，改掉过时结论并简述原因；继续建设时读取已有依据，仅更新本次变化。仅要求讨论或评审时，不因这个框架擅自新增文档体系。

## 两种能力如何接续

product-design 提供任务与完成标准、对象和页面关系、代表性内容与关键状态、保留及变化范围、视觉重点和检查目标。frontend-craft 继续决定页面内容如何组织、怎样构图、字体与颜色怎样配合，以及控件如何表现。

上下文足够即可进入具体设计，不要求先完成整套文档或经过额外确认。配套技能按宿主的可用能力发现，不写死安装路径，也不强制另起 Agent。

只有新的事实或结果造成实质影响才重开相关判断：

- 必须同时比较的对象被分到互斥页面，或切换后丢失核心选择，需要修正页面关系和状态决定。
- 素材不足以支撑主视觉，需要更新素材假设及表现方向，而非拿占位图宣布完成。
- 按钮在背景上沉重、标题断行不佳，先由页面设计调整，不退回产品访谈。

依据文件或配套技能缺失时，利用已知上下文继续；只有必要信息确实未知才补问。不得把两个技能互相推荐变成往返调用流程。
