# Product design

让产品理解改变实际界面。用户围绕什么对象工作、要作出什么判断，决定哪些内容共同可见、哪些形成连续的阅读面、哪些在相关时出现；这些关系继续影响尺度、对比、颜色与空间。分析的产出是可执行的取舍，并能在相应画面或操作中核对。

用户价值包括完成任务，也包括欣赏、探索、期待、信任与记忆。把内容、品牌、素材和表现方向一起考虑。成熟产品与公开设计经验可提供默认依据，用户明确的要求优先；行业名称、功能数量或“高级、简洁”等形容词不足以决定布局和风格。

## 判断本次变化

读用户要求、项目约定及已有依据，明确对象范围、主要任务、保留与可变内容，以及本次交付是评审、方案还是实现。用户当前要求优先于历史决定。

| 情况 | 从哪里开始 |
| --- | --- |
| 从零建设 | 理清必要的对象关系与核心任务范围，选择代表性流程，尽早让真实内容和视觉方向进入实现 |
| 重设计或新增能力影响角色、导航、页面关系或核心流程 | 查看现状与具体问题，只重审受影响的决定 |
| 已有充分依据，继续建设 | 复用有效决定，补足本次新增的内容、状态与约束 |
| 单页、组件或样式调整，不改变核心关系 | 在当前范围内使用可用的 frontend-craft，不补做全平台分析 |

按变化实质判断：一页也可能重构核心流程，多页也可能只改样式。纯业务逻辑按工程流程处理；仅要求讨论、评审或方案时按该范围交付。

信息卡、侧栏或窗口的局部重排可以调整内容分组、顺序、显隐和动作组织。外层关系已成立不等于局部只能改 CSS；只要对象含义与核心流程不变，就沿用当前产品依据，由页面设计完成，不因功能较多补做全产品分析。

## 从依据到画面

### 1. 找到足以开始的事实

先读产品说明、用户原话和已确认决定，再查看相关页面、对象、路由、角色与素材；有运行条件时走查涉及的流程。区分已确认要求、代码与运行事实、假设与提议。已有功能提供能力证据，当前 CSS 提供实现线索，二者都不自动成为展示优先级或品牌规范。

缺失信息会改变主要对象、核心流程或已有承诺，且现有材料无法确定时，集中澄清该分歧并继续不受影响的工作。可逆的设计细节自行作有依据的选择。没有访谈、行为数据或使用频率证据时，不把推断写成调研结论。

### 2. 建立对象、任务与页面关系

找出用户认识和持续使用的对象、对象之间的联系，以及进入、判断、行动、取得结果和继续使用的过程。对相关页面说明用户在这里理解什么、判断什么、操作什么，操作后怎样继续；同时考虑当前对象、选择、输入与阅读位置如何延续。

结合对象关系和任务安排导航。稳定的对象入口、上下文链接与围绕对象发生的动作各有用途，不把任务动词、后端实体或功能目录逐项变成菜单。分别判断能力是否保留、入口在哪里、何时需要突出；一个页面可以承载相关职责，不为每项能力建立独立区域。

多信息、多功能区域需要说清动作针对哪个对象、依赖什么条件、改变什么，以及结果归属哪里。区分正在编辑、已经生效与历史记录等实际状态，让内容和反馈对应其所支持的判断；具体控件与空间由页面设计深化。

### 3. 作出会改变画面的取舍

选择最影响本次体验的关键关系，把 **依据、取舍、预期界面变化、检查方式** 串起来。简短文字或表格均可，复用已有材料，不为每项功能重复制作交接记录。

- **确定视觉地位。** 保证对象可识别，突出当前判断所需的内容与动作。优先级可体现为面积、对比、持续可见或出现时机，不要求重要信息全部置顶。主体可以是正文、一组比较对象、数据表或作品。
- **处理竞争目标。** 同屏比较、内容完整、阅读宽度、操作可达和品牌表现可能互相牵制。说明这次优先满足什么、用什么方式保留另一项价值，以及什么实际结果会促使调整。
- **让真实内容约束决定。** 尽早使用真实或脱敏材料；缺少数据时，用符合实际长度、数量差异和相关状态的样本并标明。保留必要字段、真实差异和素材主体，不靠等长卡片或统一缩字维持构图。
- **建立整体表现方向。** 从使用节奏、素材与品牌确定主体、密度差异、图文关系和表现力度。同一产品的浏览、阅读与精确操作可以有不同尺度，共同对象、状态和视觉身份保持连贯。
- **采用具体参考。** 选择任务和内容形态相近的成熟案例，说明其中哪种关系适合本次决定。区分实际看过的画面、来源文字与尚未验证的设想。没有额外个人偏好时，可据成熟经验直接选定合理起点，无需逐项请用户选风格。

例：当前需要核对解释与证据，因此二者要保持可定位的关联；连续阅读仍需足够空间。页面设计据真实内容决定并置或切换方式，再用实际往返操作检查关系是否成立。这里确定目标与取舍，具体比例、字体、表面和颜色由页面设计共同深化。

### 4. 在代表性页面中兑现决定

交付包含实现时，在现有工程中选择能暴露主要关系和约束的页面或工作状态，完成必要入口、内容、操作、结果及相关状态。代表性流程是验证切口，不自动成为整站唯一结构，也不限定为首页。

Web 界面有 frontend-craft 可用时，按宿主机制读取其能力，继续完成参考选用、构图、文字、配色和交互。让关键产品取舍对应到实际区域和行为：需要比较的是否能比较，需要连续读的是否连贯，支持操作是否可达且分量适当。只写“阅读优先”或完成一份样式参数表，还没有兑现这些决定。

依据足够就继续深化；实际分歧会改变设计时，作足以判断的轻量比较。默认直接推进项目中的代表页面，独立原型仅用于用户要求或确有必要隔离的问题。无需固定候选数量、两个独立 Agent 或额外交接审批。

### 5. 按结果修正，再完成约定范围

用代表性内容看实际画面并操作，分别判断任务完成、对象与上下文连续、整体视觉质量和实现可靠性。文档齐全、规则通过或构建成功只说明各自检查的结果。

新事实或实际实现、使用结果表明当前解法无法满足主要任务、页面关系或已确认约束，或推翻素材假设时，重审受影响的决定。不能自行解决的重要要求冲突按第 1 步处理，不把用户要求改写成方便实现的假设。普通字形、颜色、边界和局部空间问题由页面设计处理；不把两个技能互相推荐变成往返流程。

成立的关系继续覆盖本次其余页面和状态。代表性页面通过不代替约定范围的完整交付。交付说明重要取舍、实际变化、看过和操作过的范围，以及仍未验证的部分；没有画面或运行条件时如实说明，不宣称视觉效果已经提升。

## 保存必要依据

持续建设时更新项目已有产品或设计材料；缺少合适位置且确有后续复用需要时，建立一份简短依据。保存能改变后续工作的事实与选择：当前任务、完成标准、对象关系、真实内容、保留范围、关键取舍和检查目标。保留来源，更新过时决定，不为每次试色另建文档。仅讨论或评审时可直接在交付中说明。

设计理由留在项目材料中，使用者界面呈现其任务所需内容。配套技能不可用时依现有依据继续，不依赖固定安装路径或擅自安装；其他媒介按其实现与验收方式处理。
