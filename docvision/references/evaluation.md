# 评测

本文的 `maintenance/docvision/evals/` 回归命令适用于 SkillMarket dev 工作树；main 或独立技能包不包含维护测试。独立使用时运行 doctor、公开小样本 convert/refine、实际看图与 verify 即可验收环境。

目标不是给模型打一个“总分”，而是回答：**这份文档、这个任务，输出能不能用？** 评测要能复现、能定位失败页、能比较路线，不用“看起来不错”代替证据。

## 最小样本集

按实际用途选样，不为通用性凑类别。个人论文阅读先用 3 页公开真实论文覆盖正文、密集公式和复杂表格，再从中选 2 个区域精读；只重复其中一个区域观察速度波动。架构图另以实际看图检查连接关系，不把 OCR 转写当成图形理解。中文扫描材料有实际需求再加入；只有结果无法决定分工时才补样，不把大规模评测设为使用前置条件。可从下面的类别选取，不只使用干净合成 PDF：

1. **数字版论文**：双栏、摘要、公式、表、图、参考文献。
2. **扫描书页**：轻微倾斜/阴影，中文正文 + 页眉页脚。
3. **复杂表格**：合并单元格、多层表头、跨页。
4. **截图/幻灯片**：小字、彩色背景、图表。
5. **手写/印章/票据**（如实际会用）：低清、遮挡、多语言。

每份记录：来源类型、页数、扫描分辨率、是否含公式/表格/图表、语言、隐私级别（决定能否远程）。不要把真实敏感文件提交到仓库；评测记录只放脱敏结论和可公开的合成样本。

## 指标

| 维度 | 怎么量 |
|---|---|
| 完整性 | 缺页/缺段/空页数；对照原文页数 |
| 正文准确率 | 抽样 20-50 个句子，人工/编辑距离；记录错字类型 |
| 公式 | 公式编号、上下标、括号层级；按 CDM 或人工逐条 |
| 表格 | 列/行/合并单元格/TEDS 或人工核对 |
| 阅读顺序 | 双栏、侧栏、图注是否错位 |
| 图表 | 轴/图例/单位/趋势是否描述正确；数字是否可追溯 |
| 可定位性 | 每页/块是否有页码/bbox；能否裁剪复核 |
| 稳定性 | 同一文件重跑是否一致；失败是否可复现 |
| 资源 | 单页耗时、峰值显存、模型下载体积 |
| 成本 | 本地电费/时间；远程页数×单价，按实际账单 |

`qa.json` 只覆盖结构（空正文、图片引用、页号、表格标签、公式 `$` 平衡），**不是准确率**。准确率必须看页面图或人工标注。

## 对比方法

- 同一文件、同一页范围、同一语言提示，分别跑本地 MinerU、PaddleOCR-VL、远程候选。
- 固定输出目录和随机种子（如 provider 支持）；记录版本、模型、设备、耗时。
- 先看失败页，不要只看平均分；一个模型在公式页崩掉，平均分可能仍高。
- 公式/表格单独抽样，不要被正文分数掩盖。
- 远程比较要记录实际计费页数，不要把“免费额度”当零成本。
- 以同一批难页的核对结果决定分工：精度较好的路线负责关键区域，另一条只有在实测更快或资源更省时才用于批量。若两者同源且输出一致，不把一致当成独立验证。
- 速度分开记录文字层筛读、OCR 冷启动、连续批处理、区域精读和缓存复用；报告端到端耗时中位数与慢页，不能用文字层或缓存速度代替 OCR 推理速度。
- 保留少量人工校正的公式、表格单元格和图形关系作为回归答案。优先统计会改变论文理解的漏项、错符号和错连接，再考虑总体编辑距离；最终比较完成可靠阅读所需的总时间。
- 小样本只决定当前工作流的初始分工：若关键内容同样正确，优先更快的一条；若整页与裁图速度结论相反，按任务大小分工；若有关键错误，记录具体类型并选择该区域更可靠的结果。两次时差很小或波动明显时不强行排名，也不声称代表所有论文。

## 历史实测范围（2026-10-28）

以下为早期维护记录，设备为当时的 16 GB 显存机器；不代表当前设备性能。MinerU 云端已经移除，相关成功/失败记录仅用于解释历史，不能作为当前可用路线。

**已做**：

- MinerU 4.0.12 本地：`mineru-kit parse --format zip`，2 页合成 PDF（含公式、简单表）标准档，约 13 秒；`middle_json` 页/块/bbox 正确；`read --page`、`pages`、`crop`、`verify` 可跑通。
- PaddleOCR 3.7.0 + PaddlePaddle GPU 3.2.1（conda，RTX 4070 Ti SUPER）：单页 PNG、2 页 PDF，GPU 单页约 1.4 秒推理；逐页 JSON/Markdown 合并、页码映射、中文文件名可跑通。
- MinerU Agent API：2 页合成 PDF 上传、轮询、下载 Markdown 成功；确认它只返回 Markdown、无图片/bbox。
- 输出契约、`verify`、`read`、`crop`、`pages`、`resume`、`dry-run`、中文输出名。
- 单元级 mock 覆盖 PaddleOCR 云端适配器的协议解析与错误映射（不调用真实服务）。

**未验证/不能声称**：

- 当时 `MINERU_TOKEN` 无效（401/A0202），**Standard 云 API 未做真实端到端**；Agent 成功不代表 Standard 成功。
- 云端只有 PaddleOCR 一条路线，且有真实 token 的公式/合并表格验证记录；其他云端 OCR 已移除，不是“未验证但保留”。
- 没有验证真实额度耗尽的服务端响应（mock 覆盖了错误映射）；没有验证极低额度账号的限频行为。
- 没有做大规模准确率评测；合成样本只证明流程可跑，不证明论文/扫描件质量。
- 没有验证 8 GB 显存机器上的峰值显存/长文档稳定性；只验证了 16 GB 机器。
- 没有验证所有 PDF 变体（加密、旋转、混合语言、超大页、跨页表）。
- 没有验证 PaddleOCR 的图表/印章/手写质量；只验证了基础文本+公式+表格。
- 没有验证本地视觉模型（Ollama/vLLM）对图形的解释质量；没有 8 GB 真机与长文档基准。

## 0.4.0 个人论文阅读验证（2026-10-29）

当前机器仅使用 core 依赖测试，没有下载模型或更改已有 OCR 环境。Python 3.12.14、pypdf 6.10.0、pypdfium2 5.14.0、Pillow 12.3.0；样本为公开的 Attention（15 页）、ResNet（12 页）、VAE（14 页）论文。

| 项目 | 结果与边界 |
|---|---|
| 数字论文初读 | `convert <目录> --tier fast --workers 1 --resume`，41 页；三轮独立进程和新输出目录，中位总耗时 1.693 秒（含解释器启动） |
| 相同请求复用 | 每轮随后重跑，中位总耗时 0.4566 秒；三份全部跳过、重新处理 0 页 |
| 批量缓存查找 | 合成的 300 份元数据、30 次查找：元数据读取从 4,380 降至 330 次；含索引建立约 0.196 秒，对照约 1.467 秒。仅说明查找成本 |
| 独立前向阅读 | 从技能说明出发批读三篇，生成 Attention 第 3 物理页 300 DPI 精读包，实际打开图片核对模块、箭头和正文；原命令重跑全部复用 |
| 回归 | 207 项 unittest 中 206 通过、1 项 Windows 符号链接权限测试跳过；另 5 项契约检查通过；skill 元数据验证通过 |

这证明 core 可完成“文字层筛读 → 选页 → 看图精读 → 复用”流程，**不证明公式 OCR 精度提升**。本次没有在当前 8 GB 机器运行 MinerU 4 / PaddleOCR 3.7，也没有调用真实云端 API；本地和云端谁更准、更快仍需同图对照。fast 没有图块坐标，双栏顺序、公式和表格不能仅凭文字层确认；扫描件仍需 OCR 或实际查看页面图。

开发仓库保存可核对的来源、SHA256、逐轮耗时与限制：`maintenance/docvision/evals/personal-workflow-0.4.0-2026-10-29.json`。修复与验证记录见 `maintenance/docvision/reports/personal-reading-upgrade-0.4.0-2026-10-29.md`；独立安装包不包含这些维护文件。

## 0.4.1 小规模真实 OCR 对照（2026-10-29）

在上述文字层测试之后，新建了当前 RTX 4060 Laptop 8 GB 机器的 MinerU 4.0.12 环境并验证标准模型，再与真实 PaddleOCR-VL-1.6 API 对照。输入为 Attention 物理页 4、8 与 VAE 物理页 4，以及其中的复杂公式和合并表格裁图；共预设 20 个核对点。每条路线仅 4 次调用、6 个逻辑页输入；本地另有 1 页安装验收。

| 输入 | 本地 | API |
|---|---:|---:|
| 3 页整页 | 30.91 秒（standard） | 126.05 秒 |
| 公式裁图首次 | 22.01 秒（quality/advanced） | 10.30 秒 |
| 表格裁图 | 19.58 秒（quality/advanced） | 46.53 秒 |
| 相同公式再次处理 | 18.70 秒 | 1.05 秒 |

均为端到端时间，不含环境安装；本地已经预先单页验收。API 重复公式的原始 JSONL/logId/资源地址完全一致，jobId 不同，支持服务端复用的推测；不能把 1.05 秒当作重新推理速度，也没有账单证据。日志确认本地 llama-cpp 后端，GPU 采样不足以确认加速器归因。

本地保留了选定公式、编号和表格结构；API 公式裁图丢编号 (7)，正文另有 `d_k → d_x`。两端表格 9 个预设检查点均通过，本地题注也存在 `newstest2014` 的拼写误识。云端原始结果中的脚注被导出遗漏，已在适配层补回；这类导出修复与模型精度分开记录，不猜测改写符号。

同次测试还修复了 MinerU 嵌套算法/图注被转成字典文本、表格题注在结构/按页输出中遗漏的问题；以保存的 raw 成员离线重解析核对，不新增模型调用。最终回归 210 项中 209 通过、1 权限跳过，另 5 项契约检查通过。

本样本支持本地承担主要识别；API 首次公式裁图较快，但没有观察到精度优势。0.5.0 据此将 API 定位为疑难区域辅助纠错：先看原图，有疑点再显式取第二份转写，核对后保存校正。auto 不自动调用 API。当前小样本不覆盖所有论文或长文档，后续按真实错误页补充即可。详见开发仓库 `maintenance/docvision/reports/single-user-review-and-small-probe-2026-10-29.md` 与 `maintenance/docvision/evals/small-probe-2026-10-29.json`。

## 真实任务验收

一次转换至少检查：

1. `doctor` 路线是否符合隐私/硬件。
2. `meta.pages` 与源文件页数；`content.json` 页号连续。
3. 抽 3 页对照页面图：正文、公式、表格、图注。
4. `verify` 无 `fail`；`warn` 是否能解释。
5. 关键引用有页码/块 id。
6. 耗时/成本可接受；失败页能换路线重跑。

只有“输出落盘 + 页面图核对 + 关键结论可追溯”才算完成。不要用“模型说识别成功”代替验收。

## 维护评测

把每次真实任务的失败页、错误类型、引擎版本记录到 `maintenance/docvision/evals/`（dev 分支），不要放真实敏感原文。下一次升级后先重跑这些失败页，确认没有回归，再扩大样本。
