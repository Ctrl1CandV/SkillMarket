# 开工：问清再动手

开工的产出是一份**确认单**：写下用户确认过的需求、倾向和验收条目。实现照它做，`dev-acceptance` 照它验。用户确认之前，只读、只查、只问，不写功能代码。

## 1. 查清事实，定项目档位

先读能读到的材料：README、AGENTS.md 或 CLAUDE.md、现有代码与依赖、任务书或作业要求、`docs/briefs/` 里以前的确认单、已有的管理文档。能从材料里得出的**事实**自己定；用户只回答**决定**，即取舍、偏好和只有他知道的情况。环境情况（语言版本、已装的包、可用的浏览器等工具）先用命令查过，再写进事实。已有项目加功能时，只问这次改动涉及的部分。

再判断项目档位。拿不准的，放进第一轮问题：

- **规模**：一次会话能做完，还是要几次。
- **寿命**：短期的（作业、一次性工具、演示），还是要长期迭代。
- **交给谁**：自己用，交给老师或同学评，还是给别人长期用。

完成标准：能分别列出已知事实、待定决定和项目档位。

## 2. 按决定树一轮轮问

把待定决定排成一棵**决定树**：每个决定下面挂着依赖它的决定。

- 每一轮只问前提都已定的那一圈，一次问完；依赖本轮其他问题的，留到下一轮。
- 每题附推荐答案和一句理由。有几条明确的路，就把它们列出来。措辞要让用户回“是”就等于接受推荐。
- 用户答完，重算这一圈，再问下一轮。

问的渠道看宿主：

- **宿主有提问工具**（Claude Code 的 AskUserQuestion、Codex 的 request_user_input 等）：用工具问。第一个选项放推荐答案，标“（推荐）”，同时保留用户自己填写的入口。一次放不下就连续调用几次，把同一轮问完。
- **宿主没有提问工具**：在对话里编号列出问题，每题后面写推荐答案。告诉用户可以逐题回答，也可以回“全部按推荐”。

用户的回答常常比选项多出东西。以用户原话为准，把多出的内容带来的新分支加进树里。

问的深度跟着档位走：自用小工具常常一两轮就够；交给别人评分或要长期迭代的项目，每个分支都问到底。

完成标准：第 3 节的六个方面都有结论，树上没有未定的分支。结论可以是用户的回答，也可以是用户说“你定”之后你写明的选择。

## 3. 六个必问的方面

小项目可以一题问几个方面，但每个方面都要有结论。

1. **使用者与任务**：谁用，在什么场景用，要完成哪些事，成果交给谁。
2. **倾向**：偏好的语言、框架、做法和参考对象，以及明确不想要的。
3. **功能与架构**：做哪些、不做哪些，数据从哪来，怎么运行和部署，要和哪些现有的东西接上。
4. **内容与展示**：有哪些页面或输出，各放什么，主次怎么排。
5. **审美**：会被人看到的东西（页面、图表、图片、幻灯片、视频、报告）要什么样子，包括风格、喜欢的参考、要精致到什么程度。问到倾向和参考为止；具体构图与排版交给对应技能，见“交给谁”。
6. **完成标准与验证档位**：做到什么算完成，每条怎么验证、由谁验证。档位按项目定，先推荐，再请用户定：
   - 自用小工具：主要用法跑通、显示效果好，就算完成。
   - 交给别人评分或使用：每项功能逐条验证；核心算法和数据处理要有测试，用 `tdd`。
   - 长期迭代：核心逻辑要有自动化测试，以后的改动能回归。

## 4. 写确认单，请用户确认

写到 `docs/briefs/YYYY-MM-DD-主题.md`；项目已有别的约定就照它。格式见 [references/brief-template.md](references/brief-template.md)。

验收条目每条都要能判断过没过，写清操作、预期结果和验证方式。“界面美观”这类说法要改写成能看、能量的条目，比如“参照用户给的某某风格；手机和电脑宽度下都没有横向滚动”。

把确认单发给用户确认。用户改了，就跟着改确认单，直到用户明确说可以开始。确认单和这次的第一个功能提交一起入库。

完成标准：用户已明确确认；确认单里没有“待定”，只有写明理由的假设。

用户确认后开始实现。确认单里写了要交给哪些技能的部分，先读对应的技能（见“交给谁”），再动手。

## 5. 长期项目的管理文档

短期项目只留确认单。

长期项目沿用已有的管理文档，比如 README、STATUS、CHANGELOG、AGENTS.md。一份都没有时，建一份 `docs/STATUS.md`，写现状、下一步和已知问题。项目里有容易混淆的词，或有难以回头的决定时，再加术语表或决定记录。这些文档每次收尾时更新。

## 交给谁

实现阶段按确认单的对应部分使用下面的技能。它们会先读确认单，已定的事不再重复问。

- 网页或软件的整体体验、页面职责：`product-design`。页面实现与精修：`frontend-craft`。
- 图片：`imagecraft`。幻灯片：`presentation-craft`。视频：`video-craft`。
- 核心逻辑先写测试：`tdd`。模块接口怎么设计：`codebase-design`。排错：`diagnose`。
- 做完、提交之前：`dev-acceptance`。
