# 确认单格式

文件名：`docs/briefs/YYYY-MM-DD-主题.md`。用用户的语言写。只写结论，不写问答过程。没有内容的小节写“无”，不要删掉。

```markdown
# 确认单：<主题>

日期：YYYY-MM-DD　状态：待确认 / 已确认（YYYY-MM-DD）

## 一句话目标

## 项目档位
- 规模：
- 寿命：
- 交给谁：
- 验证档位：

## 使用者与任务

## 倾向
- 想要：
- 不要：

## 功能与架构
- 做：
- 不做：
- 数据：
- 运行与部署：

## 内容与展示

## 审美
- 风格与参考：
- 精致程度：
- 交给：（product-design / frontend-craft / imagecraft / presentation-craft / video-craft）

## 验收条目
| 编号 | 条目（操作 → 预期结果） | 怎么验证 | 谁验 |
|---|---|---|---|
| A1 |  | 运行命令 / 跑测试 / 打开页面截图 / 对照参考 | 开发者自测 / 审查者 / 两者 |

## 假设与“你定”的选择
- 选择：理由

## 验收结果
（由 dev-acceptance 填写：每条通过、不通过或没验证，附证据位置，写明审查方式）
```

“谁验”的分法：

- 必须了解实现才测得准的，归“开发者自测”，比如边界输入、核心算法的已知答案、内部状态。
- 其余的归“审查者”，比如用户能看到的功能、展示和审美、范围有没有多做或漏做。
- 关键功能写“两者”。
