# 长期学习路线与研究准备

本协议补充跨篇学习规划和研究机会判断；选文、综述与单篇讲解继续使用原协议。它提供有依据的建议，不决定研究方向、不保证录用。

## 1. 何时使用，依据什么

用户要求长期学习路线、探索研究方向或判断何时开始研究/写作时使用。已明确采用双轨流程的后续阅读，先回答眼前问题；出现会改变路线或研究判断的实质线索时再简短提示。普通单篇阅读和概念解释不自动附加选题审查。

复用本次目标、已授权背景和指定材料，区分：可用读物、用户明确表示读过的内容、用户自述或可见实践支持的理解、仍不确定的先修。生成导读、打开页面、收藏论文和平台收录都不证明掌握；不根据已读篇数推断水平。缺信息但不影响下一步时保留假设，只有会改变路线或投入判断时才询问。

长期学习方向、正在探索的候选和已决定投入的课题分别表述。发表目标采用用户明确要求，保留“或/且”关系、评价体系、版本/年份及文章轨道。CCF 类别、中科院大类/小类分区、JCR 分区不能直接互换；受托做近似对齐时明确是规划假设，具体刊会与资格回官方记录核验。没有明确门槛时不预填。发表目标不降低已有选文的质量标准。

## 2. 先建立地图，只细化下一步

将长期方向拆成能回答具体问题的知识模块，标出必要前置、已有材料和缺口。先覆盖核心关系，再围绕当前最重要的理解障碍安排少量主读与互补；不一次堆满书单，不把完整地图变成开始实践的门槛。

综述用于建立分类和争议地图，经典工作用于理解基础概念和推导，近期工作用于校准现状。每篇说明它解决哪个疑问、为何此时读、必要先修及与已有材料的关系。找、选论文走 [selection-protocol.md](selection-protocol.md)；完整综述与精读分别走 [survey-protocol.md](survey-protocol.md) 和 [reading-protocol.md](reading-protocol.md)，不在这里另造阅读标准。

用自然交流或已有实践检查路线是否合适，例如能否解释两个机制的区别、指出结论的成立条件、完成一个小复现。练习按需要安排，不强制每次考试。根据用户的明确反馈调整下一篇与解释深度，说明建议的依据，不擅自宣布已经掌握。允许学习与小实验并行，也允许一段学习暂时没有论文产出。

需要交付到阅读平台时，遵守目标平台已有的内容合同、来源核验和导入流程。候选清单、已完成导读与已导入条目分开报告，生成文件不等于导入成功。

## 3. 从疑问收敛到可检验的窄问题

有实质线索或用户请求判断时，先形成一个简短候选：

- 什么对象在什么条件下出现什么局限，为什么值得解决；
- 最接近的工作是什么，已核到哪里，区别落在哪个机制、设置或证据缺口；
- 预期主张是什么，什么观察会支持它，什么反例或替代解释会使它不成立；
- 用现有知识、代码、数据和预算，最先能验证哪个关键假设。

先查影响判断的原始论文和实现；没有直接命中不等于无人研究。区分作者开放问题、用户想法与 AI 推测。只改名字、拼接模块或更换应用场景，不自动构成研究贡献；但有明确问题、合理差异和相称证据的增量改进、边界分析或评价研究，可以按目标刊会考虑，不默认要求突破性理论或全面领先。

优先安排成本可控、能区分解释的最小验证，写清必要对照、观察指标及继续/改向条件。检查关键假设比先搭完整系统更有用。支持性结果、负结果和环境故障分别判断；调试失败不能直接证明想法无效。讨论建议不等于授权执行实验，也不代替人的选题决定。

## 4. 根据证据提醒，不等全部学完

| 当前状态 | 合适的建议 |
| --- | --- |
| 关键概念或问题边界仍模糊 | 继续针对性阅读，说明缺口；能做的小验证可并行 |
| 问题与关键假设明确，有可行验证途径，差异尚待核实 | 值得做小实验或补关键检索，暂不承诺可发表 |
| 最接近工作已核，差异有意义，验证路径和资源可行；已有初步支持或明确可执行的方案 | 建议收敛课题并开始写作，列出仍需验证的主张；相关工作、问题定义和方法草稿可先写 |
| 核心证据能支持限定后的主张，主要对照及局限已交代 | 建议完成稿件，区分必要补证与可选扩展，避免无限打磨 |
| 稿件与证据齐备 | 转入目标刊会适配及投稿核对；仍不保证录用 |

提醒至少说明“为什么是现在、最关键的剩余不确定性、下一步是什么”。基础不足不自动否决方向；证据充分也不因缺少宏大创新而无限延后写作。阶段可回退或交叉，不设固定论文数、得分线或统一月数。

## 5. 评估预计投稿时的机会

先估计必要准备、最小验证、主体实验/分析、写作修改和缓冲，注明每周可投入时间、资源可得性及已完成工作。区分工作量与日历时间，明确哪些串行、哪些可重叠；给条件化区间，材料不足时只给阶段顺序和关键未知项，不编造精确日期。可以边实验边写，不把所有阶段机械相加。

将“当前是否值得探索”和“预计投稿时贡献是否仍有意义”分别回答。判断落到具体贡献，核查最近邻工作、预印本与正式版、代码/数据可用性及相关刊会范围；记录检索日期、实际来源和覆盖缺口。热门领域不自动否决，冷门也不证明有机会。相近论文已出现时重审差异；期限受竞争影响时先验证关键点或缩小问题，不用赶时间替代证据。

可以给出窗口较宽、受竞争挤压或证据不足的判断，但须说明依据、时间假设和可能推翻判断的新进展。不预测录用概率，不把一次查重变成长期新颖性证明。给下一次复核触发点，如关键实验完成、准备立项/成稿或出现直接竞争工作；只有实际设置了授权自动化才能承诺后台监测，否则在下次相关交互时更新。

## 6. 复用记录流程，控制持久化

默认在会话中给简短路线或阶段建议；用户要求完整路线时再展开。已授权保存则执行，不重复索要许可；未授权时不自动建配置、台账或个人档案。需跨会话保存而位置不明确时，先说明拟保存内容与项目允许的位置，不擅自写全局规则或插件源码。

个人目标、阅读状态及研究判断保留在指定的私人记录中，不进入公共导读或通用技能默认值。本协议不新增配置字段或数据格式。

- 阅读与个人状态沿用 grad-radar 的脚本和授权边界。
- 要登记候选或更改选题状态时交 [idea-ledger](../../idea-ledger/SKILL.md)，保留归属与来源。
- 实际实验及主张溯源交 [run-provenance](../../run-provenance/SKILL.md)；它只登记核对，不执行实验，不把计划或作者结果记为本人实验。
- 投稿前交 [submission-gate](../../submission-gate/SKILL.md)；其未覆盖的刊会规则明确缺口，不臆造检查结果。
