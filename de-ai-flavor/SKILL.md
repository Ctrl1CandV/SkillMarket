# de-ai-flavor

把要说的事写清楚，让读者读得顺。目标是改善表达，不是消除一切所谓“AI痕迹”，也不是把所有文字改成口语或短句。

## 这里说的“AI味”是什么

这里用“AI味”指一组可观察的表达问题：话很多却没说清具体内容，普通动作写得绕口，段落反复套同一个结构，语气与用途不合，或句子之间需要读者自己补关系。人写的文字也可能有这些问题；不能据此判断文本是否由AI生成。

判断时指出具体句段及阅读上的问题，再选择改法。某个词、破折号、三项列表或正式语气本身不是问题。已经合适的表达可以保留。

| 常见问题 | 怎么看出来 | 怎么改善 |
| --- | --- | --- |
| 空泛或夸大 | 换个产品、主题也能照用；只说重要、全面、高效 | 写出材料里已有的功能、动作、原因或条件；没有依据就收窄说法，不编细节 |
| 绕口或搭配生硬 | 简单动作被名词层层包住；动宾不搭；指代不清 | 直接说谁做什么，修顺搭配，必要时拆句或补明确的对象 |
| 结构机械、反复复述 | 每段都先宣告再列三点；标题、正文、结尾说同一件事 | 按读者的问题安排内容，合并同义复述，保留独立理由与必要步骤 |
| 关系没讲清 | 短标签堆在一起；结论跳过理由；比喻比概念更难懂 | 补上必要的因果、条件与衔接，使用准确术语并按读者基础解释 |
| 语气不合场景 | 普通通知像广告，报告像演讲，按钮像口号 | 按用途调整语气；礼貌可以留，夸赞、煽情和口号不必强加 |
| 正文混入制作话语 | 页面写“本模块为新增”，文章写“以下是优化后的版本” | 成品只写读者需要的内容；修改说明放在交付说明里 |

## 从零生成

1. 从任务确定读者、用途和要传达的信息。不需要先找原作者或要求样稿；普通语气选择可以直接按场景处理。
2. 用已知内容安排顺序。通知先说事情与行动，说明讲清操作和条件，文章展开观点与理由；不默认套“背景—意义—三点—展望”。
3. 先写具体内容，再调整句子。材料少就写得相称；长稿靠解释、推导和合适的例子展开，不靠同义复述凑长度。缺少会影响结论的资料时再询问。
4. 按下方复查后交付。不要为了显得像真人，硬加经历、情绪、反问、俏皮话或故意写错。

## 修改已有文本

1. 通读，确认原意和交付要求。若提供了原稿或样稿，保留其中适合当前用途的语气、判断和表达习惯；没有这些材料时，按读者和场景写，不预设某种作者声线。
2. 找出最影响阅读的具体问题，先调整内容顺序与重复，再改句子和用词。不要只做同义词替换，也不要把空话清单合成一条空话长句。
3. 保留有用的解释、论证和例子。简洁不是缩成摘要：短标签适合按钮和表头，完整句子适合需要解释的正文与口播。
4. 对照原文复查。自然的句子不必改；不强行统一句长、标点、段落形状或个人表达。

## 表达可以变，意思别变

保留事实、数字、专名、否定、条件、证据强弱与引用归属。“可能”不能变成“会”，目标不能变成成果；不为生动补造经历、数据或产品能力。引语、代码、公式、链接和固定文案按任务要求保留，只改获准修改的自然语言。明确要求虚构时可以创作，不把虚构当事实。

## 交付前读一遍

- 读者能否顺着读懂：说的是什么，对谁有用，需要知道或做什么？
- 是否还有空泛的评价、同义复述、生硬搭配或跳过的解释？删掉后会不会损失独立信息？
- 有没有改强结论、漏掉条件，或为了“自然”加了材料没有的承诺？
- 语气、长度与格式是否适合用途？专业术语、必要限定、有效的小结和列表不必删。

默认给可直接使用的成品；用户要求审校时，再列具体问题与修改理由。不附“AI味评分”或宣称已经根除AI味。文字清楚、自然并满足任务后就停止，不再换一种模板重写。
