# 按用途选表达

写新稿与改旧稿都先看读者、载体与文体温度。有作者样稿时优先贴合样稿声线；日常简短对话回复直接用 `readable-reply`，成稿与界面文字按下表安排。

| 用途 | 读者关心什么 | 温度与结构安排 |
| --- | --- | --- |
| 文章与深度评论 | 核心主张、过硬依据、真实摩擦 | 锋利实在：从具体反差切入，靠因果链推进；长短句错落，全篇金句最多 1–2 处，无伪具体随机数字与加粗卡片 |
| 故事与人物叙事 | 现场温度、情绪起伏、核心高潮 | 鲜活滚烫：过渡事件 1–2 句快剪，把过半笔力压进 1–2 个主场景，留住烟火气与反差幽默，绝不写成均温动作流水账 |
| 邮件与通知 | 事情、行动、时间、条件 | 清爽干脆：第一句写清请谁做什么、何时截止、有何限制；保留得体称呼与原有时态 |
| 报告与研究摘要 | 发现、证据范围、局限、待决事项 | 严谨平实：分清现状、目标和已验证结果；用数据支持判断，原样保留样本量与测试范围限定 |
| 技术文档与 README | 怎么用、前置条件、预期结果、排错 | 冷静准确：按操作依赖排步骤，前提写在动作前面；保留准确术语、命令和参数，省去给技术词起模糊外号 |
| 网页与产品介绍 | 解决什么问题、怎么工作、如何开始 | 利落直观：用实际功能和使用场景说明价值，按钮直接写具体动词；混在正文里的布局与版本制作话语直接删去，文末零备注 |
| 界面提示与短标签 | 当前状态、操作对象、下一步动作 | 干脆直接：表头与按钮用简短词组；报错提示直接写明原因与恢复办法（如“文件超过 20 MB，请压缩后重传”） |
| 口播与课程讲稿 | 听得懂的完整句子、当前推演到哪一步 | 讲台现场感：写成顺口可念的完整句，补足中间推导与算例，去掉播音员设问与报幕起手；投影片放短要点，讲稿放完整解释 |
| 正式文件与规范 | 稳定准确的权责边界与执行条件 | 严密稳重：保留严谨书面语、固定层级与“应、须、可”的义务区分，在保持准确的前提下理顺长句 |

## 篇幅与节奏由内容决定

简单通知两三句话讲清即可停笔。机制推导、教学讲稿和深度分析则需要把前提、中间步骤、算例和边界展开写透。如果前后两处分别承担“先给定义”和“代入边界验算”，属于有效递进，予以保留；如果只是换几个词把同一个结论再夸一遍，直接合并。该一两句说完的段落就独立收住，不必硬凑成均匀块状。

## 温度贴合场合，反冷 AI 味也反热 AI 味

专业文本靠概念准确、逻辑紧扣体现专业，省去多层名词包装；友好沟通靠替对方省时间、说清下一步体现体贴，省去感叹号和公关辞令；故事、随笔与讲演则靠真实的人情温度、节奏涨落和核心场打动人，绝不为了显得“高级克制”而把所有文本洗成同一种 37°C 冷淡白描。

## 格式服务于阅读过程

先后步骤用编号，并列条目用列表，多维对比用表格，连续的因果、评审、说理与叙事用自然段。结构化文件（JSON、YAML、HTML、代码注释）只修改任务指定的可见自然语言文案，键名、ID、占位符与代码逻辑保持原样。
