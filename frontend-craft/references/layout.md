# 构图与布局

先让内容与任务在整屏中形成关系，再选择布局原语实现。CSS 配方、比例和间距值是可调整的起点，不能代替构图判断。已有结构成立的局部任务只处理相关关系。

## 确定同一画面中的关系

读取产品依据和真实内容，明确当前工作发生在什么对象上。用少量可执行判断确定：

- **共同可见**：用户必须同时比较或核对的内容，怎样在可用空间内保持关联？
- **连续呈现**：正文、工作画布、表格等是否应形成完整的面，哪些边界会打断它？
- **主体与支持**：主要内容需要多大空间，导航、工具与辅助材料应怎样承托它？主体可以是一段正文、一组比较对象或整张表，不必是单个大标题。
- **阅读与操作顺序**：第一眼进入哪里，随后怎样理解、判断和继续？重要性也可通过面积、对比和出现时机表达，不全部转成置顶区域。

需要新视觉方向时，按[参考选用](reference-selection.md)查看合适的完整画面；说清本次采用哪种比例、分组或阅读关系。用[范例](exemplars.md)校准整体分量，不从多个页面各摘一块拼出互不相称的容器。

## 分配空间与视觉分量

先让主要内容达到可用的阅读、比较或操作尺寸，再安排支持区域。连续正文有合适行长，比较属性可对齐，关键图形在实际尺寸下可辨。字体、行高、内容宽度与表面关系一起决定，不先定小盒子再持续缩字。

**把比例写具体，并说明依据。** 例如“宽屏阅读区以约 38em 为起点，旁注区约 16rem；空间不足时改变旁注呈现”。这些数字只说明一个方案，真实字体、长内容和窗口会决定调整。列表与详情的比例由阅读需求决定，不要求等分或固定三栏。

**用稳定基准组织整屏。** 标题、正文、工具与图像建立可感知的对齐线；同类信息使用相称的尺度与位置。有意错位可以服务作品或观看节奏，不能用无依据的小偏移替代构图。

**留白承担关系。** 它可以承托主体、分开任务、连接段落或留给后续操作。区分有用途的等待空间与未组织好的空洞；也不要为了填满屏幕添加摘要、统计或介绍。

**保留结构中的有效部分。** 只做样式精修时尊重用户明确锁定的结构；在既有信息关系内允许为字形、行高与控件体量调整必要空间。需要改变主要分区或阅读顺序时，识别为结构问题。

## 密度与节奏

密度先由阅读方式、判断所需属性、单项内容长度和操作方式决定，再结合总量、视口与输入方式选择。十几项需要快速比较的参数可以紧凑；大量文献中的每项若要阅读摘要，也可能需要多行。同一页面允许紧凑工具与舒展正文共存。

- 单行、字段稳定的桌面数据行，可以从约 36–44px 的最小行区域高度试起，这不是文字的 `line-height`；多行描述按真实内容扩展，不用此数值裁切必要文字。
- 连续阅读把正文宽度、行距和段落间距一起安排，见[中文排版](cjk-typography.md)；“阅读舒适”不意味着所有导航和按钮都加大间距。
- 作品、图文长页依据素材比例和观看顺序改变疏密；需要比较的同类内容仍保持稳定位置。

优先复用项目已有间距尺度。新建时用少量明确角色建立尺度，例如组内、组间、区域间；4、8、12、20、32、56px 可以作为一组试用值，不是必须覆盖全部间距的规范。分组需要组内与组间的差异，整页统一 `gap` 并不能自动建立节奏。

如果用户必须反复展开才能判断，或某一区持续被迫缩字、窄列换行，重新检查信息组织与空间分配。不要只增加整体留白或进一步压缩所有区域。

## 选择布局模式与原语

先选符合内容关系的模式，再组合实现方法：

| 模式 | 适用关系与调整依据 |
| --- | --- |
| 列表与详情 | 反复选择对象并阅读其详情；详情很少时可以行内展开，不因“工具页”固定增加多栏 |
| 主体与支持区 | 支持内容依附当前主体，如编辑工具或随文批注；宽度和出现时机由两者共同使用的需要决定 |
| 连续阅读面 | 论述需要连续阅读；目录、注释、宽图按实际需要进入，不把正文统一拉成全屏宽 |
| 比较集合 | 多个对象按共同依据判断；维度稳定时表格有效，长文本与图像比较需重新安排尺度 |
| 分段长页 | 各段推进主题；根据内容选择图文、引言、步骤或比较结构，不给每段同一个卡片网格 |

以下片段展示局部实现，类名仅作示例；采用时接入现有结构与 token。

**堆叠与成簇。** 前者适合顺序内容，后者适合允许自然换行的同级控件。

```css
.stack { display: flex; flex-direction: column; gap: var(--space-group, 1rem); }
.cluster { display: flex; flex-wrap: wrap; align-items: center; gap: var(--space-inline, .5rem); }
```

**主体与侧区。** 侧区约 18rem、主体最小约 60% 是这个片段的起点；只有换行后仍符合阅读顺序时才直接使用此模式。

```css
.with-sidebar { display: flex; flex-wrap: wrap; gap: var(--space-section, 2rem); }
.with-sidebar > .side { flex-basis: 18rem; flex-grow: 1; min-inline-size: 0; }
.with-sidebar > .main { flex-basis: 0; flex-grow: 999; min-inline-size: 60%; }
```

**阅读宽度。** 将字号设在正文容器上，再用相对宽度控制行长。图表可有不同宽度，不因此拉长全部正文。

```css
.reading-body {
  box-sizing: border-box;
  inline-size: 100%;
  max-inline-size: 38em;
  min-inline-size: 0;
  margin-inline: auto;
}
.reading-body img { max-inline-size: 100%; block-size: auto; }
.scroll-region { max-inline-size: 100%; overflow-x: auto; }
```

**网格与数据行。** 网格适合同类条目，最小宽度应由实际内容决定。需要列比较时使用语义表格或共享列定义，不能只凭独立行恰好对齐。窄屏重排时保留对象、表头和必要比较关系。

```css
.item-grid {
  display: grid;
  gap: var(--space-group, 1rem);
  grid-template-columns: repeat(auto-fill, minmax(min(16rem, 100%), 1fr));
}
```

## 明确滚动边界

普通阅读优先使用自然页面滚动。固定视口的工作区确需独立滚动时，明确哪块面板拥有滚动，不把所有容器一律设为 `overflow: auto`。

下面只展示“唯一视口壳 + 顶栏 + 宽屏双面板”的高度与滚动边界，不是完整应用模板。已有外层应用壳时使用其可用高度，不再次嵌套 `100dvh`；窄屏切换由实际选择状态决定。

```css
.workspace {
  display: grid;
  grid-template-rows: auto minmax(0, 1fr);
  block-size: 100dvh;
}
.workspace-main {
  display: grid;
  grid-template-columns: minmax(15rem, 22rem) minmax(0, 1fr);
  min-block-size: 0;
}
.workspace-list, .workspace-detail {
  min-inline-size: 0;
  min-block-size: 0;
  overflow: auto;
}
```

设置 `sticky` 前确认它依附的滚动容器、顶栏偏移和可用高度。长目录或长注释不能被固定区裁掉。表格、代码等确需横向滚动的内容在自己的区域中处理，检查键盘与触屏能否到达；避免把溢出扩散到整页。

## 空间变化时延续任务

以内容的最小可用空间和用户当前动作选择重排时机，不单靠设备名称套布局。

- **列表到详情**可以分步显示；保留当前选择、返回入口和列表位置。
- **核对或比较**需要保持对应关系；无法并置时，让切换保留对象、定位与必要语境，不简单把辅助材料移到长页最末。
- **支持操作**可收纳到抽屉、菜单或后续区域；入口可发现，打开后焦点和返回行为清楚。
- **窗口变宽**时，判断用户需要更多条目、每条更多内容，还是保持阅读宽度；不因有空位就新增无关面板。
- **固定操作栏**预留实际占用空间与安全区；软键盘、缩放和长内容变化不遮住当前操作或焦点。

完成后按[看图与修订](review.md)检查整屏比例、实际文字尺寸和相关操作。布局变化应体现内容与任务的关系，不能只以“没有溢出”判定完成。

## 方法来源

- [Every Layout](https://every-layout.dev/layouts/)：用可组合原语和内容约束组织布局；保留浏览器重排能力。
- [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)：借鉴关键对齐线、节奏，以及“更多条目 / 每条更多内容”的空间判断，不整体移植 IBM 的尺寸体系。
- [Android canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)：借鉴列表—详情与主体—支持区的关系区分，Web 实现按自身媒介处理。
