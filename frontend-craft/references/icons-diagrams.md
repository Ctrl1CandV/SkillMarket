# 图标与示意图

系统做得太素会像没做完，做得太花又会像活动页。这一篇讲中间那条路：给自己的对象做一套成套的图标，把形状或位置本身是信息的东西画成示意图。完整的例子见起步样例 [system](../assets/starters/system/index.html)。

## 先定语气

图形的语气跟着页面类别走，不跟着题材走。菜园、宠物、社团这些题材本身很轻松，但它们的管理系统仍然是工作系统。

| 页面 | 用什么 | 不用什么 |
| --- | --- | --- |
| 多人来用的系统、工作台、后台 | 线描图标；对象的示意图（仪器正面、地块排布、座位图） | 卡通平涂插画、表情、拟人；每张卡一种颜色的彩色图标 |
| 数据看板 | 几乎不用图标，图就是数据 | 指标卡上的装饰图标 |
| 图鉴、目录 | 对象本身：照片，或按真实特征画的示意图，标明不是照片 | 用色块或通用图标冒充藏品 |
| 活动页、落地页、面向孩子或大众的展示 | 可以用插画，主视觉最好就是内容本身 | 和内容无关、去掉也不影响的大插图 |

拿不准时问一句：这一页的人是来办事的，还是来逛的？办事的用线描和示意，逛的才考虑插画。

## 线描图标：一套，不是一堆

**画布和线。** 同一个 24×24 画布，四周各留约 2 单位；线宽 1.5 到 1.75，圆头圆角；不填色，颜色用 `currentColor` 跟着文字走。整套图标里只要有一个换了线宽或改成填色，就会被一眼看出来。

**画什么。** 每个对象取轮廓加一个能认出它的细节：番茄是圆加萼片，喷壶是壶身加长嘴，显微镜是镜筒加载物台。不要画阴影、高光和透视，也不要为了“好看”多加一笔。

**用在哪。** 图标放在导航、对象列表的行首、概览卡和状态旁边，帮人更快认出东西，不替代文字。底块用中性浅灰；只有表示状态的图块（需要处理、逾期）才用状态色。不要给每张卡换一种颜色。

**同一套里不混。** 不混用两个图标库，不把自画的和 emoji 放在一起，不让有的图标带底块、有的不带。

写法：图标放进页面开头的一个隐藏 SVG，用 `<symbol>` 定义，用 `<use>` 引用。

```html
<svg width="0" height="0" style="position:absolute" aria-hidden="true">
  <symbol id="i-can" viewBox="0 0 24 24"><g fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round">
    <path d="M5 10h9v8a1.5 1.5 0 0 1-1.5 1.5h-6A1.5 1.5 0 0 1 5 18z"/><path d="M14 12.5l4.6-3.8M7.2 10V8.6a2.3 2.3 0 0 1 4.6 0V10"/>
  </g></symbol>
</svg>
<span class="icon"><svg aria-hidden="true"><use href="#i-can"/></svg></span>喷壶
```

图标旁边已经有文字时加 `aria-hidden="true"`；只有图标的按钮，给按钮写 `aria-label`。

## 示意图：形状或位置本身是信息

有些东西，人是按样子或位置认的：地块在第几排、仪器的哪个口、座位在哪一桌、机柜的第几层。这时候画一张示意图，比表格和卡片都快。

- 按真实的排布和比例画，标上人们口头用的叫法（“B 排第 7 块”，而不是数据库编号）。
- 线细（1 像素）、底浅，状态用颜色填在格子里，同时写在文字或 `title` 里，不能只靠颜色。
- 自己的那一格用粗边框标出，不靠换颜色。
- 示意图是信息，不是装饰：它要能回答一个问题（哪块地该浇了、哪台机器空着）。回答不了，就别画。

## 看一遍

1. 把整套图标排成一行，按实际尺寸看：粗细、大小、离边距离是否一致，有没有哪个显得特别重或特别轻。
2. 放回页面整屏看：图形是在帮人认东西，还是在抢正文的注意力？整页是像工作系统，还是像活动页？
3. 去掉所有图形再看一次：页面变得更难认、更难用，说明图形有用；看不出区别，就删掉一部分。
