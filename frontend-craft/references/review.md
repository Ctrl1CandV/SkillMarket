# 看图与修订

用实际页面检查产品判断与整体设计是否成立，再处理局部缺陷。内容减少、静态检查通过或参考来源优秀，都不能替代对本次结果的判断。

## 从本次目标开始

读取当前任务、需要保留的关系，以及本次选定参考中实际要借鉴的部分。把主要产品决定定位到画面或操作：共同比较的内容是否一起出现，连续阅读是否得到空间，支持工具是否占据了不相称的分量。

参考提供质量和关系的依据，不要求像素复制。比较主次、尺度、密度、文字层级、表面与颜色分量；根据当前真实内容判断差异是否合理。没有查看参考图时，说明只依据了文字资料，不声称已完成视觉对照。

## 分三个尺度观察

| 观察尺度 | 看什么 |
| --- | --- |
| 完整视口与相邻段落 | 主体、区域比例、疏密、阅读路径、整体明暗；主体可以是一组工作对象 |
| 实际显示尺寸及必要局部 | 字形、断行、文字对比、控件、图标、边界，以及图中细节是否看得清 |
| 相关操作过程 | 加载、展开、筛选、切换和结果更新后，位置、焦点、对象关系与视觉层级是否连续 |

整页缩略图用于看整体分布，不能据此证明正文可读；局部截图用于看细节，不能据此证明构图成立。先识别已有的好关系，局部收益不以削弱主体和阅读顺序为代价。

整体重点检查：

- 第一眼的落点是否符合当前任务，随后能否自然阅读、比较或开始操作？
- 主体与支持区域的尺度、图文关系和密度是否相称，是否仍有大量元素在竞争同等注意力？
- 内容是否充分、语气是否自然，常用判断依据是否容易找到？
- 字体、颜色、素材和控件是否配合，用户认可的身份与表现是否得到保留？

## 检查范围

使用可用的浏览器或截图工具查看实际渲染。新页面查看代表性桌面与窄屏、下半部及与任务相关的关键状态；跨页工作检查对象与上下文的延续。局部修改只查受影响的区域、状态及相邻关系。

用真实或明确标注的代表性内容，包含实际会出现的长短差异、数量与素材。先解决字体未加载、缺字、错误回退和明显占位问题，再判断视觉质量。用户缩放、窄栏和长内容暴露具体风险时，定向扩展检查。

截图保存只是取证步骤；实际打开并观察后，才能声称看过画面。工具失败时尝试环境允许的替代方式，不绕过访问限制；仍不可用则明确缺口，继续完成可验证的部分。不要为一次受阻持续搭建无关演示系统。

## 用现象定位问题

下表是诊断线索，不是每次必跑的矩阵，也不预先证明病因。

| 观察到的现象 | 优先判断与修订 |
| --- | --- |
| 重点不明确或到处抢眼 | 检查当前主体、必须共同可见的内容及支持区的分量；结构成立时先调整文字、表面与动作的反差 |
| 页面整齐但平、散或空 | 检查完整内容、主次比例与阅读节奏，建立有依据的尺度差和连续面；单纯加大页名或逐段换背景未必有效 |
| 对齐了仍显碎 | 判断内容是否被过度切开，是否需要完整表面或共同基准；保留能支持主次与节奏的有意错位 |
| 正文或主要对象被挤走 | 检查页头、工具区和辅助内容的空间与出现时机；需要调整空间时，不继续缩字 |
| 清理后显得简陋 | 检查是否误删有效内容、识别元素或视觉细节；补足文字、色彩、素材和控件的配合 |
| 文字难读或层级弱 | 在实际尺寸看字形、字重、宽度、行高、对比与回退，结合[中文排版](cjk-typography.md)调整整套角色 |
| 颜色发灰、刺眼或主次混淆 | 在真实面积与相邻背景中检查角色配对，定位最影响整体的来源；避免全局增色、压淡或只轮换色相 |
| 各组件单看合理，组合却脱节 | 比较中性色、文字与图标重量、边缘和光影，指出具体不相称的关系再调整，见[视觉样式](visual-style.md) |
| 操作、选中或状态彼此覆盖 | 检查实际组合状态和各自语义，调节分量与识别手段；保留键盘、触屏与真实反馈 |
| 素材有图却没有表达作用 | 检查素材角色、观看尺寸、裁切与相关文字；图中信息不可读时考虑放大、局部查看或调整布局 |
| 展开、加载或更新时画面跳动 | 检查内容占位、滚动所有权、焦点与阅读位置；按当前意图保留上下文 |
| 窄屏可显示但任务被拆散 | 核对哪些内容需要对照，哪些可以分步；明确返回和定位，不机械地将所有侧栏下移 |
| 辅助说明仍然散乱 | 检查标签、状态与操作是否已表达含义；修正不清楚的控件及分组，再处理无用重复，见[内容编排](content.md) |

## 操作与内容的基本检查

走一遍本次涉及的主要操作，确认控件语义与可访问名称正确，焦点可见且不被固定区域遮挡，触屏入口可用。错误贴近相关输入并提供恢复途径，异步结果可感知；不要丢失用户已有输入。使用原生下拉框时也查看展开后的文字与底色。

区分未知、无数据、无匹配结果、处理中和失败，按实际发生的情况表达。保存、刷新、选择与连接语义保持真实。需要影响当前决定的条件或实质后果应及时可见，已知常规行为不因此在每个按钮旁重复说明。

跨页或面板切换后，当前对象、选择、输入和必要阅读位置应按任务延续。相同状态与动作的含义一致，区域密度和表达节奏可以不同。动态图像、展开和结果追加等本次行为，不应无故抢走阅读位置或焦点。

对比度按实际前景、背景及透明合成检查，适用范围见[视觉样式](visual-style.md)。准确内容、可读性与可操作性是底线；它们通过以后，仍需判断整体表现。

## 修订与收敛

把“普通、不舒服、不协调”改写成具体观察：哪个元素与谁不相称，影响了什么阅读或判断，准备改变哪一种关系。先修最影响整体的几处，再在相同条件下复看受影响区域。

精修保留内容语义、主要信息关系、操作行为和用户明确锁定的结构，允许字形、行高与局部空间的必要联动。主要分区或阅读路径确有问题时，按任务范围调整构图；不要只因一个局部边框问题推翻整页。

实际内容或操作结果表明主要任务、页面关系或已确认约束不成立时，修正对应产品决定。普通字体、颜色、空间和控件问题继续在前端解决，不在两个技能之间反复交接。

需要比较改动效果时，尽量保持主要任务、真实内容、视口和关键状态可比。只比较颜色则保留其他条件；整套样式或结构一起变化时如实说明变量，不把一次结果归因于某条规则。

本次关键关系成立、相关操作可用、主要缺陷已解决且没有新的具体风险时交付。不要以无依据的自评分数宣布优秀，也不默认追加候选页、完整矩阵或多轮评审。明确尚未验证的部分；证据不足与已经失败是两种不同结论。

## 交付

简述重要改变及其依据，说明实际查看的画面和操作范围，以及仍存在的具体缺口。只有执行过的内容才能写成“已检查”；构建通过、截图生成、图片实际查看与操作成功分别陈述。

日常页面交付不要求用户逐轮审批风格，也不额外生成评分报告。技能升级或用户要求独立审查时，按照对应的评估计划提供证据，不能用本文件的自检代替外部验收。
