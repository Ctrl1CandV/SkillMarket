# 看图与修订

先判断画面整体是否成立，再处理局部缺陷。可用性检查通过，并不等于页面有表现力；删掉文字也不自动等于更好看。

## 先看整体

- 第一眼的落点是否符合任务？随后能自然读下去或开始操作吗？
- 主次尺度、图文比例与疏密是否形成节奏？展示页的作品得到承托了吗，工具页的辅助区是否压过了对象和操作？
- 内容是否充分、语气是否自然？常用依据能否直接读到，还是为了干净变成一串折叠入口？
- 字体、颜色和细节是否属于这个题材？改版后，原有标识、色彩与画面气质是否被无故削弱？

精修时同时看哪些关系已经成立，先保留它们。对齐、留白或删文案的局部收益，不应以削弱主视觉和阅读顺序为代价。

## 检查到哪里

用可用的浏览器或截图工具查看实际渲染。新页面看桌面和窄屏的首屏、下半部，以及与任务有关的关键状态；局部修改只看改动和相邻区域。确认中文字体正常显示，缺字或回退异常先解决再判断排版。

先集中修复影响最大的几处，再在相同宽度与状态下复看受影响区域。出现具体新问题才扩大检查，没有新问题就交付；不把下面的诊断表变成每次必跑的测试矩阵。截图工具失败时尝试可用的替代方式，仍不可用则说明未验证部分，不持续搭建额外演示系统。

## 发现问题时查

| 问题 | 判断与修法 |
| --- | --- |
| 视线没有落点 | 先调整主要对象、图文尺度与主次比例；加大页名或增加色块未必有用 |
| 节奏平或散 | 检查段落之间的疏密与阅读路径；让变化跟随内容，不靠逐段换背景制造层次 |
| 清爽却显得简陋 | 检查是否删掉有效导语、备注或视觉细节；恢复有价值的内容与品牌关系，补足字体、色彩、表面与控件的完成度，不靠堆提示填空 |
| 对齐关系不清 | 本应一起阅读或比较的元素建立稳定基准；能突出主次、延续节奏的有意错位可以保留 |
| 首屏落空或拥挤 | 工具页减少挤走任务的页头与说明；聊天等待空间、展示页主视觉按用途判断，不能一律压缩留白 |
| 解释过量、区域过碎 | 标签和控件已表达的说明删掉；相关状态、选择与操作就近安排，并撤掉无用途的标题、容器和分隔，见[内容编排](content.md) |
| 重复操作抢眼 | 降低次要动作的权重；悬停显示同时提供键盘与触屏入口，不让每行按钮比内容更显眼 |
| 中文难读 | 检查实际字号、字重、对比与断行，不靠持续缩字塞内容；短语、长链接和字体回退按[中文排版](cjk-typography.md)处理 |
| 颜色失去主次 | 先检查真实底色上的对比、色块面积和角色；保留品牌与状态辨识，不按色相名称直接换色 |
| 素材削弱画面 | 检查分辨率、主体裁切和图文比例；素材变化与版式变化分开判断，不把占位图造成的问题归咎于布局 |
| 遮挡、窄屏拆散 | 按任务重排，固定栏留足空间；相关动作靠近对象，横向滚动限制在需要它的表格或代码容器内 |
| 开发者的话进入使用者界面 | 按主要使用者判断：实现链路、策略与开发历史留在开发文档；有用的出处、内容版本与实际限制保留，不把移出的说明全塞进帮助 |

## 操作与内容底线

走一遍本次涉及的主要操作：控件有语义与可访问名称，键盘焦点可见且不被遮挡，触屏可用；错误贴近相关输入并给出恢复方法，异步结果可感知。原生下拉框检查展开后的文字和底色。

新的收费方式、接收方、权限或不可逆后果在有关决策前可见，已知常规行为不逐按钮重复。精简文案没有改变保存、刷新、选择或连接的实际语义；保留输入和必要的失败重试。

## 怎样修、怎样交付

整体主次和阅读路径有问题时，回到构图调整；字体、色彩、素材不合适时，替换对应选择；局部缺陷局部修。不要用细节抛光回避结构问题，也不因一处缺陷推翻已成立的页面。

交付简述改动、看过的宽度与状态、尚未验证的部分。构建或静态检查不能代替视觉判断，自检不等于用户认可；无需生成额外评分报告，除非用户要求。
