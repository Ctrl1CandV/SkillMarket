# 视觉样式

把当前任务、真实内容和已认可的视觉关系组织成完整画面。字体、空间、色彩、素材与控件共同决定视觉质量；内容变少或规则通过，只说明部分问题得到处理。

## 先定整体方向

1. **找到画面的主体。** 主体可以是连续正文、一组比较对象、整个工作面或一件作品。确定哪些内容要共同可见、哪些保持连续、哪些提供支持，再安排尺度和表现力度。同一产品的不同区域可以有不同密度与节奏。
2. **继承成立的关系。** 改版先识别用户认可的标识、字体、色彩和表现方式；现有 CSS 默认值不自动成为品牌规范。把要保留的关系与本次可以调整的细节分开。
3. **选择可见的依据。** 需要建立或明显改变方向时，按[参考选用](reference-selection.md)选择与任务、内容形态和密度相近的整体参考，实际查看选中的画面。已有项目页面足以提供方向时直接复用；不为每次局部修改重新选风格。
4. **用具体关系描述选择。** 说明主要反差在哪里、哪些表面承托内容、文字之间怎样分出层级、哪些空间紧凑或展开。用实际内容检验这些选择；“专业、舒服、有高级感”不能替代它们。
5. **让构图与样式一起成立。** 字形和行高会改变体量，颜色和边界会改变区域分量。方向有实质分歧时，用相同内容做足以判断的轻量比较；方向已有依据时直接深化，不固定候选数量。

保留成熟的操作模式。品牌与展示表达可以检查题材、素材和文案是否真正影响画面；工具与阅读界面检查真实对象、判断依据和工作关系是否影响组织。换个产品名称仍然适用的控件或布局，不因此成为缺陷。

从内容本身建立气质：比较任务通过对齐和差异呈现，证据核对通过引用与定位关系，长文通过章节和图文节奏，作品通过比例和观看顺序。标识、纹理、插画、边框和动效也可以建立氛围，不要求每一笔增加业务信息；它们的分量应与主要内容相称。

## 样式精修的范围

保留内容语义、主要信息关系、操作行为和用户明确锁定的结构。为实现选定的文字层级与控件分量，允许联动调整字形、字重、行高、局部间距和必要尺寸；复查断行、内容高度与相邻区域。

如果主要分区或阅读顺序必须改变才能解决问题，明确识别为结构调整，按当前授权范围处理。不要把模型自己的“布局已定”假设当成用户要求，也不要借精修扩展为无关的导航或流程重构。

## 字体与文字层级

按用途共同确定字形、字号、字重、行高、字距与可用宽度，再看它们在一屏中的关系：

| 文字角色 | 共同判断 |
| --- | --- |
| 对象标题、章节标题 | 怎样帮助识别与定位；与正文、图片和工具区形成什么尺度差 |
| 连续正文 | 实际字形、行长、行距与段落节奏是否支持持续阅读 |
| 列表条目与判断属性 | 用户是在认对象、找字段还是比较值；相应信息获得合适分量 |
| 导航、按钮、输入与状态 | 与操作频率和控件尺寸相称；辅助地位仍然清楚可读 |
| 数字、代码、引用标记 | 需要成列比较时使用等宽数字或合适字形；独立展示按用途选择 |

一款字体配合适当字重可以成立；两款字体应有清楚分工。不要为了风格数量增加字族。用真实中文、英文、数字和相邻图标检查笔画、基线、回退与光学重量；相同 CSS 字重不保证视觉上一样重。

正文与工具文字可以采用不同密度。具体尺寸从实际字形、内容和阅读条件出发，结合[中文排版](cjk-typography.md)的起点调整。某一区持续依赖缩字才能容纳内容时，回到空间分配和内容呈现判断。

需要观察成套文字、表面与控件的配合时，查看[候选样式样张](style-samples.md)，不要把单独字号或一组色值当成完整设计。

## 颜色：先整体承载，再局部配对

先看页面底、内容表面与素材共同形成的明暗和色调，再安排正文、辅助文字、主要操作、选中和状态。复用项目已有 token 的语义；具体值可以随本次问题调整，不为完整性预建所有角色。

**中性色参与搭配。** 背景、文字与边界可以保持中性、带共同色调，也可以有意形成冷暖差异。检查组件之间无依据的脱节；图片或彩色标签丰富时，注意带色底与它们的邻接关系。修正局部冲突不等于将全页去色。

**比较有意义的差异。** 独立新方向缺少约束时，观察底调、明暗、色彩面积和表面层级不同的组合。只轮换按钮色、其余关系完全相同，不能说明已经探索了不同整体方向。同一产品继续保持身份连贯，局部修复不为求新换色。

可用的成套起点见[配色方向与模板](color-directions.md)和[样式样张](style-samples.md)。需要更多选择时，可扩展整体明暗与表面关系，也可提供同体系的配色变体；明确变化的是哪一层，避免把“保持结构”误解为“只能沿用原色”。这些是候选方案，需在当前内容中检查；行业名称不直接决定色相，参考网站的颜色也不自动适合移植后的画面。

| 角色 | 一起确定什么 |
| --- | --- |
| 正文与辅助文字 | 各自与内容表面的对比，彼此的轻重；辅助文字退后但仍须可读 |
| 主要操作 | 填充、前景及相关悬停和按下状态；明亮底色可能需要深色文字 |
| 选中项 | 底、文字、标记与周围条目的区别；持续选中与瞬时主操作各有合适分量 |
| 链接与焦点 | 在实际表面上的辨识，与正文、选中和状态的区别；需要时配合下划线或轮廓 |
| 彩色品牌区域 | 主次文字、图标与彩底的关系；检查冷暖、明暗和透明叠加，不强制所有灰都染色 |
| 语义状态与数据 | 含义稳定、必要差异可辨，并以文字、形状或纹理补充颜色 |

**用面积和强度安排主次。** 同色铺满背景与用于小图标，视觉分量不同。检查标签、边框和装饰是否消耗了主要内容或操作的辨识力，素材是否已经贡献丰富颜色。工具可以使用鲜明大色面，阅读区也可以形成明确反差；不按固定颜色比例或色块数量限额设计。

**色阶和透明需要落到实际配对。** 派生色可用 OKLCH 分别调明度、色度与色相；用途决定变化，不追求机械等步长。透明层在实际背景上合成后检查；跨背景失稳时使用明确颜色。调整成熟色阶后重新检查，不能沿用原先的对比保证。

**可见性与美观分别判断。** 按 WCAG 2.2 的适用条件，普通文字与背景至少 4.5:1，大字至少 3:1；识别控件和状态所必需的边界或图形与相邻色至少 3:1。正确处理标识、装饰和不活动控件等例外，不把所有分隔线加重。阈值通过不证明配色协调。

深色主题在任务涉及时单独安排表面、文字、边界与强调。根据实际关系调整明度与色度，不机械反转浅色，也不默认所有强调都更亮。

## 表面、边界与控件

- **表面表达层级。** 页面底、内容面、嵌入区和浮层按实际需要区分；同等地位具有相称分量，较重处理对应主次或层级。不要仅为了展示 token 而增加容器。
- **边界采用清楚的主要手段。** 底色、边线、投影和高光可以配合，但不必同时强烈突出。需要明确范围或材质时保留有效组合；内外圆角与内距、轮廓相衔接，不要求数值相同。
- **光影属于整体表达。** 方向、软硬和强度支持所选材质与不同层级。纹理、渐变和模糊可以承托氛围，放回整页判断其分量。
- **文字与图标一起看。** 延续项目图标语言，在实际尺寸下协调笔画、端点、光学大小与对齐。允许不同形状作必要微调，不把相同 CSS 数值当成视觉一致。
- **熟悉的控件表达熟悉的行为。** 样式变化保留可辨的交互范围、状态与反馈。编号、日期和 ID 只有在成列比较等场景下才需要统一为等宽数字。

多种控件共同出现时，把字段、说明、状态和动作组作为完整区域看待；同类控件建立一致尺度，不同角色保留主次。分组与操作范围仍散乱时，先按[局部界面组织](local-interfaces.md)调整关系，再精修表面。

## 素材与图形

先判断素材承担的作用，再决定尺寸、邻接文字和观看方式：

| 素材作用 | 呈现重点 |
| --- | --- |
| 用户要看的对象 | 保留有意义的形态、比例与观看顺序；作品可以主导构图 |
| 证据或实际结果 | 保留语义、来源与必要标注；缩小后仍能判断，必要时提供放大或局部查看 |
| 解释关系 | 让图形表达真实的结构、过程或差异，并与对应文字相连 |
| 品牌或氛围 | 与题材、色彩和文字分量协调，明确它如何承托整体表达 |

用实际素材检查分辨率、主体位置、裁切与色调。科研图、代码截图或信息图即使像素足够，缩进页面后也可能失去可读性；作品关键部分不为统一卡片而被切掉。复用已有图题、图例与正文解释，仅补理解需要的信息。

素材不足时区分当前可以成立的部分与尚未成立的视觉目标。占位图不证明最终视觉质量；不要编造实物、数据或来源来填满画面，也不擅自替换用户认可的素材。

## 变化中的界面

按本次涉及的行为，安排默认、悬停、按下、焦点、选中、处理中、成功和失败的关系。检查实际出现的组合，例如选中项仍有键盘焦点、保存中仍需显示已有选择；多个状态可以叠加，但语义与层级应清楚。

- 加载图片、字体和异步内容时，尽量保持主要阅读区域与操作位置稳定。
- 展开、筛选、面板切换和结果追加后，让用户辨认变化位置，按操作目的延续焦点和阅读位置。
- 流式或持续更新内容遵循用户当前的阅读意图；用户在查看上文时，不无故把视口拉走。
- 动效可以解释展开、移动和反馈，也可有适度的表现性；频繁操作保持直接响应，提供适用的减少动态效果处理。
- 静态精修不因此增加无关动效。只检查本次实际存在的行为，不制造一套无业务含义的状态面板。

实现后按[看图与修订](review.md)在完整视口、实际显示尺寸和相关操作过程中检查。

## 方法依据

- [Impeccable 的页面目的与上下文](https://impeccable.style/docs/context/)：按具体页面与区域的用途判断，保留通用操作模式；不整体搬用它的工作流。
- [Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/style-strategies)：文字尺度与当前任务共同决定，同一产品可以有不同表达节奏。
- [Radix 色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)与[色板组合](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette)：用途与前景背景共同选择，不能直接移植配对保证。
- WCAG 2.2 [文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)与[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)：适用条件与可见性底线。
- [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)：借鉴焦点、异步反馈、滚动位置与变化中的稳定性，按项目条件采用。

这些资料提供方法与起点；本技能的候选样张及本次实现效果，需要各自的实际查看证据。
