# 视觉样式：字体、色彩、素材与细节

结构成立后，样式把主次变成看得见的画面。样式强化内容关系，不是装饰填空；克制不等于单调，丰富不等于堆砌。样式问题不靠返回布局解决，先查角色和档位是否明确。

## 字体角色

- 为标题、正文、元数据、数字/代码、控件指定角色：各用什么字族与字重、多大字号、如何与背景区分。一个清楚的角色系统可以只靠一款字族加字重完成，两种字体角色也不等于必须下载两款字体。
- 用同一组真实内容做小样张再决定：最长中文标题、中英混排、正文段落、成串数字与按钮文字同屏比较字面大小、黑度、行宽与换行。系统栈可以是好选择，但应是看过样张后的选择，不是没比较过的默认。
- 声明的 font-family 不等于实际加载的字体：核查中文覆盖、字重是否存在、载入失败时的后备效果与许可。单独替换一款拉丁展示字体未必改变中文页面的气质。
- 层级靠字号、字重、颜色与间距共同形成；不靠堆数量。

## 色彩的角色与面积

- 先定功能色：文本与背景的层级色（主文、次文、元数据、边界）、语义色（错误、成功、选中、链接）、一个主强调色；装饰色最后考虑。
- 强调色靠面积对比指向当前任务：大面积中性底色上的小面积强调最醒目；强调色到处都是等于没有重点。给出大致面积关系即可，不设固定配额。
- 对比在真实底色上计算：正文按 WCAG AA 4.5:1、大字 3:1；控件边界与状态信息通常 3:1。hover、焦点、禁用各自核对，不只算默认颜色。
- 深浅主题各自成体系，不是简单反转；语义色与强调色在两种主题下都要重新核对。
- 灰度检查用来确认层级不依赖颜色，是辅助手段不是通关标准；图表与状态仍需非颜色线索，不为灰度牺牲必要语义。

## 素材的角色

- 先问这张图、图表或图形承担什么信息或情绪；没有正当角色就不用素材，也不用普通图库图填洞。纯排版同样是完整答案，可以很有表现力。
- 候选按最终尺寸试放再决定：主体清楚、留白合适、裁切讲究、清晰度与风格同页一致，手机裁切不丢主体；不合适就淘汰，不为填空降级。
- 图表、图像、原创图解按内容选择，关键素材在结构阶段预留位置。图标成套使用、线重一致、与文字基线对齐。

## 细节一致性

- 边框、圆角、阴影、间距、图标基线各用少量档位并全局一致；档位数得出来，通常说明体系立住了。
- 同一元素在默认、hover、焦点、禁用等状态的变化有规律，不是逐处临场决定。
- 局部细节偏差局部修；多处细节共同松散往往说明字体或色彩角色没立住，回角色与档位，不为流程完整强制来回。

## 自检问句

- 强调色的面积落在当前任务上了吗？
- 字体样张的气质放到真实页面还成立吗？标题、正文、元数据拉得开吗？
- 素材拿掉后信息是否仍完整？加上后是否明显更好？
- 全页的圆角、边框、阴影有没有一处是例外的档位？
