# 视觉样式

## 判断起点

第一眼的偏好研究可以帮助检查复杂度和熟悉感，不能直接推导出所有界面的色度、色相或留白配方。先按目标用户、任务和素材判断，再用实际画面与反馈校准。

- **层次来自关系。** 对齐、比例、组间距、字体角色共同区分主要内容和辅助信息；减少重复后仍要有视觉主角，不能只剩一屏相同的灰字。
- **熟悉感服务操作。** 工具的控件与导航遵循惯例，阅读页保护正文，作品展示让作品当主角。个性可以来自排版、色彩、图形和素材，不必重造操作方式。
- **丰富程度符合题材。** 标识、插画、纹理、边框、色块和动效可以建立识别、氛围与完成度，不要求它们增加业务信息。判断它们是否协调、是否抢走主角、是否影响阅读；聊天的等待空间与内容丰富的展示页都可以成立。

## 方向：先决定画面怎样成立

- **先看成功标准**：工具让用户完成操作，阅读页帮助理解，落地页支持选择，作品页呈现作品的气质。密度跟随内容量与使用频率，个人工具不必像企业后台一样紧凑。
- **继承已有视觉身份。** 改版先看标识、字体、主色与细节的组合，保留用户认可的部分。结构精简与品牌换新是两个决定；不能顺手把已有标识换成纯文字、把特色色彩换成默认色板。
- **从主题找特色。** 如阅读产品的书页标识、展览的纸张质感、数据工具的状态符号。它可以帮助识别、建立氛围或理解内容；没有合适图形时，用字体、比例与配色完成设计。
- **把方向落实为画面关系。** “精致、现代、有高级感”不足以指导实现。新建时定下视觉主角、阅读路径、图文尺度与疏密，字体参与构图。内容和布局已成立时，明确要改善的样式关系：哪块表面承托文字、主要反差落在哪里、选中与主要动作怎样区别、光影如何表达层级。理由留在开发记录中，页面不增加设计说明。
- **构图方向开放时作一次轻量比较。** 同样内容可以由大作品带入，也可以由标题与多幅作品共同构图；比较尺度、图文关系和阅读路径，仅换颜色不足以比较构图。纯样式任务可以保留骨架，只调整颜色、字形与材质；已有明确方向或局部修复直接继承，不默认制作双份 demo 或等待额外审批。
- **让突出有集中点。** 展示页可以用有分量的标题、作品裁切、色块或有意错位建立记忆点，其余部分承托它。工具也可以有鲜明的品牌和精细的控件，主要工作区仍易读易操作。若换个产品名也完全成立，检查是否只是套了默认模板；不为追求不同破坏熟悉的操作。

## 字体

- **角色**：标题、正文、界面文字、数字与编号，各定一种处理方式。一款黑体配几个字重往往就够了；宋体等衬线体适合正文阅读和需要书卷气的标题；等宽字体适合编号、时间码和代码。
- **尺度随页面类型变化**：
  - 数据密集的管理页：界面文字 13–14px，表格行高 36–44px。
  - 十几到几十条的个人列表：条目标题 15–17px。
  - 阅读页：正文 16–18px。
  - 展示页：标题可以很大。
- **让层级一眼可见**：展示标题可以承担主视觉；工具页主要对象和动作应突出，不必把页名做成海报。
- **看实际字形的分量**：用真实中文、英文、数字和相邻控件检查笔画轻重、基线与回退；相同 `font-weight` 不保证看起来一样重。标题与正文可以有意对比，同级标签不应因字体来源不同而意外抢眼。调整字体后复查行数、控件高度和窄屏断行。
- 上述字号是起点；手机、长中文和实际字体要重新看，不能为塞进屏幕持续缩字。
- 中文字体的细节见[中文排版](cjk-typography.md)。

## 颜色

**先看承载关系，再定局部配对。** 整页配色先看页面底、内容表面与素材的整体色调，再安排文字、主要操作、选中和细节；局部问题直接检查该元素与相邻背景。保留用户认可的视觉身份，复用已有 token 的角色；具体取值可随待解决的问题调整。新方向从题材、素材和使用环境取色，不默认降低饱和度或套行业色板。

**中性色也参与搭配。** 背景、表面、文字与边界可保持中性、带共同色调，也可有意形成冷暖对比。检查的是组件各用一套灰造成的意外脱节，不能仅因冷暖不同就统一。彩色标签或图片很多时，过强的带色底可能干扰它们，先调整底调及邻接关系，不把全页一起去色。

**方向开放时，别沿用上一页的配色惯性。** 新建独立项目或用户要求更多风格时，简短比较底调、明暗与主色面积不同的搭配，结合内容和素材选定一种。若独立方案只换强调色、底调和表面仍高度相似，检查是否沿用了与题材无关的惯性；同样的组合适合内容时可以保留。同一产品的页面继续保持身份连贯，局部精修不为求新而换色。

下面是可调整的**假设搭配起点**，不是观察过的正例、固定色板或按行业分配的答案。仅在方向未定时参考；色值和对比须放回实际画面确定。

| 搭配方向 | 颜色怎样分工 | 字形与表面怎样衔接 |
| --- | --- | --- |
| 冷白与钴蓝 | 冷白承托正文、近黑作文字，钴蓝承担主操作或品牌面；选中用浅蓝与明确标记，避免和实色动作同重 | 清楚的黑体层级、利落边线与平整表面；大块蓝底另配可读前景 |
| 墨色与冰青 | 墨色背景配稍亮的内容面，灰白正文、冰青动作配深字；选中可用青色边缘或局部底，避免整片发亮 | 有分量的标题与克制的控件边缘；光泽或辉光集中在视觉主角，普通面板靠明度分层 |
| 浅粉与莓红 | 浅粉或中性白承托内容，深莓色文字与重点，主操作用莓红实底配浅字；图片里的颜色仍按自身层次保留 | 标题可用有性格的衬线或黑体，正文保持清楚；柔和色面也能配锐利边界，不必同时变圆变软 |
| 明黄与墨紫 | 明黄可承担品牌大面，墨紫文字形成反差；连续阅读区可用浅色表面，选中用标记区分，别把所有标签染成品牌色 | 大字、图形与实色边缘可形成鲜明节奏；控制强反差的位置，不给每个区域都加粗描边 |

**重要角色成对选择。** 按当前页面实际用到的角色处理，复用已有命名与组件，不为完整性预建整套 token：

| 用途 | 一起确定什么 |
| --- | --- |
| 正文与次级文字 | 各自与内容表面的对比、彼此的轻重；次级文字通过适当对比和字重退后，仍须可读 |
| 主要操作 | 填充与前景，以及本次涉及的悬停、按下状态；明亮底色可能需要深字，不能只换底色、全部套白字 |
| 选中项 | 底、文字与标记相对周围条目的辨识度；持续选中若压过主要动作，可用相关浅底加清楚标记，也可保留符合品牌的实色表达 |
| 链接与焦点 | 在实际表面上的辨识，及与普通文字、选中的区别；按用途配合下划线、轮廓等，不要求每个角色另用一种色相 |
| 彩色品牌区域 | 主次文字、图标与彩底的关系；弱文字显脏或脱节时检查冷暖、明暗和透明叠加，可改用与前景或底色相关的颜色，不强制所有灰染色 |

**用面积和强度安排主次。** 同一颜色铺满背景与用于一个图标，分量不同；许多小强调也会分散注意。看主要动作是否被标签、装饰耗尽识别力，图片是否已贡献丰富颜色，再调整相关角色。工具可保留鲜明的大色面，展示可用品牌色或深色承托作品；不按固定颜色比例或色块数量限额处理。

- **语义与数据**：成功、警告、错误按项目惯例保持含义，和品牌色共存时仍须可辨识；用文字、形状或纹理补充颜色。数据系列保持必要区分，不为统一而混成近色。
- **色阶与透明**：需要派生色时可用 OKLCH 分别调明度、色度与色相；近白、近黑端按用途调色度，不追求等步长或固定级数。透明层在实际底色上合成后检查，跨背景失稳时改用明确颜色。调整现有色阶后重新核对配对，不能继承原色阶的对比承诺。
- **对比度**：在实际前景与底色上计算。普通文字至少 4.5:1，大字至少 3:1；识别控件和状态所必需的边界或图形，与相邻色至少 3:1。按 WCAG 的适用条件处理装饰、标识和不活动控件，不把所有分隔线都加重；通过阈值只证明相应可见性要求，不证明搭配好看。
- **深色主题**：任务涉及时单独安排表面层级、文字、边界与强调，按实际组合调整明度和色度；不机械反转亮色，也不默认所有强调色都提亮。

## 素材与图形

- **让素材进入构图决策**：先看清晰度、比例、主体位置和色调，再定尺寸与裁切。作品的关键部分不为塞进统一卡片而被切掉；多幅作品按观看顺序安排，不默认等尺寸平铺。
- **按用途选图形**：数据图回答问题，标识帮助识别，插画与材质可以营造氛围。选用与主题相称的图形，不把临时占位图当成最终视觉质量的证据，也不擅自替换用户认可的作品。

## 表面、控件与细节

- **先分清已有表面的层级**：页面底、内容表面、嵌入区与浮层按实际需要区分，不因此新增容器。同层且同等重要的元素应有相称的视觉重量；更重的处理应对应主次、层级或有意的表现，不让普通面板因重投影意外像浮层。
- **边界有主要手段**：底色、边线、投影和高光可以配合，但同一边界不必全部强烈突出。显得厚重时先减弱重复强调；需要明确操作范围或材质时保留有效组合。嵌套圆角按形体、内距与轮廓衔接调整，内外不必数值相同。
- **光影延续所选材质**：检查方向、软硬与强度是否支持同一种表达及不同层级，不要求所有组件共用一个阴影值。纹理、渐变、模糊与高光可承托品牌和氛围；局部处理放回整页判断，不自动给每张卡片加效果。
- **图标与文字一起看**：沿用项目图标语言，在实际尺寸下协调笔画、端点、光学大小与对齐；不同形状可微调尺寸和线宽，不把相同 CSS 数值当成视觉一致。字体笔画、控件边缘与投影共同决定轻重，不套“细字必须配细边框”等配方。
- **相关状态延续同一逻辑**：本次涉及的悬停、按下、焦点、选中、错误和处理中与默认态一起配色和定边缘，保持语义可辨，不为柔和削弱反馈。已有动效的速度与幅度应支持同一手感，静态精修不因此新增动画。
- **编号、日期、ID**：需要成列比较时用等宽字体或 `tabular-nums`，独立展示按字形与页面气质选择。

- WCAG 2.2 [文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)：适用条件与可见性底线。

- 历史研究背景包括 Reinecke & Gajos（CHI 2014）、Tuch 等（IJHCS 2012）、Palmer & Schloss（PNAS 2010）、Schloss & Palmer（2011）与 O'Donovan 等（SIGGRAPH 2011）。它们研究的对象、任务和偏好指标不同，不据此设通用色相禁令或 CSS 数值。
