# 中文排版

让字形、尺度、行长与空间共同形成文字层级。先选适合当前任务的文字系统，再处理回退、混排和断行；技术属性正确不自动等于整页好读或好看。

## 先看同一画面里的文字角色

按实际需要安排对象标题、章节标题、正文、列表条目、元信息、控件和数字。它们可以共享字族，通过字重、字号、宽度与间距形成层级；不必每一级换一种字体。

在同一张真实内容样张中共同判断：

| 角色 | 重点观察 |
| --- | --- |
| 当前对象与章节标题 | 能否定位内容，体量是否与主体相称，真实长标题如何断行 |
| 连续正文 | 字形、行长、行距与段落节奏是否支持持续阅读 |
| 条目与元信息 | 对象及关键差异是否可扫读；次级信息退后但仍清楚 |
| 导航、按钮、输入和状态 | 与图标、边界和点击区域的分量是否协调；不套正文的长行距 |
| 数字、英文、引文与标记 | 基线、大小、字重和间距是否与中文相称，含义能否辨认 |

使用[样式样张](style-samples.md)或当前项目的代表性页面检查这些关系。样张是起点，不能用短英文标题的效果证明长中文也成立。工具区可以紧凑，正文可以舒展；同一任务内部保持连贯。

## 字体候选与实际可用性

以下是常见候选，不是安装保证。系统版本、语言资源、可选字体包、发行版和应用环境都会改变可用性；依据实际渲染与目标环境判断。

| 环境 | 常见候选与注意点 |
| --- | --- |
| Windows | Microsoft YaHei、SimSun；DengXian、KaiTi、FangSong 等还可能依赖可选语言字体包 |
| macOS / iOS | PingFang SC、Songti SC 等；具体供应与字重以系统版本和字体资源为准 |
| Android | 系统中文回退常见 Noto CJK 系列，厂商配置可能不同；不要假定某个 CSS 字族名必然可用 |
| Linux | 已安装的 Noto Sans CJK SC、Noto Serif CJK SC 等；依赖发行版与实际软件包 |

保留合理回退。例如以下是一组候选栈，按项目字体和目标环境调整：

```css
--font-ui: "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", sans-serif;
--font-reading: "Songti SC", "Noto Serif CJK SC", "Noto Serif SC", SimSun, serif;
```

拉丁字体放在中文候选前，可以让它优先处理所覆盖的字形；检查中文回退后两种字形的大小、基线与分量，不把 CSS 中相同的 `font-weight` 当成相同的视觉重量。

**区分真实字面与合成效果。** 字族缺少所需粗字重或倾斜字面时，浏览器可能回退、匹配其他字面或合成。需要明显粗细变化的标题，优先选具有相应字面的字体；SimSun 等单字重候选不能承担已验证的多字重承诺。宋体可以用于阅读，但实际效果取决于字号、显示与渲染条件，不保证所有平台表现一致。

**按需加载网页字体。** 先确认字体覆盖、许可和目标环境的可访问性。中文字体可采用适当子集或 `unicode-range` 分片；标题专用子集不能冒充覆盖动态正文的完整字体。检查字体尚未到达、加载完成及失败回退时的断行与控件体量，不为特定字形牺牲基本可读性。

## 连续正文

以下只作为连续中文阅读的起点：字号约 16–18px，行高约 1.7–1.9，每行约 30–40 个汉字。相对宽度设置在正文自身的字号基础上，实际行长受字体、标点与混排影响；手机与不同窗口按可用宽度调整，不保持不可缩小的固定宽度。

- 将字号、行高、行长一起看。行变长时需要重新判断行距；图表、公式与长英文进入后，检查阅读节奏，不机械套用数值。
- 段间距或首行缩进可以表达分段，选择适合内容与版式的主要手段；避免无理由叠加过强间距和缩进。
- 默认使用 `text-align: start`。需要两端对齐时，检查真实中文、英文和链接在窄栏中的字距，不让个别行被拉得过散。
- 标题的尺度与字重由层级和字形决定。600–700 可作部分黑体标题的试用范围，不能替代实际观察，也不要求所有标题都粗到同一范围。
- 大字号中文标题显得松散时，可从约 −0.01 到 −0.02em 的字距微调；保留真实断行和字形可读性。小文字不套同样的收紧处理。

正文宽度与辅助区的关系见[构图与布局](layout.md)。宽图、表格或公式可以使用独立的可用空间，不因此把全部正文一并拉长或缩小。

## 中英混排与强调

**混排间距。** 保留材料已有的合理空格。需要自动间距时可以将 `text-autospace: normal` 作为渐进增强；核对目标浏览器的支持与实际默认行为，不把“支持属性”当成“默认启用”。不批量改写代码、URL 和标识符中的字符。

**标点和名称。** 中文句子使用适合中文语境的标点，完整英文句子内部保留其排版；专有名词采用官方写法。原文、代码、公式与引用中的字符保持准确，不能为视觉统一改变含义。

**中文强调。** 常见中文字体通常缺少独立倾斜字面，不默认依赖合成倾斜来强调中文。可用相称的字重、着重号或颜色；实际字体提供相应字面时，按真实字形判断。必要含义不能只靠颜色表达。英文书名或论文名是否斜体，遵循内容规范与上下文。

```css
.emphasis-dot {
  font-style: normal;
  text-emphasis: filled dot;
  text-emphasis-position: under right;
}
```

**数字与代码。** 成列比较的数字可用 `font-variant-numeric: tabular-nums`；编号、时间码或代码可使用合适等宽字体。独立数字按页面角色选择，不要求所有元信息都等宽。公式交由项目已有数学呈现方式处理，保留符号与来源含义。

## 断行与标点

- `line-break: strict` 可用于需要更严格禁则的中文排版，检查目标浏览器和实际标点组合。不能靠它修复容器过窄或整体不可换行的问题。
- 短标题可使用 `text-wrap: balance` 改善断行；正文可考虑 `text-wrap: pretty`。它们是渐进增强，不保证消除孤字，支持和行为按目标浏览器核对。
- 日期、金额或章节号等短语确需保持完整时，可局部使用 `white-space: nowrap`；先确认短语在窄屏能容纳，不把整条长标签都禁止换行。
- 长 URL、哈希等可用 `overflow-wrap: anywhere` 保护布局。普通英文保留自然词界；`word-break: break-all` 只在明确允许任意拆分的局部内容中考虑。
- 代码块、长表格等使用自己的溢出区域；保留可操作的滚动与上下文，不用整页横向溢出解决。
- 连续标点的挤压受字体和浏览器影响。`text-spacing-trim` 的支持按目标环境核对；先看真实样本，再决定是否启用，不把实验性效果作为基本可读性的前提。

## 实现后检查

先看完整视口里的文字层级，再以实际显示尺寸看正文、控件和混排。确认字体确实按预期显示后再判断气质；只看字体栈名称或页面缩略图不足以确认字形效果。

用本次内容中的长标题、普通段落、数字、链接及必要符号检查。字体替换、窗口缩放和关键加载状态后，确认断行、控件高度、焦点与阅读位置没有被意外破坏。发现问题时联动调整字形、宽度与空间，不只持续缩字。

## 方法来源

- W3C [中文排版需求](https://www.w3.org/TR/clreq/)：借鉴字体、版心、混排、断行与标点的关系；作为排版资料，不将书刊数值直接规定为网页标准。
- W3C [中文系统字体映射资料](https://w3c.github.io/clreq/others/system-font-mappings.html)：区分内置、可选和依赖软件包的字体供应。
- W3C [CSS Fonts](https://www.w3.org/TR/css-fonts-4/#font-style-prop)：区分实际字面与合成字面；具体特性以目标浏览器支持为准。
- [Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/style-strategies)：借鉴按任务组织文字角色和表达强度，不移植其字族与 token 数值。
- MDN：[text-autospace](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-autospace)、[text-spacing-trim](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-spacing-trim)、[text-wrap](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap)：查询目标浏览器条件，不把文档中的支持状态永久写成技能结论。
