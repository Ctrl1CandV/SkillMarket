# Frontend craft

让内容、构图、样式与操作共同成立。用户的任务决定哪些关系需要被看见；字体、空间、颜色、图形和交互让这些关系成为完整画面。清晰、丰富、安静与鲜明都可以合适，文字少、容器少或风格陌生都不是独立的质量目标。

## 确定本次范围

先读用户要求、真实内容、现有界面和项目约定。识别当前对象、要完成的判断或操作、需要共同可见的内容、已认可的视觉关系与允许调整的范围。沿用仍有效的决定，核对已否定方案及原因，避免在下一次精修中无依据地恢复。当前用户要求优先于项目默认；已认可的品牌与行为优先于本技能起点，偶然形成的 CSS 不自动成为品牌。

新建平台、调整核心流程或跨页关系，且依据不足时，使用宿主可用的 product-design；已有依据足够则继续设计。按变化实质判断，一页也可能改变核心流程，多页换主题也可能只需样式工作。无需两个 Agent、固定安装路径或重复交接包。

区分结构工作与样式精修。精修保留内容语义、主要信息关系、交互行为和用户明确锁定的结构；允许字形、字号、行高、局部间距与必要尺寸联动。若问题必须靠改变主要分区或阅读顺序解决，说明这属于结构调整，并在本次授权范围内处理。仅评审或出方案时交付相应结果。

卡片、侧栏、窗口或页面内区域也可能需要局部结构重排：改变分组、顺序、显隐和操作组织，保留外层已成立的关系。已有任务依据足够时直接在本技能内处理，不因功能较多就重新启动产品设计流程。

## 工作过程

### 1. 把任务变成当前画面的取舍

复用已有产品依据，只留下会改变本次页面的判断：主要对象是什么，哪些信息支持判断，什么需要同时可见，什么在相关状态出现，怎样算完成。重点可以是一段正文、一组比较对象或整张表，不必是大标题或按钮。

尽早使用真实或脱敏内容。缺少数据时，用符合实际长度、数量、差异和状态的样本并标明用途。决定内容之间的关系，再决定读法和容器；不要把功能清单逐项变成首页模块，也不要为整齐缩短全部标题或删掉必要依据。

同一区域有多类信息、多项功能，出现入口混杂、分组散乱或内容互相挤占时，读[局部界面组织](references/local-interfaces.md)。先梳理判断、动作、依赖与状态，再把它们组织成完整画面；一般内容取舍见[内容编排](references/content.md)。

### 2. 选择并查看适用的参考

需要新建或明显改变视觉方向时，先读[参考选用](references/reference-selection.md)，再从[范例索引](references/exemplars.md)按任务、内容形态和实际密度选择。已有项目方向成立时，可以直接把项目中的认可页面作为整体参照。

用可用的图像或浏览器能力实际查看选中的画面；文件路径、网页链接和文字说明不等于已经看图。先建立一个连贯的整体依据，必要时补局部参考。简短说明继承什么关系、调整什么条件；无需每次让用户选择风格，也不默认制作多套完整方案。

记录中的候选、方法参考与已核验画面保持区别。缺少图片时可依据配套说明继续工作，但不能声称已视觉核对。原创[样式样张](references/style-samples.md)提供可调整的实现起点，不代表外部成功案例或已验证的最佳答案。

需要更多配色选择、现有页面总落到相近色调，或需要可复制的搭配模板时，读[配色方向与模板](references/color-directions.md)。可复用整体方向，也可在成立的体系内选配色变体；用当前内容检查，保留用户的品牌与结构。

### 3. 联合决定构图与样式

先让主要内容达到可用的阅读、观看或比较尺寸，再分配导航与支持区域。决定共同可见关系、连续面、主次比例、疏密变化和滚动归属，再选择布局原语实现。数值写成有内容依据的起点，真实内容持续逼迫缩字或过度换行时回到空间分配。

在同一画面中决定文字角色、主要明暗、表面层级、强调用途、素材与边缘处理。配色同时考虑底调、邻接、面积和状态，不能只换一个按钮颜色。工具与阅读界面的完成度可以来自稳定的秩序和精细的关系；品牌展示可有更强表达，熟悉的操作仍保持熟悉。

具体取舍见[构图与布局](references/layout.md)、[视觉样式](references/visual-style.md)；中文内容结合[中文排版](references/cjk-typography.md)。实际方向分歧影响选择时，用相同内容作最小必要比较，方案数量由分歧决定。

### 4. 用代表性内容落实，再完成范围

在目标工程中先完成能体现关键关系的页面或工作状态，并兑现前面的产品决定。让长内容、图表、真实数量与相关操作进入设计；素材不足时明确缺口，不能用占位素材证明视觉目标成立。

窗口与状态变化时延续对象、阅读位置和判断关系。设计当前涉及的加载、选择、焦点、错误和结果更新，组合状态保持可辨。共享对象与控件语义一致，不同区域可以有不同密度与节奏。样式样张或代表页面通过后，继续完成用户约定的其余范围。

### 5. 看实际结果，修最大的问题

先看完整视口的主体、比例、密度和明暗，再按实际显示尺寸查看文字、图文、控件和边界；涉及操作时看变化过程。对照当前任务与选定参考的关键关系，不要求像素复制。

修订要说清哪个可见关系失配、准备改什么、预期改善什么。集中处理影响最大的具体问题，再复看受影响处。新事实或实际结果证明产品判断不成立时，更新对应依据；普通视觉问题在页面内解决。

按[看图与修订](references/review.md)完成当前范围检查。截图失败时尝试可用替代方式，仍不可用就准确记录缺口；构建通过、规则通过和截图文件存在都不能替代实际看图。没有新的具体问题就交付，不默认追加演示工程、完整测试矩阵或多轮评分。

## 内容与操作的底线

正文、导语、作品叙述和判断依据按用途编排；辅助说明只在帮助当前选择、输入、理解或恢复时出现。重复的实现解释留在开发材料，必要标签、来源、条件、可访问名称与状态反馈保留。功能性重复可以帮助定位和确认，不以出现次数直接判冗余。详细取舍见[内容编排](references/content.md)。

保存、刷新、连接、收费和数据去向以真实能力表达；新实质后果在相关决定前清楚可得。示例内容标明身份，不能伪造数据、研究、评价或功能。素材、字体与代码按来源条件使用，不制造品牌背书。

## 交付

说明重要变化及理由、实际查看的画面和操作、未验证的部分。技术栈、依赖、提交与发布按项目现状和用户授权处理。制作记录与评测留在项目维护材料；运行技能只保留执行所需的规则、参考和资产。
