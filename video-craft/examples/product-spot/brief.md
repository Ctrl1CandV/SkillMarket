# 《开场，提前十五分》

这支 25.5 秒的小剧场软件广告，只卖一个观众能当场试的用处：演出提早，灯光、音响、入场都要重排。改一次开场时间，拿到能交给全组的同一张执行台本。片中使用的产品就是随附的 [倒场](product.html)，双击即可在浏览器操作和下载文本。

![从编码成片提取的分镜与时间码](frames.jpg)

## 拆开看

| 时间 | 观众看到、听到什么 | 制作时借哪一招 |
|---|---|---|
| 0–4.00 s | 小剧场的舞台还空着。短促的三声响过，舞台牌从 19:30 跳成 19:15。 | 给时间变化一个人物和地点。切换两侧都留住同一块牌，观众能亲眼看出早了多少。 |
| 4.00–7.40 s | 统筹问“灯光几点到？音响呢？”后台纸单上的四个旧时刻逐行划掉。 | 这张纸写的是产品算出的旧台本。全片只跟一个现场变更，旧版的音响联调时间 18:50 留作后面对照。 |
| 7.40–13.10 s | 同一产品全景中，9.00 s 输入改成 19:15，右侧仍是旧结果。10.85 s 点击“倒排台本”，右侧四行同时更新。 | 采集修改前、已输入、已提交三个状态，锁住裁切。少了中间状态，观众会以为键入一个数字立刻改动所有人手里的台本。 |
| 13.10–17.55 s | 正视的界面局部可读。左边把同一个音响组的 18:50 划去，留下 18:35。指针停稳后点“下载文本台本”。 | 读出真实新旧值，先让观众确认其中一个人的新时刻，再表现导出。 |
| 17.55–21.40 s | 一张文本台本滑出，灯光 18:15、音响 18:35、观众 19:00、开场 19:15。 | 纸的颜色与纸边都是美术处理；每一行内容来自浏览器实际下载的 UTF-8 文件。产品提供下载，统筹将它交给执行组。 |
| 21.40–25.50 s | 同一舞台重新出现，灯变亮，表演者走到话筒。旁白“下一场，倒着排。”画面给出可用入口。 | 让开头的麻烦有一个看得见的结尾。观众可以打开随片的 product.html，填自己的时间。 |

首版的结果特写左边写“每一组，都有准点”。把图缩到 450 像素宽，只看出一张表，没看出音响要几点来。第二版把左边换成了同一行的 **18:50 → 18:35**，右侧仍保留原始三组数据。核对自己的广告时，可以让陌生人指一下旧结果到底变成了什么。

## 照着换一次

把整份技能复制到工作目录，保留 `examples/` 与 `kit/` 的相对位置，在副本的 `examples/product-spot/` 中操作。原样出片可直接使用包内素材，跳到最后两条渲染命令。

**收到“原定二十点二十，提前十分钟”时，只输入原开场和提前量。** 以下两条命令生成新广告输入，并在 [实际软件](product.html) 中重新填写、点击和下载。

```text
node retime.mjs 20:20 10 out/spot.json
node capture.mjs out/spot.json
```

第一条根据 [原输入](spot.json) 算出 **20:20 → 20:10**，同时生成片名、变更前后画面文字和第一句旁白“今晚，开场提前十分钟。”两个小时就填 `120`。如果新开场落在前一天，脚本会显示对应时刻并提示当前广告支持的同日范围。输出路径应选一个新文件。

第二条将三张状态图、控件位置和下载内容更新到工作副本的 `material/`。核对这一版应为 **19:10 灯光对位、19:30 音响联调、19:55 观众入场、20:10 正式开场**。具体结果可读 [proof.js](material/proof.js) 的 `exported`，随后画面直接从中取值。需要调整特写对象时，改新输入的 `copy.featureTask`（从零开始），再用同一文件重采。

录好新台词并替换工作副本的 `voice/01.mp3`。也可以用本地 VoxCPM 重新生成：在 PowerShell 运行 `./voices.ps1 -CasePath ./out/spot.json -Scratch ./out/recordings`，它用 `promo` 声音卡生成六句，每句三遍取最好，先保存分句 WAV，再更新包内 MP3。跨平台可运行 `python ../../kit/narrate.py out/spot.json out/voice --voice promo --takes 3`，然后用 `--vo out/voice` 混音。没有显卡时加 `--engine edge --voice zh-CN-YunxiNeural` 改用微软在线声音。时长变化影响下一镜时，调整新输入中的 `voice[].at` 与 `shots`，再运行 `node capture.mjs out/spot.json`。

在本示例目录运行，环境设置见[工具说明](../../references/kit.md)：

```text
node ../../kit/audio.mjs index.html score.html out/sound.webm --vo voice --wav out/sound.wav
node ../../kit/render.mjs index.html video out/picture.mp4 --audio out/sound.wav --mux out/film.mp4
```

两个与这支片有关的修改位置：

- 换软件时，在 [capture.mjs](capture.mjs) 中换掉页面、选择器和导出断言。先留下真实的原始输入与输出，确认按钮触发了什么，再决定哪些界面区域需要放大。屏幕内的指针按脚本录到的控件坐标重演，画面使用三个真实状态截图。
- 换传播场景时，从 [scene.js](scene.js) 的 `opening` 与 `brand` 动手。例如换成印务软件，就可以让同一张印样从有问题的打样走到成品。画面若要展示五行以上，重新取景并复查字号与画面底边。

本例的六句旁白由本地 VoxCPM1.5 克隆 `promo` 声音卡整句生成，首尾留出辅音和气口，配乐和按钮声由 [score.js](score.js) 合成。看成片先试着读出音响的实际改动，再点开产品，用另一组数字独立复算一遍。
