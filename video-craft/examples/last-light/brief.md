# 《最后一盏灯》· 跟着一段录音剪的 MV

湖这边一间小屋，湖那边一个村子。天黑时他点上窗台的灯，对岸的灯一盏盏亮起，船一条条回港，他的码头一直空着。村子睡下，只剩他这一盏。最后一次副歌开始，他自己吹熄了它，银河从湖上升起来。全片 54.7 秒，1920 × 1080，30 fps，画面全部用代码画成。

[有声预览](preview.mp4) · [从成片解码的六格画面](frames.jpg) · [歌曲地图](map/songmap.md)

这个工程示范**手里只有一段录音**时怎样做 MV：页面不知道曲子是怎么写的，所有时间都来自 `songmap.py` 对录音的分析。拿到别人的歌时，照这个结构换掉画面即可。

## 1. 歌曲地图

```text
python ../../kit/songmap.py song.m4a map
```

`map/songmap.md` 给出 96 BPM，第一拍在 0.19 秒（两拍弱起），第 0 小节从 1.44 秒开始；分成四段：

| songmap 的段落 | first bar | 实际听到的 | 这个片子按小节再拆 |
|---|---|---|---|
| #1 0:00–0:16 | pickup | 弱起、前奏、主歌 | 前奏 0–1，主歌 2–5 |
| #2 0:16–0:26 | 6 | 副歌，最响 | 副歌 6–9 |
| #3 0:26–0:36 | 10 | 鼓停，只剩钢琴 | 桥段 10–13 |
| #4 0:36–0:55 | 14 | `same as #2`：副歌回来 | 最后的副歌 14–17，尾声 18–19 |

机器分段常把前奏并进主歌、把尾声并进最后一段。用 `first bar` 和能量曲线核对后，按小节自己拆开。

## 2. 概念

1. **情境**：一个人每晚点灯，等一条没回来的船。
2. **唱的人的态度**：这首是器乐，没有歌词，态度从曲子的形状里找。`songmap` 能读出三件事：桥段（#3）被标成 `quiet, drops`，四个小节里只有两个低频重音，鼓停了；最后的副歌（#4 的前四小节）标成 `same as #2`，每小节的响度和第一次副歌几乎一样，回来了，却没有更满、更高；尾声两个小节没有一个重音，余音在 51.9 秒散尽，不落在重拍上。这是放下，不是等到。和弦 `songmap` 给不出来。这段录音是我们自己写的，[score.js](song/score.js) 里桥段停在 D 小和弦和悬着的 E 上，第一次副歌落到 A 小和弦，最后一次落到 C 大和弦，和上面的判断一致；拿到别人的歌又听不到时，不要猜和弦，问用户这首歌在讲什么。所以结局不让船回来，而是让他自己熄灯。熄灯也不是绝望：灯一灭，眼睛适应了黑暗，满天的星和银河才看得见。
3. **视觉世界**：夜里的湖，倒影把天和灯都翻一倍。
4. **反复出现、每次不同的东西**：他的灯和那根空的系船桩。前奏刚点亮；主歌里对岸的灯和船越来越多，桩还是空的；副歌时他这盏只是许多盏之一；桥段里村子一扇扇熄灯，只剩他的；最后的副歌由他熄掉；尾声镜头沿着码头走到那根桩，桩上只有盘好的绳子，水里是银河。

## 3. 镜头表（全部切在小节线或半小节上）

| 段落 | 小节 | 镜头 | 观众新看到什么 |
|---|---|---|---|
| 前奏 | 弱起–1 | 全景，慢推 | 黄昏的湖；第 0 小节第一拍，他的窗亮了 |
| 主歌 | 2–3 | 对岸近景，横移 | 窗一扇扇亮（每个重音亮几扇），三条船带着灯回港 |
| | 4 | 码头，沿码头望出去 | 空的系船桩，对岸一排灯 |
| | 5 | 窗外近景 | 窗台上的油灯，湖和对岸在左边 |
| 副歌 | 6–7 | 全景，升高 | 第 6 小节第一拍村子剩下的灯一起亮；萤火从岸边升起，随高频重音闪 |
| | 8 | 对岸近景 | 船已靠岸，满村灯火 |
| | 9 前半 | 桩的近景 | 萤火绕着空桩 |
| | 9 后半 | 窗，更近 | 飞蛾绕灯 |
| 桥段 | 10–13 半 | 一个 8.8 秒的长镜头 | 鼓停。桥段每个钢琴音熄掉几扇窗，最后只剩他的灯 |
| 最后的副歌 | 13 半–14 半 | 窗 | 第 14 小节第一拍，灯灭，一缕烟升起 |
| | 14 半–15 | 从屋顶升向天空 | 银河在两小节里浮现；最强的高频重音上划过一颗流星 |
| | 16–17 | 全景 | 村子和小屋都黑了，湖面倒映整条银河 |
| 尾声 | 18–结束 | 沿码头走到桩前 | 空桩、盘好的绳子、水里的银河；余音结束后淡出 |

镜头长度：6.4、5、2.5、2.5、5、2.5、1.25、1.25、8.75、2.5、3.75、5、8.2 秒。副歌切得最密，桥段一个长镜头。

## 4. 代码里怎样跟歌

都在 [scene.js](scene.js) 的开头：

- `bar(n, beat)` 从 `SONG.downbeats` 取第 n 小节第几拍的秒数。镜头表 `SHOTS` 只用它，不用 BPM 推算。
- 对岸的窗：主歌里的 `SONG.accents`（大约每小节一个重音）每次亮几扇，第 6 小节第一拍亮剩下的。桥段没有鼓，用 `SONG.hits.mid` 里强度大于 0.3 的钢琴音一批批熄灭。
- `LAMP_ON = bar(0)`、`LAMP_OUT = bar(14)`：他的灯。`mwAt` 让银河在熄灯后的两小节里升起。
- `songAt(SONG, s)` 的 `kick` 让灯焰和船灯轻轻跳一下，`snap` 让亮星和萤火闪。整个画面不跟鼓点跳。
- 每个画面是一个函数：`wide`、`farShore`、`pierShot`、`windowShot`、`skyShot`。近景都按自己的尺度重画，不是放大全景。

天空和银河用 [`shader.js`](../../kit/shader.js)，山脊、雾、光、倒影用 [`draw.js`](../../kit/draw.js)，做法见[用代码画出完成的画面](../../references/drawing.md)。

## 5. 出片和检查

```text
node ../../kit/render.mjs index.html video out/picture.mp4 --crf 20
python ../../kit/mux_original.py out/picture.mp4 song.m4a out/film.mp4
python ../../kit/shotlist.py out/film.mp4 --song map/songmap.json
```

`mux_original.py` 原样复制录音的音频，不重新编码，也不改响度。

渲染 1640 帧约 80 秒（RTX 4070 Ti SUPER 上的 Chrome）。`shotlist.py` 找到 13 个切点：12 个是镜头表里的切点，另一个在 0:36.47，是同一镜头里灯灭了（见下）。全部落在拍点 1.5 帧以内，中位 25 ms（切点取下一帧）；黑场合计 0.3 秒，是结尾的淡出。第一版还标出桥段 8.7 秒、最后副歌的全景 5 秒“几乎不动”，前者加大拉远并让雾贴着湖面流过，后者加大推近，并在这两小节的高频重音上划过流星。剩下的标记和理由：

- 0:36.47 被当成“只放大上一镜的切”：那是同一个镜头里灯灭了，画面整体变暗。
- 0:41.5–0:43.7、0:44.3–0:46.5 各约 2 秒“变化少”：熄灯后的暗场全景，推得慢，星和流星很小；是有意停留的一眼。
- 0:48.5–0:52.8 “变化少”：最后的和弦响着，镜头慢慢停在桩前，停住就是结尾。

[六格画面](frames.jpg)依次取自 4.5、12.5、23、33.5、39.5、50 秒。

## 换成自己的歌

1. 对自己的录音跑 `songmap.py`，把 `map/` 换掉；读 `songmap.md`，按小节拆出段落。
2. 回答上面四个问题，尤其是第 2 问，再写镜头表。
3. 改 `SHOTS` 的小节号和每个画面函数。窗灯亮灭、熄灯时刻这类事件改成你的歌里对应的小节和重音。

`song/` 里是这段录音的来源：用 `sound.js` 合成的一首 96 BPM 原创器乐，只为了让示例有一段可以分析的录音。MV 页面从不读取它。重新生成：

```text
node ../../kit/audio.mjs song/score.html song/score.html out/song.webm --wav out/song.wav
ffmpeg -i out/song.wav -c:a aac -b:a 192k song.m4a
```
