# Video craft：用代码做出能直接用的视频

能直接用的视频有这几个特点：

- **画面自己把事讲明白。** 数字和现象由代码算出来、模拟出来：五个人之间 20 根转账箭头收成 4 根，天空的颜色由散射公式算出。不要在幻灯片上贴一句结论。
- **有质感。** 渐变的光、光晕、发光的线、景深、细颗粒、暗角；颜色从题材里来。
- **镜头连续。** 同一个模型在不同尺度下用不同细节去画，一条相机路线走到底。转场本身就在讲故事，比如推进到手机屏幕里，或者升到太空看地球。
- **声音和画面用同一张时间表。** 画面里每个事件都有对应的声音，音乐的起伏跟着叙事走。
- **看过实际画面。** 每一轮都看渲染出来的帧，不靠读代码判断效果。

用代码做视频，难的不是写代码，而是先想清楚每一帧该是什么，做完再实际去看。下面的顺序每一步都产出一件能看的东西。

## 准备

先看机器能做什么：

```text
node <skill>/kit/doctor.mjs
```

它会报告浏览器、WebGL、编码器、ffmpeg 和语音合成是否可用。工具包需要 Node 18+、playwright-core 加一个 Chromium，以及 ffmpeg（至少要有 VP9；要出 MP4 还需要 libx264）。找不到时用环境变量指定，见 [工具包](references/kit.md)。项目已经在用 Remotion、HyperFrames 或 Manim 时，继续用原来的引擎，方法照样适用；kit.md 写了检查工具怎样配合其他引擎。

## 工作顺序

用户只要脚本、分镜或局部修改时，只做那一部分。

1. **任务单。** 写 `brief.md`，内容包括：
   - 观众、平台与画幅、时长；
   - 看完要记住的一句话；
   - 要不要配音；
   - 事实与数字核对：所有数字都由代码从同一份数据算出来，并在这里写明来源。

   缺的信息用默认值补上，交付时说明：横屏 1920×1080 或竖屏 1080×1920，30 fps，中文；科普 45–90 秒，宣传 20–40 秒。

2. **核心画面。** 读 [核心画面与结构](references/pictures.md)。写出 3–5 个“观众不看字也能看懂”的画面。这一步决定了大部分质量，后面的风格和动效都是在它上面加分。

3. **美术方向与样帧。** 读 [画面质感](references/look.md)：
   - 从题材里定出 4–6 个颜色、字体和光的处理方式；
   - 动画之前，先按最终分辨率做 2–4 张最关键的静帧；
   - 看过、改到满意再往下走。

4. **分镜与时间网格。** 读 [运动、镜头与节拍](references/motion.md)。写一张表，每行是一个时间段，列出画面、文字、镜头与转场、声音。所有时间写成常量：
   - 有配音时，用 `vo.mjs` 量出每段配音的长度，再从这些长度生成时间；
   - 有节拍音乐时，所有时间都写成拍的倍数。

5. **实现。** 从 `examples/` 里最接近的一个改起，不要从空白页开始：

   | 示例 | 适合 |
   |---|---|
   | `starter` | 起步模板：时间线来自旁白或配音，加字幕、颗粒和暗角 |
   | `sky` | Canvas/WebGL 的物理科普，跨尺度的连续镜头，声音直接表现物理规律 |
   | `promo` | DOM 实现的产品宣传：手机界面、推进穿过屏幕、120 BPM 节拍 |

   每一帧都只由时间决定：`seek(t)` 是纯函数，不用 CSS 动画，不用 `Date` 或 `Math.random`。

6. **看帧修订。** 读 [审查](references/review.md)。按下面的顺序看，每轮改完再看一遍：
   1. 每秒一帧的联系表；
   2. 关键帧原尺寸；
   3. 转场处的切点帧条；
   4. 字幕交接处；
   5. `textcheck`。

7. **声音。** 读 [声音](references/sound.md)：
   1. 场景页导出事件表；
   2. 在 `score.js` 里把每类事件配成音乐和音效；
   3. 用 `mixcheck` 看响度曲线，确认音效和人声在事件处听得见；
   4. 用 `audio.mjs` 输出音轨。

8. **渲染与交付。** 用 `render.mjs video … --audio` 出成片，再从成片里解码几帧复查。交付时告诉用户四件事：
   - 文件路径；
   - 规格：分辨率、时长、编码、响度；
   - 做过哪些检查；
   - 哪些没能做，例如没有配音、没有 MP4。

## 命令速查

`<kit>` 指本技能的 `kit/` 目录。

| 目的 | 命令 |
|---|---|
| 环境探测 | `node <kit>/doctor.mjs` |
| 原尺寸静帧 | `node <kit>/render.mjs page.html stills out/ 2.5 10 31` |
| 联系表 | `node <kit>/render.mjs page.html sheet out/sheet.jpg --every 1`（或 `--times a,b,c`） |
| 切点帧条 | `node <kit>/render.mjs page.html strip out/strip.jpg --at 9.85,18.2` |
| 字幕检查 | `node <kit>/textcheck.mjs page.html` |
| 配音计时 | `node <kit>/vo.mjs vo/ vo/vo.js` |
| 响度曲线 | `node <kit>/mixcheck.mjs page.html score.html out/mix.png [--vo vo/]` |
| 输出音轨 | `node <kit>/audio.mjs page.html score.html out/audio.webm [--vo vo/] [--stems]` |
| 成片 | `node <kit>/render.mjs page.html video out/film.webm --audio out/audio.webm`（`.mp4` 需要 libx264） |
| 并排看几张图 | `node <kit>/montage.mjs out/k.jpg 900 a.png b.png` |
| 听不到时看声音 | `node <kit>/audiocheck.mjs out/film-av.webm page.html out/check.png` |

## 交付前核对

- 第一帧就有完整的构图（标题和主体都在），不是空白或纯色。
- 每个数字都能在任务单里找到出处，示意图注明“未按比例”。
- 字幕：
  - 上一句完全退出后，下一句再进；
  - 最小字号不小于画面高的 1/30；
  - 都在安全边距内（`textcheck` 通过）。
- 变形的元素先在画面里出现，再变形；转场前后的形状能接上。
- 换场没有重影：上一镜的图和字退完，下一镜再进，切点帧条里看不到两镜的字叠在一起。
- 画面不冻住：联系表输出里列出的静止段，每段都有理由，或者已经改成缓慢运动。
- 结尾卡停留 2–3 秒。
- 声音：
  - 响度 −16 LUFS，峰值不高于 −1.5 dB；
  - 关键音效在事件处高过音乐；
  - 音乐不压人声。
- 从编码后的成片里解码抽帧看过：文字周围的方框、渐变色带这类问题，只在编码后才出现。

## 时间参考

实测：
- 59 秒的 WebGL 科普，1770 帧，在软件 GL 上渲染约 4.7 分钟；
- 28 秒的 DOM 宣传片约 1.5 分钟；
- 合成音频不到 15 秒。

一条片子从任务单到交付，通常要改 4–6 轮，每轮都靠看图发现问题。
