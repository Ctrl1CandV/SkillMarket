# 用代码画出完成的画面

代码画面的问题很少出在“画不出来”，多半是画成了幻灯片：纯色底、居中的图标、一行标题，所有东西一样亮、一起淡入。下面讲代码擅长画什么、一帧画面怎样分层、光和颜色怎样定，以及什么时候借用生成图。可直接改的参考是 [layers 示例](../examples/layers/scene.js)：10 秒的山谷从黄昏到入夜，全部用 Canvas 2D 画成，工具函数在 [`kit/draw.js`](../kit/draw.js)。

## 先选代码画得好的东西

| 代码画得好 | 画法 |
|---|---|
| 光：灯、窗、日落、霓虹、火、星 | 径向渐变加 `lighter` 叠加，单独一层做 `bloom`。光源最亮，周围的东西被它照亮 |
| 大量小东西：星空、雪、雨、尘、萤火、火花、鸟群、远处的人群灯光 | 几千到几万个点，`rng(seed)` 固定位置；亮度和大小用幂律分布：少数很亮，多数很暗 |
| 线：星座、轨迹、航线、电路、手写笔画、流线 | `strokeTo(ctx, pts, k)` 按长度逐渐画出，笔尖放一个光点 |
| 剪影和纵深：山脊、城市天际线、屋顶、树林、窗框、人物背影 | `ridge` 生成轮廓，由远到近变暗、变不透明，层间加雾 |
| 天空和水：渐变天空、晨昏、倒影、波纹 | 天空两三色渐变随时间混合；水面把上半画面逐行翻转并错位 |
| 几何与抽象：圆环、网格、隧道、粒子聚散成形 | 参数化图形；聚散用同一组粒子在两种排布间插值 |
| 流动的光和气：星云、极光、烟、云海、水下焦散、液态光 | 逐像素的片元着色器，`shader.js` 生成一层再叠进画面（见下文[着色器层](#着色器层)） |
| 模拟和数据：物理、光学、增长、流动 | 数值由公式或数据算出，画面直接显示结果，见 [sky](../examples/sky/brief.md) |
| 界面、文字、图表、地图 | DOM 或 Canvas；真实产品优先录真实界面 |

代码画不好：写实的人脸和手部五官细节、多关节复杂人体动作、动物、复杂写实材质。**绝对不要拿圆头胶囊和折线硬拼火柴人或“兔耳手指”**，改用以下干净成立的拍法：

- **建筑框景、光影与日常器物演处境（首选）**：删掉笨拙小人时，绝不能把人的处境一并删掉——让最关键的动作落在窗框、门缝、影子或物件上：门合上时走廊暖光缩成一线（告别），桌上两只杯子只有一只冒热气（缺席），手机屏幕上的字一个个退格删掉再扣在桌面（欲言又止），挂在门把上的圆牌亮起蓝光（提醒带伞）。改完静音看一遍，照样能一眼看懂发生了什么。
- **整体剪影与远景背影**：确实需要人入画时，只用干净利落的**整体外轮廓剪影**（窗前背影、伞下轮廓、逆光侧影），全片保持同一种剪影画法，不在近景突然画五官或拼多根手指关节：
  - 人站在栏杆、窗台或桌前时，注意前后遮挡层序，身体延伸出画幅底边，避免像浮在半空的胸像；
  - 人在强光里淡出时，先画在独立离屏层用窗光颜色填满再模糊降透明度，避免直接降透明度变成透出背景的“X 光片”。
- **光学气氛补足空间（`kit/draw.js`）**：用 `lightBeam` 画斜射进屋的窗光、路灯锥或舞台光束（侧边自动羽化，不显生硬多边形），用 `bokeh` 画幂律分布的远近虚化光斑（预缓存精灵图，软件渲染依然飞快），用 `withHandheld(cam, t)` 给长镜头加细微呼吸感。
- **生成底图按层辅助（仅在显卡空闲或获准时）**：需要真实人物或油画质感底图时，可用用户素材或 `imagecraft` 分层垫底（见文末），运动、光影与节奏仍由代码掌控。

画什么由内容决定，不由“代码擅长什么”决定（见 [MV 的内容设计](music-video.md#2-内容设计这首歌唱给谁说中他们什么)）。一首唱毕业后失联的朋友的歌，要画的是那间宿舍、那副分着用的耳机、那条打了又删的消息；代码负责把台灯的光、窗外的夜色和屏幕的冷光画好，人用背影和手。

## 一帧画面从后往前画

1. **天空或背景**：两三色的纵向渐变。光源方向加一团大而淡的暖晕或冷晕。
2. **远景**：颜色接近天空，只比天空略暗，对比最低（大气透视）。
3. **中景**：主体所在的层，层与层之间加雾。
4. **主体**：全画面明暗反差最大的地方。暗剪影衬亮背景，或者亮物衬暗背景。
5. **前景**：最暗、最大，可以模糊（`ctx.filter = 'blur(6px)'`），用来拉出纵深。
6. **光层**：画在离屏画布上，`bloom` 叠回主画面。
7. **气氛**：雾、尘、飘动的粒子。
8. **收尾**：`finish(ctx, frame)`，加暗角和逐帧变化的颗粒。

每层用 `view(ctx, cam, depth, fn)` 套同一个相机。远的层 depth 小，相机一动，层与层之间就有视差。每一层都画得比画面宽（例如 `ridge(seed, W + 400, …)`，画时 `dx: -200`），高度也留余量，相机平移和推拉时才不会露出层的边缘。

## 光和颜色（暗调与日光亮调各有画法）

- **先按剧本/歌词时辰锁死主光**：先确定此刻是正午白墙、阴雨清晨、黄昏逆光还是深夜台灯，再定光从哪来、什么颜色。朝光面亮，背光面暗，绝不把白天的台词画进黑夜模板。
- **暗调场景靠加法辉光，亮调/日光场景靠投影与色温对比**：
  - 暗底上发光体用 `glow`、`lightBeam(..., { blend: 'lighter' })` 与 `bloom` 叠出空气感；
  - 亮底、日光房间或浅色纸面上，`lighter` 加法混合会发白消失——改用 `source-over` 暖金光带（`lightBeam(..., { blend: 'source-over' })`）、窗框投在墙面/桌面的斜向冷灰投影（`multiply` 或半透明深冷灰多边形）以及明快的高饱和主体色来建立立体感。
- **调色板 4–6 色从当前题材长出**：晴朗午后可以是暖白墙、水洗蓝天、樟木棕与青草绿；复古印刷可以是米白纸、炭黑墨与朱砂红；雨夜室内可以是冷灰蓝与琥珀台灯。不用纯黑 `#000` 和死白 `#fff`；时间推移时用 `mix(a, b, k)` 让整套光色协同过渡。
- **亮度与尺寸服从幂律层级**：光源和焦点最醒目，其余压低；光斑与散景（`bokeh`）少数大而柔、多数小而淡，拒绝满屏等大圆点。

## 让每个镜头都在动

三种速度的运动同时存在：

- **相机慢动**：推、移、升，有视差。
- **主体的动作**：本镜头要讲的那件事。
- **环境在动**：粒子飘、灯闪、雾流、水波。

动作做完以后，环境和相机还要继续动。连续 2 秒以上几乎不变的画面，`shotlist.py` 会标出来。

推近时，按新的尺度重新画，不要放大已经画好的位图（会糊、会出方块）。细节随尺度增加：远看是一个光点，近看是一颗有光芒的星，再近能看见星尘沿连线流动。切到近景时必须多出新的细节，否则只是把上一镜放大，没有信息。

转场可以：

- 推进穿过窗、屏幕或一个光点；
- 用形状相同的东西接上下镜头；
- 在鼓点上闪一下光；
- 让前景物体划过画面完成切换；
- 用光的熄灭或亮起换场。

## 着色器层

Canvas 2D 一个个画形状；星云、极光、烟这类每个像素都在变的东西，用片元着色器更好看也更快。`shader.js` 把一段 GLSL 变成一张画布，在 `seek` 里画好，再像普通图层一样 `drawImage` 进画面，后面照样叠 Canvas 画的剪影、光点和 `finish`。

```js
import { shader } from '<kit>/shader.js';
const sky = shader(W, H, `
void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * res) / res.y;
  vec2 q = vec2(fbm(p * 2.0 + t * 0.03), fbm(p * 2.0 + 5.2 - t * 0.02));
  float d = fbm(p * 2.5 + 3.0 * q);                    // 用噪声扭曲噪声：流动的星云
  vec3 c = mix(vec3(0.02, 0.03, 0.09), vec3(0.45, 0.25, 0.65), smoothstep(0.35, 0.8, d));
  c = mix(c, vec3(1.0, 0.62, 0.45), smoothstep(0.62, 0.95, d) * (0.7 + 0.5 * pulse));
  o = vec4(c, 1.0);
}`, { scale: 0.5 });

function seek(t) {
  sky.draw(t, { pulse: 0.5 + 0.5 * Math.sin(t * 2) });  // 每个键成为一个 uniform（数或数组）；跟歌时传 songAt(SONG, t).kick
  ctx.drawImage(sky.canvas, 0, 0, W, H);
  // 再画山脊、人物剪影、光层……
}
```

- 着色器里已有 `t`（秒）、`res`（像素尺寸）、输出 `o`，以及 `hash`、`noise`、`fbm`。自己的 uniform 不要再叫这几个名字。
- 每一帧传同一组键。某个键只在部分帧有值时，写进 `shader(…, { uniforms: ['pulse'] })`，没传的帧按 0 算。
- 柔和的东西（星云、雾、光晕）用 `scale: 0.5` 渲染再放大，看不出差别，快四倍。有清晰边缘的东西用 1。
- 时间只从 `t` 来，不要在着色器里累加状态，帧才能任意顺序渲染。
- 先跑 `doctor.mjs` 看 `webgl2` 与 `gpu.busy`。没有物理 GPU 或显卡正被其他重任务高占用（`gpu.busy === true`）时，设环境变量 `VC_SOFTWARE_GL=1` 走 SwiftShader 软件渲染，并将柔和背景着色器设为 `{ scale: 0.5 }` 提速。
- 本机 `imagecraft`（ComfyUI + FLUX）需要数 GB 显存：**当 `doctor.mjs` 报告 `gpu.busy === true` 或空闲显存不足时，未经用户明确许可严禁在后台调起本机生图**。

## 画面里的文字

字少、字大，成为画面的一部分：歌词写在天上，标签贴在物体旁边，数字长在图上。全片一个字体家族，最多两种字重；版面式的片子另加一种等宽字做小标签，见[版面式动态设计](graphic.md)。一页标题加几条要点的版式只适合真的在演示幻灯片的时候。

## 常见的“像 PPT”及改法

| 看到的 | 改法 |
|---|---|
| 纯色底，居中放图标和标题 | 先画一个空间：地平线、光源、远近层次。讲概念或数据时，也可以排成[完成的版面](graphic.md) |
| 所有元素一起淡入淡出 | 动作分先后，有因果：先亮灯，再有人抬头 |
| 下一镜只是把上一镜放大 | 换角度、换尺度，给新的细节，或者让主体做下一件事 |
| 光斑一样大、一样亮 | 亮度用幂律分布，少数有光芒，大多数暗 |
| 推近后画面糊或出方块 | 按当前尺度重画，不缩放位图 |
| 相机一动，露出层的尽头或空白边 | 每层画得比画面宽、比画面高 |
| 动作结束后画面停住 | 相机、光和环境继续动，或者提早切走 |
| 颜色鲜艳但杂乱 | 回到 4–6 色的调色板，只留一个强调色 |

## 生成图：需要时的加强

本机有 imagecraft 技能（本地 ComfyUI + FLUX）或用户给了图片时，可以用生成图补代码画不好的东西：真实的地点、人物、油画般的氛围。只把它当底版，画面的运动、光和节奏仍由代码负责。

- **按层生成，不按镜头生成。** 远景一张，中景一张，主体单独一张，纯色背景方便抠出。所有图用同一套风格描述、同一画幅和同一调色倾向。
- **用代码让它活起来。** 层间有视差，前面叠代码画的光、粒子和雾，整体调色统一到片子的调色板。避免每个镜头都是一张图在慢慢放大（Ken Burns）的幻灯片。
- **检查。** 手、文字、透视这些生成图常出错的地方要看原尺寸。图的分辨率要够最大推近倍数用。
- **记下来源。** 在任务单里写明哪些画面是生成的、用了什么模型，交付时告诉用户。

性能：静态的层预先画到离屏画布上缓存；粒子的位置在开头一次算好，每帧只算运动；`ctx.filter` 模糊较慢，只用在光层和前景上。1080p 的 Canvas 2D 场景在无头浏览器里约每秒 3–10 帧。
