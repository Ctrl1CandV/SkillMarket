# 声音

## 声音讲同一件事

先决定观众听什么。教程可以只保留清楚的人声和实际操作提示音，产品片可以用设备响动和音乐，叙事短片可以让安静、环境音和空间感支撑镜头。声画也可以形成反差，例如空荡的房间里仍响着欢乐的广播。用声效强调少数值得听见的动作。以歌曲为主要结构时见 [音乐驱动与 MV](music-video.md)。

- **把规律变成声音**。[sky 的配乐](../examples/sky/score.js) 用音高和音量做了一层听觉比喻：
  - 每种颜色对应一个音高，红色最低，紫色最高；
  - 白光是六个音同时响，光被拆开时六个音依次弹出；
  - 日落的光束丢掉蓝光时，高音逐个消失，最后只剩红色那个低音；
  - 散射段的蓝光每弹开一圈响一声，红光提示音的增益约为蓝光的 1/5.9。

- **音乐的段落帮助观众分辨前后**。[promo 的配乐](../examples/promo/score.js) 这样进入、收住、再展开：
  - 开头的鼓被低通滤掉一半，消息提示音越来越密；
  - 画面变亮的那一拍，鼓组全部进来；
  - 揭晓核心卖点时停一小节鼓，只留和弦和逐拍上行的音；
  - 卖点揭晓完，鼓组回来；印章落在重拍上。
- **让声音先于画面改变注意力**。车站叙事里可以先听见下一场列车驶来，再从空站台切入车窗；当人物摘下耳机时，音乐退去并露出环境声。沉默同样可以建立期待，切进切出的位置可以直接写进分镜。

## 一张时间表

用工具包从画面事件生成声音时，场景页导出供配乐使用的事件表：

```js
// scene.js
register({ …, meta: { events: [{ t: 4.0, type: 'reveal' }, { t: 15.0, type: 'bold', k: 0 }, …] } });
// score.js
function score(m, events, duration) { for (const e of events) switch (e.type) { case 'reveal': impact(m, m.sfx, e.t); break; … } }
install(score, { reverb: 0.2, irSec: 2.4 });
```

按需要给事件带上序号、屏幕横坐标、颜色、持续时间。由配乐跟随画面的事件时，改动作时间即可同步对应声音。用用户给出的歌曲、录音或环境音作主轨时，反过来把重要乐句、歌词、停顿和起音标到时间线上，再定位画面。素材来源、使用范围和是否公开在任务记录里注明，听过实际使用的片段再对齐。

## 工具包里的两种配乐起点

| 类型 | 适合 | 做法（kit/sound.js） |
|---|---|---|
| 氛围型，无鼓 | 科普、自然、宇宙 | `warmPad` 和弦随段落变化，`tone` 做低音，`piano` 做稀疏旋律，`wind` 做环境底噪；混响时长 3–3.5 秒 |
| 节拍型 | 宣传、产品、快节奏 | 120 BPM：`kick` 每拍一下、`clap` 落在第 2、4 拍、`hat` 打反拍、`bass` 按十六分音符的切分型、`pluck` 做琶音；铺底和弦随底鼓侧链压低（每拍压到 0.35，0.24 秒恢复）；`riser` 放在进鼓之前，`crash` 放在进鼓那一下 |

这些是现有示例的音色与组织方式。做新的音乐时，按题材选调性、密度与织体。人声被盖住时，可以减轻同一频段的持续声，或在关键台词处减少配器和压低音乐。

## 音效词汇

| 画面事件 | 声音 |
|---|---|
| 元素出现、弹出 | `pop`（音高随序号上行） |
| 界面点击、计数 | `tick` |
| 揭晓、成功、打勾 | `chime` / `pluck`，音阶上行 |
| 镜头移动、飞入 | `whoosh`（推进时频率由低到高，拉出时由高到低） |
| 推进、升空、进鼓之前 | `riser` |
| 盖章、落地、画面翻转 | `impact`，可加 `crash` |
| 下落、减弱 | `glide` 下行 |
| 场景的底噪 | `wind`（换中心频率就能做室内底噪） |

## 配音

1. 按镜头或自然说话的句组录音。在 [starter](../examples/starter/score.js) 的工作流里，每段一个文件，如 `vo/01.wav`、`vo/02.wav`，与场景里的 `LINES[i].id` 对应。
2. 用 `node <kit>/vo.mjs vo vo/vo.js` 量出每段长度。场景 `import` 这份结果，用它生成时间线。按动作、换气和阅读留空。
3. 在 `score.js` 里用 `voice(m, t, id)` 把每段放到对应的位置。音乐压过台词时，可试 `duck(m.music, 说话区间, { depth: -9 })` 后实际试听。
4. 渲染和检查时都加上 `--vo vo/`。

配音可以来自用户录音或可获授权的语音合成。浏览器的 `speechSynthesis` 在无头环境里常缺可用声音，用 `doctor.mjs` 看当前环境。字幕按需求交付，录音中的数字、专名和指令与画面同步核对。

## 检查声音

从成片试听，优先听台词、关键动作、段落交接和结尾，在常用设备音量下听一遍。用 `mixcheck.mjs` 查看音乐、音效、人声和总混音的短窗曲线以及事件时间，可以定位以下现象：

- 短点击只有几十毫秒，400 毫秒的窗口会把它平摊。对齐和清晰度可以用波形、频谱加实际试听核对。
- 某个揭晓音效需突出时，可先试在该处压低音乐约 4 dB。有台词处关注清晰度，响度差提供定位线索。
- 如果峰值集中在少数冲击或鼓点，同时输出头部被大量限幅，比较降低峰值音效前后的表现。原始峰值和原始积分响度的差可以定位这类段落。
- 遇到平顶、空段或缺声，先对照分镜与音轨。刻意使用的安静也可复听前后，确认进入、停留与退出是否都有作用。

`audiocheck.mjs` 能从成片解出声音，画出频谱和包络。用它帮助定位事件线与起音。重要提示音在小扬声器上是否可辨，也要听实际输出。只有曲线可用时，在交付中写明核对了哪些技术指标和哪些位置，标出试听尚待确认。

## 响度与格式

- `audio.mjs` 默认把 −16 LUFS 作为积分响度目标，限幅默认采样峰值为 −1.5 dBFS。交付规格有不同的积分响度目标时，可用 `--target` 调整。按交付要求测量最终编码结果的响度和峰值。
- 加 `--stems` 会分别报告音乐、音效、人声各自的响度和峰值。
- 输出 WebM（Opus）；`render.mjs --audio` 用流复制合进视频，目标是 `.mp4` 时转成 AAC。

## 常见问题

- `exponentialRampToValueAtTime` 的目标值不能是 0；工具包的包络已经加了下限，自己写的时候也要注意。
- 分轨静音要用总线之后的独立节点（kit 里的 `bus.mute`）。如果直接改总线增益，会和配乐里对这条总线的自动化冲突。
- 密集的重复提示需要表现来得更急时，可试逐渐缩短间隔，或者轻微改变音高和声像。保留实际产品提示音时，使用原录音并控制叠加后的音量。
