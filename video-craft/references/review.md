# 审查

读代码看不出画面效果。三次实验里，每一轮看图都能发现读代码发现不了的问题。看图也有成本：先看缩小的联系表，只在需要的地方看原尺寸。

## 看的顺序

1. **每秒一帧的联系表**：`render.mjs page.html sheet out/sheet.jpg --every 1`。
   - 看节奏：哪里空、哪里挤、哪几秒画面没变化。和上一格几乎一样的格子会标“= same”，连续 2 秒以上的静止会在命令输出里列出来。每一段都要有理由（读字的时间、高潮前的停顿）；没有理由就缩短，或者让画面带着缓慢的推近、漂移、数字或指针的变化。
   - 看字幕有没有叠在一起。
   - 看主体有没有穿过文字。
   - 宣传片这类节奏快的，用 `--every 0.5`。
2. **关键帧原尺寸**：`stills` 渲染 3–6 帧，用 `montage.mjs` 两两并排缩到 900 px 宽来看。
   - 主体认不认得出：俯视的人像不像眼球？
   - 质感：光晕烧白了没有？远山颜色对不对？
   - 字的大小和对齐。
3. **转场处的切点帧条**：`strip --at 9.85,18.2 --offsets -4,-2,-1,0,1,2,4`。
   - 形状能不能接上；
   - 有没有一帧露出边框，或者闪出空画面；
   - 变形有没有从画面外开始；
   - 有没有半透明的重影：上一镜的图和标签还没退完，下一镜已经叠上来，字压着字。
   - 文字和图是不是同一刻换：左边已经换了新标题，右边还是上一张图，就是各自计时了。
4. **字幕交接处**：在每句的结束时刻前后按 0.1 秒取帧，看上一句是否退干净了。
5. **`textcheck.mjs`**：自动找出越过安全边距、或字号小于画面高 1/30 的字幕。
6. **从成片解码抽帧**：

   ```text
   ffmpeg -ss 22.05 -i out/film-av.webm -frames:v 1 -update 1 out/dec.png
   ```

   有些问题只在编码后才出现：文字周围的浅色方框、渐变里的色带、暗部糊成一片。
7. **声音**：`mixcheck` 的曲线和 `audiocheck` 的频谱，读法见 sound.md。

每一轮改完都要重新看图，再说“改好了”。

## 常见问题：现象、原因与改法

| 现象 | 原因 | 改法 |
|---|---|---|
| 第一帧是空的或纯色 | 所有元素都从 0 秒开始入场 | 首屏元素的入场时间设成负数 |
| 上一镜的元素残留在下一镜 | 父层 `visibility:hidden` 被子元素的 `visible` 覆盖 | 用 `display:none`，或者逐个设透明度并在 `seek` 里统一归零 |
| 两句字幕叠在一起 | 交叉淡化 | 下一句等上一句退完再进 |
| 换场时两镜的图和标签叠在一起，字压着字 | 整个画面交叉淡化 | 上一镜的图和字先退（约 0.3 秒），下一镜再进；只有背景、底色这类没有字的层可以交叉淡化 |
| 标题已经换了，图还停在上一镜 | 文字和图各自计时 | 同一镜的文字和图都从时间常量表里取同一个换场时刻 |
| 太阳或主体正好穿过标题 | 字的位置和镜头路线没一起排 | 按镜头路线把字放到另一侧 |
| 编码后文字周围有方框 | 逐行遮罩切掉了文字阴影 | 遮罩留内边距并用负外边距抵消 |
| 渐变上有一圈圈色带 | VP9 量化 | 加 6–7% 的颗粒 |
| 要变形的元素从画面外飞进来 | 它在变形开始前已经滚出画面 | 让它全程留在画面内，或换一种排布 |
| 推进时露出手机边框 | 放大还没盖满画面，新画面就出现了 | 推进先完成，再出新画面；推进用加速曲线 |
| 拉出时边框透过半透明画面 | 全屏画面先淡出，手机后缩小 | 让全屏画面跟着屏幕一起缩小 |
| 一边飞一边变形，糊成一团 | 两种运动同时进行 | 先原地变形，再移动 |
| 主体缩小后认不出 | 画法只适合一种尺度 | 换一个在缩略图上也认得出的画法（背影、剪影、外轮廓） |
| 光晕把画面烧白 | 光晕大小是固定值 | 大小和强度随情境变化 |
| 远景发灰发土，或被照成亮黄 | 颜色写死，或者没考虑逆光 | 从天空采样，逆光时整体压暗 |
| 天空发灰 | 曝光不够，或者缺臭氧吸收 | 提高曝光、加饱和度；加入臭氧吸收后，黄昏天顶会变成蓝紫 |
| 结尾卡太长、一动不动 | 时长没按节拍算 | 2–3 秒，加缓慢推近 |
| 每段动画做完就停住几秒，像翻幻灯片 | 只给入场做了动画，留给读字的时间里画面冻结 | 读字时画面继续缓慢运动（starter 的整片推近就是这样）；没有要读的字就缩短这一段 |
| 画面里的数字和旁白对不上 | 写死在两处 | 都从同一份数据算出来 |
| 有几秒既没有新内容也没有字 | 分镜里有空档 | 补一句文字或一个动作，或者缩短这一段 |

## 对自己诚实

- 按“这是不是一条好视频”来判断，不按“规则有没有遵守”来判断。检查清单全过了，片子仍可能平庸。
- 不确定的地方直接告诉用户（比如“音乐是合成的，我听不到，只能从图上判断”），不要替用户下结论。
- 用户的反馈优先于自己的检查清单。用户觉得“和原来差不多”，就要换核心画面，不是继续打磨细节。
