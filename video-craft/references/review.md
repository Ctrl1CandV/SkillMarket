# 审查

先按目标设备的视窗和正常速度完整看一遍，记下观众可能错过的具体瞬间。联系表用来定位大范围的问题，原尺寸帧和切点帧条用来判断原因。静止、黑场、硬切、叠化和静音要结合分镜中承担的作用来看。只能取帧或测轨道时，记录实际验证到了哪一步。

## 看的顺序

0. **静音看一遍，对照内容设计**。关掉声音、不看字幕看一遍；看不了视频时，按每个段落中点做联系表（`--times`），逐格写下观众此刻看到了什么、明白或感受到了什么，和任务单里的内容设计对照：
   - 对观众最要紧的那几个时刻都到了吗？MV 的戳人句子、产品片里观众的那个麻烦、教学里卡住的那一步，各有专门的镜头吗？那一镜里有内容设计写下的物件或动作，而不只是天空、粒子和光效吗？
   - 高潮落在人的心情或问题的解决上，还是落在道具和奇观上？
   - 全片有几个场景，各回来几次？同一个场景回来而内容没有往前走，是内容设计里的时刻不够，补时刻，不是改剪辑。
1. **成片镜头表**。渲染出整片后跑 `python <kit>/shotlist.py out/film.mp4`（讲题加 `--mode lesson`，MV 加 `--song out/song/songmap.json`）。它列出每个镜头的起止和长度，并标出几类情况：
   - 连续同长的镜头，或一半以上镜头同长：剪辑在走网格；
   - 只把上一镜放大的切；
   - 黑场、白场，以及超过 2 秒（讲题 4.5 秒）几乎不动的段落；
   - MV 中既偏离拍点（`>120ms`）又不在唱词乐句起音上的切点，以及重复乐段（如第二次副歌）画面几乎未变的同构重复。

   每条标记要么改掉，要么在任务单里写下故意这样做的理由。这一步几秒钟就跑完，比人眼翻联系表更早发现节奏与段落重复问题。
2. **联系表**。短片可试 `render.mjs page.html sheet out/sheet.jpg --every 1`。整首歌先按段落各选一个时刻，例如 `--times 4,18,42,74,98,122,150,178,205,220 --cols 5 --w 240`，再去看有疑问的切点。快切段可用 `--every 0.5 --from 12 --to 16`。长片反复审图时，原尺寸帧留在工程目录，每轮只给模型看新改的几格，把问题、时间码和修改结果记成文字。会话中断后，凭这些记录和已存工程可以从渲染或复查继续。
   - 找出有无信息被挤在同一瞬间、空档是否合适、有没有动作和结果被剪开。
   - 和上一格几乎一样的格子会标“= same”，连续静止会在命令输出里列出。判断是留时间读、刻意停顿，还是忘了下一步。误冻时再缩短、恢复该有的动作或加合乎情境的运动。
3. **关键帧原尺寸**。用 `stills` 渲染开头、关键动作与结果、信息最密处和结尾。`montage.mjs` 可将几个候选并排，再打开原尺寸与实际播放尺寸核对。
   - 检查主体的轮廓与位置、反光和暗部、界面控件与真实状态、文字大小和对齐。
   - 看教程与软件演示时，回看动作前后同一对象是否还认得出。按实际播放尺寸暂停，看能否读全命令、选项、数值或最终结果。把关键镜头与原始录屏或数据对照。
4. **转场处的切点帧条**：`strip --at 9.85,18.2 --offsets -4,-2,-1,0,1,2,4`。
   - 匹配剪切查位置和形状，穿屏查是否露出边框，变形查旧对象是否可追踪。
   - 判断是否出现意外空帧、跳位、遮挡、难读的字叠字或错配的标题。声画有意错开时，检查时间与语义是否和分镜一致。
5. **字幕交接**。抽看句尾前后，核对字幕和说话、歌词或动作是否匹配，实际阅读时长够不够，平台控件会不会遮住。
6. **文字与版面检查**。`textcheck.mjs` 自动抽检 `#caps .cap`、`#lyric` 与 `#captions` 的安全边距和最小字号（横竖屏自适应 `min(W, H) / 30`）；课程讲题与密集图解另跑 `boardcheck.mjs` 清零公式堆积、重叠与无底衬穿字。画在 Canvas、视频像素或外部录屏里的文字用原尺寸帧查看。
7. **从成片解码抽帧**：

   ```text
   ffmpeg -ss 22.05 -i out/film-av.webm -frames:v 1 -update 1 out/dec.png
   ```

   核对文字边缘、渐变色带、暗部层次和高运动镜头。用户拿到的文件是这一步要看的版本。
8. **声音与实时播放**。试听最终成片的人声、音乐与环境音，检查起音、乐句与剪切是否衔接，确认有意留白前后有作用。用 `mixcheck` 的曲线和 `audiocheck` 的频谱定位技术问题。 [声音](sound.md)

改完复看受影响的镜头和相邻的切点，最后确认交付文件包含已验证的修订。用片段、帧或时间码描述证据。

## 常见问题：现象、原因与改法

| 现象 | 原因 | 改法 |
|---|---|---|
| 画面好看，观众却无动于衷 | 没写观众是谁、处在什么处境；内容放在了好看的道具和奇观上 | 回到 SKILL.md 第 2 步内容设计，把内容放在对这群人最要紧的时刻 |
| 同几个场景或镜位来回切 | 内容设计里的时刻太少，只好用同一组画面填满时长 | 补上故事或问题里不同的时刻，再排镜头 |
| 开头意外空白，错过第一句旁白 | 所有元素都从 0 秒开始缓慢入场 | 按开头需要提前放好形状或标题，必要时设为负的入场时间 |
| 上一镜的元素残留在下一镜 | 父层 `visibility:hidden` 被子元素的 `visible` 覆盖 | 用 `display:none`，或者逐个设透明度并在 `seek` 里统一归零 |
| 同一位置的字幕叠到读不清 | 交叉淡化 | 在句间直接切换，或等上一句退完再进 |
| 叠化时两镜的图注互相遮挡 | 文字跟画面一起叠化 | 分开安排图注和画面的切换，把叠化留给仍能辨认的形状与色面 |
| 标题已经换了，图还停在上一镜 | 文字和图的时间意外错开 | 用同一换场时刻，或在分镜里明确前后关系 |
| 太阳或主体正好穿过标题 | 字的位置和镜头路线没一起排 | 按镜头路线把字放到另一侧 |
| 编码后文字周围有方框 | 逐行遮罩切掉了文字阴影 | 遮罩留内边距并用负外边距抵消 |
| 只有编码后的渐变有一圈圈色带 | 编码量化 | 对比提升编码质量、降低渐变强度或加轻微颗粒后的结果 |
| 要变形的元素从画面外飞进来 | 它在变形开始前已经滚出画面 | 让它全程留在画面内，或换一种排布 |
| 推进时露出手机边框 | 放大还没盖满画面，新画面就出现了 | 推进先完成，再出新画面；推进用加速曲线 |
| 拉出时边框透过半透明画面 | 全屏画面先淡出，手机后缩小 | 让全屏画面跟着屏幕一起缩小 |
| 一边飞一边变形，糊成一团 | 两种运动同时进行 | 先原地变形，再移动 |
| 主体缩小后认不出 | 画法只适合一种尺度 | 换一个在缩略图上也认得出的画法（背影、剪影、外轮廓） |
| 光晕把画面烧白 | 光晕大小是固定值 | 大小和强度随情境变化 |
| 远景发灰发土，或被照成亮黄 | 颜色写死，或者没考虑逆光 | 从天空采样，逆光时整体压暗 |
| 天空发灰 | 曝光不够，或者缺臭氧吸收 | 提高曝光、加饱和度；加入臭氧吸收后，黄昏天顶会变成蓝紫 |
| 结尾卡读不完，或读完很久还未结束 | 可读时间与音乐、画面收束对不上 | 在平台尺寸下读一次，按读完的时间、尾音和签名画面定片尾长度 |
| 画面像幻灯片：纯色底、居中图标、一行标题 | 没有空间、光和层次 | 按[用代码画出完成的画面](drawing.md)从后往前分层，先定主光；或者按[版面式动态设计](graphic.md)排成有网格、字号对比和细节层的版面 |
| 连续几个镜头一样长，切点与音乐无关 | 镜头表按固定秒数排 | 按段落和乐句排，`shotlist.py` 复查 |
| 切到近景只是放大上一镜，糊或有方块 | 缩放位图代替切镜 | 换角度、换尺度，按新尺度重画并加入新细节 |
| 每段动画后节奏都塌下来 | 只设计了入场，停住之后没有留给观众继续看的东西 | 缩短空档，或给观众时间看清真实结果。需要持续空间感时可试 [starter](../examples/starter/scene.js) 的缓慢推近 |
| 演示点击和结果像是无关的 | 关键控件被指针遮住，或切掉正在变化的状态 | 停在能一起看到控件与结果的裁切里，等结果出现再剪走 |
| 画面里的数字和旁白对不上 | 画面与配音稿引用了不同的值 | 共同使用同一数据，人工复核已录好的音轨与字幕 |

## 对自己诚实

- 逐项核对交付文件的事实、可读性和音画技术问题，再整片观看一次，判断观众能不能跟上关键动作、看懂主题或感到预定的变化。
- 不确定的地方直接告诉用户（比如“音乐是合成的，我听不到，只能从图上判断”），不要替用户下结论。
- 用户指出问题时，先定位到他们实际看到的画面和时间。若问题出在观点、气质或叙事，回到内容设计和段落；若出在局部可读性、听感或切点，修改对应镜头再复看。
