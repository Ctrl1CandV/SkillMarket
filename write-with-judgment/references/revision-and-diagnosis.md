# 实质改稿与文本诊断清单

用于实质改写、多版本取舍与审校诊断。日常字句微调直接输出成品即可；用户要求解释改动或只做审校时，按本文结构处理。

## 一、改稿前：先认准原稿哪些地方不能改掉

动刀前通读一遍原稿，圈出已经成立的亮点：
1. **准确的判断与分寸**：原稿对证据强弱的把握（如“初步迹象”“在中小样本下成立”）、对未知原因的坦诚（如“为什么会这样，现在还没查清”）。
2. **有现场感的细节与独特观察**：作者亲眼看到的动作、顺手举出的真实例子、带个人印记的冷峻或幽默句子。
3. **有效的呼吸与停顿**：为强调某个转折特意放慢的铺垫，或干脆利落的一句定音。

改稿的目标是帮原稿把没立住的地方撑起来，绝不是把有棱角的作者声音磨成千篇一律的公文或冷淡白描。

## 二、七类实质病灶的动刀方向与复查项

| 原稿病灶 | 动刀动作 | 改后复查（防止矫枉过正） |
| --- | --- | --- |
| **1. 只有干瘪结论，或方案像 5 条正确废话** | 回到材料算清数字反差、因果链条与真实摩擦；提对策压到 2–3 条并“写一条、配一坑”；缺材料时收窄或标 `〔待确认：……〕` | 验算比率与分摊的分子分母；确认没靠随手编造随机整数装作有细节 |
| **2. 均温流水账，过场和主场景一样长** | 挑出 1–2 个主场景/核心关节分配过半篇幅写透，其余赶路、寒暄与常规背景压成 1–2 句快剪 | 检查虚构创作是否敢给情绪与温度；非虚构经历改写是否守住零新增感官 |
| **3. 材料有据，但读者读到半途接不上** | 在读者产生疑问的位置提前引入对象与前提，或换一个更具体的切口进场 | 检查是否提前剧透了叙事本来要留到后文的悬念 |
| **4. 几段话在同一处原地打转，或段段甩金句** | 合并同义复述，按因果推进重分详略；全篇金句限流至 1–2 处，其余段落平实落到后果或条件 | 检查被删掉的句子里是否藏着独立的限定条件、例外提醒或情绪铺垫 |
| **5. 说话姿态偏离场合（居高临下、报幕或过度讨好）** | 删去“先给结论：”“先把账算清楚：”等报幕起手，回到平视直说 | 检查是否把作者原本明确有力的立场改成了模棱两可的退让 |
| **6. 强调和预告很多，后文却没分量** | 把“极具颠覆性、必须高度重视”换成真正站得住的差异与证据；普通事项放平语气 | 检查真正的安全警示、高风险提示是否依然醒目 |
| **7. 局部句子漂亮，放进全篇却抢重心** | 从前后段落的走势重看该句：喧宾夺主的枝节收短，把篇幅让给核心关节 | 通读相邻三段，确认主线推进顺畅、结尾分量相称 |

## 三、严格区分改稿中的三类变化与四项复核

修改幅度较大时，在内部（或按用户要求在交付说明中）分清三类变化：

1. **只动了组织与表达**：事实、观点、时态与不确定程度完全未变，仅调整了进场切口、篇幅配额、操作前提顺序或句法呼吸。这是最安全的默认改写范围。
2. **展开了材料内部的隐含关系**：没有引入外部新事实，而是把原材料里已有的数字做对比、把已给代码代入边界验算。这类展开能显著提升文章厚度，直接采用。
3. **新增了外部事实、经历、感官或承诺**：必须来自用户补充的材料或明确的虚构创作授权。在非虚构改稿中，待确认的外部原因用 `〔待确认：……〕` 标出，绝不混入正文冒充原作者经验。

**出稿前四项快核**：
- **数值口径**：凡是新算出的占比、倍数、均值贡献，分子与分母是否与文字表述一致？无外部数据时是否避免编造无来源随机整数？
- **时态进度**：原文的“将要/正在/已经”是否原样保留，没有把计划中的排查写成已完成？
- **叙事边界**：非虚构经历是否零新增感官与心理？虚构叙事高潮是否写透而非冷白描流水账？
- **零报幕与零规则台词**：开头是否删净“先给结论：”等报幕冒号，正文是否零“这里不给原因判断以免误导”“比草稿里那句”之类元话语？

## 四、“只作诊断”模式的标准输出结构

当用户要求“先看看这篇稿子有什么问题 / 帮我审校一下，先别大改”时，直接按下面四步给出紧凑、可落地的诊断报告（无需空谈写作理论，也不拿规则条目给文章打分）：

1. **整体印象（1–2 句）**：直说读第一遍时最直观的感受——主线清不清楚、读到哪里开始发闷、失温或卡壳。
2. **已经立住的地方（1–2 点）**：明确指出原稿哪一段、哪一个观察或哪一句判断写得好，改稿时应当保留。
3. **核心问题与具体位置（1–3 点）**：
   - 引用原稿的具体句段；
   - 直指问题本质（例如：“前两段把买早点、晒被子写得和核心重逢一样长，把高潮摊薄了”“第 4 段把备份配置写在了执行升级命令后面”）；
   - 给出明确的修改动作。
4. **局部改写样板（1 段）**：挑原稿最核心或问题最集中那一段，直接附上一版改好的文字，缺数据处用 `〔待确认：……〕` 标出，让作者一眼看清“按建议改完后长什么样”。
