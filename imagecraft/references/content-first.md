# 准确内容与丰富视觉：不必二选一

先固定准确的文字、数值和关系，**不等于必须用 HTML/CSS/SVG 重画整张图**。内容规格负责验收，图像模型仍可负责整幅视觉；只有需要改错或独立排字时，才用程序处理相关区域。用户想要生图的材质、插画和多样风格，不应拿一张朴素框图替代后就称效果更好。

本地生成 CLI 仍只有 ComfyUI 后端；经授权的官方原生云端生图是另一条执行路径，见 [云端备选](cloud-fallback.md)。本技能另有 [局部修补与排字工具](raster-repair.md)，但没有通用自动布局、OCR 推断原文或自动修复任意架构图的功能。

## 按效果与总成本选择

| 路径 | 什么时候值得用 | 代价与边界 |
|---|---|---|
| 直接生成完整图，再核对 | 网页视觉图；追求插画、材质和整体风格，且模型能在当前任务中给出可用文字 | 仍会错字、漏控件或连错边。内容对了可以直接交付 PNG，不必为了使用代码而重画 |
| 无字素材＋真实文字/确定连线 | 内容必须准确，素材区域与留白可提前规划；标题、海报、网页首屏及分层示意图 | 生成后仍要检查无字、留白和素材数量；排字、布线与合成不是零设计成本。画面主体仍来自生成素材 |
| 生成图＋少量局部修补 | 原图很好，只有几处错字或孤立错线，周围背景可修复 | 需要可靠原文、明确位置及验收。简单底色上的局部修补可能比整图重建便宜，不必默认上分割模型 |
| 内容→SVG/HTML/CSS | 要真实数据图、可编辑结构、密集表格、可交互前端，或整图错误太多 | 准确性与修改方便，但首次设计、编码、布局和字体检查有成本；不能保证保留原图美术表现 |

网页**视觉参考**允许用户认可范围内的小瑕疵，但不能把错数据、假控件或大块乱码隐瞒为完全可用。正式架构图不设“差不多”的容忍度：逐字、逐节点、逐边核对，有遗漏、错向或歧义就不标完成。准确架构图也可以是经核验的生成图或局部修正版，不强制全部改成矢量框图；需要可编辑性时另交结构源。

## 从源头减少问题

1. **独立保存内容。** 从需求、真实数据或用户确认的节点清单记录原文、数值与单位、节点 ID、边的起终点和方向。没有原文时询问，或明确采用合成演示数据；乱码不能作为事实来源。节点名称与 ID 分开。
2. **让视觉和内容各有空间。** 文字尽量简短，给标签及连线留干净通道，不让它们压在复杂纹理上。丰富的插画可以集中在节点/素材内部；少量文字不代表视觉必须贫乏。对无字素材明确比例、位置、留白与禁止文字，生成后仍要看图。
3. **区分提示与硬约束。** 在提示词中逐字给出标题、加引号、列出全部边，或提供正确参考图，都不等于锁定像素。整图再生成可能改变正确文字和连线。本地首版参考编辑不是精确蒙版编辑，不能把“保留原字”当作已实现的保证。
4. **需要确定性时，不重绘内容层。** 让模型生成视觉层，用真实字体排字、明确路径画线，最后合成。程序不必画人物、产品或整个网页；也可以仅在无字整幅底图上补文字，不使用 HTML。最终合成后不要再把文字/连线层送回整图扩散，并宣称它会原样保留。
5. **按交付用途核验。** 网页看层级、主要文字及数据、操作数量和整体效果；架构对照完整边清单核对源、终点、箭头方向、无重复/多余/遗漏及歧义。OCR 只能辅助查字，不能证明拓扑。真实字体也要检查缺字、溢出、遮挡与整体排版。

图表的曲线、坐标及数值如果代表真实结果，应从原始数据渲染，不能用模型画出“看起来对”的曲线。用户只要视觉概念图时可使用明确标注的合成数据。HTML/SVG 内容须转义，不把文案当脚本或外部资源 URL；本机字体能用于渲染不等于可以随技能分发字体文件。

## 已有生成图如何处理

保留原图，先把问题分成**字错、线错、结构缺失**。两处字错不要求重建整个页面；一条孤立错线可以单独修正。但改两个标签不能补回缺失组件，把错线擦掉也不等于剩余拓扑正确。

- 简单/平缓背景、少量错误：可用已有 OpenCV Telea 擦除局部，再用 Pillow 补指定文字或路径。工具使用周围像素估计背景，不会恢复真实原文；少量渐变背景的成功不能外推到复杂纹理、遮挡和大面积重建。
- 大量乱码或连线交织：先算定位、擦除、重排和验收成本。必要时改用文字能力更好的已授权生成路径，或重建内容层；不默认反复抽图、安装 SAM3/LaMa 或增加模型。
- 只认可风格、无需原像素：可以重建可编辑版本，但明确这是重建，不是无损修复，也不是从乱码恢复了原文。

修补工具只验证输入、尺寸、文字框和像素变化范围，**不会自动批准文字含义或拓扑**。例如，完整图有七条边，仅修一条后仍要重新核对全部七条；实际查看修复接缝、箭头及标签后才交付。源码、原图、蒙版、透明叠加层和最终图分别保存。

## 成本怎么算

计入首次设计、宿主推理、原始生成、内容判断、掩膜定位、典型修改、追加推理、审图、依赖与维护。已经有模板/坐标后，CPU 排字或补线可以很快；这不是从需求到交付的总耗时。无新增生图调用也不等于总成本为零。

只改标题、数值或节点显示名时优先复用素材；拓扑或版式改变时重新评估布局和布线。不要用两处局部修复的耗时估算整张复杂图的修复成本，也不从一个成功样例推定所有模型或提示词的质量。已经获认可的人物、风景不因文字问题重新选型。

## 可查证的方法与素材

核对日期：2026-11-01。下列项目不是自动安装项；代码、权重、字体与素材许可证分别核验。

- [OpenCV inpaint](https://docs.opencv.org/4.x/df/d3d/tutorial_py_inpainting.html)：小范围局部修补；本机已有环境可复用。不是语义生成模型，也不识别原文。
- [AnyText2](https://github.com/tyxsspa/AnyText2)：已有公开代码/checkpoint，利用字形、位置、字体、颜色条件提高多语言文字控制，而非仅强化提示词。官方要求另建环境、下载权重并建议至少 8GB 显存；论文的文字准确率也不是 100%。本轮未安装或实测，不假定兼容现有 FLUX 工作流，也不为这一功能直接改原环境。
- [AntV Infographic](https://github.com/antvis/Infographic)、[D2](https://github.com/d2lang/d2)、[Satori](https://github.com/vercel/satori)：可参考内容/模板/主题分离、结构与布线分离、显式字体渲染的方法。AntV [关系图画廊](https://infographic.antv.vision/gallery?filter=relation) 已看过；本轮未安装这些项目，Satori 也不是完整浏览器 CSS 的等价实现。
- [AutoFigure-Edit](https://github.com/ResearAI/AutoFigure-Edit)、[IOPaint](https://github.com/Sanster/IOPaint)：复杂旧图分割重建或神经修复的候选。额外模型、环境和多阶段处理均需预算，本轮未安装或实测。
- [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji)：有可复用图形素材，[MIT 许可](https://github.com/microsoft/fluentui-emoji/blob/main/LICENSE)要求保留相应版权及许可声明。挑选具体文件后再记录来源与许可，不把整库默认下载进技能。素材也不自带正确的架构关系。
- [unDraw 许可](https://undraw.co/license)：虽允许许多个人/商业用途，但含 AI/ML 训练、验证/测试以及自动集成等限制；不能仅凭“免费商用”就把图库抓进本技能或评测集。本轮未使用其素材。

现有有限样例覆盖中文静态页、固定拓扑 SVG、一个本地无字 Hero 的真实字体合成，以及生成图的少量标签/箭头修补。任意拓扑自动布局、复杂旧图像素保真恢复、自动定位全部错误、跨机器字体和生产级云端编排仍未验证。网络素材不是无条件可用的整张答案，采用前要同时检查内容匹配、具体文件许可和用途限制。
