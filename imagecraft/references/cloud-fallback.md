# 云端路径：用已有的 GPT 订阅

核对日期：2026-11-02。这条路已实际跑通，共 11 张图（9 张满意、2 张需重出），但**执行者不是本技能的 Python CLI**：CLI 只有本地 ComfyUI 后端。云端由宿主侧的官方客户端（Codex app-server 或可用的原生图像工具）出图，本技能负责写契约、验收、记录和额度观察。

## 什么时候走这条

本机不适合（见 [三层分工](routing.md) 的硬件闸），或者这张图要求高、可以接受栅格成品。需要反复修改的不要走这里。

## 一次性的前提

1. 用户已有的订阅登录能正常使用，且当前会话确实有原生图像工具（查 `capabilities/read` 里的 `imageGeneration`；为真仍不保证本次回合暴露了工具）。
2. 网络能到 `chatgpt.com`。本机曾因 DNS 污染把该域解析到伪造地址，导致代理 TLS 握手失败，表现为“提交了但没有任何产物”；这不是封锁也不是额度问题，换 DoH 或让代理做远程解析后即恢复。
3. 用户同意把本次提示词与指定参考图交给该服务。

## 每次怎么做

先把内容写成契约（同 [内容契约法](routing.md#内容契约法)），然后：

1. 一次只提交一张，提示词里写满逐字清单与禁止项。
2. 提交后读回执里的状态：有完成的原生图像项且拿到可保存文件，才算生成成功。
3. 把文件取回本机，放 `<project>/.imagecraft/jobs/<slug>/`，不塞进本机 ComfyUI 任务目录。
4. 打开图逐项核对文字、结构、箭头；偏离要记录。
5. 记录提交前后的额度读数，差值不是固定单价。

## 额度怎么算

- 读的是 `usedPercent`（**已用**）。用户界面显示“剩余 87%”时，接口读到的就是 13%。汇报时必须说清是已用还是剩余。
- 实测每张约 2–3 个百分点，随尺寸和复杂度浮动，不是固定价格，也不是服务端硬上限。
- 只有 `codex` 一个桶，没有独立的图像池；生图与普通回合同池扣减。官方“image generation usage limits”页面在本机 403，未能核实，所以只能说实测现象。
- 失败尝试也可能计入。回执丢失时先查原请求，不重交、不换服务、不买 credits。

## 已知限制

- 产物是栅格图：改一个字要重出；要做多语言版本、要更新数字，成本按整张算。
- 输出尺寸由服务端决定，不保证等于请求值（曾请求 1024×1024 得到 1254×1254）。
- 单张成功不代表这类任务稳定；没有多 seed 统计。
- 会自作主张添加没要求的东西（如坐标轴刻度），也会漏小字。所以必须逐项核对。
- 放在 16:9 幻灯片里通常需要裁边或留白。

## 证据

以下为本机历史记录，用于说明边界，不是长期保证。

## 先判断是否值得在这台机器上运行

权重磁盘大小不是显存或 RAM 下限。本地推理的内存开销取决于权重精度、卸载策略、尺寸、参考图及竞争进程；降低到 512 像素也不会让全部模型权重缩小到四分之一。不要从一台 16GB 显卡的成功样例推定 4GB/8GB 显卡、集成显卡或低内存笔记本一定可用。

没有安全余量、已有 GPU 任务，或用户不愿安装本地环境时，先给出备选，而不是自动下载另一套量化模型。云端路径不在本机执行图像推理，因此不要求本机下载这套权重或具备 CUDA；仍需客户端、网络、账户权限和可用额度。

## 三种路径，不混用权限与账单

| 路径 | 适合什么 | 必须区分的边界 |
|---|---|---|
| 官方 Codex 原生生图，或当前宿主已暴露的官方图像工具 | 已有支持该能力的订阅，希望 Agent 协助出图 | 能力由产品、账户、登录方式和本次会话决定，不是任意 Agent 换用 OpenAI 文本模型就能获得 |
| ChatGPT 官方网页或应用 | 少量图片、愿意人工交接提示词和下载结果 | 网页里能生图，不代表 Codex/其他宿主有同样的工具、额度或文件落盘能力 |
| OpenAI 官方 API | 跨宿主自动化、稳定的程序化接入与任务记录 | 使用 API key 和 API 账本；订阅不等于 API key 或通用免费额度。若账户有已激活赠款，应另核验余额与适用条件 |

官方 Codex 文档给出了交互式 CLI 的 `$imagegen` 用法。订阅登录下，原生生图计入 Codex 通用用量；官方当前估计，相似回合启用生图会平均快约 **3–5 倍**消耗包含额度，具体受质量和尺寸影响。包含额度耗尽后可能继续消耗已有 credits，因此不能称为“无限免费”或默认不会产生额度支出。Codex 的 Free 计划当前不提供原生生图；不要把其他产品的免费图片权益套过来。

改用 API key 登录时遵循 API 计费规则，而不是套用 ChatGPT 包含额度。任何赠款、工作区限制和账户余额都应由用户在官方账户页面确认，不预设所有 Plus/Pro/Business 账户相同。

## 如何估计一张图占多少五小时额度

**3–5 倍不是 3–5%。** 官方没有给“稍复杂图片”统一的 Plus 占比。若同一模型、相近上下文的一次普通回合占该窗口的 `p%`，只能暂以约 `3p%–5p%` 作规划示例：普通回合 0.5% 对应约 1.5%–2.5%，1% 对应约 3%–5%，2% 对应约 6%–10%。这些基线是假设，不是账户实测，也不是每张图片的保证上下限；尺寸、质量、多次修改和 Agent 自身回合都会影响用量。

核对当日的价格页按不同模型给出不同的 Plus 五小时本地消息估计，并强调不是固定条数；同页写明 Pro 当前没有五小时限制，仍可能有周限额及其他池限制。因此不能把“20×”简单理解成每张占比除以 20，也不能把 ChatGPT 网页图片权益混入 Codex 窗口。实际账户返回的窗口、池与重置时间才是测量依据。

最小标定是在用户允许后，用 Plus 账户的全新短上下文生成一张非敏感样例，读取同一账户、同一额度池在生成前后的 `usedPercent`、`windowDurationMins` 和 `resetsAt`。暂停该账户的其他 Agent 任务，排除窗口重置，等到用量更新稳定后再比较；有并发使用或跨重置时不能将差值全部归因于图片。整数百分比可能掩盖小消耗，差值为零不证明免费。需要多张才能提高分辨率时另行确认预算，不自动批量测量。不能从 Pro 测量值直接反推 Plus。

## 一次登录与候选接入方式

官方支持 `codex login` 后在浏览器完成 **ChatGPT 订阅登录**。Codex 缓存并复用登录状态，在使用期间自动刷新令牌；退出登录、撤销授权、凭据失效或组织策略变化时仍可能要求重新登录。持久存储使用官方文件或系统凭据库，由 Codex 自己管理；`ephemeral` 只在当前进程内保留，不满足跨进程复用。不要为了持久登录读取、复制或改写 token，也不要默认更改已有客户端的认证存储配置。

对于其他 Agent，候选方案是让本机官方 `codex app-server` 负责订阅认证与原生图片工具，imagecraft 只做已授权任务的编排、额度观察和产物校验。这不是通用 OpenAI API，也不是把订阅 token 交给别的模型供应商。固定选择一个账户；需要多个账户时使用独立配置/状态目录，并实际核验账户隔离，不抢写同一认证文件，不自动轮换账户规避额度。客户端可用独立 `CODEX_HOME`，但需先确认宿主配置及凭据存储约束。

官方 CLI 0.154.0 的 `app-server` 已在外部限定探针中通过订阅账户查询、跨进程登录复用、原生图片回执及文件解码测试。相关协议字段包括：

- `modelProvider/capabilities/read` 响应含 `imageGeneration`，可用于前置检查；为真仍不证明本次模型回合暴露了工具。
- `account/rateLimits/read` 提供整数 `usedPercent`、窗口时长及重置时间；识别具体池，不假定 `primary` 永远是五小时窗口。
- `item/completed` 可报告 `imageGeneration` 项及可选 `savedPath`。必须确认状态、最终文件、解码和内容；只有事件或内联展示、没有可取得文件时，不能报告交付成功。

### 本次限定实测

经用户授权，复用现有 Plus 登录，不重新登录，不读取认证文件，也不使用 API key 或购买 credits。首次尝试在在线额度查询阶段遇到网络错误，模型提交数为零；随后显式沿用已有代理完成一次提交。这不能单独证明首次网络故障的根因。

- 客户端提交一个回合，收到一个完成的原生 `imageGeneration` 项，回合耗时 **44.699 秒**。从原生内联结果取回 PNG，解码并实际看图；无字纸张与玻璃素材满足此次视觉用途。
- 实际图片 **1254×1254**，不是提示词请求的 1024×1024。精确尺寸、质量参数及回合内调用次数的服务端硬限制仍未验证。
- 同一 Codex 池、相同窗口与重置时间下，五小时整数用量 **0% → 2%**，周用量 **25% → 25%**，三次后置查询一致。差值包含调度回合及取整影响；未独立排除其他同账户活动，不能宣称“每张固定 2%”、周额度免费或据此承诺可生成张数。
- 控制模型返回 `gpt-6-astra`，图像模型 ID 未提供；不能把控制模型或官方介绍当作本图的图像模型身份。

以上是第一张无敏感参考图的样本。随后另经授权进行了两张文字/视觉样例，各一次提交、一次原生图片返回，没有质量重抽：

- **中文网页图**：1536×1024，回合 58.871 秒；指定的三处中文、四项导航、三项指标及其数值、MODEL、三行 RUN 编号和 Done 均在实际画面中核对通过，视觉素材丰富。它仍是演示数据的静态图片，不是网页实现，也不证明任意长正文都正确。
- **中文架构图**：1536×1024，回合 79.864 秒；标题与六个标签都对，但七条边中一条连错目标。原生图不能直接按准确架构验收；用 CPU 擦除那条孤立错线再补正确路径，复核六节点/七边后才接受修正版。画面仅约 0.75% 的 RGB 像素变化，其余插画与原有文字保留；没有重生成。
- **额度读数**：同池、同窗口/重置，五小时 `2% → 4% → 6%`，周读数仍 25%。本轮两张期间观测约 +4 个百分点，不是每张固定价格，也未独立排除同账户其他使用。第二张首次后置查询成功得到 6%，后续复查网络失败，未完成三次稳定回读。
- **状态必须分层判断**：第二张原生回合/图片项均 completed、文件已解码，但外部探针在后置额度查询异常后把总状态写成 `inspect_existing_thread_do_not_resubmit`。这是额度观测不完整，不是图片生成失败；保留原报告及单独的视觉评审，不重交请求。正式适配器须分别记录提交、生成、取回、审图、额度观察和清理状态。

三张样本的图像模型 ID 均未提供。这里没有编辑保真、复杂拓扑或长期稳定性保证，不需要再次处理其他账户授权。

若实现该适配器，应只给新会话发送本次批准的提示词和参考图，不让其默认扫描仓库；运行前核验订阅模式，禁止静默切 API key 或购买 credits。先只提交一个单图任务、禁止自动重抽；回执不明则查原请求而非重交。适配器能限制自己发出的任务数；原生 Agent 回合内的调用次数与单次张数能否强制限制，要另行验证，不能把提示词里的“只生成一张”当成硬上限。额度百分比预测也不是服务端硬预算。跨 Agent 启动仍要符合宿主委派规则。**外部限定探针已有上述证据，但正式适配器、恢复与预算边界尚未完成；Python CLI 仍无此后端。**

## 使用订阅路径前的核验

先确认用户允许把**本次提示词及指定参考图**交给该云服务，并确认允许消耗的额度/图数。已有订阅并不等于已授权上传私人照片、未公开设计或论文。只发送需要的素材，不把本地配置、完整运行日志或工作目录打包上传。

检查当前会话是否真的有原生图像工具，以及能否返回最终图片和可保存文件。只知道 CLI 版本、登录成功或功能开关开启，均不足以证明这条链路可用。官方文档中的交互式用法不能替代对当前版本 `codex exec` 的实际验证；没有工具就停止，不用 Pillow/SVG 占位图冒充原生 AI 生图。

可由用户在官方交互式客户端发起一张无敏感素材的小样，并要求使用原生生图、不要转到另外计费的 API、返回真实产物及保存位置。若要由当前宿主另启一个 Codex/其他 Agent 会话，仍须遵守宿主的委派授权规则；本指南不授权后台启动其他 Agent。

不要读取或搬运浏览器 cookie、原始会话令牌或其他客户端的认证文件来拼接非公开接口。缺少官方接入能力时，提供人工交接方案，或等用户明确授权后设计 API 接口，不把订阅包装成不受支持的 HTTP 服务。

## 云端也要保存来源、查验结果

单独记录实际服务/宿主、模型标识（仅在服务确实提供时）、输入及输出哈希、最终文件位置、请求/产物标识和观察到的限制。没有提供 seed、耗时或计费数据就写未提供，不套用本地 ComfyUI 字段或估造数值。分别记录请求数与实际返回图数，只有后端确实提供的限制才能当作硬上限；估算费用不等于服务端账单硬上限。

原生工具生成的图片仍需检查真实文件、解码、尺寸和内容。文字、物件计数、手部、参考一致性及图的连线都可能出错；云端不是免验收通道。需要准确标题、数据或拓扑时，先按 [内容前置](content-first.md) 固定文案和关系作为验收依据。可以直接生成整图后核对，少量问题用 [局部修补](raster-repair.md)，也可以使用无字素材与确定性内容层；不强制改成纯 HTML/SVG，不把提示词当硬保证。代表真实结果的曲线和数据必须回到原始数据，不能靠生图猜测。

本地 CLI 的 `verify/review` 校验的是其自身 ComfyUI 任务结构，不能将云端文件塞入本地任务目录来伪造来源。云端产物应放在独立目录，由宿主另行校验；将来新增程序化后端时再实现独立回执、错误状态与测试。提交回执不明时先查原请求，不自动重交、换服务、追加额度或购买 credits。
