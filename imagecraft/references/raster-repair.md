# 局部修补、真实排字与连线叠加

`scripts/repair_image.py` 是独立的 CPU 工具，不是 ComfyUI 的精确蒙版扩散编辑，也不是云端后端。它保留原 PNG，在显式指定的矩形内用 OpenCV Telea 估计背景，然后以真实字体/路径叠加内容。`masks: []` 时只做叠加，可以在无字生成底图上排字，不需要擦图或重新生成。

## 适合与不适合

适合少量、明确位置的错字/孤立错线，以及已有留白的无字素材。原文和正确关系须由用户需求或可靠清单给出，不能猜乱码。复杂纹理、文字与物体粘连、大面积重建、自动识字、拓扑推断和自动连线路由不在范围内。

用已有 Python 环境，叠加需要 Pillow、numpy，擦除另需 OpenCV。缺依赖时停止并报告，不自动安装，不修改原 ComfyUI 环境。工具不加载生图权重、不用 CUDA、不调用云服务；字体文件由用户提供本机合法可用路径，不随技能分发。

## 使用

1. 保留原图并实际看图；按**原图像素坐标**选区域，不用缩放预览上的坐标直接套用。先核对文案/关系，再决定需擦除的区域。
2. 在仓库外保存 JSON 规格，绑定原图 SHA-256 和尺寸。矩形是 `[left, top, right, bottom]`，右/下边界不包含在擦除区内；坐标、宽度及字号必须是整数。
3. 运行到一个不存在的绝对目录：

```text
<python> <skill>/scripts/repair_image.py --source <source.png> --spec <repair.json> --output <new-absolute-directory>
```

规格示例（尺寸、哈希、区域、字体路径均须替换成实际值）：

```json
{
  "schema": "imagecraft.raster-repair/1",
  "source_sha256": "<source-file-sha256>",
  "size": [1536, 1024],
  "masks": [{"rect": [100, 100, 260, 150]}],
  "texts": [{
    "text": "任务队列",
    "box": [100, 100, 260, 150],
    "font_file": "C:/Fonts/your-licensed-cjk-font.ttf",
    "font_size": 28,
    "color": "#14304A",
    "align": "left"
  }],
  "paths": [{
    "points": [[500, 400], [500, 500], [750, 500]],
    "width": 6,
    "color": "#288DDD",
    "arrow": true
  }]
}
```

这不是一套通用架构图坐标，只是格式示例。路径按点的顺序绘制，箭头朝最后一个点；必须由宿主核验是否真正指向目标节点、是否遮挡其他元素。仅补字时 `paths` 可为空；仅补线时 `texts` 可为空；没有错误内容需要擦除时 `masks` 可为空。三者至少有一个操作，每类最多 32 项。

## 验证与输出

输入限单帧、不透明、8-bit RGB/RGBA PNG，≤32 MiB、≤24MP、方向已规范化。不接受需要 ICC/gamma/色度转换的源图；如需转换，应先显式生成单独的规范化副本，重新看图、计算哈希和选择坐标，而非悄悄改变原图。JSON ≤64KiB，禁止网络共享路径。

- 擦除区合计不能超过全图 10%；这是保守范围限制，不是质量保证。
- 文字每项一行、1–200 字符、字号 8–160；字体为已有 `.ttf/.ttc/.otf`，左对齐或居中。文字放不下就报错，不悄悄缩字、改文案或裁切。字体覆盖与真实字形仍需看图，`fits` 不代表没有缺字。
- 路径 2–16 点、宽度 1–24；检查短末段、越界与箭头裁切，不做自动布线。
- 比较解码 RGB 像素，确认变化未超出**擦除蒙版或实际叠加层**。这不证明所选区域合理，也不证明语义正确；遮住旁边内容、擦除接缝或错误箭头仍需实际检查。
- 输出 `image.png`、`erasure-mask.png`、`overlay.png`、`spec.json`、`report.json`，记录原图/产物/工具哈希、变化范围和耗时。已有目录拒绝写入，原图不覆盖。

退出码 0 只代表操作及技术检查完成；状态仍是 `repaired_visual_and_semantic_review_required`。实际打开最终图片，核对文字、节点及所有边，再单独保存视觉/语义评审。局部修两处字不代表整页乱码或缺失组件已解决；原生生成、CPU 修补和整图重建必须分开标注。

报告中的 `repair_seconds` 是给定内容和坐标后，函数内导入、处理、读取字体/图片及写出 PNG 的时间，不含确定内容、找错、定位、进程启动和审图，也不是完整交付报价。简单背景的快速结果不能外推到复杂纹理修复。修改内容时保留素材、规格和旧产物，用新的输出目录生成派生图。
